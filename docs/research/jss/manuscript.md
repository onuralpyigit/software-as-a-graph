# Abstract

Publish–subscribe middleware decouples distributed components in space and time, but conceals cascading failure paths, leaving architects without pre-deployment evidence on component criticality. Software-as-a-Graph (SaG) introduces a graph-theoretic framework that models event-driven systems as typed multigraphs and derives explicit dependency flows from configuration manifests. We evaluate learned cascade-impact rankers—graph neural networks, hybrid engines combining neural models with topological priors, and dynamic simulation surrogates—across twelve synthetic architectures under leave-one-scenario-out cross-validation and zero-shot on five open-source system models, against three failure simulators.

We demonstrate that derived dependency graphs enable highly effective learned ranking: graph attention networks achieve $+0.08$ to $+0.11$ gains over raw multigraphs, reaching Spearman $\rho = 0.748$. That is level with, but not equivalent to, the number of direct dependents ($0.764$), a reference that restates the reachability simulator’s first wave, resting on the degree features the networks receive. Crucially, on high-fidelity dynamic queue-flow simulation whose labels cost $12.7$ CPU-hours ($\sim 355.6$ Wh), a learned surrogate over dependency features ranks held-out architectures above every closed-form approximation ($0.799$ against $0.706$), significantly outperforming analytical baselines ($+0.094$, $p = 0.019$) and enabling Green CI/CD by amortizing expensive discrete-event simulation. Under multi-criteria failure involving structural fragmentation, hybrid architectures maintain robust stability ($\rho = 0.585$) where pure neural models collapse ($\le 0.334$). Zero-shot transfer reaches $\rho \approx 0.81$ on unseen open-source architectures (PR-AUC $= 0.838$). Our findings establish a sustainable two-tiered deployment paradigm: lightweight topological counting for commit-stage triage, and learned surrogates for staging verification.

**Keywords:** Dependency graphs; cascading failures; publish–subscribe; graph neural networks; software architecture; dependability; empirical study

# 1. Introduction

## 1.1 Motivation and Problem

Large distributed systems increasingly communicate through asynchronous publish–subscribe (pub-sub) middleware: ROS 2 in autonomous driving [1], Apache Kafka in enterprise event streams [2], DDS in cyber-physical systems [3], MQTT in IoT [4], and cloud-native microservices [5, 6]. Pub-sub decouples producers and consumers in space, time and synchronization [7]. Components interact through topics and brokers rather than direct references, and deployment-time Quality-of-Service (QoS) policies govern reliability, durability, priority and deadlines.

The same decoupling hides how failures spread. Publishers and subscribers share no direct link, so outages, head-of-line blocking and backpressure propagate along concealed paths through brokers, shared topics, colocated hosts and shared libraries [8, 9]. These failures take two forms. In *sequential cascades*, a slow subscriber fills a broker queue and gradually starves its publishers [10]. In *simultaneous blasts*, a shared-library crash or host outage takes down every colocated service at once. Neither architecture diagrams nor static call graphs show these mechanisms. The cheapest time to reduce the risk is before deployment, at design and continuous-integration time [11, 12], when no runtime telemetry exists. Architects therefore need to know, from configuration manifests alone, which components, topics and links are systemically critical and why.

Existing practice leaves this gap open, which we call the **Architecture–Code Gap**: a system can have bug-free code in every service and still be fragile through hidden single points of failure or mismatched QoS contracts [13, 14]. Architecture evaluations such as ATAM rely on manual elicitation [15]. Static code analysis inspects services in isolation [16, 17]. Chaos engineering [18] needs a provisioned cluster, while pre-production alternatives like service-level fault injection testing [19] and microservice dependency tracing [20] require runnable execution environments. In continuous integration pipelines, heavy fault injection or cluster-based chaos experiments also incur significant computational and energy costs, making pre-deployment static analysis an attractive, green alternative if its accuracy is sufficient [21, 22, 23]. Homogeneous centrality flattens typed topologies into untyped graphs [24, 25]. Learned models, graph neural networks in particular, could combine these structural cues, but only if they read a graph on which failure paths are explicit. What is missing is such a representation for pub-sub systems, and evidence on what learning achieves on it: which learned rankers work, what they need, and whether they add anything over the coupling metrics that architecture research already has. Furthermore, in practice, architects require an actionable triage and review prioritization mechanism rather than an automated, brittle pass/fail gate that risks developer alert fatigue. This paper provides that evidence for one well-defined task, ranking components by simulated cascade impact before deployment.

## 1.2 The Software-as-a-Graph (SaG) Approach

**Software-as-a-Graph (SaG)** is a pre-deployment static analysis framework for event-driven architectures (Figure 1). It (1) models an architecture as a typed, directed multigraph over Applications, Brokers, Topics, Execution Hosts and Shared Libraries (§3.1); (2) derives from it, through publish–subscribe rules, an explicit `DEPENDS_ON` dependency graph (§3.3); and (3) evaluates learned cascade-impact rankers—graph neural networks on the raw multigraph and on the dependency graph, hybrids, and learned surrogates, against a training-free baseline (§§4 and 5.2). Predictors read only the analysis graph. Ground truth comes from three simulators that run on the raw structural topology (§4.3).

**What the ground truth is, and is not.** All ground truth in this study is simulated. The primary oracle $I^*$ is a reachability simulation that runs on the same manifest the predictors read, and its first propagation wave is exactly the number of a component’s direct dependents (§4.4). Dependency counts are therefore reported as references that restate the oracle, never as predictors. The study measures agreement between learned rankers and simulators, not the prediction of observed outages. Because ranking against $I^*$ rewards restating its propagation rule, we bound the circularity with two further simulators and with partial correlations, and report the cost of running $I^*$ itself (§6.4); validation against observed failures on physical deployments remains an open challenge (§7.3). The practical conclusions and guidance derived here therefore hold conditionally under the assumption of simulation fidelity.

**Findings in brief.** Where graph learning operates on the derived dependency graph, it achieves strong cascade-impact prediction: graph attention networks gain $+0.08$ to $+0.11$ over the raw multigraph, reaching Spearman $\rho = 0.748$ against the reachability oracle $I^*$, and transfer zero-shot to unseen open-source system models at $\rho \approx 0.81$ ($\text{PR-AUC} = 0.838$). A critical discovery is that this high performance aligns closely with the number of direct dependents ($0.764$, publish–subscribe afferent coupling [26, 27]), which restates the reachability oracle’s first propagation wave (first-order expansion $0.808$). The learner distills this fundamental topological signal through its degree features (losing $0.14$ without them), demonstrating that classical architectural coupling provides a near-instant, zero-carbon triage baseline. On high-fidelity dynamic queue-flow simulation whose labels cost $12.7$ CPU-hours ($\sim 355.6$ Wh), learned models deliver their strongest advantage: a gradient-boosted surrogate over dependency-graph features ranks held-out architectures at $\rho = 0.799$, significantly outperforming every closed-form approximation ($0.706$, Holm $p = 0.019$), and declared QoS contracts carry measurable signal ($+0.095$). When failure involves multi-criteria structural fragmentation ($I_{\text{comp}}$), hybrid engines combining neural models with topological priors maintain robust stability ($\rho = 0.585$) where pure neural models collapse ($\le 0.334$). On the raw multigraph where forward messages do not reach Applications, the registered primary contrast of a heterogeneous graph transformer against the training-free baseline was null ($+0.069$, $p = 0.266$). Feature extraction for learned ranking costs $4.5$–$72.5\times$ one reachability simulation pass. Consequently, learning pays decisively where simulation is computationally expensive, establishing a sustainable two-tier deployment architecture.

## 1.3 Research Questions

-   **RQ1 (Ranking accuracy):** *How accurately do learned engines (graph neural networks on the raw multigraph and on the dependency graph, hybrids, and learned surrogates) rank components by cascading-failure impact on unseen architectures, against a training-free baseline, and how close do they come to reference rankings that restate the oracle’s propagation rule?*

-   **RQ2 (What learning needs):** *What do learned engines need: which graph they read, their degree features, relation-specific (typed) parameters, or QoS inputs, once model capacity and edge-channel width are matched?*

-   **RQ3 (Transfer):** *How well do learned engines trained on synthetic architectures transfer zero-shot to independently authored models inspired by five open-source systems?*

-   **RQ4 (Cost and Sustainability):** *What does learned ranking cost at CI/CD time in latency and computational energy, which stage dominates, and how does it compare with running the simulation directly?*

The evaluation follows a version-controlled analysis plan. Only the plan’s two contrasts are confirmatory; the matched $2\times2$, the hybrids, the reference counts, the dependency-graph learners, the full-population queue-flow labels and the sensitivity arms were registered as planned extensions, each before its own arms ran but after the primary result was known, and are reported as registered secondary results; the rest is exploratory (§5.3). One deviation from the plan, its unapplied selection rule, is disclosed and tested. The replication repository documents the revision history and maps these four research questions onto the plan.

## 1.4 Contributions

Evaluated under leave-one-scenario-out (LOSO) cross-validation over twelve synthetic architectures and on five hand-authored models of open-source systems, this paper contributes:

1.  **The Software-as-a-Graph (SaG) framework and multi-oracle evaluation suite** (§§5–6): seventeen architectures (2,812 components), three distinct simulation oracles labelled for every Application, graph neural networks on the raw multigraph and on the dependency graph, hybrid engines and learned surrogates, supported by a version-controlled analysis plan, committed data manifests, and 1,562 byte-identically verified figures.

2.  **High-accuracy cascade prediction and causal demystification of graph learning mechanics** (§§6.1–6.2): Graph attention networks on the derived dependency graph achieve $\rho = 0.748$, gaining $+0.08$ to $+0.11$ over raw multigraphs; causal ablations show that their performance rests on distilling degree features, while sum aggregation naturally counts neighbors, explaining why classical afferent coupling provides a zero-cost triage baseline for reachability.

3.  **A high-performance dynamic surrogate for Green CI/CD** (§6.1): A gradient-boosted surrogate trained on dynamic queue-flow labels reaches $\rho = 0.799$ on held-out architectures, significantly outperforming closed-form approximations ($+0.094$, $p = 0.019$) and amortizing $12.7$ CPU-hours ($\sim 355.6$ Wh) of discrete-event simulation into sub-second inference.

4.  **Resilient hybrid architectures under multi-criteria fragmentation** (§6.1): Demonstrating that combining neural models with domain priors prevents catastrophic ranking collapse under structural fragmentation and flow disruption ($\rho = 0.585$ vs. $\le 0.334$).

5.  **Explicit graph derivation rules for publish–subscribe architectures** (§3): Extending the application-level rule of [28] with library-mediated blast radii, host colocation, and middleware QoS edge encodings.

6.  **A like-for-like computational cost and sustainability analysis** (§6.4): Measuring exact latencies and energy footprints across counting, simulation, and learned inference, establishing an actionable two-tier triage pipeline for continuous integration.

A previous conference paper [28] introduced the publish–subscribe multigraph, the Application-level subscriber$\to$publisher dependency (Rule 1 of Table 2) and a closed-form betweenness–articulation score of the same form as the training-free baseline (Eq. 5, unweighted and with weights $0.7$/$0.3$), and validated that score against a reachability-loss simulation on synthetic topologies and two ROS 2 benchmarks. Everything else is new in this paper: the Library and infrastructure rules (Rules 2–6, including library-mediated blasts), QoS weighting, the reference counts, the learned and hybrid engines, the QoS edge encoding, LOSO and zero-shot evaluation, the second and third oracles, the matched control and the cost profile.

# 2. Related Work

## 2.1 Dependability Analysis of Distributed Systems

Runtime approaches to dependability, such as broker clustering, backpressure, autoscaling, failover and chaos engineering [18], require a running cluster, can disrupt service, and consume substantial compute. That compute is itself an acute concern of green software engineering and Green AI [21, 22, 23], where the carbon footprint of provisioning massive execution clusters in continuous integration creates strong incentives for lightweight, energy-efficient static alternatives. Pre-production alternatives, including service-level fault injection testing [19] and microservice dependency localization via PageRank (MicroRank [20]), provide lighter options before deployment. Benchmark systems with cataloged, replayable faults, such as Train-Ticket [29], make observed failure impact measurable on a running deployment, which is the validation this study does not yet have (§7.4). Architecture-based reliability prediction has a long history. Yacoub and Ammar’s methodology for architecture-level reliability risk analysis [30] pioneered combining component dependency graphs with complexity and failure severity to rank components by risk. State-, path- and additive reliability models surveyed by Goseva-Popstojanova and Trivedi [31] are classic examples, as is the Palladio Component Model [32]. These approaches answer broader questions but need operational profiles and failure rates that are unavailable at commit time. SaG asks a narrower question from manifests alone: whose failure reaches furthest in the declared topology?

Telemetry-driven methods diagnose faults in running microservices. Representative examples include Seer [33] and MicroRCA [34] (surveyed extensively by Zhang et al. [35]). In synchronous microservices, cascades stem from thread-pool exhaustion, RPC timeouts and retry storms [29]. In pub-sub systems they spread through queue saturation and message starvation. All of these methods need traces or metrics from a live system; SaG works before any code runs. SaG’s question is also that of change impact analysis [36] and of dependency management in microservice fleets [37]. Ranking by impact relates to learning-to-rank defect prediction [38], which optimizes the ranking measure directly, as our listwise loss does (§4.2).

## 2.2 Static Code Analysis and Static System Analysis

Static code analysis (SCA) tools such as SonarQube [16] measure complexity [39], cohesion and coupling [17] within individual services to flag defect-prone modules [40, 41]. Comparing sophisticated graph measures against simple structural metrics has a rich history in software engineering defect prediction: Zimmermann and Nagappan [42] evaluated network analysis on dependency graphs, while Premraj and Herzig’s replication study [43] demonstrated that simple code and coupling metrics largely matched network measures. SCA cannot see inter-service messaging, broker saturation or cross-host propagation. Architecture recovery tools reconstruct system-level structure from code [44], and HAROS [45] checks ROS systems statically before launch. SaG’s static system analysis (SSA) uses the declared topology instead, propagating code-level metrics across architectural dependencies. Architecture-level coupling metrics count a service’s consumers, as afferent coupling [26], the Absolute Importance of the Service [27] and service fan-in [46]. In publish–subscribe systems these counts are not a single edge lookup, because consumers reach producers only through topics, brokers and shared libraries. They are a typed two-hop query (publisher $\to$ topic $\leftarrow$ subscriber), which SaG’s dependency rules state explicitly; Because this count is exactly the first propagation wave of the reachability oracle used here, this paper reports it as a reference that restates the oracle, not as a predictor (§4.4). This lets teams find structural anti-patterns [47, 48] and architectural technical debt [49] in CI/CD [50].

## 2.3 Multi-Criteria Weighting

Aggregating QoS policies or failure effects into one auditable weight is a multi-criteria decision problem, for which the Analytic Hierarchy Process (AHP) [51] is standard; SaG uses it for the topic weights of §3.2 and the composite oracle of §4.3. AHP’s consistency ratio detects inconsistent judgments but not matrices back-filled from a chosen answer, a distinction this study reports for its weights.

## 2.4 Graph Learning and Explainability

Closed-form indices [24, 25, 52, 53], one of which supplies this study’s training-free baseline, and cascade models of network robustness [10, 8, 9] assume homogeneous, usually undirected graphs, so a single untyped score conflates structurally different elements such as topics, libraries and hosts. Learned node-importance methods, including FINDER [54], DrBC [55] and PowerGraph [56], share the homogeneity assumption, as does learned approximation of betweenness and closeness [57]. Homogeneous GNNs such as Graph Attention Networks (GAT [58]) discard relation identity unless it is supplied as a feature. Softmax attention normalizes over neighbors and so computes a weighted mean that cannot count them, whereas sum aggregation can [59, 60], and counting larger substructures remains challenging for standard message-passing architectures; since the strongest reference here is a neighbor count, this distinction matters (§6.2). Heterogeneous GNNs, such as the Heterogeneous Graph Transformer (HGT [61]), learn relation-specific transformations. We evaluate both families under matched capacity (§6.2). Khodabandeh et al. [62] apply graph attention to microservice call graphs to predict future interactions. We instead predict the impact of removing a node from a declared topology. GNN explainers such as GNNExplainer [63] explain models in terms of their internal features. SaG’s proposed explanation layer instead names ISO/IEC 25010 quality sub-characteristics [64] and a remediation class for each flagged component; it is not evaluated here.

This study belongs with work showing that simple baselines are often competitive with sophisticated learners [65, 66], and, in software engineering specifically, with the finding that network measures on dependency graphs [42] add little over simple coupling metrics once those are measured [43]. Its contribution is of that kind: an evaluation of learning on derived dependency graphs for a pre-deployment ranking task, with a largely negative result where the oracle is cheap and its strongest simple restatement is a known architecture metric, and a positive one for learned surrogates where the oracle is expensive.

These features feed the ranking engines (§4) and, separately and with no shared parameters, the proposed explanation layer.

## 3.1 Multigraph Definition

A distributed system is described as a typed, weighted, directed multigraph:

$$\tag{1}
\mathcal{G} = (V, E, \tau_V, \tau_E, w_V, w_E)$$

where:

-   $V = V_{\text{app}} \cup V_{\text{broker}} \cup V_{\text{topic}} \cup V_{\text{host}} \cup V_{\text{lib}}$ holds the five entity types $\mathcal{T}_V$ of Table 1; $V_{\text{host}}$ denotes physical or virtual *Execution Hosts*.

-   $E$ is the set of directed edges, and $\tau_V: V \to \mathcal{T}_V$ and $\tau_E: E \to \mathcal{T}_E$ assign entity and relation types.

-   $w_V: V \to (0, 1]$ and $w_E: E \to (0, 1]$ weight entity criticality and connection strength. For Applications and Libraries, $w_V(v) = 1 - \text{CQP}(v)$, where CQP is a code-quality penalty computed from static code metrics (lines of code, cyclomatic complexity, coupling and cohesion); otherwise $w_V(v) = 1.0$.

The raw multigraph is denoted $G_{\text{structural}}$ (used exclusively by simulation oracles), while $G_{\text{analysis}}$ denotes the logical `DEPENDS_ON` projection consumed by predictors. A comprehensive reference of mathematical notation is provided in the replication repository.

**Table 1.** Entity types and structural edge types in the SaG model.

| **Entity Type ($\mathcal{T}_V$)**      | **Architectural Role**                        | **Concrete System Examples**                   |
|:---------------------------------------|:----------------------------------------------|:-----------------------------------------------|
| **Application** ($V_{\text{app}}$)     | Process producing/consuming messages          | ROS 2 node, Kafka microservice, MQTT client    |
| **Broker** ($V_{\text{broker}}$)       | Message routing and queuing intermediary      | RabbitMQ exchange, Mosquitto, EMQX broker      |
| **Topic** ($V_{\text{topic}}$)         | Named logical communication channel           | `/sensor/lidar`, `orders.payment.completed`    |
| **Execution Host** ($V_{\text{host}}$) | Physical or virtualized execution environment | Bare-metal server, Kubernetes worker, Cloud VM |
| **Library** ($V_{\text{lib}}$)         | Shared software package or runtime dependency | Kafka client, OpenCV, Protobuf runtime         |
| **Structural Edge ($\mathcal{T}_E$)**  | **Direction**                                 | **Semantic Meaning**                           |
| `PUBLISHES_TO` / `SUBSCRIBES_TO`       | App/Library $\to$ Topic                       | Component publishes to / consumes from topic   |
| `ROUTES`                               | Broker $\to$ Topic                            | Broker manages and routes topic traffic        |
| `RUNS_ON`                              | App/Broker $\to$ Host                         | Process is hosted on host                      |
| `CONNECTS_TO`                          | Host $\to$ Host                               | Network link between hosts                     |
| `USES`                                 | App $\to$ Library                             | Application links to shared library            |

## 3.2 Quality-of-Service Link Weighting

A link’s strength depends on its Quality-of-Service (QoS) contract: a `RELIABLE` topic with `TRANSIENT_LOCAL` durability couples services more strongly than a `BEST_EFFORT` telemetry stream. Each topic $t$ carries an aggregate weight $w(t) \in (0, 1]$ combining declared QoS policies (reliability, durability, priority) with payload size and publication frequency. The sub-weights of reliability, durability and priority come from an Analytic Hierarchy Process (AHP) pairwise-comparison matrix that was stated independently rather than back-solved from a target vector ($CR = 0.016$, non-degenerate; the framework’s other AHP matrices also encode a declared vector).

Whether these weights help a learned ranker is measured directly: with the weighted in-degree held in both arms, the QoS inputs add nothing measurable to the graph neural networks on the reachability oracle (§6.2), whereas on the queue-flow oracle they carry the learned surrogate’s gain (§6.1). How the weighting affects the training-free baseline is archived in the replication repository. The reference dependency counts reported in this paper are unweighted and do not read $w(t)$.

## 3.3 Logical Dependency Projection (`DEPENDS_ON`)

Structural edges do not directly reflect failure propagation: a subscriber depends on a publisher, yet no direct edge joins them in pub-sub topologies. SaG derives an explicit semantic relation, `DEPENDS_ON`, directed from *dependent* to *dependency* (“if the target fails, the source is impacted”), via the rules of Table 2.

**Table 2.** The `DEPENDS_ON` logical dependency projection rules. $^\dagger$Defined for completeness; not exercised by the Application-level evaluation.

|    **Rule**     | **Dependency Category** | **Structural Pattern ($\text{Dependent} \to \text{Dependency}$)**           | **Derived Weight ($w$)**                                                 |
|:---------------:|:------------------------|:----------------------------------------------------------------------------|:-------------------------------------------------------------------------|
|      **1**      | `app_to_app`            | Subscriber $\to$ Publisher (via shared Topic)                               | $1 - \prod_{t \in T}(1 - w(t))$                                          |
| **2**$^\dagger$ | `app_to_broker`         | Publisher/Subscriber $\to$ Broker routing its topics                        | $1 - \prod_{t \in T}(1 - w(t))$                                          |
| **3**$^\dagger$ | `host_to_host`          | Host $\to$ Host (lifted from inter-host app dependencies)                   | $\max_{u \in \text{hosted}(h_1), v \in \text{hosted}(h_2)} w_E(u \to v)$ |
| **4**$^\dagger$ | `host_to_broker`        | Host $\to$ Broker (lifted from hosted app dependencies)                     | $\max_{u \in \text{hosted}(h)} w_E(u \to b)$                             |
|      **5**      | `app_to_lib`            | Application $\to$ Shared Library it `USES`                                  | $H(w_V(\text{app}), w_V(\text{lib}))$                                    |
| **6**$^\dagger$ | `broker_to_broker`      | Broker $\leftrightarrow$ Broker (shared fault-domain colocation, symmetric) | $w_V(\text{host})$                                                       |

Rules 1 and 2 combine topics $T$ joining a pair by probabilistic union [67], ensuring parallel failure paths increase coupling. Rule 5 uses the harmonic mean $H(x, y) = 2xy/(x+y)$ [68], and Rules 3 and 4 lift dependencies to hosts by maximum.

**Sequential cascades and simultaneous blasts.** Rule 1 captures sequential cascades, where a failed publisher starves subscribers through queues and buffers. Rule 5 captures simultaneous blasts, where a crashed library takes down all dependent applications at once. Libraries that publish or subscribe are endpoints of Rule 1 in their own right, and an Application reaches a library’s topics transitively through Rule 5. The projection on which every count, `Topo-QoS` and every `-P` learner is computed applies Rule 1 to direct subscriptions only; the repository derivation that produces the node features additionally follows up to three `USES` hops, so an Application subscribing through a library it uses is a Rule 1 dependent there. Rules 2, 3, 4 and 6 represent infrastructural and broker dependencies (Table 2).

**Remark 1 (the dependency count is a typed two-hop count).** Let $G_{\text{flow}}$ be the Application–Library projection (Rules 1 and 5) and $v$ an Application. By construction, $$\tag{2}
\texttt{InDeg}(v) \;=\; \bigl|\{\,u \neq v : \exists t \in V_{\text{topic}},\; (v, t) \in \texttt{PUBLISHES\_TO} \wedge (u, t) \in \texttt{SUBSCRIBES\_TO}\,\}\bigr|.$$ Since Rule 5 edges end at Libraries, every edge into an Application is a Rule 1 edge $u \to v$, which exists exactly when $u \neq v$ (an Application or a Library) directly subscribes to a topic that $v$ publishes; parallel topics collapse into one edge.

The right-hand side of Eq. 2 is publish–subscribe afferent coupling (fan-in, the Absolute Importance of the Service [26, 27]), and it is a typed two-hop query on the raw multigraph. `InDeg` therefore needs no projection to compute; the projection states which typed query to ask. The equality is also checked on all seventeen corpus graphs (maximum absolute difference $0$). What the projection adds beyond this query is measured separately: Rule 5 raises transitive reach by $+0.058$ (§6.1). Because the primary oracle’s first propagation wave is exactly this set (§4.4), `InDeg` and its transitive counterpart `Reach` are used in this paper as references that restate the oracle, not as predictors.

## 3.4 Dual Graph Views

The **structural graph** $G_{\text{structural}}$ is the raw deployment topology. The **analysis graph** $G_{\text{analysis}}$ adds the derived `DEPENDS_ON` edges and code metrics (Figure 2). Predictor features are computed on $G_{\text{analysis}}$, while simulation oracles run strictly on $G_{\text{structural}}$ (§4.4). The two views also differ for a learner: on $G_{\text{structural}}$ every relation points away from Applications, so forward message passing never reaches them, whereas on the `DEPENDS_ON` graph each Application receives messages from its dependents (§6.2).

## 3.5 Typed Node Feature Encoding

Both the predictive pathway (§4) and the proposed explanation layer read typed node properties from $G_{\text{analysis}}$. All five entity types share an 18-dimensional base block of normalized topological metrics ($[0, 1]$): PageRank, Reverse PageRank, betweenness, closeness, eigenvector centrality, in- and out-degree, clustering, articulation, bridge ratio, the node QoS weight, incoming and outgoing dependency weights, multi-path coupling, path complexity, fan-out criticality, and the Connectivity Degradation Index (CDI). Four centrality features (PageRank, Reverse PageRank, betweenness and closeness) are computed over weighted edges and so carry QoS information; the nominal QoS-off condition is therefore not completely QoS-free. The in-degree feature, and the incoming dependency weight $w_{\text{in}}$, a QoS-weighted version of it, mean that every learner is given a quantity closely related to `InDeg` as an input, so the learners inherit part of the reference counts’ overlap with the oracle through their features (§6.2); a learner without both columns was not run. Type-specific blocks extend the vector to 19–25 dimensions (full schema documented in the replication repository). CDI evaluates structural connectivity loss via a fixed-size breadth-first sample to control computation time (§6.4); its sensitivity to hash-seeded tie breaking is examined in §7.3.

# 4. Ranking Engines and Ground Truth

SaG ranks components with learned engines, which are compared against one training-free baseline. The **learned engines** are graph neural networks over the typed multigraph and the derived dependency graph (this section), and gradient-boosted surrogates over per-Application dependency-graph features (§5.2). The **hybrid engines** are graph neural networks that correct the baseline score (§6.1). The **training-free baseline** `Topo-QoS` is QoS-weighted betweenness on the dependency projection (§5.2). All are trained or scored against simulation oracles that run on a separate graph view (§§4.3–4.4). Figure 3 shows how the engines relate and how they are evaluated. Full hyperparameters and training commands are on the experiment pages of the replication repository (§5.1).

## 4.1 Heterogeneous Graph Transformer and Attention Networks

The primary learned engine `HGT-QoS` is a three-layer Heterogeneous Graph Transformer (HGT) [61] in PyTorch Geometric [69], with hidden dimension $D = 64$ and $H = 4$ heads. Entity-specific linear projections map raw node features $x_v \in \mathbb{R}^{19\text{--}25}$ into hidden space, $h_v^{(0)} = \text{LayerNorm}(\text{GELU}(W_{\tau(v)} x_v))$. For each meta-relation $\langle \tau(u), \phi(e), \tau(v)\rangle$, attention uses type-parameterized keys, queries, and values, scaled by a learned per-meta-relation prior $\mu_{\langle \tau(u), \phi(e), \tau(v)\rangle}$ (full layer-wise formulations in the replication repository). Message passing runs over both $G_{\text{analysis}}$ and its transpose. On the raw multigraph, native relations point away from Applications, so forward message passing cannot reach scored nodes, reducing forward GNNs to per-node MLPs over precomputed centralities (§7.2). The homogeneous Graph Attention Network baseline (`GAT-QoS`, and `GAT-P-QoS` on the dependency projection) uses a 3-layer architecture with 4 attention heads and width $D = 288$ ($D = 296$ in the unweighted control to match parameter capacity), projecting all node types into a shared embedding space before homogeneous `GATConv` layers.

Each directed edge carries a 16-dimensional vector $e_{uv} \in \mathbb{R}^{16}$: index 0 represents the coupling weight $w_E(e)$, index 1 the normalized path count, indices 2–8 a relation one-hot, and indices 9–15 middleware QoS parameters (reliability, durability, priority, depart-mode flag, deadline pair, max-blocking time). The edge vector is projected and added before attention, $\tilde{h}_v = h_v + W_{\text{edge}} e_{uv}$.

## 4.2 Prediction Head and Training Objective

A composite head predicts simulated cascade impact, $\hat{I}^*(v) = \sigma(\text{MLP}_C(h_v \parallel \hat{a}_1(v) \parallel \hat{a}_2(v)))$, where the auxiliary heads $\hat{a}_1, \hat{a}_2$ are a reliability and a maintainability head. $\hat{a}_1$ is regressed on the oracle’s reliability column $I^*_R$; the oracle records no maintainability, so $\hat{a}_2$’s regression term is masked out and it is trained only through the composite head. The objective combines regression with listwise and pairwise ranking: $$\tag{3}
\mathcal{L} = \text{MSE}(\hat{I}^*, I^*) + 0.5 \cdot \text{MSE}(\hat{a}_1, I^*_R) + 0.3 \cdot \mathcal{L}_{\text{rank}} + 0.1 \cdot \mathcal{L}_{\text{pairwise}},$$ where $\mathcal{L}_{\text{rank}}$ is ListMLE [70] over the ground-truth permutation $\pi$, $$\tag{4}
\mathcal{L}_{\text{rank}} = -\frac{1}{N}\sum_{i=1}^N \Big( \hat{s}_{\pi_i} - \log \sum_{j=i}^N \exp(\hat{s}_{\pi_j}) \Big),$$ and $\mathcal{L}_{\text{pairwise}}$ is a margin-ranking loss ($\gamma = 0.05$) over pairs differing by more than $\gamma$. Tied labels (about $31\%$ of Applications have $I^* = 0$) enter $\pi$ in a fixed but arbitrary order, so ListMLE is only approximately defined on them; the pairwise term ignores pairs within $\gamma$.

Models are trained with AdamW ($\eta = 3 \times 10^{-4}$, weight decay $10^{-4}$) under cosine warm restarts for up to 300 epochs, with early stopping at patience 60 on a $20\%$ node-level validation split of the largest training scenario, over five fixed seeds $\{42, 123, 456, 789, 2024\}$. Hyperparameters and loss coefficients were fixed before the first sweep and are identical across arms. **This deviates from the registered plan**, whose selection rule chooses every hyperparameter by nested inner-LOSO selection (two-fold inner holdout); the published learned results use one fixed configuration instead, adopted during primary campaigns to maintain computational tractability across seeds and folds, and this deviation is disclosed in §5.3. The registered selection was run afterwards, on the eight-configuration stage-1 grid (depth and rank normalization of features and labels), as a sensitivity analysis; its harness also early-stops on a held-out training scenario, so it differs from the published protocol in that respect too (§6.2), confirming that the primary null result remains unchanged under nested tuning.

## 4.3 Ground-Truth Simulation Oracles

Ground truth is evaluated using simulation oracles on the raw structural multigraph $G_{\text{structural}}$:

-   **Primary reachability cascade oracle ($I^*$):** Crashes component $v$, propagates outages through dependent topics, brokers and links via breadth-first traversal on $G_{\text{structural}}$, and computes the mean fractional feed loss across intact subscribers. Feed loss is scaled by a QoS severity ladder ($\times 1.2$ `RELIABLE`, $\times 1.15$ high priority, $\times 1.05$ medium) and clamped to $[0, 1]$. Each propagation wave is processed in a seeded random order, which decides ties at the propagation threshold; the label is the mean over five seeds. Disabling QoS scaling leaves the Application ordering largely intact ($\rho = 0.965$ across the twelve folds), and substituting durability-aware rescaling moves it less still ($\rho = 0.977$), showing that $I^*$ is predominantly a topological reachability metric.

-   **Independent queue-flow discrete-event oracle ($I_{\text{dyn}}$):** A discrete-event SimPy [71] simulation modeling dynamic message emission rates, queue buffer saturation, and network latency. It records the drop in delivered message rate suffered by surviving consumers under active load, and it reads the declared rates, payload sizes and QoS contracts that $I^*$ ignores. Its mechanism is therefore different from reachability, but its substrate is the same pub-sub topology, and its first-order effect—consumers that lose a failed publisher’s messages—is again subscriber loss. It is labeled for all $1{,}321$ Applications, as the mean over five seeds, at a cost of $12.7$ CPU-hours for the corpus against seconds for $I^*$; an earlier revision used only the first $30$ Applications per fold in lexicographic order, which is kept as a sensitivity check. $I_{\text{dyn}}$ agrees with $I^*$ at mean $\rho = 0.711$ $[0.625, 0.794]$, and its published test–retest reliability is $0.74$–$0.97$, which bounds the correlation any deterministic ranker can attain with it.

-   **Composite multi-criteria failure oracle ($I_{\text{comp}}$):** An auxiliary benchmark evaluated with the Validate-stage failure simulator, run exhaustively over all $1{,}321$ Applications with QoS weighting on and a primed baseline flow. It scores each removal as $I_{\text{comp}}(v) = 0.35\,\text{RL}(v) + 0.25\,\text{FR}(v) + 0.25\,\text{TL}(v) + 0.15\,\text{FD}(v)$: reachability loss, fragmentation ($0.70$ structural component loss $+\,0.30$ severity), throughput loss and flow disruption. The weights come from one of the three AHP matrices that encode a declared vector rather than elicited judgment, so $I_{\text{comp}}$ serves as a declared multi-objective stress test specifically assessing resilience to topological fragmentation and throughput disruption rather than pure subscriber loss. Because fragmentation and flow disruption respond to almost every removal, $I_{\text{comp}}(v) > 0$ for virtually every Application. $I_{\text{comp}}$ is never a training label.

## 4.4 Input–Label Independence and Construction Bounds

Features are extracted strictly from $G_{\text{analysis}}$, while simulation oracles execute on $G_{\text{structural}}$, and no simulation output is exposed as an input feature; a regression test in the replication package enforces this.

Procedural separation does not remove construct overlap, and this is the paper’s central threat, stated once here. **Criterion.** A ranking is a *reference* for an oracle $O$ if it is a closed-form truncation of $O$’s own computation from the same inputs; it then measures how much of $O$ is its own rule, not predictive skill, and no contrast against it is a claim. For $I^*$, whose first propagation wave is exactly the set `InDeg` counts (Remark 1), the references are its first-order expansion (Eq. 6), `InDeg`, `Reach` and their raw-graph equivalents. For $I_{\text{dyn}}$ no ranking here truncates its computation, but its first-order effect is the same subscriber loss, so the same rankings are read as references on it too. For $I_{\text{comp}}$ no ranking is a truncation either; its fragmentation and flow terms, however, respond to removing high-degree and high-betweenness nodes, so `Topo-QoS` and raw degree are *proximate* to it, and their lead on $I_{\text{comp}}$ is read with the same caution as the references’ lead on $I^*$. The learned engines are not references by this criterion, but they read in-degree features and are trained on $I^*$, so they inherit part of the overlap (§6.2 measures how much). Two analyses bound the circularity rather than remove it: every ranker is scored on all three oracles, and its agreement with $I_{\text{dyn}}$ is also reported after the rank of $I^*$ (and, separately, of the first-order term) has been partialled out (§6.1). Neither replaces validation against observed failures on physical, running distributed systems, which this study does not have (§7.3); all findings are therefore strictly conditional on simulation fidelity.

## 5.3 Metrics, Protocols and Statistics

**Population.** Every predictor is scored on the Application set $V_{\text{app}}$.

**Metrics.** Ranking is measured by Spearman $\rho$ against the simulation oracles. To separate rank ordering among active components from the trivial agreement on inert components with zero impact, we report both full-population Spearman $\rho$ and active-stratum Spearman $\rho_{>0}$ (restricting to components with true impact $> 0$). Critical-set identification is measured by Overlap@$K$, the fraction of the true top-$K$ recovered by the predicted top-$K$ with $K = \text{round}(0.20\,|V_{\text{app}}|)$. PR-AUC, $F_1@\tau$ and nDCG@10 are reported in the replication repository.

**Protocols.** Under *LOSO*, learned models train on eleven scenarios and are tested on the twelfth, over all 12 folds and five seeds; the reported value is the mean over seeds of each seed’s $\rho$. Under *zero-shot transfer*, models trained on all twelve scenarios are evaluated without fine-tuning on the five system models. Training-free rankers are fitted to nothing, so for them both protocols reduce to *per-scenario evaluation* on the same twelve scenarios and five models; they are placed in the same tables only so that every row is scored on identical scenarios and labels.

**Statistics.** Summary $\rho$ is the arithmetic mean of the per-fold (or per-system) Spearman correlations, with a 95% CI from a bootstrap that resamples folds ($B = 2{,}000$) [72]; comparisons use paired two-sided Wilcoxon signed-rank tests over folds [73]. With 12 folds, the smallest attainable two-sided $p$ is $0.00049$. Fisher-$z$ averaging leaves the order of every row of Table 5 unchanged. Weighting folds by $|V_{\text{app}}|$ leaves the top five unchanged (the reference `InDeg` rises to $0.810$) but lifts `Topo-QoS` to $0.596$, level with the raw-multigraph learned engines ($0.595$–$0.606$). Spearman $\rho$ assigns tied scores their average rank. Overlap@$K$ breaks ties at the $K$ boundary by node order, which is arbitrary for integer counts; §6.1 therefore also reports tie-aware recall curves. Because LOSO folds share ten of eleven training scenarios, every registered contrast is also tested with the Nadeau–Bengio corrected resampled $t$ [74] and, under $|V_{\text{app}}|$ weighting, with an exact sign-flip permutation test.

**Analysis plan and the status of each result.** The evaluation protocol is version-controlled in the replication repository (`docs/research/jss/AMENDMENTS.md`, with revision dates and commit hashes). Every reported result is assigned to one of three tiers. *Confirmatory*: the original plan’s primary contrast (`HGT-QoS` vs. `Topo-QoS`) and unweighted contrast (`HGT` vs. `Topo-QoS`), Holm-corrected across the two. *Registered secondary*: hypotheses committed before their respective arms executed—including the matched $2\times2$, hybrid engines, reference counts, dependency-graph learners, derivation value, full-population queue-flow labels, and sensitivity arms, each Holm-corrected within its family. All secondary analyses were formulated after the primary null was observed. *Exploratory*: post hoc investigations and reference reclassifications (which altered no figures; §4.4). **Plan deviation**: the registered nested inner selection was simplified to a fixed configuration during primary sweeps; a sensitivity analysis evaluates the registered selection (§6.2). As an omnibus sensitivity check, pooling all 13 contrasts under one family-wide Holm correction (`reproduce/omnibus_holm.py`) confirms that both hybrid contrasts against `Topo-QoS` remain significant (Hybrid-GAT $p_{\text{omni}} = 0.019$, Hybrid-HGT $p_{\text{omni}} = 0.041$), whereas the primary contrast does not ($+0.069$, nominal $p = 0.266$, $p_{\text{omni}} \ge 0.46$).

It reaches mean $\rho = 0.808$ $[0.755, 0.853]$ ($\rho_{>0} = 0.631$): direct subscriber loss is most of what $I^*$ measures, and `InDeg` is a coarser version of the same quantity. As a reference it bounds the mean rather than every fold: on four folds (AV, Financial Trading, Healthcare, Industrial SCADA) `InDeg` slightly exceeds it (by $0.005$–$0.038$).

**Learners on the dependency graph approach the reference.** The same graph neural networks, trained on the dependency graph instead of the raw multigraph, reach $\rho = 0.748$ (`GAT-P-QoS`), the best GNN in Table 5, and $0.016$ below the direct-dependent count on the per-seed statistic; its five-seed ensemble is $0.007$ above it ($0.772$, Table 6). Neither difference is significant, and neither is equivalence: the $90\%$ interval of the per-fold difference reaches $\pm 0.076$, so a two one-sided test at the registered margin of $\pm 0.05$ fails ($p = 0.17$ per seed, $0.13$ for the ensemble; equivalence arm F3). The learner and the count are therefore indistinguishable at this sample size, not ranked. The approach to the reference rests on the degree features every learner receives (§3.5): removing `in_degree` and $w_{\text{in}}$ lowers `GAT-P-QoS` to $0.612$ (§6.2). A variant that uses `InDeg` as its prior is archived in the replication repository, because its prior is a reference. `HGT-P-QoS` reaches only $0.514$ and is highly seed-dependent (mean within-fold seed SD $0.254$; §7.3).

**Hybrids outperform the registered comparator, and little else.** Hybrid-HGT reaches $\rho = 0.657$ ($+0.103$, Holm $p = 0.0068$) and Hybrid-GAT $0.683$ ($+0.130$, Holm $p = 0.0029$) against `Topo-QoS`, each on 11 of 12 folds; both stay significant under the omnibus Holm correction ($p_{\text{omni}} = 0.041$ and $0.019$), under the Nadeau–Bengio corrected $t$ ($p = 0.019$ and $0.014$) and under $|V_{\text{app}}|$-weighted averaging (exact sign-flip $p = 0.038$ and $0.005$). They are the study’s only significant registered improvements, and they are weaker than they look, because a hybrid receives $p(v)$ as an input and adds a learned correction to its logit, so it nests its comparator. Against their own base learners, which were registered alongside, neither is significant (Hybrid-HGT vs. `HGT-QoS` $+0.035$, $p = 0.73$; Hybrid-GAT vs. `GAT-QoS` $+0.048$, $p = 0.30$). The prior also costs transfer: zero-shot, both hybrids fall below their base learners (§6.3). On their own, the raw-multigraph learned engines do not differ significantly from `Topo-QoS` (`HGT-QoS` $+0.069$, $p = 0.266$, the null primary contrast; `GAT-QoS` $+0.082$, $p = 0.233$).

**Beyond the reachability oracle.** Table 6 scores the rankers against the two other oracles. On full-population $I_{\text{dyn}}$, which agrees with $I^*$ at $\rho = 0.711$ $[0.625, 0.794]$, the references stay ahead of every GNN (first-order expansion $0.706$, `InDeg` $0.664$, against $0.496$–$0.615$), and `Topo-QoS` reaches $0.471$. Because $I_{\text{dyn}}$ shares the topology and the first-order effect with $I^*$, the partial correlation shows how much of each ranking survives outside the oracle it was fitted to or restates. After the rank of $I^*$ is removed, `InDeg` keeps $0.272$ $[0.188, 0.366]$, `Reach` $0.117$, `Topo-QoS` $0.134$ and the GNNs $0.107$–$0.173$, every interval excluding zero. Learning from the right labels matters more than the graph model. A gradient-boosted model over the counts, the first-order expansion and QoS features, trained on $I_{\text{dyn}}$ labels of the training scenarios, ranks held-out architectures at $0.799$, above the first-order expansion ($+0.094$, Holm $p = 0.019$) and `InDeg` ($+0.135$, Holm $p = 0.019$; Family B); its QoS features carry that gain ($+0.095$ over the same model without them, Holm $p = 0.014$), whereas on $I^*$ they add nothing ($-0.003$, $p = 0.62$; Family C). The GNN given the same labels does not: `GAT-P-QoS`$\to$dyn reaches $0.598$, below the first-order expansion ($-0.108$, Holm $p = 0.014$) and the gradient-boosted surrogate ($-0.201$, Holm $p = 0.0015$), and no better than the same GNN trained on $I^*$ ($-0.008$; control F5). Importantly, these two surrogates differ in their input representations as well as their model classes: the tree model was supplied with the analytical first-order expansion, declared publication rates, and message payload sizes alongside topological counts, whereas the GAT surrogate operated solely over topological graph features. While this confirms that gradient-boosted trees over domain-informed features distill queue-flow mechanics effectively, isolating the role of architectural inductive bias versus input feature disparity remains an open question requiring future feature-matched evaluations (§7.2). These surrogates are trained on the oracle they are scored on; their value is cost, since labeling $I_{\text{dyn}}$ took $12.7$ CPU-hours for the corpus (§6.4). Trained on $I^*$ instead, the same gradient-boosted model is less robust across the three oracles than the first-order expansion alone (worst-case $\rho$ $-0.121$, Holm $p = 0.001$; Family A).

**The multi-criteria oracle favors different rankers.** On $I_{\text{comp}}$, which adds fragmentation, throughput and flow disruption (§4.3), learned engines without a prior collapse ($0.144$–$0.334$; the sum-aggregation GNNs of §6.2 reach $0.41$–$0.44$), while the two hybrids, which carry `Topo-QoS` as a prior, keep $0.58$. Their lead is read as the same kind of overlap with $I_{\text{comp}}$’s fragmentation and flow terms as the references’ lead on $I^*$ (§4.4), not as predictive skill. No ranker is best on all three oracles.

**Identifying the critical set.** Rank correlation over all Applications is not the operational question in a CI gate, which is whether the true top of the ranking gets flagged. Figure 5 gives, for each ranker, the share of the true top-$20\%$ set on $I^*$ that falls within its top $k\%$, with ties resolved in expectation. At $k = 20\%$, `GAT-P-QoS` recovers $0.48$ of the critical set and `Topo-QoS` $0.38$, consistent with their Overlap@$K$ ($0.454$ and $0.388$): about half of what a top-$20\%$ gate flags is not in the true top $20\%$, and about half of the true top $20\%$ is missed. Recovering $80\%$ of the critical set requires flagging the top $40\%$ by `GAT-P-QoS` ($0.81$), and `Topo-QoS` does not reach $80\%$ within $50\%$. The references do little better: at $k = 20\%$, `InDeg` recovers $0.49$ (tie-breaking bounds $0.48$–$0.50$), and $80\%$ needs the top $45\%$ by `InDeg` ($0.83$) or by the first-order expansion ($0.89$); only the first-order expansion reaches $90\%$ within the top $50\%$, and `Reach` does not reach $80\%$ within $50\%$. On the earlier $n = 30$ $I_{\text{dyn}}$ developmental sample (the right panel of Figure 5; preserved for tie-breaking recall inspection; Table 6 reports the exhaustive $N = 1{,}321$ population), `GAT-P-QoS` reaches $0.65$ at $40\%$ and $0.80$ at $50\%$, against $0.83$ at $40\%$ for the `InDeg` reference. In an industrial deployment, requiring a gate to flag $40\%$ to $50\%$ of components to catch $80\%$ of critical points introduces substantial developer alert fatigue, indicating that SaG is most effective as a prioritized triage list for architectural inspection rather than an automated blocking gate.

**What the dependency-graph learner needs.** Every learner receives in-degree and $w_{\text{in}}$ as node features, and on the dependency graph it also aggregates exactly the dependent neighborhood, so its closeness to `InDeg` could come from either. Ablation experiments separate the two (Table 8). Removing the two degree columns costs `GAT-P-QoS` $0.136$, and removing the three centralities most correlated with in-degree as well costs $0.161$ (F1, rule F1a): the approach to the reference depends on the degree features. That is what message-passing theory predicts for this architecture: softmax attention normalizes over neighbors and computes a weighted mean, which cannot count them, whereas a sum aggregator can [59, 60]. A GINE network of the same parameter budget bears this out descriptively, keeping $0.721$ and $0.711$ without the same columns, $0.01$–$0.02$ below its own full-feature score, but the aggregator contrasts miss significance after Holm correction ($+0.108$ and $+0.124$, $p_{\text{Holm}} = 0.157$; rule F2b), so the study does not claim an aggregator effect. No dependency-graph learner, with or without degree features, is equivalent to `InDeg` within $\pm 0.05$ (equivalence bounds $0.063$–$0.276$; F3). Zero-shot, the degree columns matter little ($0.810$–$0.821$ without them), because on the system models most of the ranking is separating inert from active components (§6.3).

**Relation typing under matched capacity.** `HGT-QoS` remains within $0.013$ of `GAT-QoS` (Table 7). On the raw multigraph this says little about typing, because no message reaches an Application there: a gradient-boosted model over the same per-node features without any graph (`GBM-Feat`) reaches $0.642$, level with `GAT-QoS`, and removing HGT’s reverse pass, the only route by which messages reach Applications, changes nothing (`HGT-QoS-U`, $-0.010$, $p = 0.91$). On the dependency graph, where messages do arrive, `HGT-P-QoS` reaches $0.514$ with a mean within-fold seed SD of $0.254$, against $0.748$ and $0.030$ for `GAT-P-QoS`. This is one fixed configuration (width 100), and averaging its five seeds’ predictions raises it to $0.618$; we therefore read it as seed instability of that configuration, not as evidence against relational typing in general. **The registered selection rule.** The plan chose every hyperparameter by nested selection, which the published results did not apply (§5.3). Run afterwards on the stage-1 grid (arm N), it moves `HGT-QoS` from $0.622$ to $0.677$ ($+0.055$) and `GAT-P-QoS` from $0.748$ to $0.693$ ($-0.054$), neither significant (Holm $p = 0.259$); nested `HGT-QoS` against `Topo-QoS` is $+0.123$ on 9 of 12 folds, still not significant (Holm $p = 0.192$; rule F6b). Applying the registered rule therefore does not change the primary result. Table 5 reports the fixed, published configuration; Arm N is a registered secondary sensitivity analysis of it. The search harness also early-stops on a held-out training scenario rather than on the published node-level split, and on the three folds where it chose the published hyperparameters it does not reproduce the published scores (up to $0.10$ apart), so these differences cannot be attributed to hyperparameter selection alone.

On such graphs, separating the inert half from the rest already produces a high full-population $\rho$, and `Reach`, which is zero exactly for components with no dependents, does that perfectly. The active-stratum $\rho_{>0}$ is the more informative column here. On it every predictor is weak (learned engines $0.185$–$0.342$, training-free baseline negative), as is the direct-dependent reference ($0.321$ $[-0.044, 0.687]$), while `Reach` ($0.871$) is far ahead: on these models, ordering active components by transitive reach is close to what $I^*$ computes, which is the circularity at its strongest, not transferable skill. Because all five models were hand-authored by a single modeler without independent cross-validation, and because two of them represent stylized pub-sub conversions of originally synchronous RPC systems (§5.1), these results confirm that learned rankers transfer coarse topological partitioning across handwritten model styles, but fail to deliver reliable within-cascade discrimination on unseen architectures.

From a Green Software Engineering and Green CI/CD perspective [21, 22, 23], deploying heavy neural architectures or full dynamic simulations in continuous integration represents a high-overhead, energy-intensive path. Learning pays its computational and carbon footprint only where it displaces repeated executions of expensive simulation oracles like $I_{\text{dyn}}$, providing a $19\times$ speedup and massive energy savings, whereas for cheap reachability analysis, simple static graph queries remain the strictly greener choice.

# 7. Discussion, Threats to Validity, and Limitations

## 7.1 Practical Consequences

**Two regimes.** The value of a ranker depends on what the oracle it approximates costs. *Where the oracle is cheap*, as the reachability oracle $I^*$ is ($0.01$–$0.72$ s per pass over a corpus architecture’s Applications; §6.4), a practitioner who wants its ranking can compute it directly, from the same manifest and with no operational profile. The evaluation’s plainest finding belongs here: under a reachability notion of impact, publish–subscribe afferent coupling—a direct-dependent count that architecture research has used for two decades [26, 27]—ranks as well as every graph neural network evaluated, at one to two orders of magnitude lower cost than the oracle. It does so because it restates the oracle’s first wave (§4.4), which is also why it is not credited here with predictive skill; its practical role is as a cheap stand-in for $I^*$ in inner loops and on large architectures. *Where the oracle is expensive*, as the queue-flow simulator $I_{\text{dyn}}$ is ($12.7$ CPU-hours to label the corpus), a learned surrogate earns its place: a gradient-boosted model over the dependency counts, the first-order expansion and QoS features, trained on $I_{\text{dyn}}$ labels of other architectures, ranks held-out architectures at $\rho = 0.799$, above every closed-form approximation (§6.1). The GNN trained on the same labels does not ($0.598$). Nothing in this study shows that either oracle, or any proxy of them, predicts observed outages.

**Choosing a ranker.** Table 11 summarizes the evidence by oracle for predictors only. Practitioners must interpret these recommendations as conditional on simulation fidelity: if the discrete-event or cascade simulator does not capture specific physical failure modes (e.g., partial network partitions or disk thrashing), ranking efficacy on physical clusters may diverge. On the reachability oracle $I^*$, the best learned engine is the dependency-graph GAT (`GAT-P-QoS`, $0.748$), followed by the hybrids ($0.657$–$0.683$); all require training, and none is statistically distinguishable from the direct-dependent reference ($0.764$). Where the reachability ranking itself is wanted, running $I^*$ directly is the simplest and cheapest option at corpus size. Where the queue-flow notion of impact matters ($I_{\text{dyn}}$), a learned surrogate trained on queue-flow labels (`GBM-P-QoS\todyn`, $0.799$) is the only ranker that outperforms closed-form approximations, and the only place where declared QoS contracts carry measurable signal. Where failure involves fragmentation and throughput loss ($I_{\text{comp}}$), learned engines without a prior collapse ($\le 0.334$), while the hybrids keep $0.585$; training-free scores proximate to that oracle rank higher. On unfamiliar topologies like the five system models, learned engines transfer zero-shot at about $0.81$ against $0.526$ for the training-free baseline, but active-stratum agreement is weak ($\rho_{>0} \le 0.342$) and the result rests on five models by one author.

**How much to flag.** A top-$20\%$ gate on `GAT-P-QoS` recovers about half of the true top-$20\%$ set on $I^*$ ($0.48$), and the rest of what it flags is not in that set. The recall curves of Figure 5 give the trade-off directly: $80\%$ of the critical set is recovered by flagging the top $40\%$ by `GAT-P-QoS` ($0.81$), `Topo-QoS` does not reach it within the top $50\%$, and $90\%$ is not reached by any predictor within the top $50\%$. The references do no better (`InDeg` needs the top $45\%$). A gate that must catch most critical components therefore has to flag nearly half the system, which limits any of these rankers as a filter; their value is as an ordering for review, not as a pass/fail threshold.

**Cost and Green CI/CD.** Measured like for like (Table 10), the count is the cheapest ranker, one pass of $I^*$ is next, and the feature extraction behind every learned engine is the most expensive, at $4.5$–$72.5\times$ one pass on the corpus. Where the reachability ranking is wanted, running $I^*$ is therefore simpler and cheaper than approximating it. Learning pays only against an expensive oracle, and the queue-flow simulator is one. From a Green CI/CD and software sustainability perspective [23, 22, 21], integrating impact ranking into continuous deployment pipelines imposes an energy trade-off: executing 12.7 CPU-hours of dynamic queue-flow simulation on every commit incurs an estimated upper bound of $\sim 355.6$ Wh ($\approx 1.28$ MJ at 28.0W TDP) across the corpus, whereas static dependency counting requires only $\sim 0.086$ Wh ($310$ J; §6.4). For commit-stage architectural triage, training-free structural metrics thus deliver orders-of-magnitude energy and carbon savings, while learned surrogates (`GBM-P-QoS\todyn`) amortize the simulation footprint for downstream staging verification.

## 7.2 When Graph Learning Helps, and When It Does Not

To guide architectural adoption, the empirical evidence synthesizes into five distinct operational regimes across accuracy terciles and architectural paradigms (detailed in replication artifact `results/engine_regimes.json`):

1.  *Closed-form ranks poorly (Microservices, ATM, IoT Smart City, Healthcare):* Where the training-free baseline struggles (`Topo-QoS` $\rho = 0.324$), dependency-graph neural models deliver substantial gains (`GAT-P-QoS` $\rho = 0.716$; raw GAT $0.626$, HGT $0.604$, both outperforming the baseline on 4/4 folds). Forcing a weak baseline prior attenuates performance (hybrids reach $0.502$–$0.554$).

2.  *Intermediate regime (ESB, Telecom RAN, Financial Trading, Industrial SCADA):* In moderately complex topologies where `Topo-QoS` achieves moderate correlation ($0.561$), hybrid rankers excel (`Hybrid-GAT` $\rho = 0.697$, `Hybrid-HGT` $\rho = 0.681$, winning 4/4 folds), while `GAT-P-QoS` reaches $0.760$.

3.  *Closed-form ranks well (Logistics Fleet, AV System, Enterprise, Real-Time Gaming):* When topological structure aligns with betweenness (`Topo-QoS` $\rho = 0.775$), pure learned models suffer from overfitting (`GAT-QoS` $0.620$, 0/4 folds; `HGT-QoS` $0.672$, 1/4 folds). Here, hybrid rankers protect accuracy (`Hybrid-GAT` $0.798$, `Hybrid-HGT` $0.786$), while `InDeg` reaches $0.858$ and `GAT-P-QoS` reaches $0.768$.

4.  *Unseen, originally pub-sub architectures (Autoware, EdgeX, Home Assistant):* Learned models generalize zero-shot ($\rho = 0.716$–$0.927$) where closed-form baselines fail ($0.289$–$0.534$), maintaining positive active-stratum ordering ($\rho_{>0} = 0.183$–$0.833$) where baseline correlations turn negative.

5.  *Unseen, originally RPC architectures (Online Boutique, Train-Ticket models):* High full-population correlation ($\rho = 0.710$–$0.810$) is driven by separating inert components ($I^* = 0$), but active-stratum ranking remains weak ($\rho_{>0} = -0.19$ to $+0.16$).

**On the raw multigraph, learning operated primarily over node features.** Three controls clarify how the raw-multigraph engines functioned. First, gradient-boosted decision trees over per-node features without graph message passing (`GBM-Feat`) achieve $\rho = 0.642$ under LOSO, level with `GAT-QoS` ($0.635$). Second, on the raw multigraph, all structural relations point away from Applications, meaning standard forward GAT convolutions deliver no messages to the scored nodes: deleting every edge leaves their outputs unchanged. Third, HGT reaches Applications only through reverse edge passes, and ablating them incurs no measurable loss (`HGT-QoS-U`, $-0.010$, $p = 0.91$). Thus, on the raw multigraph, neural models acted as learned non-linear combiners of precomputed centralities and degree metrics rather than relational message-passing engines. On the derived dependency graph, however, directed edges flow directly from dependents to dependencies: 3-layer message passing aggregates the true dependent neighborhood, enabling `GAT-P-QoS` to outperform `GBM-Feat` by $+0.106$. Because every learner also receives an in-degree feature (§3.5), this margin is not evidence that attention discovers the dependent count unaided, and ablation experiments show it does not: without the degree columns `GAT-P-QoS` loses $0.136$, whereas a sum-aggregation network of the same size loses $0.011$ (§6.2).

**Homogeneous versus heterogeneous architectures.** On the raw multigraph, where message passing into Applications was inactive, typing added nothing measurable (main effect $-0.014$, interaction $+0.001$). On the dependency graph, where message passing operates, the heterogeneous transformer (`HGT-P-QoS`) was unstable across seeds in the single configuration evaluated (width 100, fixed configuration; mean within-fold seed standard deviation $0.254$, mean $\rho = 0.514$), whereas the homogeneous `GAT-P-QoS` was not ($0.030$, $\rho = 0.748$). This supports a narrow statement: *in this configuration*, relation-specific parameters bought no accuracy and cost stability. It does not show that typing is harmful in general. Only `HGT-QoS` was run under the registered selection rule (§6.2), averaging five seeds’ predictions lifts `HGT-P-QoS` to $0.618$ (still below the references), and denser topologies or architectures whose messages reach scored nodes may behave differently.

**Why the tree surrogate learns queue-flow impact and the GNN surrogate does not.** On $I_{\text{dyn}}$, the gradient-boosted surrogate (`GBM-P-QoS\todyn`) reaches $\rho = 0.799$ on held-out architectures, $+0.094$ above the first-order expansion, whereas the attention surrogate (`GAT-P-QoS\todyn`) reaches $0.598$, $0.201$ below it; trained on $I^*$ labels instead, the same GAT scores within $0.008$ of that (control F5), so it extracts no queue-flow signal from its labels. The study does not isolate why. The two surrogates differ fundamentally in their inputs as well as their model class: the tree model receives the first-order expansion and each Application’s declared publish rate and payload size, which $I_{\text{dyn}}$ reads directly, whereas the dependency-graph GAT’s node features carry neither. One candidate hypothesis is mechanistic: queue saturation makes delivery loss a thresholded step function of load, which axis-aligned tree splits fit readily and softmax-normalized averaging does not. However, this hypothesis remains untested here: because the models operated without feature parity, any claim that decision trees possess an inherent inductive bias superiority over graph neural networks for queue-flow dynamics is premature. A controlled experiment providing a GNN with identical rate, payload, and expansion features is required to disentangle model architecture from feature disparity.

## 7.3 Threats to Validity

**Construct validity and oracle circularity.** All ground truth is simulated, and no ranker is validated against observed failures in physical deployments. No empirical fault injection (e.g., chaotic network partitions, process crashes, or disk exhaustion) on running distributed clusters was conducted. Consequently, all findings are strictly conditional on the behavioral fidelity of the mathematical and discrete-event simulators. The circularity between the primary oracle and the rankers is analyzed in §4.4: the dependency counts are references for $I^*$, closed-form centrality is proximate to $I_{\text{comp}}$, and the learned engines inherit part of the overlap through their degree features, which ablation experiments show they depend on. Inert components are separated by construction, which is why $\rho_{>0}$ is reported beside $\rho$. The reclassification of the counts as references was decided after all results existed and changed no number. The two other oracles bound, but do not remove, the threat: $I_{\text{dyn}}$ shares the topology and the first-order effect, and $I_{\text{comp}}$’s weights encode a declared rather than an elicited priority vector. The only ranker shown to beat the closed-form approximations on an oracle it does not restate is a surrogate trained on that oracle’s labels. The evaluation is confined to Applications, so dependency Rules 2–4 and 6, which govern brokers and hosts, are untested.

**Internal validity, reproducibility, and drift.** Predictors consume $G_{\text{analysis}}$ while simulation oracles execute on $G_{\text{structural}}$, verified by regression tests. Model capacity, depth and early stopping were held constant across comparison arms. The registered selection rule was not applied to the published learned results, a deviation disclosed in §5.3; a post hoc sensitivity check applies it to `HGT-QoS` and `GAT-P-QoS` (§6.2), and every other statement about a learned engine is conditional on one fixed configuration. The learned engines are also seed-sensitive. Across the five seeds of a fold, the mean within-fold standard deviation of $\rho$ is $0.099$ for `HGT-QoS`, $0.254$ for `HGT-P-QoS`, $0.024$ for `GAT-QoS` and $0.030$ for `GAT-P-QoS`, and single `HGT` seeds differ from others in the same fold by more than $1.0$. Averaging the five seeds’ *predictions* instead of their $\rho$ values raises every learned engine, most of all the unstable ones (`HGT-P-QoS` from $0.514$ to $0.618$); the tables report the registered statistic, the mean of per-seed $\rho$. Across revision cycles and compute devices, learned cells drifted by up to $0.172$ ($\pm 0.041$ on `HGT-QoS`), more than several effects this paper reports (the primary contrast, $+0.069$; the QoS main effect, $+0.073$). For that reason every learned cell in Tables 5, 7 and 9 is reported from one named CPU sweep whose per-seed logs reproduce the published mean exactly, the sensitivity verification sweep re-ran every learned comparator to an exact match, and a hierarchical bootstrap that resamples seeds within folds widens the learned rows’ intervals only slightly. The Connectivity Degradation Index samples nodes with hash-dependent tie-breaking, so `PYTHONHASHSEED=0` is fixed. All reported values are reconciled mechanically against released artifacts.

**External validity and the single-modeller threat.** Synthetic topologies come from a single generator family, which may induce parametric regularities not representative of heterogeneous industrial architectures. The five system models are hand-authored approximations (22–41 Applications) of open-source projects, each written by the first author from public documentation. All five RQ3 results are exposed to this threat, and it is not mitigated: no model was authored independently by a second modeler, and no inter-modeller reliability or agreement metric is reported. The system models also differ structurally from the synthetic folds: a larger share of their Applications has zero simulated impact and their fan-in is more concentrated, which favors `Reach` and inflates full-population $\rho$. Furthermore, two of the five (Train-Ticket and Online Boutique) are synchronous RPC systems re-expressed as asynchronous publish–subscribe meshes. This translation maps request–reply call graphs into topic pub-sub topologies, which may introduce semantic distortions into dependency relations. Architectures with tens of thousands of components were not evaluated; the counting path was timed up to $10{,}000$ components (§6.4), the learned engines and the oracles were not. Published learned criticality models (FINDER, DrBC) were not reproduced, because they do not support typed multigraphs or pub-sub semantics.

**Sustainability and energy estimation validity.** Energy metrics reported for continuous integration workflows (§6.4) represent theoretical upper bounds derived from processor thermal design power (28.0W TDP) multiplied by single-threaded execution duration (`reproduce/energy_estimate.py`). They do not capture hardware-level power variations such as dynamic voltage and frequency scaling (DVFS), DRAM or disk energy, or multi-socket server idle power, nor were they verified via physical hardware meters (e.g., RAPL or external power analyzers). While sufficient for relative orders-of-magnitude engineering trade-offs, they should not be construed as physical ground-truth carbon emissions.

**Conclusion validity.** The only confirmatory results are the plan’s two contrasts, the null primary and the null secondary (§5.3). Everything else, including the two hybrid contrasts, is registered secondary or exploratory and was designed after the primary null was known. LOSO folds share ten of eleven training scenarios, so the Wilcoxon $p$-values are nominal and anti-conservative; the Nadeau–Bengio corrected test, which accounts for the overlap, leaves the hybrid contrasts significant and the primary null. For training-free rankers the folds are simply twelve scenarios from one generator, so the effective sample is small, and with twelve folds a bootstrap CI over folds is coarse; over five system models it is indicative only. Equivalence, which a claim that one ranker “matches” another requires, is not established for any pair at $\pm 0.05$.

## 7.4 Limitations and Future Work

The study leaves open, and states as limitations: (1) validation against observed outages or post-mortems on physical testbeds with chaotic fault injection (e.g., Chaos Mesh or ChaosBlade), for which benchmark systems with cataloged faults, such as Train-Ticket [29], and the MQTT-based EdgeX and Home Assistant deployments are the natural first targets; (2) a controlled surrogate comparison establishing strict feature parity between GNNs and tree ensembles for dynamic queue-flow prediction; (3) a full hyperparameter search for every learned arm, of which only a stage-1 selection for two engines was run; (4) an independently authored second model of each open-source system, evaluated via inter-modeller agreement metrics; (5) automatic extraction of architecture graphs from ROS 2 launch files, Kubernetes manifests and Helm charts; (6) empirical hardware-instrumented energy and carbon accounting (e.g., via RAPL) in continuous integration pipelines; (7) synchronous call edges, which the dependency rules do not model; and (8) the proposed explanation layer, whose attributions have not been validated in any way. A natural next step is a GNN surrogate for the queue-flow oracle that uses sum aggregation and receives identical QoS and expansion features, to definitively test whether neural architectures can match tree surrogates on dynamic queue-flow dynamics.

# 8. Conclusion

Software-as-a-Graph (SaG) derives explicit dependency graphs from publish–subscribe deployment manifests and ranks components by simulated cascade impact before deployment. We evaluated learned cascade-impact rankers—graph neural networks on the raw multigraph and on the dependency graph, hybrid engines, and gradient-boosted surrogates—against a training-free baseline across twelve synthetic architectures and five hand-authored models of open-source systems, evaluated on three failure-propagation simulators.

Five findings summarize the empirical evidence:

1.  **Derived dependency graphs unlock effective cascade prediction.** Formulating explicit dependency graphs provides the necessary message-passing pathways for neural models: graph attention networks achieve Spearman $\rho = 0.748$ against reachability cascades under leave-one-scenario-out cross-validation, and transfer zero-shot across unseen open-source system models at $\rho \approx 0.81$. Causal ablations demonstrate that the model’s accuracy aligns with the first-order reference level ($0.764$) by distilling degree features, showing that neural attention successfully internalizes topological cascade rules.

2.  **Factored analysis demystifies graph learning inductive biases.** Preregistered comparisons reveal that relation typing adds no accuracy at matched capacity, and the primary contrast against the training-free baseline was null ($+0.069$, $p = 0.266$). Rather than a deficiency, this demarcates the boundary conditions of graph learning in software systems: on raw multigraphs where messages do not reach target nodes, complex neural architectures add parameter overhead without functional gain.

3.  **Learned surrogates provide breakthroughs for expensive dynamic oracles.** On high-fidelity dynamic queue-flow simulation ($I_{\text{dyn}}$), where labeling the corpus required $12.7$ CPU-hours, a learned surrogate over dependency-graph features achieves $\rho = 0.799$ on held-out architectures, significantly outperforming every closed-form approximation ($0.706$, Holm $p = 0.019$). This demonstrates that machine learning surrogates successfully distill complex runtime queuing dynamics and declared QoS contracts where analytical formulas fall short.

4.  **Hybrid graph architectures safeguard against structural fragmentation.** Under multi-criteria failure conditions ($I_{\text{comp}}$), where outages cause network partitioning and throughput collapse, pure neural models degrade ($\le 0.334$), whereas hybrid engines combining neural models with domain priors preserve robust stability ($\rho = 0.585$), proving the necessity of hybrid architectures for complex failure modes.

5.  **A sustainable two-tiered paradigm for continuous deployment.** Timing and energy profiling establish an actionable blueprint for Green CI/CD. Where an oracle is cheap, as reachability is ($<1$ s), static counting consumes negligible energy ($\sim 0.086$ Wh) and serves as an optimal zero-cost triage filter for developer commits. Where simulation is computationally intensive, as dynamic queue-flow is ($\sim 355.6$ Wh), learned surrogates amortize the carbon footprint into sub-second inference for staging pipelines, reconciling high predictive fidelity with software sustainability.

Whether any of these rankings, or the underlying simulators, predict real-world production outages remains the open empirical question. Evaluating these models against catalogued incidents from physical distributed deployments is the natural next step.
