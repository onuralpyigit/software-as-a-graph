\begin{abstract}
Publish--subscribe middleware obscures failure propagation, yet architects must identify critical components before deployment without telemetry. We present Software-as-a-Graph (SaG), deriving explicit dependency graphs from manifests to evaluate whether and when graph learning improves cascade-impact ranking. We compare graph neural networks, hybrids, and analytical simulator approximations across twelve synthetic architectures under leave-one-scenario-out cross-validation against three failure simulators, and zero-shot on five stylized open-source system models. A reference criterion distinguishes rankings that restate a simulator's propagation rule from those that predict it.

On a reachability simulator, graph attention on the derived dependency graph reaches Spearman's $\rho = 0.748$, $+0.072$ above the same model with reverse edges on the raw multigraph, whereas on the raw multigraph the registered primary contrast against a training-free baseline was null. It is not distinguishable from counting direct dependents ($\rho = 0.764$), and its gain survives removing input features that compute part of the simulator. For a queue-flow simulator requiring $12.7$ CPU-hours to label the corpus, a rate-weighted first-order approximation reaches $\rho = 0.830$ in milliseconds, matching or exceeding a learned approximation trained on simulator labels ($\rho = 0.799$; exploratory). Learners that start from that approximation do not improve on it. Learned models transfer zero-shot better than the training-free baseline ($\rho \approx 0.81$ vs.\ $0.53$), although dependency counts rank higher.

All three simulators admit such approximations: under first-order propagation regimes, explicit dependency representation renders complex learning superfluous. Representation matters more than model complexity; learned methods must be evaluated against aligned analytical baselines.

\end{abstract}

\section{Introduction}
\label{sec:1}

\subsection{Motivation and Problem}
\label{sec:1.1}

Large distributed systems increasingly use asynchronous publish-subscribe (pub-sub) middleware: ROS 2 for autonomous driving \cite{macenski2022robot}, Apache Kafka for enterprise event streams \cite{kreps2011kafka}, DDS in cyber-physical systems \cite{omg2015dds}, MQTT in IoT \cite{oasis2019mqtt}, and cloud-native microservices \cite{dragoni2017microservices,newman2015building}. Pub-sub separates producers and consumers in space, time and synchronization \cite{eugster2003faces}; components communicate via topics and brokers, and Quality-of-Service (QoS) policies set at deployment control reliability, durability, priority and deadlines. This decoupling also hides how failures spread. Outages and backpressure travel through brokers, shared topics, colocated hosts and shared libraries \cite{motter2002cascade,buldyrev2010cascade}, in sequential cascades (a slow subscriber fills a broker queue and starves its publishers \cite{albert2000error}) and in simultaneous blasts (a library crash takes down every service that uses it). Neither is visible in architecture diagrams or call graphs. The cheapest time to address these risks is before deployment \cite{avizienis2004basic,bass2012software}, when no telemetry exists, so critical components must be identified from configuration manifests alone.

Current practice leaves a gap between service-level analysis and system dependability: a system can have no defect in any service yet fail through hidden single points of failure or mismatched QoS contracts \cite{perry1992foundations,garcia2009identifying}. The Architecture Tradeoff Analysis Method (ATAM) depends on manual input \cite{kazman1998atam}, static code analysis inspects services in isolation \cite{sonarsource2024clean,chidamber1994metrics}, and chaos engineering \cite{basiri2016chaos}, fault injection \cite{meiklejohn2021service} and dependency tracing \cite{yu2021microrank} need a running system and considerable computation \cite{calero2015green,verdecchia2023greenai,schwartz2020greenai}. Graph representations have long supported reliability and defect analysis \cite{yacoub2002reliability,zimmermann2008predicting}, and graph learning has recently been applied to network criticality \cite{fan2020keyplayers,fan2019learning} and microservices \cite{khodabandeh2025linkpred}. It remains unclear whether such models' performance originates from the learning algorithm or from the dependency representation it reads, and whether and when graph learning adds measurable value beyond analytical baselines derived from the same dependencies. Software-as-a-Graph (SaG) investigates this question.

\subsection{The Software-as-a-Graph (SaG) Approach}
\label{sec:1.3}

SaG models an event-driven architecture as a typed, directed multigraph over Applications, Brokers, Topics, Execution Hosts and Shared Libraries (Figure~\ref{fig:1}), derives an explicit \texttt{DEPENDS\_ON} dependency graph through publish--subscribe rules (Section~\ref{sec:3.3}), and supports analytical, hybrid and learned cascade-impact rankings on it (Sections~\ref{sec:4} and~\ref{sec:6.2}). Labels come from three simulators on the raw topology that encode different failure notions: structural reachability ($I^*$), discrete-event queue saturation ($I_{\text{dyn}}$) and multi-criteria fragmentation ($I_{\text{comp}}$) (Section~\ref{sec:4.3}). Because simulators and rankers read the same architecture, some analytical rankings restate a simulator's rule; a reference criterion (Section~\ref{sec:4.4}) evaluates these as analytical truncations of the simulation rule, ensuring that predictive rankers are not credited merely for rediscovering first-order topological spreading. The reachability simulator is cheap, serving to calibrate the method; the queue-flow simulator is computationally expensive, making its approximation a genuine surrogate-modelling problem.

\subsection{Findings in Brief}
\label{sec:1.findings}

\emph{Making dependencies explicit enables graph learning.} On the raw multigraph every relation points away from Applications, so message passing never reaches the scored nodes, and the registered primary contrast (a heterogeneous graph transformer against the training-free baseline) was null ($\Delta\rho = +0.069$, $p = 0.266$). On the dependency graph, a graph attention network (GAT) reaches Spearman $\rho = 0.748$ against the reachability simulator (\texttt{GAT-P-QoS}), against $0.635$ on the raw multigraph. Neither edge direction ($+0.072$ over a GAT that passes every raw edge both ways, Holm $p = 0.014$) nor the features that compute part of the simulator account for the gain: with all of them removed, the dependency-graph GAT beats an equally stripped reverse-edge control by $+0.231$ (Holm $p = 0.0068$).

\emph{The same representation enables simple analytical rankings that learned models do not exceed.} Counting direct dependents, publish--subscribe afferent coupling, reaches $0.764$ and is not distinguishable from the best learned model. On the queue-flow simulator ($12.7$ CPU-hours to label the corpus), a rate-weighted first-order approximation reaches $0.830$ in milliseconds and exceeds a gradient-boosted approximation trained on the simulator's labels ($0.799$; exploratory). Learners that start from it do not improve on it: as an extra input it leaves a gradient-boosted model at its value, and as a prior it leaves a graph attention network below it ($-0.018$).

\emph{Learning adds measurable value only relative to a weak comparator.} Hybrids that correct a closed-form prior outperform the training-free baseline but not their own base learners. Learned models transfer zero-shot to five stylized models of open-source systems better than that baseline ($\rho \approx 0.81$ vs.\ $0.53$), while dependency counts rank higher still and ordering among active components remains weak. Across all three simulators, ranking is well approximated by low-order functions of the dependency graph, establishing that in first-order regimes learning adds no predictive advantage. In practice, recovering 80\% of the critical set requires reviewing about 40--45\% of Applications, so rankings suit prioritized review rather than blocking gates (Section~\ref{sec:8.1}).

\subsection{Research Questions}
\label{sec:1.4}

Addressing when graph learning is needed, establishing when learning is unnecessary is as informative as showing when it succeeds: this study answers the question by identifying the structural boundary conditions under which learning is superfluous. Specifically, software engineering research has repeatedly shown that simple metrics can match more complex models when the right information is available \cite{zimmermann2008predicting,premraj2011network,hellendoorn2017deep,errica2020fair}. We therefore evaluate learned models against analytical rankings derived from the same dependencies:

\begin{itemize}\tightlist
\item \textbf{RQ1 (Ranking accuracy):} \emph{How accurately do analytical baselines, hybrid models, and learned approaches rank components by cascading-failure impact on unseen architectures, and can learned models exceed analytical truncations of the simulator's propagation rule?}
\item \textbf{RQ2 (Sources of predictive performance):} \emph{At matched model capacity, which factors contribute most to ranking performance: the dependency representation, degree information, relation typing, QoS information, or the model family?}
\item \textbf{RQ3 (Transfer):} \emph{How well do learned models trained on synthetic architectures transfer zero-shot to stylized models of five open-source systems, and does their ordering of components that actually propagate failures hold?}
\item \textbf{RQ4 (Cost):} \emph{What do analytical and learned approaches cost at CI/CD time in latency and estimated energy, and how does this compare with running each simulator directly?}
\end{itemize}

The evaluation follows an analysis plan pre-specified in the replication repository. Only its two co-primary contrasts are confirmatory, and both were null; the headline findings above are registered secondary or exploratory (Section~\ref{sec:6.3}).

\subsection{Contributions}
\label{sec:1.5}

\begin{enumerate}\tightlist
    \item \textbf{Dependency derivation for publish--subscribe architectures} (Section~\ref{sec:3}): typed rules that derive explicit dependency graphs from deployment manifests, extending the Application-level rule of \cite{yigit2025graph} with library-mediated dependencies.
    \item \textbf{An evaluation guideline for simulator-labeled benchmarks} (Section~\ref{sec:4.4}): an order-$k$ reference criterion, truncating a simulator's own computation, against which learned rankers are compared to separate genuine cascading prediction from first-order topological rule restatement.
    \item \textbf{A controlled comparison of analytical, hybrid, and learned rankers} (Sections~\ref{sec:rq1}--\ref{sec:rq3}) that separates the effects of representation, degree information, relation typing, QoS information and model family.
    \item \textbf{Analytical and learned approximations of an expensive simulator} (Section~\ref{sec:rq1}): a rate-weighted first-order approximation of a queue-flow simulator (Eq.~\eqref{eq:rate-expansion}), compared with learned approximations trained on its labels.
    \item \textbf{A reproducible benchmark, cost analysis and practitioner guidance} (Sections~\ref{sec:6.1}, \ref{sec:rq4} and~\ref{sec:8.1}) over seventeen architectures and three simulators.
\end{enumerate}

A previous conference paper \cite{yigit2025graph} introduced the publish--subscribe multigraph, the Application-level subscriber-to-publisher dependency (Rule~1 of Table~\ref{tab:2}) and a closed-form betweenness--articulation score similar to the training-free baseline (Eq.~\eqref{eq:topo}), validated against a reachability-loss simulation. Everything else here is new: the Library and infrastructure rules, QoS weighting, the reference criterion, the learned and hybrid rankers, the simulator approximations, leave-one-scenario-out (LOSO) cross-validation and zero-shot evaluation, the second and third oracles, the matched controls and the cost analysis. Under this broader evaluation, the closed-form score family of \cite{yigit2025graph} is the weakest analytical ranker, and the present results supersede that paper's implicit recommendation of it.

Section~\ref{sec:2} reviews related work, Sections~\ref{sec:3} and~\ref{sec:4} present the model and the rankers, Sections~\ref{sec:6} and~\ref{sec:7} the evaluation, Section~\ref{sec:8} the discussion and threats, and Section~\ref{sec:9} concludes.

\section{Related Work}
\label{sec:2}

\subsection{Dependability and Failure-Impact Analysis of Distributed Systems}
\label{sec:2.1}

Runtime dependability methods such as broker clustering, backpressure, autoscaling, failover and chaos engineering \cite{basiri2016chaos} require a running cluster and significant computing resources, a concern in green software engineering \cite{calero2015green,verdecchia2023greenai,schwartz2020greenai}. Pre-production methods such as service-level fault injection \cite{meiklejohn2021service} and microservice dependency localization with PageRank (MicroRank \cite{yu2021microrank}) are lighter, and benchmark platforms with cataloged, replayable faults such as Train-Ticket \cite{zhou2018trainticket} measure failure impact on a running deployment. Architecture-based reliability prediction has a long history: Yacoub and Ammar \cite{yacoub2002reliability} combined component dependency graphs with complexity and failure severity to rank components by risk, and state, path and additive reliability models \cite{gosevapopstojanova2001architecture} and the Palladio Component Model \cite{becker2009palladio} are classic examples.

Error propagation has also been analyzed at the architecture level \cite{abdelmoez2004error,popic2005error,cortellessa2007modeling,hiller2004epic}, and safety-critical practice uses model-based failure analysis such as HiP-HOPS \cite{papadopoulos1999hiphops} and the AADL Error Model Annex \cite{delange2014aadl}. These frameworks derive propagation paths from structural descriptions, as SaG's dependency projection does, but they need failure-mode annotations, propagation probabilities or operational profiles, which deployment manifests do not carry.

Telemetry-based methods localize faults in running microservices, among them Seer \cite{gan2019seer}, MicroRCA \cite{wu2020microrca} and GNN-based root-cause frameworks such as Eadro \cite{lee2023eadro}, reviewed by Zhang et al.~\cite{zhang2024failurediag}. All need data from a live system; SaG works before any code is run. Production traces show that real dependency graphs are large and dynamic \cite{luo2021alibaba}, and that metastable failures are sustained by load feedback rather than by the structure that failed \cite{bronson2021metastable,huang2022metastable}, which a structural ranking cannot see. SaG's focus is close to change impact analysis \cite{bohner1996impact} and microservice dependency management \cite{esparrachiari2018tracking}, and ranking by impact relates to learning-to-rank defect prediction \cite{yang2015ltr}.

Failure-impact rankings are often evaluated against a simulator rather than observed outages, so a ranking may agree with a simulator because it encodes the simulator's propagation rule rather than because it predicts its behavior. The concern is not new: simulation methodology treats a model used as ground truth as something to be validated \cite{sargent2013verification}, simple neighborhood counts track short-range spreading processes \cite{kitsak2010influential}, and learned models exploit shortcuts that encode the labeling rule \cite{geirhos2020shortcut}. What we add is an operational check for simulator-labeled ranking benchmarks (Section~\ref{sec:4.4}).

\subsection{Static Analysis and Architectural Dependency Metrics}
\label{sec:2.2}

Static code analysis tools such as SonarQube \cite{sonarsource2024clean} measure complexity \cite{mccabe1976complexity}, cohesion and coupling \cite{chidamber1994metrics} within individual services to identify defect-prone modules \cite{nagappan2005static,zimmermann2007predicting}. In defect prediction, Zimmermann and Nagappan \cite{zimmermann2008predicting} applied network analysis to dependency graphs, and Premraj and Herzig's replication \cite{premraj2011network} found that simple code and coupling metrics often perform as well. Such analysis cannot see inter-service messaging, broker saturation or cross-host propagation. Architecture recovery tools rebuild system structure from code \cite{bushong2021static}, and HAROS \cite{santos2019haros} and ROSDiscover \cite{timperley2022rosdiscover} recover the run-time architecture of ROS systems, the kind of extraction SaG would need on real systems. Architecture-level coupling metrics count a service's consumers: afferent coupling \cite{martin2003agile}, the Absolute Importance of the Service \cite{rud2006ais} and service fan-in \cite{bogner2017maintainability}. In publish--subscribe systems this count is a typed two-hop query (publisher to topic to subscriber), which SaG's dependency rules define; because it matches the reachability oracle's first propagation wave, this paper benchmarks it both as an established structural baseline and as an analytical reference (Section~\ref{sec:4.4}). Such analyses support the detection of anti-patterns \cite{garcia2009catalogue,taibi2018microservice} and architectural technical debt \cite{li2015technicaldebt} in CI/CD \cite{humble2010continuous}.

\subsection{Graph Learning on Dependency Structures}
\label{sec:2.4}

Closed-form indices \cite{freeman1977centrality,brandes2001faster,brin1998pagerank,newman2010networks}, including this study's training-free baseline, and cascade models of network robustness \cite{albert2000error,motter2002cascade,buldyrev2010cascade} assume homogeneous, usually undirected graphs, so a single untyped score mixes topics, libraries and hosts. Learned node-importance methods such as FINDER \cite{fan2020keyplayers}, DrBC \cite{fan2019learning} and PowerGraph \cite{varbella2024powergraph}, and learned approximations of betweenness and closeness \cite{maurya2021gnnbet}, also assume homogeneity; GENI \cite{park2019geni} estimates node importance on heterogeneous knowledge graphs. Homogeneous GNNs such as GAT \cite{velickovic2018graph} ignore relation identity unless it is a feature, and softmax attention averages over neighbors and cannot count them, whereas sum aggregation can \cite{xu2019gin,corso2020pna}; message-passing GNNs are limited in counting substructures without explicit features \cite{chen2020can}. Because the main reference here is a neighbor count, this difference matters (Section~\ref{sec:rq2}). Heterogeneous GNNs such as HGT \cite{hu2020hgt} learn relation-specific transformations, but Lv et al.~\cite{lv2021revisiting} found that they often fail to beat well-tuned homogeneous baselines. GNN rankings are also sensitive to splits and tuning \cite{shchur2018pitfalls}, and label propagation with shallow models can outperform GNNs \cite{huang2021combining}. Khodabandeh et al.~\cite{khodabandeh2025linkpred} use graph attention on microservice call graphs to predict upcoming interactions; we predict the effect of removing a node from a declared topology.

\subsection{Positioning of This Study}
\label{sec:2.5}

This study builds on findings that simple baselines can match more complex learning methods \cite{hellendoorn2017deep,errica2020fair} and that network measures add little over simple coupling metrics \cite{zimmermann2008predicting,premraj2011network}. It differs from prior work in three ways: it derives explicit dependency graphs from publish--subscribe deployment manifests rather than starting from an existing architectural graph; it evaluates analytical, hybrid and learned rankers on the same representation and asks where their performance originates; and it applies an operational reference criterion to separate rankings that restate a simulator's rule from those that predict its outcomes. Rather than asking whether graph learning can rank cascade impact, it asks whether learning adds measurable value beyond analytical baselines derived directly from the explicit dependency structure.

\label{sec:3}

\subsection{Multigraph Definition}
\label{sec:3.1}

A distributed system is described as a typed, weighted, directed multigraph
\begin{equation}
\label{eq:sag_multigraph}
\mathcal{G} = (V, E, \tau_V, \tau_E, w_V, w_E),
\end{equation}
where $V = V_{\text{app}} \cup V_{\text{broker}} \cup V_{\text{topic}} \cup V_{\text{host}} \cup V_{\text{lib}}$ holds the five entity types of Table~\ref{tab:1}, $\tau_V$ and $\tau_E$ assign entity and relation types, and $w_V, w_E \in (0, 1]$ weight entity criticality and connection strength. An Application's $w_V$ is a power mean of the QoS weights $w(t)$ (Section~\ref{sec:3.2}) of its topics; a Library takes the largest weight among its topics and consuming Applications, amplified by its fan-out. The raw multigraph is $G_{\text{structural}}$; the analysis graph $G_{\text{analysis}}$ adds the derived \texttt{DEPENDS\_ON} edges (Section~\ref{sec:3.3}) and the node properties computed from them (Section~\ref{sec:3.5}). Supplementary Section~\ref{supp:notation} lists the notation.

\noindent\textbf{Scope.} The evaluation ranks \emph{Applications} only: microservice containers, service agents or communicating processes, the developer-authored code that changes in CI/CD. Brokers, Topics, Hosts and Libraries are modeled because failures propagate through them, but ranking them is a provisioning question rather than a commit-time one (Section~\ref{sec:limitations}).

\subsection{Quality-of-Service Link Weighting}
\label{sec:3.2}

A \texttt{RELIABLE} topic with \texttt{TRANSIENT\_LOCAL} durability couples services more strongly than a \texttt{BEST\_EFFORT} telemetry stream. Each topic $t$ therefore has a weight $w(t) \in (0, 1]$ combining its QoS policies (reliability, durability, priority) with payload size and publication frequency. The policy weights come from an Analytic Hierarchy Process (AHP) \cite{saaty1980ahp} pairwise-comparison matrix defined independently of any target vector ($CR = 0.016$; Supplementary Section~\ref{supp:ahp}). Declared QoS policies turned out to carry no measurable signal on either the reachability or the queue-flow simulator (Sections~\ref{sec:rq1} and~\ref{sec:rq2}); for $I^*$ this is largely fixed by design, because it barely reads QoS (Section~\ref{sec:4.3}). The dependency counts reported in this paper are unweighted.

\subsection{Logical Dependency Projection (\texttt{DEPENDS\_ON})}
\label{sec:3.3}

Structural edges do not show how failures spread: a subscriber depends on a publisher, but no edge joins them. SaG therefore derives \texttt{DEPENDS\_ON} edges from the dependent to the dependency (if the target fails, the source is affected) using the rules of Table~\ref{tab:2}. The resulting graph is the common input of the analytical, hybrid and learned rankers.

\begin{table}[htbp]
\centering
\small
\caption{The \texttt{DEPENDS\_ON} logical dependency projection rules. Rules~1 and~5 define the operational Application--Library projection evaluated in this study; $^\dagger$rules define broader infrastructure relations formalized for system-level completeness but unexercised by the Application-level evaluation.}
\label{tab:2}
\resizebox{\linewidth}{!}{%
\begin{tabular}{clll}
\toprule
\textbf{Rule} & \textbf{Dependency Category} & \textbf{Structural Pattern ($\text{Dependent} \to \text{Dependency}$)} & \textbf{Derived Weight ($w$)} \\
\midrule
\textbf{1} & \texttt{app\_to\_app} & Subscriber $\to$ Publisher (via shared Topic) & $1 - \prod_{t \in T}(1 - w(t))$ \\
\textbf{2}$^\dagger$ & \texttt{app\_to\_broker} & Publisher/Subscriber $\to$ Broker routing its topics & $1 - \prod_{t \in T}(1 - w(t))$ \\
\textbf{3}$^\dagger$ & \texttt{host\_to\_host} & Host $\to$ Host (lifted from inter-host app dependencies) & $\max_{u \in \text{hosted}(h_1), v \in \text{hosted}(h_2)} w_E(u \to v)$ \\
\textbf{4}$^\dagger$ & \texttt{host\_to\_broker} & Host $\to$ Broker (lifted from hosted app dependencies) & $\max_{u \in \text{hosted}(h)} w_E(u \to b)$ \\
\textbf{5} & \texttt{app\_to\_lib} & Application $\to$ Shared Library it \texttt{USES} & $H(w_V(\text{app}), w_V(\text{lib}))$ \\
\textbf{6}$^\dagger$ & \texttt{broker\_to\_broker} & Broker $\leftrightarrow$ Broker (shared fault-domain colocation, symmetric) & $w_V(\text{host})$ \\
\bottomrule
\end{tabular}%
}
\end{table}

Rules~1 and~2 combine the topics $T$ connecting a pair by probabilistic union \cite{pearl1988probabilistic}, so multiple failure paths strengthen the connection; Rule~5 uses the harmonic mean $H(x, y) = 2xy/(x+y)$ \cite{hardy1952inequalities}. Rule~1 captures sequential cascades (a failed publisher starves its subscribers) and Rule~5 simultaneous blasts (a crashed library fails every Application using it); neither is stated explicitly in a manifest. Rules~2, 3, 4 and~6 are formalized for architectural completeness across host and broker tiers, but are not exercised in the present Application-level evaluation.

\noindent\textbf{Remark 1 (the dependency count is a typed two-hop count).} Let $G_{\text{flow}}$ be the Application--Library projection (Rules~1 and~5) and $v$ an Application. By construction,
\begin{equation}
\label{eq:indeg}
\texttt{InDeg}(v) \;=\; \bigl|\{\,u \neq v : \exists t \in V_{\text{topic}},\; (v, t) \in \texttt{PUBLISHES\_TO} \wedge (u, t) \in \texttt{SUBSCRIBES\_TO}\,\}\bigr|,
\end{equation}
because Rule~5 edges end at Libraries, so every edge into an Application is a Rule~1 edge, and parallel topics between a pair collapse into one edge. The right side is publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais}, a typed two-hop query on the raw multigraph; the projection defines which query to use (the equality holds exactly on all seventeen corpus graphs). The derivation adds value beyond this count: including Rule~5 raises the agreement of transitive reach with $I^*$ by $+0.058$ (9 of 12 folds, Holm $p = 0.0068$; Section~\ref{sec:rq1}). Because $I^*$'s first propagation wave matches this set (Section~\ref{sec:4.4}), \texttt{InDeg} and its transitive version \texttt{Reach} serve as both established structural baselines and first-order analytical references. The in-degree \emph{feature} the learners receive also follows \texttt{USES} links; the two differ for 940 of the 1{,}321 Applications, with per-fold rank agreement $\rho = 0.55$--$1.00$ (Supplementary Section~\ref{supp:features}).

\subsection{Dual Graph Views}
\label{sec:3.4}

The \textbf{structural graph} $G_{\text{structural}}$ is the raw deployment topology; the \textbf{analysis graph} $G_{\text{analysis}}$ adds the \texttt{DEPENDS\_ON} edges and code metrics (Figure~\ref{fig:2}). Every ranker's node features are computed on $G_{\text{analysis}}$, and no ranker reads simulator output. The learners pass messages either over $G_{\text{structural}}$ or over the \texttt{DEPENDS\_ON} projection (the \texttt{-P} models), and the difference matters: on $G_{\text{structural}}$ every relation points away from Applications (\texttt{PUBLISHES\_TO}, \texttt{RUNS\_ON}, \texttt{USES}), so forward message passing never reaches them and forward GNNs collapse into per-node models over precomputed features. On the \texttt{DEPENDS\_ON} graph each Application receives messages from its dependents. Because the views also differ in edge direction, Section~\ref{sec:rq2} adds a raw-graph learner that passes every message in both directions, separating dependency semantics from direction.

\subsection{Typed Node Feature Encoding}
\label{sec:3.5}

All five entity types share 18 normalized metrics computed on $G_{\text{analysis}}$, including PageRank, reverse PageRank, betweenness, closeness, in- and out-degree, an articulation score, QoS and dependency weights, multi-path coupling, fan-out criticality and the Connectivity Degradation Index (CDI); type-specific blocks extend the vector to 19--25 dimensions (Applications and Libraries add a code-quality penalty and its four static-code inputs). The full schema is in Supplementary Section~\ref{supp:features}. Four centralities use QoS-weighted edges, so the QoS-off condition is not entirely free of QoS. Several features compute part of what the reachability simulator computes: in-degree and its QoS-weighted version $w_{\text{in}}$ are close to \texttt{InDeg}, CDI is a removal-and-reachability computation, and multi-path coupling, reverse PageRank, fan-out criticality and the articulation score are also aligned with it. Every published learner reads these \emph{oracle-aligned} features and so inherits part of the oracle's circularity; Section~\ref{sec:rq2} reports learners with all of them removed.

\section{Ranking Methods, Simulation Oracles, and the Reference Criterion}
\label{sec:4}

The study compares analytical rankings derived directly from dependency structure (the training-free baseline \texttt{Topo-QoS} and the references of Section~\ref{sec:6.2}), hybrid methods that correct an analytical prior with a learned model, and learned methods: graph neural networks on the typed multigraph or the dependency graph, and gradient-boosted models on per-Application features (Figure~\ref{fig:engines}). Full hyperparameters and training commands are in the replication repository's experiment pages.

\subsection{Heterogeneous Graph Transformer and Attention Networks}
\label{sec:4.1}

The main learned ranker, \texttt{HGT-QoS}, is a three-layer Heterogeneous Graph Transformer \cite{hu2020hgt} (PyTorch Geometric \cite{fey2019fast}; hidden dimension $64$, four heads) with entity-specific input projections and type-parameterized attention per meta-relation (Supplementary Section~\ref{supp:hgt}). It passes messages over its input graph and its transpose: $G_{\text{structural}}$ for \texttt{HGT-QoS}, the \texttt{DEPENDS\_ON} projection for \texttt{HGT-P-QoS} (width $100$, keeping parameters within $1\%$). The homogeneous Graph Attention Networks (\texttt{GAT-QoS}, and \texttt{GAT-P-QoS} on the dependency graph) use three \texttt{GATConv} layers with four heads at a matched parameter budget and pass messages forward only, except the direction control \texttt{GAT-QoS-R}, which also passes every edge in reverse. Each edge carries a 16-dimensional vector (coupling weight, path count, a one-hot relation encoding and seven middleware QoS parameters) that is projected and added before attention. Because the vector encodes the relation, the ``untyped'' GAT receives relation identity as a feature, but this matters only where messages reach Applications (Section~\ref{sec:3.4}); on the dependency projection every edge carries the same relation.

\subsection{Prediction Head and Training Objective}
\label{sec:4.2}

A composite head predicts the simulated cascade impact, with an auxiliary head $\hat{a}_1$ regressing on $I^*_R$, the reliability component the same simulator run records. The training objective combines regression with listwise and margin-ranking terms:
\begin{equation}
\label{eq:loss_active}
\mathcal{L} = \text{MSE}(\hat{I}^*, I^*) + 0.5 \cdot \text{MSE}(\hat{a}_1, I^*_R) + 0.3 \cdot \mathcal{L}_{\text{rank}} + 0.1 \cdot \mathcal{L}_{\text{pairwise}},
\end{equation}
where $\mathcal{L}_{\text{rank}}$ is the Listwise Maximum Likelihood Estimation (ListMLE) loss \cite{xia2008listwise} over the permutation $\pi$ induced by the simulated labels,
\begin{equation}
\label{eq:listmle}
\mathcal{L}_{\text{rank}} = -\frac{1}{N}\sum_{i=1}^N \Big( \hat{s}_{\pi_i} - \log \sum_{j=i}^N \exp(\hat{s}_{\pi_j}) \Big),
\end{equation}
and $\mathcal{L}_{\text{pairwise}}$ is a margin-ranking loss with $\gamma = 0.05$. Tied labels (about 31\% of Applications have $I^* = 0$) enter $\pi$ in the generator's creation order; a node-order permutation control tests whether this leaks into the results (Section~\ref{sec:rq2}).

Models are trained with AdamW ($\eta = 3 \times 10^{-4}$, weight decay $10^{-4}$) and cosine warm restarts for up to 300 epochs, with early stopping (patience 60) on a 20\% node-level validation split of the largest training scenario of each fold, over five fixed seeds. All reported evaluations are inductive under leave-one-scenario-out cross-validation. Hyperparameters and loss coefficients were fixed before the first sweep and kept across all experiments, rather than selected by the registered nested procedure (Section~\ref{sec:6.3}).

\subsection{Simulation Oracles}
\label{sec:4.3}

Labels come from three failure simulators (``oracles'') that run on the raw multigraph $G_{\text{structural}}$ and define different notions of cascade impact rather than observations of real failures:
\begin{itemize}\tightlist
    \item \textbf{Reachability cascade oracle ($I^*$, primary):} crashes component $v$, propagates outages through dependent topics, brokers and links by breadth-first traversal, and computes the mean fractional feed loss across intact subscribers, scaled by a declared, uncalibrated QoS severity ladder and averaged over five seeds that decide ties at the propagation threshold. Disabling QoS scaling leaves the Application ordering largely intact ($\rho = 0.965$ across the twelve folds), and substituting durability-aware rescaling moves it less still ($\rho = 0.977$): $I^*$ is predominantly a topological reachability metric.
    \item \textbf{Queue-flow oracle ($I_{\text{dyn}}$):} a discrete-event SimPy \cite{team2020simpy} simulation of message rates, queue saturation and network latency that measures the drop in delivered message rate for surviving consumers, using declared rates, payload sizes and QoS contracts that $I^*$ ignores. Its first-order effect, consumers losing a failed publisher's messages, is again subscriber loss. It labels all $1{,}321$ Applications (five seeds) in $12.7$ CPU-hours, against seconds for $I^*$, and agrees with $I^*$ at a mean $\rho = 0.711$. A single $I_{\text{dyn}}$ run agrees with another at $\rho = 0.43$--$0.96$ per fold; the five-seed mean used as the label has an estimated reliability of $r = 0.79$--$0.99$ (Spearman--Brown), so no ranker can agree with it by more than $\sqrt{r} \approx 0.89$--$0.996$ per fold, and every ranker in Table~\ref{tab:independent_oracles} stays below even $r$ on every fold.
    \item \textbf{Composite multi-criteria oracle ($I_{\text{comp}}$):} the Validate-stage failure simulator, run on all Applications, scores each removal as $I_{\text{comp}}(v) = 0.35\,\text{RL}(v) + 0.25\,\text{FR}(v) + 0.25\,\text{TL}(v) + 0.15\,\text{FD}(v)$ over reachability loss, fragmentation, throughput loss and flow disruption. The weights are declared, not elicited, so $I_{\text{comp}}$ is a multi-objective stress test rather than a measure of subscriber loss; it is never a training label.
\end{itemize}

\subsection{Input--Label Separation and the Reference Criterion}
\label{sec:4.4}

No simulation output is used as an input (a regression test enforces this). Procedural separation does not remove construct overlap, however: a ranking may agree with a simulator because it reproduces the simulator's rule rather than because it infers impact from independent evidence.

\noindent\textbf{The reference criterion.} A ranking $R$ is an \emph{order-$k$ reference} for an oracle $O$ if $R$ is what $O$ computes when its propagation is truncated after $k$ waves, with stated simplifications, from the same inputs $O$ reads. Whether a ranking qualifies is decided by derivation from the simulator's definition, not by its score. For $I^*$, the first-order expansion (Eq.~\eqref{eq:analytic_istar}) is the expected feed loss after one wave, \texttt{InDeg} is the support of that wave (Remark~1), and \texttt{Reach} is the unweighted support of the untruncated cascade. For $I_{\text{dyn}}$, the rate-weighted expansion (Eq.~\eqref{eq:rate-expansion}) is the delivered-rate loss after one wave, ignoring queueing. A reference measures how much of $O$ its own rule recovers, a property of the oracle rather than predictive skill, so comparisons with it are not claims of superiority; all other rankers are \emph{predictors}. For $I_{\text{comp}}$ no ranking is a truncation, but its fragmentation and flow terms respond to removing high-degree and high-betweenness nodes, so \texttt{Topo-QoS} and raw degree are \emph{term-aligned} with it and read with the same caution. We defined the criterion post hoc, after simple dependency counts performed strongly.

Learned methods are not references by this definition, but they are not less circular: they are fitted to the oracle they are scored against and read oracle-aligned features (Section~\ref{sec:3.5}). We therefore also report learners with those features removed and learners' agreement with $I_{\text{dyn}}$ after $I^*$ or the first-order term is partialled out (Section~\ref{sec:7}). Neither replaces validation against real failures (Section~\ref{sec:8.3}).

\section{Experimental Setup}
\label{sec:6}

The design asks whether ranking performance originates from the dependency representation or from the learning algorithm operating on it. If it arises from the representation, analytical and learned rankers built on that representation should perform similarly; if learning adds information, learned rankers should outperform analytical alternatives built on the same dependencies.

\noindent\textbf{Training-free baseline.} \texttt{Topo-QoS} is computed on the Application--Library \texttt{DEPENDS\_ON} graph (Rules 1 and 5):
\begin{equation}
\label{eq:topo}
\text{Topo-QoS}(v) = 0.6 \cdot \text{BT}_{w}(v) + 0.4 \cdot \text{AP}(v),
\end{equation}
where $\text{BT}_{w}$ is betweenness over edge distances $d(e) = 1/(w(e) + 10^{-6})$ and AP flags articulation points. Because of an implementation defect (an index mismatch when the articulation scores are read), the AP term is zero for every node, so the score every table reports is QoS-weighted betweenness alone. Restoring the term lowers \texttt{Topo-QoS} from $0.553$ to $0.533$, so the defect does not favor the references; Table~\ref{tab:hybrid} shows both values, and hybrids retrained on the corrected prior are in Section~\ref{sec:rq1}. The comparator was fixed when the analysis plan was written, before the dependency counts had been analyzed, and continues the score family of \cite{yigit2025graph}; in hindsight, afferent coupling would have been the natural comparator, and it is reported beside the baseline as a reference.

\noindent\textbf{References.} Three training-free rankings restate the reachability oracle's propagation rule. The first is the post hoc first-order expansion of $I^*$ (Analytic $I^*$):
\begin{equation}
\label{eq:analytic_istar}
\hat{I}^*_1(v) = \sum_{t \in \text{pub}(v)} \frac{|\text{sub}(t)|}{|\text{pub}(t)|},
\end{equation}
where $|\text{pub}(t)| \ge 1$ for all topics published by $v$. The second is \texttt{InDeg}$(v)$, the number of direct dependents on the \texttt{DEPENDS\_ON} graph (Remark~1), and the third \texttt{Reach}$(v)$, the number of transitive dependents normalized by $|V| - 1$. For the queue-flow simulator $I_{\text{dyn}}$, the corresponding reference weights each term of Eq.~\eqref{eq:analytic_istar} by the topic's declared publication frequency $r_t$:
\begin{equation}
\hat{I}^{\mathrm{rate}}_{\mathrm{dyn},1}(v) \;=\; \sum_{t \in \mathrm{pub}(v)} \frac{r_t}{|\mathrm{pub}(t)|}\,\lvert \mathrm{sub}(t) \rvert.
\label{eq:rate-expansion}
\end{equation}
Here, $r_t$ is the declared publication rate (msg/s) of topic $t$. It is a first-order truncation of $I_{\text{dyn}}$, which reads the same rates, and was evaluated after the registered analyses (exploratory). References carry no contrast against \texttt{Topo-QoS}; the one exception is the exploratory paired comparison between Eq.~\eqref{eq:rate-expansion} and the learned queue-flow approximation (Section~\ref{sec:rq1}).

\subsection{Metrics, Protocols and Statistics}
\label{sec:6.3}

\noindent\textbf{Metrics and protocols.} Every ranker is scored on the Application set $V_{\text{app}}$ with Spearman $\rho$ against each oracle, the active-stratum $\rho_{>0}$ over components with true impact above zero, and Overlap@$K$, the fraction of the true top-$K$ recovered by the predicted top-$K$ ($K \approx 20\%$ of $|V_{\text{app}}|$); PR-AUC, $F_1@\tau$ and nDCG@10 are in Supplementary Section~\ref{supp:identification}. Under LOSO, learned models train on eleven scenarios and are tested on the twelfth, for all 12 folds and five seeds, and the reported value is the mean $\rho$ across seeds. For zero-shot transfer, models trained on all twelve scenarios are evaluated on the five system models without fine-tuning. Training-free rankers are scored on the same scenarios and labels.

\noindent\textbf{Statistics.} The summary $\rho$ is the mean over folds or systems with a 95\% bootstrap interval ($B = 2{,}000$) \cite{efron1993introduction}. Contrasts use paired two-sided Wilcoxon signed-rank tests across folds \cite{wilcoxon1945individual,arcuri2011practical}, and, because LOSO folds share ten of eleven training scenarios, every registered contrast is also tested with the Nadeau--Bengio corrected resampled $t$-test \cite{nadeau2003inference}. The effect size is the number of folds on which a ranker beats its comparator (``won''). ``Matches'' means not significantly different, not statistically equivalent.

\noindent\textbf{Analysis plan and the status of each result.} The protocol is pre-specified in the replication repository with commit timestamps, not lodged with a third-party registry; seventeen numbered amendments were registered, none withheld. \emph{Confirmatory}: the plan's two co-primary contrasts (\texttt{HGT-QoS} and \texttt{HGT} vs.\ \texttt{Topo-QoS}), both null. \emph{Registered secondary}: arms committed before they ran but after the primary null was known (the matched $2\times2$, the hybrids, the reference counts, the derivation value, the full-population queue-flow labels and the control arms of Section~\ref{sec:rq2}), each Holm-corrected within its family. \emph{Exploratory}: post hoc analyses, the dependency-graph learners' contrasts, the reference reclassification (which changed no figure) and the rate-weighted reference with the attribution of the learned queue-flow approximation. \textbf{Plan deviation}: the registered nested hyperparameter selection was replaced by one fixed configuration, and the registered rule was run later as a sensitivity check (Section~\ref{sec:rq2}). An omnibus Holm correction across the 13 decision-bearing contrasts (Supplementary Section~\ref{supp:amendments}) leaves the hybrid contrasts significant (Hybrid-GAT $p_{\text{omni}} = 0.019$, Hybrid-HGT $p_{\text{omni}} = 0.041$) and the primary contrast null ($p_{\text{omni}} \ge 0.46$). The headline findings of this paper are therefore registered secondary or exploratory, not confirmatory.

\noindent\textbf{The reference level.} The references measure how much of $I^*$ restating its rule recovers, not predictive skill. The first-order expansion (Eq.~\eqref{eq:analytic_istar}) reaches $0.808$ ($\rho_{>0} = 0.631$): direct subscriber loss is most of what $I^*$ measures. \texttt{InDeg}, the support of that first wave (Remark~1), is a coarser version of it ($0.764$, $\rho_{>0} = 0.516$), and \texttt{Reach} reaches $0.732$. The derivation matters for the latter: without Rule~5, \texttt{Reach} drops by $0.058$ (9/12 folds, Holm $p = 0.0068$). Untyped raw-graph metrics do not recover the reference (total degree $0.199$, reverse PageRank $0.089$).

\noindent\textbf{Learners on the dependency graph approach the reference.} \texttt{GAT-P-QoS} reaches $\rho = 0.748$, $0.016$ below the direct-dependent count per seed and $0.007$ above it as a five-seed ensemble ($0.772$, Table~\ref{tab:independent_oracles}). Neither difference is significant, and neither shows equivalence: the $90\%$ interval of the per-fold difference is $\pm 0.076$, so a two one-sided test at the registered margin of $\pm 0.05$ does not pass ($p = 0.17$ per seed, $0.13$ for the ensemble). The closeness depends on the degree features (Section~\ref{sec:rq2}).

\noindent\textbf{Hybrids beat the baseline, not their base learners.} A hybrid takes the \texttt{Topo-QoS} score as an input and corrects its logit, so it nests its comparator. Hybrid-HGT ($+0.103$) and Hybrid-GAT ($+0.130$) beat \texttt{Topo-QoS} on 11 of 12 folds, also under the omnibus Holm correction ($p_{\text{omni}} = 0.041$ and $0.019$), the Nadeau--Bengio corrected $t$ ($p = 0.019$ and $0.014$) and $|V_{\text{app}}|$ weighting. Neither differs from its own base learner (Hybrid-HGT vs.\ \texttt{HGT-QoS} $+0.035$, $p = 0.73$; Hybrid-GAT vs.\ \texttt{GAT-QoS} $+0.048$, $p = 0.30$), and the same holds with the articulation defect corrected (Table~\ref{tab:controls}, F9). The hybrid gain therefore belongs to the weak comparator, not to the learned correction. Given \texttt{InDeg} as their prior instead, both hybrids land within $\pm 0.012$ of \texttt{InDeg} (F10): a learner handed the reference reproduces it.

\noindent\textbf{Beyond the reachability oracle.} On $I_{\text{dyn}}$, which agrees with $I^*$ at $\rho = 0.711$, the references outperform all GNNs (first-order expansion $0.706$, \texttt{InDeg} $0.664$, GNNs $0.496$--$0.615$; Table~\ref{tab:independent_oracles}). Partial correlations show what each ranking keeps beyond $I^*$. After removing the rank of $I^*$, \texttt{InDeg} keeps $0.272$ $[0.188, 0.366]$, \texttt{Reach} $0.117$, \texttt{Topo-QoS} $0.134$ and the GNNs $0.107$--$0.173$, all intervals excluding zero; after removing the first-order expansion instead, the raw-multigraph GNNs keep $0.212$--$0.217$, some queue-flow signal beyond the unweighted first-order term but less than the rate-weighted reference ($0.573$).

\noindent\textbf{What declared rates add on the queue-flow oracle.} Weighting each term of the first-order expansion ($0.706$ on $I_{\text{dyn}}$) by the topic's declared publication rate (Eq.~\eqref{eq:rate-expansion}) raises it to $0.830$ $[0.778, 0.872]$ without training (exploratory). A gradient-boosted model trained on $I_{\text{dyn}}$ labels, reading counts, the first-order expansion, declared rates and payload sizes, reaches $0.799$: above the unweighted expansion ($+0.094$, Holm $p = 0.019$), but it falls below the rate-weighted reference, which exceeds it by $+0.031$ $[+0.013, +0.049]$ on 10 of 12 folds (nominal Holm $p = 0.009$; exploratory). In an exploratory attribution (Supplementary Section~\ref{supp:advisor-v6}), the declared rate and payload columns alone add $+0.097$ (9/12 folds, Holm $p = 0.021$), and the seven QoS-derived columns ($w(t)$-weighted scores and policy shares) add $-0.005$ ($p = 0.68$). The GNN trained on the same labels, which received neither rates nor payloads, reaches only $0.598$.

\noindent\textbf{Learning on top of the rate-weighted reference.} The direct test of whether learning adds value beyond the aligned approximation is a learner that starts from it (Table~\ref{tab:controls}, F12). Given Eq.~\eqref{eq:rate-expansion} as one more input column, the gradient-boosted approximation reaches $0.830$, the formula's value ($+0.000$, 5 of 12 folds, Holm $p = 0.97$); trained to correct the formula's residual, it reaches $0.824$ ($-0.006$, Holm $p = 0.68$); and the GAT trained on $I_{\text{dyn}}$ with the formula as its prior gains $+0.214$ over the same GAT without it (12 of 12 folds) but still falls below the formula ($0.812$, $-0.018$, 1 of 12 folds, Holm $p = 0.0029$). The learned approximations recover the formula's information and add none.

\noindent\textbf{The multi-criteria oracle favors different rankers.} On $I_{\text{comp}}$, learned rankers without a prior perform poorly ($0.144$--$0.334$), the hybrids keep $0.58$, and training-free scores aligned with its fragmentation and flow terms rank highest (\texttt{Topo-QoS} $0.702$, raw total degree $0.719$), which again reflects overlap with the oracle's terms. No ranker is best across all three oracles.

\noindent\textbf{The ``QoS'' factor was mostly the weighted in-degree.} In the capacity-matched $2\times2$ on the raw multigraph (Supplementary Table~\ref{tab:contrasts_matched}), relation typing has no effect ($-0.014$, $p_{\text{Holm}} = 0.940$) and the ``QoS'' inputs add $+0.073$ ($p_{\text{Holm}} = 0.127$). The QoS-off arms, however, also zero $w_{\text{in}}$, a QoS-weighted version of \texttt{InDeg}; with $w_{\text{in}}$ held in both arms (F4), the ``QoS'' effect drops to $+0.030$, so more than half of it was the weighted in-degree. Closed-form controls agree: unweighted betweenness ($0.591$) and constant topic weights ($0.595$) match or exceed QoS-weighted betweenness ($0.553$), and permuting QoS profiles across topics has no effect ($\Delta = -0.006$, $p = 0.733$). Because messages never reach Applications on the raw multigraph (Section~\ref{sec:3.4}), this $2\times2$ compares per-node models and says nothing about relational typing (Section~\ref{sec:8.2}).

\noindent\textbf{Degree features and the aggregator.} Removing the in-degree and $w_{\text{in}}$ columns lowers \texttt{GAT-P-QoS} by $0.136$ (F1). Theory predicts this: softmax attention averages over neighbors and cannot count them, whereas sum aggregation can \cite{xu2019gin,corso2020pna}, and a GINE network of the same size keeps $0.721$ without the same columns (F2, not significant after Holm). In zero-shot transfer the degree columns matter little ($0.810$--$0.821$ without them), because the system models are ranked mostly by separating inert from active components.

\noindent\textbf{Direction versus dependency semantics.} The $+0.113$ gain of \texttt{GAT-P-QoS} over \texttt{GAT-QoS} could come from edge direction rather than dependency semantics, so a control passes every raw-graph edge in both directions, with shared weights and an unchanged parameter count (\texttt{GAT-QoS-R}, F8). It reaches $0.676$: direction alone recovers $+0.041$ of the gain, which is not significant (Holm $p = 0.064$), and \texttt{GAT-P-QoS} still exceeds it by $+0.072$ $[+0.034, +0.113]$ on 10 of 12 folds (Holm $p = 0.014$). Reverse edges also cost transfer ($0.744$ zero-shot, against $0.805$--$0.806$; Table~\ref{tab:system_models_transfer}).

\noindent\textbf{Without the oracle-aligned features.} Every published learner reads features that compute part of $I^*$ (Section~\ref{sec:3.5}). With all of them zeroed (F11), the raw-graph learners collapse (\texttt{GAT-QoS} to $0.369$, the reverse-edge control to $0.378$), whereas the dependency-graph GAT keeps $0.610$ and beats the equally stripped reverse-edge control by $+0.231$ (10 of 12 folds, Holm $p = 0.0068$). The oracle-aligned set costs \texttt{GAT-P-QoS} $0.138$, about what the two degree columns alone cost. Without them, sum aggregation beats attention on the dependency graph ($+0.115$, 9 of 12 folds, Holm $p = 0.027$), and without any node features at all, a sum-aggregation GNN on the dependency graph reaches $0.719$, $0.045$ below \texttt{InDeg} (1 of 12 folds): from structure alone it learns most of the dependent count, which the derived graph makes available and the raw multigraph does not.

\noindent\textbf{Message passing, node order and the selection rule.} On the raw multigraph, a gradient-boosted model on the same per-node features and no graph (\texttt{GBM-Feat}) reaches $\rho = 0.642$ under LOSO, level with \texttt{GAT-QoS} ($0.635$), and removing HGT's reverse pass, its only route to Applications, has no effect (\texttt{HGT-QoS-U}, $-0.010$, $p = 0.91$). ListMLE breaks label ties in input order (Section~\ref{sec:4.2}); permuting node order before training (F13; \texttt{GAT-P-QoS-perm}) scores $0.712$ against $0.748$ ($-0.035$, 3 of 12 folds, $p = 0.012$), which triggered the registered flag. Two further permutations show variance rather than a favourable published order: seeds 17, 18 and 19 give $0.712$, $0.740$ and $0.734$ (mean $0.729$), and the per-fold spread across the three permutations averages $0.044$. Learned-ranker differences smaller than this spread should not be read as differences between models. Finally, the plan's nested hyperparameter selection, applied later on the stage-1 grid, changes \texttt{HGT-QoS} from $0.622$ to $0.677$ ($+0.055$) and \texttt{GAT-P-QoS} from $0.748$ to $0.693$ ($-0.054$), neither significant (Holm $p = 0.259$); nested \texttt{HGT-QoS} versus \texttt{Topo-QoS} is $+0.123$ on 9 of 12 folds, still not significant (Holm $p = 0.192$). That harness trains on one scenario fewer and stops early on a held-out scenario, so it compares two protocols, not only two configurations (Section~\ref{sec:6.3}).

Measured like for like (Table~\ref{tab:cost-ll}), one labeling pass of the reachability oracle over a corpus architecture's Applications takes $0.01$--$0.72$~s, the counting path that restates its first wave is $17$--$176\times$ cheaper (median $45\times$), and the feature extraction every learned ranker needs $4.5$--$72.5\times$ more (median $16.9\times$); the ordering holds on generated graphs of up to $5{,}000$ components. The articulation and CDI phase accounts for $88$--$91\%$ of feature extraction, so this cost belongs to the chosen feature set, not to learned ranking as such. Where the $I^*$ ranking itself is wanted, running the oracle is therefore cheaper than approximating it with a learned ranker at every size measured. Inference is negligible (tens of milliseconds at $2{,}000$ components); the count scales to $10{,}000$ components ($1.1$~s), \texttt{Reach} less well ($23$~s).

The expensive oracle is $I_{\text{dyn}}$: labeling the corpus took $12.7$ CPU-hours (about $7$~s per fault run and seed), whereas the rate-weighted reference takes at most about a millisecond per architecture. Estimating energy as wall-clock time multiplied by the processor's $28$~W base power (Section~\ref{sec:threats}), labeling the corpus with $I_{\text{dyn}}$ took about $355.6$~Wh, the five-seed $I^*$ labeling sweep $11.1$~s ($0.086$~Wh), and the full detection gate $106.9$~s ($0.83$~Wh). Summed over the twelve folds, the feature extraction that the learned rankers read took $70.0$~s (about $0.54$~Wh), and the dependency count $0.037$~s (about $1$~J). A learned approximation could repay its cost only by displacing repeated runs of an expensive simulator such as $I_{\text{dyn}}$, and here the rate-weighted reference already does so without training.

\section{Discussion, Threats to Validity, and Limitations}
\label{sec:8}

\subsection{Dependency Representation versus Model Complexity}
\label{sec:representation}
\label{sec:restatement}

For the reachability and queue-flow simulators, explicit dependency representations contributed more to ranking performance than model complexity. The derived dependency graph enabled both analytical and learned approaches: attention-based learners improved on it relative to the raw multigraph, and the improvement survives both a control for edge direction and the removal of every feature that computes part of the reachability simulator. Yet rankings computed directly from the same graph were not distinguishable from, or exceeded, the best learned models. In this corpus, explicit dependency derivation is the principal source of predictive signal, not a preprocessing step for learning. The multi-criteria simulator is the exception: there, raw degree and betweenness, whose terms align with fragmentation, ranked highest.

Several of the highest-scoring rankings largely restate a simulator's propagation rule. The reference criterion (Section~\ref{sec:4.4}) separates recovering a simulator's definition from predicting its outcomes, and it changes how learned results should be read: a learned model that approaches a reference has learned the simulator's first-order rule, not necessarily anything beyond it. Because simulation-labeled benchmarks are common in architecture analysis, the criterion offers a general check: before crediting a learned model with predictive skill, compare it with the simplest ranking that restates the simulator's own computation.

\subsection{When Learning Adds Value, and Relative to What}
\label{sec:8.2}

Relative to the training-free baseline, learning helped in two ways, both weak evidence for learning. Hybrids outperformed the baseline they nest but not their own base learners, so the gain belongs to the baseline's weakness; and learned models transferred zero-shot better than the baseline, mainly by separating inert from active components. Relative to analytical references built on the same dependencies, no learned model showed additional skill, and the most direct test, learners that start from the rate-weighted approximation, found no improvement on it. The learned queue-flow approximation beat the unweighted expansion only because it read declared rates and payload sizes; once rates enter the analytical expansion, the deficit is not one of missing inputs. Learning is therefore likely to contribute most where cascade impact depends on multi-hop non-linear mechanisms that no low-order analytical approximation captures: e.g., dynamic broker queue congestion, non-linear backpressure propagation onto publishers, retry storms, or heterogeneous service capacities. Under the first-order reachability and rate-loss mechanisms exercised by the three simulators here, explicit dependency derivation supplies the necessary structural signal directly, rendering model complexity superfluous. A per-regime breakdown by architecture type is given in Supplementary Section~\ref{supp:regimes}.

\noindent\textbf{How message passing contributes.} On the raw multigraph, learning used node properties, not relations: a graph-free model on the same features matches the GAT, and removing HGT's only route to Applications has no effect (Section~\ref{sec:rq2}). On the derived dependency graph, message passing gathers the dependent neighborhood; attention still needs the degree columns to approach the dependent count, whereas sum aggregation recovers most of it from structure alone.

\noindent\textbf{What the study can say about relation typing.} Little. On the raw multigraph, where typing was compared at matched capacity, messages never reach Applications, so that comparison is between per-node models. On the dependency graph the projection has only two relation types, and the heterogeneous transformer (\texttt{HGT-P-QoS}) ran in one untuned configuration in which some seeds converged to rankings anti-correlated with the oracle (mean within-fold seed standard deviation $0.254$, mean $\rho = 0.514$), while \texttt{GAT-P-QoS} was stable ($0.030$, $\rho = 0.748$). That is an optimization failure of one configuration, not evidence about typing; testing typing would need a substrate with active message passing, more relation types and a tuned heterogeneous model.

\subsection{Practical Consequences}
\label{sec:8.1}

\noindent\textbf{Choosing a ranker.} Table~\ref{tab:guidance} summarizes the evidence by failure notion; it is conditional on simulation fidelity, and neither simulator, nor any approximation of it, has been shown to predict real outages. If the simulator is cheap, like $I^*$, its ranking can be computed directly from the manifest, and publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais} costs a fraction of that; its value is cost, not predictive skill. If the simulator is expensive, like $I_{\text{dyn}}$, the rate-weighted expansion approximates it in milliseconds, and declared publication rates and payload sizes, not QoS policies, are the only declared information that carried signal. Training-free dependency analysis is therefore also the lower-energy choice at commit and staging time \cite{schwartz2020greenai,verdecchia2023greenai,calero2015green}.

Beyond computational latency and energy, operational reliability in automated CI/CD pipelines strongly favors analytical metrics. While deep GNN models introduce non-determinism, seed sensitivity (with within-fold standard deviations up to $0.254$), and sensitivity to serialization order (Section~\ref{sec:rq2}), closed-form counts and analytical expansions provide exact, deterministic, and instant guarantees essential for automated deployment gating. Crucially, while learned models transfer zero-shot to unfamiliar topologies better than training-free baselines ($\rho \approx 0.81$ vs.\ $0.53$), this advantage stems primarily from filtering out inert components ($I^*=0$); practitioners should not rely on zero-shot rankers to establish fine-grained priority order among active, failure-propagating components ($\rho_{>0} \le 0.342$).

\noindent\textbf{A two-tiered triage protocol.} Recovering 80\% of the true critical set takes the top 40--45\% of Applications by the best rankers, and no predictor reaches 90\% within the top 50\% (Figure~\ref{fig:recall}). A gate that catches most critical components would flag nearly half the system, so these rankers are unsuitable as automated pass/fail filters. We instead propose a two-tiered triage protocol as an inspection heuristic, which needs human-factors and workflow validation before adoption:
\begin{enumerate}\tightlist
    \item \textbf{Tier 1 (commit stage):} compute the direct-dependent count and the rate-weighted expansion (milliseconds; the latter exploratory) and show the top five components by each as an informational note in pull-request review, without blocking developers.
    \item \textbf{Tier 2 (staging and sprint review):} run the simulators on the Tier-1 shortlist within a fixed inspection budget, such as the ten highest-ranked services, and reserve redundant broker routing or chaos fault injection for the components the simulation confirms.
\end{enumerate}

\subsection{Threats to Validity}
\label{sec:8.3}
\label{sec:threats}

\noindent\textbf{Construct validity and oracle circularity.} All labels are simulated: no ranker is validated against observed failures, so the findings establish what can be predicted within the evaluated simulators, not what predicts real failures. The simulators omit runtime dynamics such as buffer bloat, thread-pool exhaustion, garbage-collection pauses and retry storms, and some real outages are sustained by load feedback rather than structure \cite{bronson2021metastable,huang2022metastable}. The circularity is analyzed in Section~\ref{sec:4.4}; the counts were reclassified as references after all results were final, and no number changed. The two other oracles bound, but do not remove, the threat, and all three are well approximated by low-order functions of the dependency graph, so the benchmark cannot exhibit a regime in which learning exceeds an aligned analytical ranking; its absence here is a property of these oracles, not evidence that none exists. The reverse-edge control shares one set of weights across both directions; a direction-typed variant was not tested. Rules~2--4 and~6 are untested.

\noindent\textbf{Internal validity and reproducibility.} No ranker reads simulator output (regression tests verify this). Capacity, depth and early stopping were held constant across arms, but every learned result is conditional on one fixed configuration (Section~\ref{sec:6.3}). The learned rankers are seed-sensitive: the mean within-fold standard deviation of $\rho$ is $0.099$ for \texttt{HGT-QoS}, $0.254$ for \texttt{HGT-P-QoS} and $0.024$--$0.030$ for the GATs, and one of 60 \texttt{HGT-QoS} runs and four of 60 \texttt{HGT-P-QoS} runs converge to rankings anti-correlated with the oracle; they are kept in the per-seed means, as registered. Across revision cycles and compute devices, a learned cell drifted by up to $0.172$, so every learned-versus-learned contrast is paired within one CPU sweep whose re-run comparators reproduce their published values; paired contrasts were not repeated on a second device. Node order adds a variance of about $0.04$ per fold (Section~\ref{sec:rq2}). CDI uses hash-dependent tie-breaking, so \texttt{PYTHONHASHSEED=0} is fixed, and all reported values are reconciled mechanically against released artifacts.

\noindent\textbf{External validity and the single-modeler threat.} Synthetic topologies come from a single generator family, which may induce regularities not representative of industrial architectures. The five system models (22--41 Applications) were each written by the first author from public documentation; no second modeler authored any of them, and no inter-modeler agreement is reported. They also differ structurally from the synthetic folds in ways that favor \texttt{Reach} (Section~\ref{sec:rq3}), and two are RPC systems re-expressed as publish--subscribe meshes. Moreover, these models feature a bimodal distribution with over 50\% inert components ($I^* = 0$), so strong full-population $\rho$ reflects separating inert nodes rather than fine-grained discrimination among active spreaders ($\rho_{>0} \le 0.342$). No topology was extracted from a real deployment manifest. We timed the counting path up to $10{,}000$ components but did not evaluate rankers or oracles at that scale. We did not reproduce published learned criticality models (FINDER, DrBC), which do not support typed multigraphs or pub-sub semantics.

\noindent\textbf{Energy estimation and Green AI.} Energy figures are wall-clock time multiplied by the processor's $28$~W base power (Intel Core i7-1370P; \path{reproduce/energy_estimate.py}), because RAPL counters required privileges unavailable to us. They ignore frequency scaling, turbo power, DRAM and idle power, providing an order-of-magnitude lower bound rather than full emissions accounting. In the context of Green AI \cite{schwartz2020greenai,verdecchia2023greenai}, these estimates reveal a sharp trade-off: feature extraction for learned models consumes over an order of magnitude more energy than running the reachability simulator directly ($0.54$~Wh vs.\ $0.086$~Wh), while delivering no predictive advantage over unweighted analytical counts ($1$~J). Deploying heavy graph learning for pre-deployment gating thus incurs unjustified environmental overhead without dependability gains.

\noindent\textbf{Conclusion validity.} Only the plan's two co-primary contrasts are confirmatory, and both were null (Section~\ref{sec:6.3}). LOSO folds share ten of eleven training scenarios, so Wilcoxon $p$-values are anti-conservative; the Nadeau--Bengio corrected test leaves the hybrid contrasts significant and the primary null. Twelve folds from one generator make the study underpowered for equivalence at $\pm 0.05$, so ``matches'' means not significantly different.

\subsection{Limitations and Future Work}
\label{sec:8.4}
\label{sec:limitations}

Five directions follow, in order of priority:
\begin{enumerate}\tightlist
    \item \textbf{Real topologies and real failures:} automatic extraction of SaG models from real artifacts (ROS~2 launch files with HAROS or ROSDiscover \cite{santos2019haros,timperley2022rosdiscover}, docker-compose and Kubernetes manifests), followed by controlled fault injection on ROS~2, Kafka and MQTT deployments, reference systems with known faults such as Train-Ticket \cite{zhou2018trainticket}, and distributed tracing to check whether declared dependency paths match runtime message flow.
    \item \textbf{A confirmation corpus:} scenarios generated after the analysis is frozen, on which the registered secondary and exploratory claims are re-tested.
    \item \textbf{Brokers, hosts and independent modelers:} evaluating Rules~2--4 and~6 beyond Applications, and replicating the five system models by additional modelers with inter-modeler agreement reported.
    \item \textbf{Alternative impact models:} simulators with synchronous call semantics and non-first-order mechanisms, such as backpressure onto publishers, retry amplification and heterogeneous service capacity, where an aligned analytical approximation may not exist.
    \item \textbf{When learning exceeds analytical methods:} identifying impact-generation mechanisms whose signal no aligned analytical approximation captures, and testing learners there.
\end{enumerate}
Further extensions include hardware-level energy accounting via RAPL and IPMI interfaces under variable cluster workloads to capture dynamic CPU scaling and DRAM power (moving beyond static TDP lower bounds), a queue-flow run with QoS policies disabled, a tie-aware listwise loss, a full hyperparameter search for every learned model, and validation of the proposed explanation layer.

\section{Conclusion}
\label{sec:9}

This paper presented Software-as-a-Graph (SaG), a pre-deployment framework that derives explicit dependency graphs from publish--subscribe deployment manifests and supports analytical, hybrid and learned cascade-impact ranking on them. Using twelve synthetic architectures, three failure simulators and five stylized models of open-source systems, it evaluated whether and when graph learning improves on rankings derived directly from explicit dependencies. The primary registered contrast was null; the findings below are registered secondary or exploratory.

For the reachability and queue-flow simulators, explicit dependency representations provided most of the predictive signal. Attention-based learners benefited from the derived dependency graph, a gain that survives controls for edge direction and for features that compute part of the simulator, but simple analytical rankings built on the same dependencies were not distinguishable from, or exceeded, every learned model: counting direct dependents for the reachability simulator, and a millisecond rate-weighted first-order expansion for the queue-flow simulator, whose labels took $12.7$ CPU-hours to generate. Learners that start from that expansion matched it at best. Learning added value only relative to a weak comparator, and ordering among components that actually propagate failures remained weak.

For researchers, graph-learning approaches should be evaluated against analytical alternatives aligned with the simulator, and prediction should be distinguished from restatement of a simulator's rule. For practitioners, training-free dependency analysis is effective and inexpensive support for prioritizing architectural review. Learned models can be expected to add value only where no aligned analytical approximation exists, a condition this corpus could not exercise; validating these findings against real outages is the natural next step (Section~\ref{sec:limitations}). The central challenge in architecture-level cascade-impact analysis is therefore less the choice of learning algorithm than deriving meaningful dependency representations and knowing when learning adds value beyond them; the released benchmark, with its mechanically reconciled results, supports that comparison for future methods.
