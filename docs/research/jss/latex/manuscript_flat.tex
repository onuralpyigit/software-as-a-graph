\title{Software-as-a-Graph: When Does Graph Learning Improve
  Cascade-Impact Ranking in Publish--Subscribe Systems?}

\author[itu]{Ibrahim Onuralp Yigit\corref{cor1}}
\ead{yigiti@itu.edu.tr}
\author[itu]{Feza Buzluca}
\ead{buzluca@itu.edu.tr}

\affiliation[itu]{organization={Department of Computer Engineering, Istanbul Technical University},
             city={Istanbul}, postcode={34469}, country={Turkey}}
\cortext[cor1]{Corresponding author}

\begin{abstract}
Publish--subscribe middleware obscures failure-propagation paths, yet architects must identify critical components before deployment, when no telemetry exists. We present Software-as-a-Graph (SaG), which derives explicit dependency graphs from deployment manifests to evaluate when graph learning improves cascade-impact ranking. We compare graph neural networks, hybrids, and analytical and learned simulator approximations with training-free rankings on twelve synthetic architectures under leave-one-scenario-out evaluation against three failure simulators, and zero-shot on five hand-authored models of open-source systems. A reference criterion separates rankings that restate a simulator's rule from those that predict it.

While the primary registered contrast was null, graph attention on the derived dependency graph reaches Spearman's $\rho = 0.748$ against a reachability simulator, $+0.072$ above the same model with reverse edges on the raw multigraph, whereas pure learned models on the raw multigraph do not outperform a training-free baseline. The learned model is not statistically distinguishable from counting direct dependents ($\rho = 0.764$; equivalence not established). For a queue-flow simulator costing $12.7$ CPU-hours to label, a rate-weighted first-order approximation reaches $\rho = 0.830$ in milliseconds, exceeding a learned approximation trained on simulator labels ($\rho = 0.799$; exploratory). Hybrids correcting a closed-form prior outperform that baseline, even with its defect corrected, but not their own base learners; learned models transfer zero-shot better than the baseline ($\rho \approx 0.81$ vs.\ $0.53$), driven by separating inert components. No learned model exceeded the best analytical ranking aligned with each simulator.

All findings concern agreement with simulators, not physical failures. Representation mattered more than model complexity; learned methods should be evaluated against analytical baselines aligned with the simulator.

\end{abstract}

\section{Introduction}
\label{sec:1}

\subsection{Motivation and Problem}
\label{sec:1.1}

Large distributed systems now often use asynchronous publish-subscribe (pub-sub) middleware. Examples include ROS 2 for autonomous driving \cite{macenski2022robot}, Apache Kafka for enterprise event streams \cite{kreps2011kafka}, DDS in cyber-physical systems \cite{omg2015dds}, MQTT in IoT \cite{oasis2019mqtt}, and cloud-native microservices \cite{dragoni2017microservices,newman2015building}. Pub-sub separates producers and consumers by space, time, and synchronization \cite{eugster2003faces}. Instead of direct references, components communicate via topics and brokers, and Quality-of-Service (QoS) policies set at deployment control reliability, durability, priority, and deadlines.

This decoupling also makes it harder to see how failures spread. Since publishers and subscribers are not directly connected, problems like outages, blocking, and backpressure can move through undetected paths involving brokers, shared topics, colocated hosts, and shared libraries \cite{motter2002cascade,buldyrev2010cascade}. Failures usually appear in two ways. In sequential cascades, a slow subscriber fills up a broker queue and gradually starves its publishers \cite{albert2000error}. In simultaneous blasts, a crash in a shared library or a host outage can bring down all colocated services at once. These issues are not visible in architecture diagrams or static call graphs. The best time to handle these risks is before deployment, during design and continuous integration \cite{avizienis2004basic,bass2012software}, when runtime telemetry is unavailable. Therefore, architects must identify the most critical application services, topics, and links using only configuration manifests.

Current practices leave a serious architectural gap between service-level static analysis and distributed system dependability. A distributed system might have no compile-time bugs in any service but still face major outages due to hidden single points of failure, unbuffered queue bottlenecks, or mismatched QoS contracts \cite{perry1992foundations,garcia2009identifying}. Approaches like the Architecture Tradeoff Analysis Method (ATAM) depend on manual input \cite{kazman1998atam}. Static code analysis inspects services in isolation \cite{sonarsource2024clean,chidamber1994metrics}. Chaos engineering \cite{basiri2016chaos} needs a working cluster, and pre-production tests like fault injection \cite{meiklejohn2021service} and dependency tracing \cite{yu2021microrank} require runnable environments. In continuous integration, heavy fault injection or chaos experiments use significant computing power and energy, so pre-deployment static analysis is a greener option if it is accurate enough \cite{calero2015green,verdecchia2023greenai,schwartz2020greenai}. Graph-based representations have long supported reliability and defect analysis \cite{yacoub2002reliability,zimmermann2008predicting}, and graph learning has recently been applied to network criticality \cite{fan2020keyplayers,fan2019learning} and to microservice architectures \cite{khodabandeh2025linkpred}. Such models can combine structural and contractual information, but it remains unclear whether their predictive performance arises from the learning algorithm or from the dependency representation it operates on, and when learning adds value beyond analytical methods derived from the same dependencies. Software-as-a-Graph (SaG) addresses this question by deriving explicit dependency graphs from deployment manifests and enabling a controlled comparison of analytical, hybrid and learned approaches to cascade-impact ranking before deployment.

\subsection{The Software-as-a-Graph (SaG) Approach}
\label{sec:1.3}

Software-as-a-Graph (SaG) is a pre-deployment analysis framework for event-driven architectures (Figure~\ref{fig:1}). It models an architecture as a typed, directed multigraph over Applications, Brokers, Topics, Execution Hosts and Shared Libraries (Section~\ref{sec:3.1}), and derives an explicit DEPENDS\_ON dependency graph through publish--subscribe rules (Section~\ref{sec:3.3}). On this basis, it supports analytical, hybrid and learned approaches to cascade-impact ranking (Sections~\ref{sec:4} and~\ref{sec:6.2}). This study uses it to determine when learned models add value beyond rankings derived directly from explicit dependencies.

Rankers never read simulator output: their node features are computed on the analysis graph, and learners pass messages over either the raw multigraph or the derived dependency graph. Labels come from three simulators that run on the raw structural topology (Section~\ref{sec:4.3}) and encode different failure notions: structural reachability ($I^*$), discrete-event queue saturation ($I_{\text{dyn}}$) and multi-criteria fragmentation ($I_{\text{comp}}$). To avoid depending on one simulator's assumptions, every ranker is evaluated against all three. Because simulators and rankers read the same architecture, some analytical rankings restate a simulator's own propagation rule. A reference criterion (Section~\ref{sec:4.4}) reports these as references that measure circularity rather than as predictors. To bound, though not remove, this circularity, we also report partial correlations after removing the primary simulator, and we time the cost of running each simulator directly (Section~\ref{sec:rq4}). All conclusions are strictly conditional on simulation fidelity; validation against real failures in physical distributed environments remains future work (Section~\ref{sec:8.3}).

\noindent\textbf{Organization of the empirical inquiry.} To evaluate when graph learning adds value, we compare learned GNNs and gradient-boosted trees against both training-free baselines and analytical references across three failure simulators. By evaluating models across raw structural topologies and derived dependency graphs, the study isolates the contribution of explicit dependency representation from learning algorithm complexity, while timing, with energy estimated from processor base power, contextualizes the cost of static triage versus full simulation in continuous integration pipelines. The study measures agreement with simulators, not with observed failures, and all three simulators turn out to be well approximated by low-order functions of the dependency graph; the benchmark therefore did not exercise any regime in which learning could exceed an analytical ranking aligned with the simulator, and the primary registered contrast was null.

\subsection{Research Questions}
\label{sec:1.4}

Establishing when learning is unnecessary is as informative as showing when it succeeds. Software engineering research has repeatedly found that simple metrics can match more complex models once the right information is available \cite{zimmermann2008predicting,premraj2011network,hellendoorn2017deep,errica2020fair}, and that analytical rankings are easier to explain, validate, and run in Continuous Integration and Continuous Deployment (CI/CD) pipelines. We therefore evaluate learned models against analytical rankings derived from the same dependencies, not only against structural baselines. Four research questions guide the study:

\begin{itemize}\tightlist
\item \textbf{RQ1 (Ranking accuracy):} \emph{How accurately do analytical, hybrid, and learned approaches rank components by cascading-failure impact on unseen architectures, and how close do they come to reference rankings that restate a simulator's propagation rule?}
\item \textbf{RQ2 (Sources of predictive performance):} \emph{At matched model capacity, which factors contribute most to ranking performance: the dependency representation, degree information, relation typing, Quality-of-Service (QoS) information, or the model family (attention or sum aggregation; graph neural network or gradient-boosted trees)?}
\item \textbf{RQ3 (Transfer):} \emph{How well do learned models trained on synthetic architectures transfer zero-shot to stylized models of five open-source systems, hand-authored by a single modeler, and does their ordering of components that actually propagate failures hold?}
\item \textbf{RQ4 (Cost):} \emph{What do analytical and learned approaches cost at CI/CD time in latency and estimated energy, which stage dominates, and how does this compare with running each simulator directly?}
\end{itemize}

The evaluation uses a version-controlled analysis plan. Only the plan's two co-primary contrasts are confirmatory, and both were null. We registered the matched $2\times2$, the hybrids, the reference counts, the dependency-graph learners, the full-population queue-flow labels, and the sensitivity arms as planned extensions. We registered each before its own tests ran but after we knew the main result, and we report them as secondary results. The rest of the analysis is exploratory (Section~\ref{sec:6.3}). One change from the plan, not applying the registered nested hyperparameter selection, is disclosed and tested. The replication repository records the revision history and shows how these four research questions fit into the plan.

\subsection{Contributions}
\label{sec:1.5}

Evaluated with leave-one-scenario-out (LOSO) cross-validation on twelve synthetic architectures, against three failure simulators, and zero-shot on five hand-authored models of open-source systems, this paper makes five contributions:

\begin{enumerate}\tightlist
    \item \textbf{Explicit dependency derivation for publish--subscribe architectures} (Section~\ref{sec:3}). Typed rules derive dependency graphs from deployment manifests and expose sequential cascades through shared topics and simultaneous blasts through shared libraries. Attention-based learners improve on the derived graph compared with the raw multigraph (\texttt{GAT-P-QoS} $0.748$ vs.\ \texttt{GAT-QoS} $0.635$), and a control that passes every raw-graph edge in both directions shows that direction alone does not account for the gain: it recovers $+0.041$ (not significant), and the derived graph adds $+0.072$ beyond it (Holm $p = 0.014$). For analytical rankings, the derivation mainly organizes signal that a typed query on the raw graph can also recover (Remark~1); its library-mediated rule adds $+0.058$ in transitive reach. We define infrastructure and colocation rules for completeness, while focusing our empirical evaluation strictly on developer-authored Application services.
    \item \textbf{A reference criterion for interpreting simulator-based evaluations} (Section~\ref{sec:4.4}). The criterion distinguishes rankings that restate a simulator's rule from rankings that predict it, so that analytical and learned methods can be interpreted on the same terms. Applied here, it shows that publish--subscribe afferent coupling recovers most of the reachability simulator.
    \item \textbf{A controlled study of when graph learning adds value beyond dependency analysis} (Sections~\ref{sec:rq1}--\ref{sec:rq3}). Matched-capacity comparisons and ablations separate the contributions of five factors: the dependency representation, which matters most; degree information, without which the learner loses $0.136$; relation typing, which has no effect; QoS information, where declared rates and payloads add signal only on the queue-flow simulator and QoS policies or QoS-weighted scores add none; and the model family. Hybrids that correct a closed-form prior significantly outperform the training-free baseline, a weak comparator they nest, also when its articulation defect is corrected ($+0.136$ and $+0.107$); but they do not differ from their own base learners and transfer less well than pure learned models, so the gain belongs to the comparator rather than to the correction. Given the direct-dependent count as their prior instead, both learners reproduce that count and add nothing to it.
    \item \textbf{Analytical and learned approximations of an expensive simulator} (Sections~\ref{sec:6.2} and~\ref{sec:rq1}). On a queue-flow simulator that takes $12.7$ CPU-hours to label the corpus, a rate-weighted first-order approximation reaches $\rho = 0.830$ in milliseconds without training and exceeds a gradient-boosted approximation trained on the simulator's labels ($0.799$; exploratory, added after the registered analyses).
    \item \textbf{A reproducible benchmark, cost analysis and practitioner guidance} (Sections~\ref{sec:6}, \ref{sec:rq4} and~\ref{sec:8.1}).
    \begin{itemize}\tightlist
        \item The benchmark comprises seventeen architectures (2{,}812 components), three simulators labeling all 1{,}321 synthetic Applications, a version-controlled analysis plan with disclosed amendments, byte-identically regenerable datasets, and mechanically reconciled results.
        \item Latencies measured on the same graphs, with coarse Thermal Design Power (TDP)-derived energy estimates, support practical guidance on when training-free dependency analysis suffices.
    \end{itemize}
\end{enumerate}

A previous conference paper \cite{yigit2025graph} introduced the publish--subscribe multigraph, the Application-level subscriber-to-publisher dependency (Rule~1 of Table~\ref{tab:2}), and a closed-form betweenness–articulation score similar to the training-free baseline (Eq.~\eqref{eq:topo}, unweighted and with weights $0.7$/$0.3$), which it validated against a reachability-loss simulation on synthetic topologies and two ROS~2 benchmarks. This paper adds the Library and infrastructure rules, QoS weighting and the QoS edge encoding, the reference criterion, the learned and hybrid rankers, the analytical and learned simulator approximations, LOSO and zero-shot evaluation, the second and third oracles, the matched control, and the cost analysis. The closed-form score family validated in \cite{yigit2025graph} is the weakest analytical ranker in the present evaluation, which adds reference rankings, the Application population and three oracles; the present results supersede that paper's implicit recommendation of it.

\section{Related Work}
\label{sec:2}

\subsection{Dependability Analysis of Distributed Systems}
\label{sec:2.1}

Runtime dependability methods like broker clustering, backpressure, autoscaling, failover, and chaos engineering \cite{basiri2016chaos} require a running cluster, can interrupt service, and consume significant computing resources. This resource use is a major concern in green software engineering and Green AI \cite{calero2015green,verdecchia2023greenai,schwartz2020greenai}, where the carbon footprint of large execution clusters in continuous integration encourages lightweight, energy-efficient static alternatives. Pre-production methods, such as service-level fault injection testing \cite{meiklejohn2021service} and microservice dependency localization with PageRank (MicroRank \cite{yu2021microrank}), offer lighter options before deployment. Benchmark platforms with cataloged, replayable faults, like Train-Ticket \cite{zhou2018trainticket}, help measure the impact of failures on a running deployment, which this study has not yet validated (Section~\ref{sec:limitations}). Architecture-based reliability prediction has a long history. Yacoub and Ammar’s method for architecture-level reliability risk analysis \cite{yacoub2002reliability} was one of the first to combine component dependency graphs with complexity and failure severity to rank components by risk. State, path, and additive reliability models reviewed by Goseva-Popstojanova and Trivedi \cite{gosevapopstojanova2001architecture} are classic examples, as is the Palladio Component Model \cite{becker2009palladio}.

Error propagation has also been analyzed at the architecture level. Abdelmoez et al.~\cite{abdelmoez2004error} estimated error propagation probabilities between architectural components, and Popic et al.~\cite{popic2005error} added them to architecture-based reliability models of component-based systems. Cortellessa and Grassi~\cite{cortellessa2007modeling} analyzed how error propagation affects system reliability, and Hiller et al.~\cite{hiller2004epic} profiled how data errors propagate across software modules (EPIC). In safety-critical systems, model-based failure analysis is standard practice, including Hierarchically Performed Hazard Origin and Propagation Studies (HiP-HOPS \cite{papadopoulos1999hiphops}) and the Architecture Analysis \& Design Language (AADL) Error Model Annex \cite{delange2014aadl}. These frameworks derive propagation paths from structural descriptions, serving as conceptual precursors to SaG's dependency projection. However, these approaches need component failure-mode annotations, propagation probabilities or operational profiles, which deployment manifests do not carry; SaG asks a narrower question using only the manifests.

Telemetry-based methods find faults in running microservices. Examples include Seer \cite{gan2019seer}, MicroRCA \cite{wu2020microrca}, and recent GNN-based root-cause frameworks like Eadro \cite{lee2023eadro}, which Zhang et al.~\cite{zhang2024failurediag} thoroughly review. In synchronous microservices, failures can spread because of thread-pool exhaustion, RPC timeouts, and retry storms \cite{zhou2018trainticket}. In publish-subscribe systems, issues spread through queue saturation and message starvation. All these methods need data from a live system, but SaG works before any code is run. SaG’s focus is similar to change impact analysis \cite{bohner1996impact} and dependency management in microservice fleets \cite{esparrachiari2018tracking}. Ranking by impact is related to learning-to-rank defect prediction \cite{yang2015ltr}, which explicitly optimizes the ranking measure, as our listwise loss does (Section~\ref{sec:4.2}).

\subsection{Static Code Analysis and Static System Analysis}
\label{sec:2.2}

Static code analysis (SCA) tools like SonarQube \cite{sonarsource2024clean} measure complexity \cite{mccabe1976complexity}, cohesion, and coupling \cite{chidamber1994metrics} within individual services to identify modules likely to have defects \cite{nagappan2005static,zimmermann2007predicting}. Software engineering defect prediction has long compared advanced graph measures with simple structural metrics. For example, Zimmermann and Nagappan \cite{zimmermann2008predicting} studied network analysis on dependency graphs, while Premraj and Herzig’s replication study \cite{premraj2011network} showed that simple code and coupling metrics frequently perform as well as network measures. SCA cannot detect inter-service messaging, broker saturation, or issues that spread across hosts. Architecture recovery tools rebuild system-level structure from code \cite{bushong2021static}, and HAROS \cite{santos2019haros} checks ROS systems before launch. SaG’s static system analysis (SSA) uses the declared topology instead, spreading code-level metrics across architectural dependencies. Architecture-level coupling metrics count a service’s consumers, such as afferent coupling \cite{martin2003agile}, the Absolute Importance of the Service \cite{rud2006ais}, and service fan-in \cite{bogner2017maintainability}. In publish–subscribe systems, these counts are not simply a single edge lookup, since consumers reach producers only via topics, brokers, and shared libraries. They require a typed two-hop query (publisher to topic to subscriber), which SaG’s dependency rules define clearly. Because this count corresponds to the first propagation wave of the reachability oracle used here, this paper reports it as a reference that restates the oracle, not as a predictor (Section~\ref{sec:4.4}). This helps teams find structural anti-patterns \cite{garcia2009catalogue,taibi2018microservice} and architectural technical debt \cite{li2015technicaldebt} in CI/CD \cite{humble2010continuous}.

\subsection{Multi-Criteria Weighting}
\label{sec:2.3}

Combining QoS policies or failure effects into a single, auditable weight is a multi-criteria decision problem. The Analytic Hierarchy Process (AHP) \cite{saaty1980ahp} is the standard method, and SaG uses it for the topic weights in Section~\ref{sec:3.2} and the composite oracle in Section~\ref{sec:4.3}. AHP’s consistency ratio can find inconsistent judgments, but it does not detect matrices that have been filled in to match a chosen answer. This study notes that distinction for its weights.

\subsection{Graph Learning and Explainability}
\label{sec:2.4}

Closed-form indices \cite{freeman1977centrality,brandes2001faster,brin1998pagerank,newman2010networks}, including one used as this study’s training-free baseline, and cascade models of network robustness \cite{albert2000error,motter2002cascade,buldyrev2010cascade} assume homogeneous, usually undirected graphs. This means a single untyped score can mix up different elements like topics, libraries, and hosts. Learned node-importance methods, such as FINDER \cite{fan2020keyplayers}, DrBC \cite{fan2019learning}, and PowerGraph \cite{varbella2024powergraph}, also assume homogeneity, as does learned approximation of betweenness and closeness \cite{maurya2021gnnbet}. Homogeneous GNNs like Graph Attention Networks (GAT \cite{velickovic2018graph}) ignore relation identity unless it is added as a feature. Softmax attention averages over neighbors and cannot count them, while sum aggregation can \cite{xu2019gin,corso2020pna}; theoretically, standard message-passing GNNs are strictly limited in counting substructures without explicit features \cite{chen2020can}. Since the main reference here is neighbor count, this difference matters (Section~\ref{sec:rq2}). Heterogeneous GNNs, like the Heterogeneous Graph Transformer (HGT \cite{hu2020hgt}), learn transformations specific to each relation. However, extensive benchmarking by Lv et al.~\cite{lv2021revisiting} demonstrated that heterogeneous GNNs often fail to outperform well-tuned homogeneous baselines like GAT, directly paralleling our typing ablation findings. More broadly, Shchur et al.~\cite{shchur2018pitfalls} showed that GNN rankings are sensitive to data splits and tuning, while Huang et al.~\cite{huang2021combining} showed that label propagation combined with shallow models can outperform GNNs on transductive node classification. We test both types with the same capacity (Section~\ref{sec:rq2}). Khodabandeh et al.~\cite{khodabandeh2025linkpred} use graph attention on microservice call graphs to predict upcoming interactions. In contrast, we predict the effect of removing a node from a declared topology. GNN explainers like GNNExplainer \cite{ying2019gnnexplainer} describe models using their internal features. SaG’s explanation layer instead names ISO/IEC 25010 quality sub-characteristics \cite{iso25010_2023} and a remediation class for each flagged component, but this is not evaluated here.

This study aligns with research showing that simple baselines perform as well as more advanced learning methods \cite{hellendoorn2017deep,errica2020fair}. In software engineering, it also supports findings that network measures on dependency graphs \cite{zimmermann2008predicting} add little value over simple coupling metrics once those are included \cite{premraj2011network}. Crucially, in line with Green Software Engineering and Green AI principles \cite{calero2015green,verdecchia2023greenai,schwartz2020greenai}, complex deep learning architectures in continuous integration pipelines must be justified against the latency, carbon footprint, and energy costs of simple static heuristics. Following guidance on statistical testing in empirical software engineering \cite{arcuri2011practical}, we use paired non-parametric tests with multiple-testing corrections, and report differences in $\rho$ with bootstrap confidence intervals as effect sizes. The main contribution here is an evaluation of learning on derived dependency graphs for a pre-deployment ranking task. On the two oracles for which a closed-form first-order expansion exists, no learned model exceeds that expansion or a known architecture metric built on the same dependencies, including a model trained on the costly oracle's own labels.

\section{The Software-as-a-Graph (SaG) Architectural Model}
\label{sec:3}

Figure~\ref{fig:1} shows the full SaG framework architecture. The shared front end handles Architecture-as-Code manifests, builds a typed multigraph, derives a logical dependency layer that makes runtime failure paths explicit, and extracts typed node properties. This representation supports graph-learning pipelines and makes software dependencies explicit, so analytical, hybrid, and learned cascade-impact rankings can be computed from the same architectural representation (Sections~\ref{sec:4} and~\ref{sec:6.2}). This common representation enables controlled comparisons between methods that differ in complexity but operate on identical dependency information. The proposed explanation layer reads the same properties separately, with no shared parameters.

\centering
\includegraphics[width=0.70\linewidth]{figures/Figure_1}
\caption{End-to-end architecture of the SaG framework. The ranking pathway runs down the center: manifest ingestion, typed structural multigraph ($G_{\text{structural}}$), \texttt{DEPENDS\_ON} logical dependency projection ($G_{\text{analysis}}$) with typed node properties, the ranking methods (analytical, hybrid, and learned; Figure~\ref{fig:engines}), and the ranked critical set. \subsection{Multigraph Definition}
\label{sec:3.1}

A distributed system is described as a typed, weighted, directed multigraph:

\begin{equation}
\label{eq:sag_multigraph}
\mathcal{G} = (V, E, \tau_V, \tau_E, w_V, w_E)
\end{equation}

where:

\begin{itemize}\tightlist
    \item $V = V_{\text{app}} \cup V_{\text{broker}} \cup V_{\text{topic}} \cup V_{\text{host}} \cup V_{\text{lib}}$ holds the five entity types $\mathcal{T}_V$ of Table~\ref{tab:1}; $V_{\text{host}}$ denotes physical or virtual \emph{Execution Hosts}.
    \item $E$ is the set of directed edges, and $\tau_V: V \to \mathcal{T}_V$ and $\tau_E: E \to \mathcal{T}_E$ assign entity and relation types.
    \item $w_V: V \to (0, 1]$ and $w_E: E \to (0, 1]$ weight entity criticality along with connection strength. In the implementation evaluated here, $w_V$ of an Application is a power mean of the QoS weights $w(t)$ (Section~\ref{sec:3.2}) of the topics it publishes or subscribes to, and a Library takes the largest weight among its own topics and its consuming Applications, amplified by its fan-out. A code-quality penalty (CQP), computed from lines of code, cyclomatic complexity, instability and cohesion, does not enter $w_V$; it and its four inputs appear only as node features of the learned rankers (Section~\ref{sec:3.5}).
\end{itemize}

\noindent The raw multigraph is denoted $G_{\text{structural}}$. The simulation oracles run on it, and the raw-graph learners pass messages over its edges. The analysis graph $G_{\text{analysis}}$ is $G_{\text{structural}}$ augmented with the derived \texttt{DEPENDS\_ON} edges (Section~\ref{sec:3.3}) and the typed node properties computed from them (Section~\ref{sec:3.5}). Its Application--Library \texttt{DEPENDS\_ON} projection is the graph the analytical rankings and the \texttt{-P} learners read. Supplementary Section~\ref{supp:notation} lists the notation.

\noindent\textbf{Scope of Evaluation and Entity Roles.} While the multigraph formalizes five entity types, this study concentrates its empirical study specifically on \emph{Applications} ($V_{\text{app}}$). In this work, the term \emph{Application} is adopted to align with publish–subscribe standards (such as OMG DDS and ROS~2 participant nodes); conceptually, it corresponds directly to individual microservice containers, autonomous service agents, or communicating daemon processes in distributed architectures. Applications represent the developer-authored, code-level services that are often changed, refactored, and tested in CI/CD pipelines, so they are the main focus for pre-deployment triage. Brokers, Topics, Execution Hosts, and Libraries are also modeled and included because they are important for understanding indirect failure propagation. For example, we cannot analyze message routing, shared fault-domain colocation, or library-related failures without them. However, ranking infrastructure components like Brokers and Hosts is more relevant to operational provisioning than to software triage at commit time, so we treat this as a separate operational issue. Consequently, the empirical evaluation in this paper focuses strictly on ranking developer-authored Applications ($V_{\text{app}}$); evaluating broker queue bottlenecks and physical host outages remains an important operational extension (Section~\ref{sec:limitations}).

\subsection{Quality-of-Service Link Weighting}
\label{sec:3.2}

A link’s strength is conceptually determined by its Quality-of-Service (QoS) contract. For example, a \texttt{RELIABLE} topic with \texttt{TRANSIENT\_LOCAL} durability creates a stronger connection between services than a \texttt{BEST\_EFFORT} telemetry stream. Each topic $t$ has an overall weight $w(t) \in (0, 1]$ that combines its QoS policies (reliability, durability, priority) with payload size and publication frequency. We set the reliability, durability, and priority weights employing an Analytic Hierarchy Process (AHP) pairwise-comparison matrix, which we defined independently and did not adjust to fit a target vector ($CR = 0.016$, non-degenerate). The framework's other AHP matrices, including the one behind the $I_{\text{comp}}$ weights (Section~\ref{sec:4.3}), were instead filled in to reproduce weight vectors chosen in advance, so their consistency ratios carry no evidential weight.

Although we formalize this multi-criteria weighting to capture declared middleware contracts, the evaluation in Section~\ref{sec:7} tests whether this contractual information improves cascade ranking. It does not: on the reachability and queue-flow simulators, declared QoS policy parameters carried no measurable signal. For the reachability simulator this null is largely fixed by design, because $I^*$ barely reads QoS (Section~\ref{sec:4.3}); the queue-flow simulator does read QoS policies, so there the null may be informative, although its sensitivity to them was not measured (Section~\ref{sec:4.3}). On the reachability oracle, more than half of the apparent QoS effect came from the QoS-weighted in-degree feature, and the remainder was not significant (Section~\ref{sec:rq2}). On the queue-flow oracle, the gains came from declared publication rates and payload sizes, while QoS-policy shares added $-0.005$ ($p = 0.68$; Section~\ref{sec:rq1}). We retain the full AHP formalization for architectural completeness and reproducibility; in this corpus, omitting QoS policy weighting did not reduce ranking accuracy. The dependency counts reported in this paper are unweighted and do not use $w(t)$.

\subsection{Logical Dependency Projection (\texttt{DEPENDS\_ON})}
\label{sec:3.3}

Structural edges do not directly show how failures spread. For example, a subscriber depends on a publisher, but pub-sub topologies have no direct edge between them. SaG therefore derives an explicit semantic relation, \texttt{DEPENDS\_ON}, from the dependent to the dependency: if the target fails, the source is affected. The derived edges expose the architectural pathways through which failures may propagate, and the resulting dependency graph is the common input for analytical rankings, hybrid methods, and graph-learning models. Table~\ref{tab:2} lists the rules.

Rules~1 and~2 combine topics $T$ that connect a pair using probabilistic union \cite{pearl1988probabilistic}, so that having multiple failure paths increases the connection strength. Rule~5 uses the harmonic mean $H(x, y) = 2xy/(x+y)$ \cite{hardy1952inequalities}. Rules~3 and~4 assign dependencies to hosts by taking the maximum value.

\noindent\textbf{Sequential cascades and simultaneous blasts.} Rule~1 describes sequential cascades, where if a publisher fails, its subscribers are affected because they do not receive messages. Rule~5 describes simultaneous blasts, where if a library crashes, all applications that depend on it fail at the same time. Neither mechanism is stated explicitly in a deployment manifest; each rule makes one of them visible. Shared-library dependencies are included because they create simultaneous blast failures that message-flow topology alone does not represent. Libraries that publish or subscribe are also endpoints for Rule~1, and an Application can reach a library’s topics through Rule~5. \texttt{InDeg}, \texttt{Reach}, \texttt{Topo-QoS} and the graphs the \texttt{-P} learners read apply Rule~1 to direct subscriptions only (Eq.~\eqref{eq:indeg}). The node-property extraction, which produces the in-degree feature every learner receives, additionally follows up to three \texttt{USES} links, so an Application that subscribes through a library it uses counts as a Rule~1 dependent in that feature only. Rules~2, 3, 4, and~6 cover infrastructure and broker dependencies (see Table~\ref{tab:2}), which define physical host failure domains and broker routing bottlenecks. Since this evaluation focuses on Application-level code, these four rules are not used in the ranking benchmarks but are included for completeness.

\noindent\textbf{Remark 1 (the dependency count is a typed two-hop count).} Let $G_{\text{flow}}$ be the Application--Library projection (Rules~1 and~5) and $v$ an Application. By construction,
\begin{equation}
\label{eq:indeg}
\texttt{InDeg}(v) \;=\; \bigl|\{\,u \neq v : \exists t \in V_{\text{topic}},\; (v, t) \in \texttt{PUBLISHES\_TO} \wedge (u, t) \in \texttt{SUBSCRIBES\_TO}\,\}\bigr|.
\end{equation}
Since Rule~5 edges end at Libraries, every edge into an Application is a Rule~1 edge $u \to v$, which exists exactly when $u \neq v$ (an Application or a Library) directly subscribes to a topic that $v$ publishes; in the presence of multiple parallel topics between the same pair, parallel topics collapse into a single directed dependency edge in $G_{\text{flow}}$.

\noindent The right side of Eq.~\eqref{eq:indeg} represents publish--subscribe afferent coupling (fan-in, or the Absolute Importance of the Service \cite{martin2003agile,rud2006ais}), and is a typed two-hop query on the raw multigraph. \texttt{InDeg} can be computed directly without projection; the projection defines which typed query to use. We checked this equality on all seventeen corpus graphs, with a maximum absolute difference of $0$. We measure the value of the derivation separately: including Rule~5 raises the agreement of transitive reach with $I^*$ by $+0.058$ (9 of 12 folds, Holm $p = 0.0068$; Section~\ref{sec:rq1}). Since the primary oracle’s first propagation wave matches this set (Section~\ref{sec:4.4}), \texttt{InDeg} and its transitive version \texttt{Reach} are used as reference points in this paper, not as predictors.

\subsection{Dual Graph Views}
\label{sec:3.4}

The \textbf{structural graph} $G_{\text{structural}}$ is the raw deployment topology. The \textbf{analysis graph} $G_{\text{analysis}}$ adds the \texttt{DEPENDS\_ON} edges and code metrics (see Figure~\ref{fig:2}). Every ranker's node features are computed on $G_{\text{analysis}}$; the learners pass messages either over the edges of $G_{\text{structural}}$ or over the \texttt{DEPENDS\_ON} projection (Table~\ref{tab:predictor_taxonomy}), and no ranker reads simulator output (Section~\ref{sec:4.4}). The two views also differ for a learner: on $G_{\text{structural}}$, every relation points away from Applications, so forward message passing does not reach them. In the \texttt{DEPENDS\_ON} graph, each Application receives messages from its dependents (Section~\ref{sec:rq2}). The raw multigraph is therefore also a comparison point in the evaluation: it exposes communication structure but not cascading dependencies. Because the two views also differ in edge direction, Section~\ref{sec:rq2} adds a raw-graph learner that passes every message in both directions, so that dependency semantics can be separated from direction.

\subsection{Typed Node Feature Encoding}
\label{sec:3.5}

Both the ranking pathway (Section~\ref{sec:4}) and the proposed explanation layer use typed node properties from $G_{\text{analysis}}$. All five entity types share a base set of 18 normalized topological metrics (ranging from $[0, 1]$): PageRank, Reverse PageRank, betweenness, closeness, eigenvector centrality, in-degree, out-degree, clustering, articulation, bridge ratio, node QoS weight, incoming and outgoing dependency weights, multi-path coupling, path complexity, fan-out criticality, and the Connectivity Degradation Index (CDI). We calculate four centrality features (PageRank, Reverse PageRank, betweenness, and closeness) over weighted edges, so they include QoS information. This means the so-called QoS-off condition is not entirely free of QoS effects. The in-degree feature and the incoming dependency weight $w_{\text{in}}$ (a QoS-weighted version) ensure that all learners receive information closely related to \texttt{InDeg}, so the learners inherit some overlap with the oracle’s reference counts (Section~\ref{sec:rq2}). We did not use any learner missing both columns. Type-specific blocks add more features, extending the vector to 19--25 dimensions (Applications and Libraries add the code-quality penalty and its four static-code inputs; the full schema is in Supplementary Section~\ref{supp:features}). CDI measures structural connectivity loss using a fixed-scale breadth-first sample to keep computation time reasonable (Section~\ref{sec:rq4}). We discuss its sensitivity to hash-seeded tie-breaking in Section~\ref{sec:8.3}.

In this study, SaG therefore serves two roles. It provides a dependency representation from which analytical rankings can be computed directly, and it provides a graph on which learned and hybrid methods operate. The evaluation in Sections~\ref{sec:6}--\ref{sec:8} examines how much ranking performance arises from this representation and how much from the models applied to it.

\section{Ranking Methods, Simulation Oracles, and the Reference Criterion}
\label{sec:4}

This study evaluates three categories of ranking methods: analytical rankings derived directly from dependency structure, hybrid methods that combine an analytical prior with a learned correction, and learned methods that infer rankings from graph representations. The training-free baseline, \texttt{Topo-QoS}, applies QoS-weighted betweenness to the dependency graph, and Section~\ref{sec:6.2} defines the analytical references. The learned methods use graph neural networks on the typed multigraph and the dependency graph, and gradient-boosted models with per-Application dependency-graph features (Sections~\ref{sec:4.1}--\ref{sec:4.2} and~\ref{sec:6.2}). Hybrid methods adjust the \texttt{Topo-QoS} score with a learned correction (Figure~\ref{fig:engines}). All methods are trained on or evaluated against simulation oracles that run on a separate graph view (Section~\ref{sec:4.3}). Because several rankings are derived from the same failure-propagation assumptions the simulators use, the evaluation distinguishes rankings that restate a simulator's rule from those that predict its outcomes (Section~\ref{sec:4.4}). Figure~\ref{fig:engines} illustrates the methods and their evaluation; full hyperparameters and training commands are in the experiment pages of the replication repository (Section~\ref{sec:6.1}).

\subsection{Heterogeneous Graph Transformer and Attention Networks}
\label{sec:4.1}

The main learned ranker, \texttt{HGT-QoS}, is a three-layer Heterogeneous Graph Transformer (HGT) \cite{hu2020hgt} built with PyTorch Geometric \cite{fey2019fast}. It uses a hidden dimension of $D=64$ and $H=4$ heads; on the dependency graph, which has fewer relation types, \texttt{HGT-P-QoS} uses width $100$ so that its parameter count ($430{,}680$) stays within $1\%$ of \texttt{HGT-QoS} ($434{,}620$). Entity-specific linear projections map raw node features $x_v \in \mathbb{R}^{19\text{--}25}$ into the hidden space, with $h_v^{(0)} = \text{LayerNorm}(\text{GELU}(W_{\tau(v)} x_v))$. For each meta-relation $\langle \tau(u), \phi(e), \tau(v)\rangle$, attention uses type-parameterized keys, queries, and values, scaled by a learned per-meta-relation prior $\mu_{\langle \tau(u), \phi(e), \tau(v)\rangle}$; full layer-wise formulations are in Supplementary Section~\ref{supp:hgt}. Message passing runs over both $G_{\text{analysis}}$ and its transpose. In the raw multigraph $G_{\text{structural}}$, native relations point away from Applications (e.g., \texttt{PUBLISHES\_TO}, \texttt{RUNS\_ON}, \texttt{USES}), so forward message passing cannot propagate messages to the scored Application nodes. As a result, forward GNNs on $G_{\text{structural}}$ collapse structurally into per-node MLPs operating over precomputed centrality features (Section~\ref{sec:8.2}). In contrast, the derived dependency graph $G_{\text{analysis}}$ explicitly directs edges from dependents to dependencies, allowing forward message passing to aggregate information from downstream consumers. The homogeneous Graph Attention Network (\texttt{GAT-QoS}, and \texttt{GAT-P-QoS} on the dependency graph) uses a three-layer architecture with four attention heads and width $D=288$ ($D=296$ in the unweighted control for parameter matching), projecting all node types into a joint embedding space before applying homogeneous \texttt{GATConv} layers.

Each directed edge has a 16-dimensional vector. Index 0 represents the coupling weight, index 1 is the normalized path count, indices 2 to 8 are a one-hot encoding of the relation, and indices 9 to 15 are middleware QoS parameters such as reliability, durability, priority, transport departure mode, deadline constraints, and max-blocking time. The edge vector is projected and added before attention.

\subsection{Prediction Head and Training Objective}
\label{sec:4.2}

A composite head predicts the simulated cascade impact, supplemented by an active auxiliary head $\hat{a}_1$ regressing on the simulator's reliability column $I^*_R$. (A secondary maintainability head defined in the schema is masked out of backpropagation because the simulator produces no maintainability labels.) The operational training objective combines mean-squared error regression with listwise and margin-ranking terms:
\begin{equation}
\label{eq:loss_active}
\mathcal{L} = \text{MSE}(\hat{I}^*, I^*) + 0.5 \cdot \text{MSE}(\hat{a}_1, I^*_R) + 0.3 \cdot \mathcal{L}_{\text{rank}} + 0.1 \cdot \mathcal{L}_{\text{pairwise}},
\end{equation}
where $\mathcal{L}_{\text{rank}}$ is Listwise Maximum Likelihood Estimation (ListMLE) \cite{xia2008listwise} over the permutation $\pi$ induced by the simulated labels,
\begin{equation}
\label{eq:listmle}
\mathcal{L}_{\text{rank}} = -\frac{1}{N}\sum_{i=1}^N \Big( \hat{s}_{\pi_i} - \log \sum_{j=i}^N \exp(\hat{s}_{\pi_j}) \Big),
\end{equation}
and $\mathcal{L}_{\text{pairwise}}$ is a margin-ranking loss with $\gamma = 0.05$ over pairs differing by more than $\gamma$. Tied labels, which affect about 31\% of Applications with $I^* = 0$, enter $\pi$ in a fixed deterministic sequence (ordered by entity identifier). While this injects an arbitrary ordering among inactive nodes into ListMLE, the margin-ranking term explicitly ignores pairs separated by less than $\gamma = 0.05$, dampening gradient penalties from tied inactive components.

Models are trained with AdamW ($\eta = 3 \times 10^{-4}$, weight decay $10^{-4}$) using cosine warm restarts for up to 300 epochs. We set early stopping at 60 epochs of patience on a 20\% node-level validation split from the largest training scenario, using five fixed seeds ($\{42, 123, 456, 789, 2024\}$); while this node-level split is transductive with respect to that scenario's internal graph, all reported evaluations are strictly inductive under leave-one-scenario-out cross-validation. We set hyperparameters and loss coefficients before the first sweep and kept them the same across all experiments. This approach differs from the registered plan, which called for selecting every hyperparameter using nested inner-LOSO selection (two-fold inner holdout). Instead, the published results use one fixed configuration, chosen during the main experiments to keep computation manageable across seeds and folds. We explain this difference in Section~\ref{sec:6.3}. We ran the registered selection later as a sensitivity analysis on the eight-configuration stage-1 grid (varying depth and rank normalization of features and labels). This analysis also used early stopping on a held-out training scenario, which is another difference from the published protocol (Section~\ref{sec:rq2}). The results confirm that the main null finding does not change under nested tuning.

\subsection{Simulation Oracles}
\label{sec:4.3}

The simulators define three different notions of cascade impact rather than direct observations of real failures, so they serve as evaluation criteria whose assumptions can favor some ranking methods over others. Labels come from three failure simulators, which serve as label oracles (we use the two terms interchangeably), on the raw structural multigraph $G_{\text{structural}}$:
\begin{itemize}\tightlist
    \item \textbf{Primary reachability cascade oracle ($I^*$):} Crashes component $v$, propagates outages through dependent topics, brokers and links via breadth-first traversal on $G_{\text{structural}}$, and computes the mean fractional feed loss across intact subscribers. Feed loss is scaled by a QoS severity ladder ($\times 1.2$ \texttt{RELIABLE}, $\times 1.15$ high priority, $\times 1.05$ medium) and clamped to $[0, 1]$. Each propagation wave is processed in a seeded random order, which decides ties at the propagation threshold; the label is the mean over five seeds. Disabling QoS scaling leaves the Application ordering largely intact ($\rho = 0.965$ across the twelve folds), and substituting durability-aware rescaling moves it less still ($\rho = 0.977$), showing that $I^*$ is predominantly a topological reachability metric.
    \item \textbf{Queue-flow discrete-event oracle ($I_{\text{dyn}}$):} A discrete-event SimPy \cite{team2020simpy} simulation to model dynamic message emission rates, queue buffer saturation, and network latency. It measures the drop in delivered message rate for surviving consumers under load, using declared rates, payload sizes, and QoS contracts that $I^*$ ignores. QoS policies act on the queues directly: on overflow, a \texttt{RELIABLE} topic drops its oldest message and a \texttt{BEST\_EFFORT} topic the newest; durable topics replay retained messages after the fault; transport priority orders service; deadlines and lifespans expire messages; and history depth sets queue capacity. No run with these policies disabled was made, so the simulator's sensitivity to QoS is not quantified. Its mechanism differs from reachability, but it shares the same pub-sub topology, and its first-order effect—consumers that lose a failed publisher’s messages—is again subscriber loss. While $I_{\text{dyn}}$ models declared rates and buffer limits, it operates on configured parameters free of physical operating-system dynamics like socket buffer backpressure, thread scheduling, or garbage collection pauses. It provides labels for all $1{,}321$ Applications, averaging over five seeds, and takes $12.7$ CPU-hours for the full corpus, compared to seconds for $I^*$. A sensitivity check restricted to the first $30$ Applications per fold in lexicographic order is reported in Supplementary Section~\ref{supp:round8} (Table~\ref{tab:r8-n30}). $I_{\text{dyn}}$ agrees with $I^*$ at a mean $\rho = 0.711$ $[0.625, 0.794]$. Across seeds, a single $I_{\text{dyn}}$ run agrees with another at $\rho = 0.43$--$0.96$ per fold; the five-seed mean used as the label has an estimated reliability of $0.79$--$0.99$ (Spearman--Brown), which bounds any ranker's agreement, and every ranker in Table~\ref{tab:independent_oracles} stays below its fold's bound.
    \item \textbf{Composite multi-criteria failure oracle ($I_{\text{comp}}$):} An auxiliary benchmark uses the Validate-stage failure simulator. We run it on all $1{,}321$ Applications with QoS weighting and a primed baseline flow. Each removal is scored as a linear combination of four degradation components: $I_{\text{comp}}(v) = 0.35\,\text{RL}(v) + 0.25\,\text{FR}(v) + 0.25\,\text{TL}(v) + 0.15\,\text{FD}(v)$, representing Reachability Loss ($\text{RL}$), Fragmentation ($\text{FR}$; $0.70$ structural component loss $+\,0.30$ severity), Throughput Loss ($\text{TL}$), and Flow Disruption ($\text{FD}$). The weights were chosen, not elicited: the AHP matrix behind them was filled in to reproduce this vector. $I_{\text{comp}}$ therefore serves as a declared multi-objective stress test to assess resilience to network fragmentation and throughput disruption, rather than just subscriber loss. Since fragmentation and flow disruption occur with almost every removal, $I_{\text{comp}}(v) > 0$ for nearly every Application. $I_{\text{comp}}$ is never used as a training label.
\end{itemize}

\subsection{Input--Label Separation and the Reference Criterion}
\label{sec:4.4}

No simulation output is used as an input: node features are computed on $G_{\text{analysis}}$, and labels come only from the oracles, which execute on $G_{\text{structural}}$; a regression test in the replication package ensures this separation. The separation is between inputs and labels, not between graphs: the raw-graph learners pass messages over the same structural edges the oracles traverse.

Procedural separation does not eliminate construct overlap, which is the main risk discussed in this paper. High agreement with a simulator does not necessarily imply predictive skill: a ranking may correlate strongly with a simulator because it reproduces the simulator's propagation rule, not because it infers impact from independent evidence.

\noindent\textbf{The reference criterion.} We established the formal concept of the reference criterion post hoc to understand why simple dependency counts performed so strongly. A ranking is a \emph{reference} for an oracle $O$ if it is a closed-form simplification of $O$’s own computation using the same inputs. A reference measures how much of $O$ comes from its own rule, not predictive skill, so comparisons with it are not claims of superiority. All other rankers, namely the training-free baseline and the learned and hybrid methods, are \emph{predictors}. For $I^*$, the first propagation wave corresponds to the set of \texttt{InDeg} counts (see Remark~1), which is classical publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais}; the references are therefore its first-order expansion (Eq.~\eqref{eq:analytic_istar}), \texttt{InDeg}, \texttt{Reach}, and their raw-graph equivalents. For $I_{\text{dyn}}$, the rate-weighted first-order expansion (Eq.~\eqref{eq:rate-expansion}) truncates its computation to direct subscriber loss weighted by declared publication rates, so it is the reference for that simulator; the $I^*$ references are also reported for comparison. For $I_{\text{comp}}$, no ranking is a truncation; its fragmentation and flow terms respond to removing high-degree and high-betweenness nodes, so \texttt{Topo-QoS} and raw degree are \emph{term-aligned} with it. They are not references under the definition above, but their performance is interpreted with the same caution. How much of each oracle its own rule recovers is read directly from the reference rows: the first-order expansion reaches $\rho = 0.808$ on $I^*$, and the rate-weighted expansion $0.830$ on $I_{\text{dyn}}$ (Tables~\ref{tab:hybrid} and~\ref{tab:independent_oracles}). The learned methods are not references by this definition, but they use in-degree features and are trained on the oracle they are scored against, so they share some overlap (Section~\ref{sec:rq2} measures this). References are therefore reported to show how much agreement can be obtained by encoding a simulator's assumptions directly, and predictors are evaluated against them to determine whether learning adds information beyond explicit dependency structure. Two analyses limit the circularity instead of removing it. Every ranker is evaluated on all three oracles, and its agreement with $I_{\text{dyn}}$ is also reported after removing the effect of $I^*$ (and separately, the first-order term) (Section~\ref{sec:rq1}). However, none of these analyses replaces validation against real failures in live distributed systems, which this study does not include (Section~\ref{sec:8.3}). All results are therefore conditional on simulation fidelity.

\section{Experimental Setup}
\label{sec:6}

The experimental design evaluates competing explanations of cascade-impact ranking performance. Some rankers derive impact analytically from explicit dependency structure, some combine analytical and learned components, and others learn directly from graph representations. The goal is not only to identify high-performing rankers, but also to determine whether ranking performance originates primarily from the dependency representation or from the learning algorithm operating on it. RQ1 therefore compares learned approaches with analytical rankings derived from the same dependency structure, and RQ2 isolates the contributions of dependency representation, degree information, relation typing, QoS information, and model family.

\subsection{Corpus and Replication Package}
\label{sec:6.1}

The corpus includes 2,812 components from seventeen architectures (see Table~\ref{tab:4}). Twelve synthetic topologies make up the LOSO folds, covering areas like autonomous vehicles, financial trading, healthcare, industrial SCADA, smart-city IoT, telecom RAN, logistics, gaming, microservices, enterprise integration, and air-traffic management. Because all twelve topologies and their code metrics come from the same family, LOSO tests transfer across several parameter settings of that generator, not across unrelated industrial systems. We can regenerate each topology exactly from its configuration, and continuous integration checks this using a SHA-256 manifest. Because every architecture is available both as a raw multigraph and as a derived dependency graph, the corpus separates the effects of dependency representation, analytical structure, and model complexity on ranking performance.

The five open-source systems are hand-crafted models. Autoware.universe (ROS~2), EdgeX Foundry, Home Assistant, and two meshes based on Online Boutique and Train-Ticket were each created by the first author as typed multigraphs using public architectural documentation. We did not mechanically extract them from source code or container manifests. Because one person modeled them, bias is possible. No second modeler re-derived any model, so this risk is not quantified (Section~\ref{sec:threats}). Some details, like brokers, QoS profiles, code metrics, and host specifications, are partly assumed. Two models differ significantly from their originals: the Online Boutique model is a 22-application pub-sub mesh with four brokers, while the original utilizes RPC and has no broker. The Train-Ticket model treats its service-discovery registry as an event broker. In both cases, we changed synchronous RPC interactions to asynchronous request-and-response topics with routing intermediaries (per-system composition in Supplementary Section~\ref{supp:corpus}; modeling notes in the replication repository's RQ3 experiment page). Specifically, synchronous RPC calls were decomposed into pairs of reciprocal topic interactions: a request topic published by the invoking caller and subscribed by the target provider, and a separate reply topic published by the provider and subscribed by the caller, both mediated by broker channels. This explicitly preserves bidirectional dataflow paths while converting synchronous blocking semantics into decoupled event streams, leaving out client-side timeout, thread-pool exhaustion, and synchronous backpressure effects. Neither model includes synchronous call edges. As a result, RQ3 tests zero-shot transfer to stylized architecture models inspired by open-source systems made by a single modeler, not to real production systems or automatically extracted call graphs.

Replication package. All datasets, harnesses, checkpoints, and result artifacts are stored on Zenodo (see Data Availability). In addition, the public repository provides documentation for each experiment, including its protocol, hyperparameters, \texttt{make} target, artifacts, and extended results (\sagexperiments).

\noindent\textbf{Training-free baseline.} \texttt{Topo-QoS} is computed on the Application--Library \texttt{DEPENDS\_ON} graph (Rules 1 and 5):
\begin{equation}
\label{eq:topo}
\text{Topo-QoS}(v) = 0.6 \cdot \text{BT}_{w}(v) + 0.4 \cdot \text{AP}(v),
\end{equation}
where $\text{BT}_{w}$ is betweenness over edge distances $d(e) = 1/(w(e) + 10^{-6})$, so tightly coupled edges attract shortest paths, and AP flags articulation points. Because of an implementation defect (an index mismatch when the articulation scores are read), the AP term is zero for every node, so the score that was executed, and that every table reports, is QoS-weighted betweenness alone. Restoring the term lowers \texttt{Topo-QoS} from $0.553$ to $0.533$, so the defect does not favor the reference counts. The hybrids' prior $p(v)$ inherits the same defect; they were not retrained with the corrected prior. The unweighted Topo baseline is reported in Supplementary Section~\ref{supp:baselines}.

Because several analytical rankings are derived from the same architectural information the simulators use, high correlation with a simulator does not by itself imply prediction (Section~\ref{sec:4.4}). These analytical approximations serve as strong references because they are derived directly from the corresponding failure-propagation assumptions. Three primary training-free rankings restate the reachability oracle’s propagation rule and are reported as references. The first is the post hoc first-order expansion of $I^*$ (Analytic $I^*$):
\begin{equation}
\label{eq:analytic_istar}
\hat{I}^*_1(v) = \sum_{t \in \text{pub}(v)} \frac{|\text{sub}(t)|}{|\text{pub}(t)|},
\end{equation}
where $|\text{pub}(t)| \ge 1$ holds for all published topics $t \in \text{pub}(v)$ by construction ($v$ publishes to $t$), preventing any division by zero. The second is \texttt{InDeg}$(v)$, the number of direct dependents of $v$ on the Application--Library \texttt{DEPENDS\_ON} graph, which for an Application equals publish–subscribe afferent coupling and is exactly the set $I^*$'s first wave reaches (Remark~1). The third is \texttt{Reach}$(v)$, the number of its transitive dependents normalized by $|V| - 1$, which is the set a reachability cascade can visit. For the queue-flow simulator $I_{\text{dyn}}$, the corresponding reference is the rate-weighted first-order expansion
\begin{equation}
\hat{I}^{\mathrm{rate}}_{\mathrm{dyn},1}(v) \;=\; \sum_{t \in \mathrm{pub}(v)} \frac{r_t}{|\mathrm{pub}(t)|}\,\lvert \mathrm{sub}(t) \rvert,
\label{eq:rate-expansion}
\end{equation}
where $r_t$ is the declared publication frequency of topic $t$. Eq.~\eqref{eq:rate-expansion} weights each term of the first-order expansion of $I^*$ (Eq.~\eqref{eq:analytic_istar}) by the topic's declared publication rate. It is therefore a first-order truncation of the queue-flow simulator $I_{\text{dyn}}$, which reads the same rates, and it is reported as a reference for $I_{\text{dyn}}$ rather than as a predictor. It was evaluated after the registered analyses and is exploratory. Because it incorporates the same rate information used by $I_{\text{dyn}}$, it is the natural reference against which learned approximations of that simulator are evaluated; in practice, it can also serve as a training-free ranking for queue-flow impact (Section~\ref{sec:8.1}). In addition, we archive raw-multigraph topic counts (Pubs-raw) and transitive closure without Rule~5 (Reach-R1) in the replication repository. A reference shows how much of an oracle a restatement of its rule recovers, which is the size of the circularity, not predictive skill. References carry no contrast against \texttt{Topo-QoS}, and a learner’s distance from them is reported as such, not as a test. The one exception is the paired comparison between the rate-weighted reference and the learned queue-flow approximation (Section~\ref{sec:rq1}), which is labeled exploratory.

\subsection{Metrics, Protocols and Statistics}
\label{sec:6.3}

\noindent\textbf{Population.} Every ranker is scored on the Application set $V_{\text{app}}$.

Metrics. We use Spearman $\rho$ to measure ranking against the simulation oracles. To distinguish between active components and those with zero impact, we report both the full-population Spearman $\rho$ and the active-stratum Spearman $\rho_{>0}$, which only includes components with true impact greater than zero. To identify critical sets, we use Overlap@$K$, the fraction of the true top-$K$ recovered by the predicted top-$K$, where $K$ is about 20\% of $|V_{\text{app}}|$. PR-AUC, $F_1@\tau$, and nDCG@10 are reported in Supplementary Section~\ref{supp:identification}.

Protocols. In the LOSO setup, we train learned models on eleven scenarios and test on the twelfth, repeating this for all 12 folds and five random seeds. The reported value is the average $\rho$ across seeds. For zero-shot transfer, we evaluate models built on all twelve scenarios across the five system models without any fine-tuning. Training-free rankers are not fitted to any data, so for them, both protocols become per-scenario analyses on the same twelve scenarios and five models. We include them in the same tables to ensure every row is scored on the same scenarios and labels.

Statistics. The analysis emphasizes effect sizes with confidence intervals and relative ranking quality, rather than identifying a single highest-performing model. The summary $\rho$ is the average Spearman correlation for each fold or system, with a 95\% confidence interval from a bootstrap that resamples folds ($B = 2{,}000$) \cite{efron1993introduction}. We compare results using paired two-sided Wilcoxon signed-rank tests across folds \cite{wilcoxon1945individual}. With 12 folds, the smallest possible two-sided $p$-value is $0.00049$. Fisher-$z$ averaging does not change the row order in Table~\ref{tab:hybrid}. Weighting folds by $|V_{\text{app}}|$ keeps the top five the same (the reference \texttt{InDeg} rises to $0.810$) but increases \texttt{Topo-QoS} to $0.596$, corresponding to the raw-multigraph learned rankers ($0.595$--$0.606$). Spearman $\rho$ gives tied scores their average rank. Overlap@$K$ breaks ties at the $K$ boundary by node order, which is arbitrary for integer counts, so Section~\ref{sec:rq1} also reports tie-aware recall curves. Because LOSO folds share ten of eleven training scenarios, we also test every registered contrast with the Nadeau--Bengio corrected resampled $t$-test \cite{nadeau2003inference} and, when weighting by $|V_{\text{app}}|$, with an exact sign-flip permutation test.

\noindent\textbf{Analysis plan and the status of each result.} The evaluation protocol is version-controlled in the replication repository. We registered sixteen numbered amendments across the study, encompassing sensitivity, ablation, and reclassification arms, with none withheld. We assign every reported result to one of three tiers. \emph{Confirmatory}: the original plan's two co-primary contrasts, QoS-weighted (\texttt{HGT-QoS} vs.\ \texttt{Topo-QoS}) and unweighted (\texttt{HGT} vs.\ \texttt{Topo-QoS}), Holm-corrected across the two; both were null. \emph{Registered secondary}: hypotheses committed before their respective arms executed---including the matched $2\times2$, hybrid rankers, reference counts, dependency-graph learners, derivation value, full-population queue-flow labels, sensitivity arms, and the direction and corrected-prior arms of Amendment~16, each Holm-corrected within its family. We conducted all secondary analyses after observing the primary null. \emph{Exploratory}: post hoc investigations, reference reclassifications (which altered no figures; Section~\ref{sec:4.4}), and the rate-weighted reference for $I_{\text{dyn}}$ (Eq.~\eqref{eq:rate-expansion}) with the input attribution of the learned queue-flow approximation, both added after all other results existed. \textbf{Plan deviation}: the registered nested inner selection was simplified to a fixed configuration during primary sweeps; a sensitivity analysis assesses the registered selection (Section~\ref{sec:rq2}). Because sequential amendment registration accumulates family-wise error throughout rounds, we also evaluate an omnibus Holm correction across all 13 decision-bearing contrasts. Both hybrid contrasts against \texttt{Topo-QoS} remain significant under this omnibus adjustment (Hybrid-GAT $p_{\text{omni}} = 0.019$, Hybrid-HGT $p_{\text{omni}} = 0.041$). In contrast, the primary contrast remains null ($+0.069$, nominal $p = 0.266$, $p_{\text{omni}} \ge 0.46$). Main-text tables report per-family Holm corrections to reflect the pre-specified hypothesis families; the amendment log in Supplementary Section~\ref{supp:amendments} lists each family and its contrasts. The headline findings of this paper are therefore registered secondary or exploratory, not confirmatory.

Taken together, the rankers allow comparison of representation-centric and model-centric explanations of ranking performance. If performance arises primarily from the dependency representation, analytical and learned rankers built on that representation should perform similarly. If learning adds information, learned rankers should outperform analytical alternatives built on the same dependencies. Section~\ref{sec:7} reports the results against these two expectations.

\paragraph{Summary} \emph{For the reachability and queue-flow oracles, explicit dependency graphs, rather than model complexity, carry most of the ranking signal. \noindent\textbf{The reference level.} As noted in Remark~1, \texttt{InDeg} represents publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais,bogner2017maintainability} and counts exactly the Applications reached by the first propagation wave of $I^*$. \texttt{Reach} counts the transitive dependents that a reachability cascade can visit. Their values on $I^*$ ($0.764$, $\rho_{>0} = 0.516$; $0.732$) show how much of the oracle is recovered by expressing again its rule, rather than measuring predictive skill. Exploratory raw-multigraph references are evaluated in the replication repository: counting published topics (Pubs-raw) achieves $0.731$, and transitive closure without Rule~5 (Reach-R1) gets $0.674$. Among the references, that derivation matters in one case: without Rule~5, \texttt{Reach} drops by $0.058$ (9/12 folds, Holm $p = 0.0068$; derivation ablation). Untyped raw-graph metrics do not recover the reference: total degree reaches $0.199$ and reverse PageRank $0.089$, while PageRank is constant for every Application because they have no incoming raw edges.

\noindent\textbf{The first-order expansion of the oracle.} The strongest reference is the post hoc closed-form first-order expansion of $I^*$ (Eq.~\eqref{eq:analytic_istar}, Section~\ref{sec:6.2}). It reaches mean $\rho = 0.808$ $[0.755, 0.853]$ ($\rho_{>0} = 0.631$): direct subscriber loss is most of what $I^*$ measures, and \texttt{InDeg} is a coarser version of the same quantity. As a reference, it bounds the mean rather than every fold: on four folds (AV, Financial Trading, Healthcare, Industrial SCADA), \texttt{InDeg} slightly exceeds it (by $0.005$--$0.038$).

\noindent\textbf{Learners on the dependency graph approach the reference.} Trained on the dependency graph rather than the raw multigraph, the strongest learned model, \texttt{GAT-P-QoS}, achieves $\rho = 0.748$, approaching but not exceeding the direct-dependent reference. This is $0.016$ below the direct-dependent count for individual seeds, and the five-seed ensemble is $0.007$ above it ($0.772$, Table~\ref{tab:independent_oracles}). These differences are not statistically significant, nor do they show equivalence: the $90\%$ interval of the per-fold difference is $\pm 0.076$, so a two one-sided test at the registered margin of $\pm 0.05$ does not pass ($p = 0.17$ per seed, $0.13$ for the ensemble). At this sample size, the learner and the count are indistinguishable and not ranked. The closeness to the reference depends on the degree features each learner receives (Section~\ref{sec:3.5}): removing \texttt{in\_degree} and $w_{\text{in}}$ lowers \texttt{GAT-P-QoS} to $0.612$ (Section~\ref{sec:rq2}). We archive a version that uses \texttt{InDeg} as its prior in the replication repository, since it is a reference prior. \texttt{HGT-P-QoS} only reaches $0.514$ and is highly dependent on the seed (mean within-fold seed SD $0.254$; Section~\ref{sec:8.3}).

\noindent\textbf{Hybrid rankers versus the training-free baseline and their base learners.} Hybrid-HGT achieves $\rho = 0.657$ ($+0.103$, Holm $p = 0.0068$) and Hybrid-GAT reaches $0.683$ ($+0.130$, Holm $p = 0.0029$) compared to \texttt{Topo-QoS}, each outperforming the baseline in 11 out of 12 folds. Both results remain statistically significant under the omnibus Holm correction ($p_{\text{omni}} = 0.041$ and $0.019$), the Nadeau--Bengio corrected $t$ ($p = 0.019$ and $0.014$), and $|V_{\text{app}}|$-weighted averaging (exact sign-flip $p = 0.038$ and $0.005$). In this comparison, a hybrid uses $p(v)$ as an input and adds a learned correction to its logit, nesting its comparator. When compared to their own base learners, neither hybrid shows a significant difference (Hybrid-HGT vs. \texttt{HGT-QoS} $+0.035$, $p = 0.73$; Hybrid-GAT vs. \texttt{GAT-QoS} $+0.048$, $p = 0.30$). Retrained with the articulation defect corrected (Amendment~16; Table~\ref{tab:a16}), both hybrids still beat the corrected baseline ($0.533$): Hybrid-GAT-AP reaches $0.669$ ($+0.136$, Holm $p = 0.0059$) and Hybrid-HGT-AP $0.640$ ($+0.107$, Holm $p = 0.0073$), each on 11 of 12 folds, and again neither differs from its base learner ($+0.034$ and $+0.018$, Holm $p = 0.94$). The hybrid gain therefore belongs to the weak comparator, not to the learned correction. Given the direct-dependent count as their prior instead, \texttt{GAT-QoS+InDeg} ($0.763$) and \texttt{HGT-QoS+InDeg} ($0.759$) gain $+0.128$ and $+0.137$ over their base learners (Holm $p = 0.0049$) and land within $\pm 0.012$ of \texttt{InDeg} itself (equivalent at $\pm 0.05$, TOST $p < 0.001$): a learner handed the reference reproduces it. The prior also reduces transfer performance: in zero-shot tests, both hybrids perform worse than their base learners (Section~\ref{sec:rq3}). On their own, the raw-multigraph learned rankers do not differ significantly from \texttt{Topo-QoS} (\texttt{HGT-QoS} $+0.069$, $p = 0.266$; \texttt{GAT-QoS} $+0.082$, $p = 0.233$).

\noindent\textbf{Beyond the reachability oracle.} Table~\ref{tab:independent_oracles} compares the rankers against two other oracles. On the full-population $I_{\text{dyn}}$, which matches $I^*$ at $\rho = 0.711$ $[0.625, 0.794]$, the reference methods outperform all GNNs (first-order expansion $0.706$, \texttt{InDeg} $0.664$, compared to $0.496$--$0.615$ for GNNs), and \texttt{Topo-QoS} achieves $0.471$. Since $I_{\text{dyn}}$ shares its topology and first-order effect with $I^*$, the partial correlation shows how much of each ranking remains after removing the oracle it was fitted to or restates. After removing the rank of $I^*$, \texttt{InDeg} keeps $0.272$ $[0.188, 0.366]$, \texttt{Reach} $0.117$, \texttt{Topo-QoS} $0.134$, and the GNNs $0.107$--$0.173$, with all intervals excluding zero. If we remove the first-order expansion instead, the order reverses: \texttt{InDeg} stays at $0.079$. Meanwhile, the raw-multigraph GNNs retain most of their value ($0.212$--$0.217$), indicating that the learners capture queue-flow signals beyond the unweighted first-order term, although less than the rate-weighted reference ($0.573$). The queue-flow oracle separates what the dependency structure provides from what declared rates add. The unweighted first-order expansion (Eq.~\eqref{eq:analytic_istar}) reaches $0.706$ on $I_{\text{dyn}}$. Weighting each of its terms by the topic's declared publication rate (Eq.~\eqref{eq:rate-expansion}) raises it to $0.830$ $[0.778, 0.872]$ without training (exploratory). A gradient-boosted model trained on $I_{\text{dyn}}$ labels, using counts, the first-order expansion, and the registered QoS feature block, which also carries each Application's declared publication rate and payload size, reaches $0.799$. It outperforms the unweighted expansion ($+0.094$, Holm $p = 0.019$) and \texttt{InDeg} ($+0.135$, Holm $p = 0.019$), but falls below the rate-weighted reference, which exceeds it by $+0.031$ $[+0.013, +0.049]$ on 10 of 12 folds (nominal Holm $p = 0.009$; exploratory). The feature block provides the gain over the unweighted expansion ($+0.095$ over the same model without it, Holm $p = 0.014$), while on $I^*$ it adds nothing ($-0.003$, $p = 0.62$). An exploratory attribution splits the block (Supplementary Section~\ref{supp:advisor-v6}): the declared rate and payload columns alone add $+0.097$ (9/12 folds, Holm $p = 0.021$), and the seven QoS-derived columns ($w(t)$-weighted scores and policy shares) add $-0.005$ ($p = 0.68$). Declared rates, rather than QoS policies, provide most of the additional information on this oracle, and the analytical formula uses that information at least as effectively as the learned model. The GNN trained on the same labels approaches neither: \texttt{GAT-P-QoS}$\to$dyn reaches $0.598$, below the first-order expansion ($-0.108$, Holm $p = 0.014$) and the gradient-boosted approximation ($-0.201$, Holm $p = 0.0015$), and is no better than the same GNN trained on $I^*$ ($-0.008$); unlike the tree model, it received neither rates nor payloads (Section~\ref{sec:8.2}). The learned approximations are trained on the oracle they are evaluated on, so their possible value is cost, since labeling $I_{\text{dyn}}$ took $12.7$ CPU-hours for the corpus (Section~\ref{sec:rq4}); the rate-weighted reference offers the same saving without training. When trained on $I^*$ instead, the same gradient-boosted model is less robust across the three oracles than the first-order expansion alone (worst-case $\rho$ $-0.121$, Holm $p = 0.001$).

\noindent\textbf{The multi-criteria oracle favors different rankers.} On $I_{\text{comp}}$, which includes fragmentation, throughput, and flow disruption (Section~\ref{sec:4.3}), learned rankers without a prior perform poorly ($0.144$--$0.334$; sum-aggregation GNNs from Section~\ref{sec:rq2} reach $0.41$--$0.44$). The two hybrids that use \texttt{Topo-QoS} as a prior maintain $0.58$. Training-free scores that correspond to the oracle's terms rank higher: \texttt{Topo-QoS} achieves $0.702$ $[0.649, 0.753]$ (higher than the direct-dependent reference at $0.650$; the reference is ahead on only 3 of 12 folds, $p = 0.110$), and raw total degree reaches $0.719$. \texttt{Reach} drops to $0.302$. This lead reflects overlap with $I_{\text{comp}}$'s fragmentation and flow terms, similar to the references' lead on $I^*$ (Section~\ref{sec:4.4}), rather than predictive skill. No ranker is best across all three oracles.

\noindent\textbf{Identifying the critical set.} Rank correlation across all Applications is not the main concern in a CI gate; the key question is whether the true top-ranked items are flagged. Figure~\ref{fig:recall} shows, for each ranker, the proportion of the true top-20\% set on $I^*$ that appears within its top $k\%$, with ties resolved by averaging. At $k = 20\%$, \texttt{GAT-P-QoS} recovers $0.48$ of the critical set and \texttt{Topo-QoS} recovers $0.38$, matching their Overlap@$K$ ($0.454$ and $0.388$). This means about half of what a top-20\% gate flags is not in the true top 20\%, and about half of the true top 20\% is missed. To recover 80\% of the critical set, \texttt{GAT-P-QoS} must flag the top 40\% ($0.81$), and \texttt{Topo-QoS} does not reach 80\% within 50\%. The reference methods do only slightly better: at $k = 20\%$, \texttt{InDeg} recovers $0.49$ (tie-breaking bounds $0.48$--$0.50$), and 80\% recall requires the top 45\% by \texttt{InDeg} ($0.83$) or by the first-order expansion ($0.89$). Only the first-order expansion reaches 90\% within the top 50\%, and \texttt{Reach} does not reach 80\% within 50\%. On the exhaustive $I_{\text{dyn}}$ labels (right panel of Figure~\ref{fig:recall}), \texttt{GAT-P-QoS} reaches $0.74$ at 40\% and $0.82$ at 50\%, compared to $0.80$ at 40\% for the \texttt{InDeg} reference. The rate-weighted reference (Eq.~\eqref{eq:rate-expansion}), which restates $I_{\text{dyn}}$'s first-order rule, recovers $0.81$ of that set at 20\% and $0.96$ at 30\% (exploratory). In practice, requiring a gate to flag 40\%--50\% of components to catch 80\% of critical points would likely cause alert fatigue in production CI/CD pipelines. This suggests that SaG is best operationalized as a prioritized informational triage list for architectural reviews, rather than as an automated blocking gate (Section~\ref{sec:8.1} proposes a two-tiered triage protocol).

\subsection{RQ2: Sources of Predictive Performance}
\label{sec:rq2}

\paragraph{Summary} \emph{Attention-based learners improve when using the dependency graph, where messages reach the scored Applications from their dependents (\texttt{GAT-P-QoS} $0.748$ vs.\ \texttt{GAT-QoS} $0.635$), whereas the typed transformer does not in the tested configuration (\texttt{HGT-P-QoS} $0.514$ vs.\ \texttt{HGT-QoS} $0.622$). The dependency-graph GAT’s closeness to the reference comes from its degree features: without them, it loses $0.14$ (Holm $p = 0.005$). A sum-aggregation GNN, which can count dependents, loses only $0.01$ without these features, though the difference is not significant after correction. When capacity is matched, relation typing has no effect; with weighted in-degree included in both arms, the “QoS” inputs also add no measurable benefit ($+0.030$, Holm $p = 0.33$). Across these ablations, the largest drops come from removing degree information ($-0.136$ for \texttt{GAT-P-QoS} and $-0.270$ for \texttt{GAT-QoS}), whereas relation typing ($-0.013$) and the choice of aggregator ($-0.016$) have little effect. For attention-based learners, the gain from the dependency representation ($+0.113$) exceeds every change of model architecture tested and survives a control that passes raw-graph edges in both directions ($+0.072$ over it, Holm $p = 0.014$), suggesting that most of the recoverable signal lies in explicit dependency structure rather than in higher-order message passing.}

\noindent\textbf{What the dependency-graph learner needs.} Each learner receives in-degree and $w_{\text{in}}$ as node properties, and on the dependency graph, it also aggregates the dependent neighborhood. This means its similarity to \texttt{InDeg} could come from either source. Ablation experiments (Table~\ref{tab:a14}) separate these effects. Removing the two degree columns reduces \texttt{GAT-P-QoS} by $0.136$, and removing the three centralities most correlated with in-degree reduces it by $0.161$ (F1). This shows that the approach to the reference depends on the degree features. Message-passing theory predicts this: softmax attention normalizes over neighbors and computes a weighted mean, so it cannot count them, whereas a sum aggregator can \cite{xu2019gin,corso2020pna}. A GINE network with the same parameter budget supports this, keeping $0.721$ and $0.711$ without the same columns, only $0.01$--$0.02$ below its full-feature score. However, the aggregator contrasts are not significant after Holm correction ($+0.108$ and $+0.124$, $p_{\text{Holm}} = 0.157$), so the study does not claim an aggregator effect. No dependency-graph learner, with or without degree features, is equivalent to \texttt{InDeg} within $\pm 0.05$ (equivalence bounds $0.063$--$0.276$). In zero-shot, the degree columns matter little ($0.810$--$0.821$ without them), because the system models most of the ranking by separating inert from active components (Section~\ref{sec:rq3}).

\noindent\textbf{Direction versus dependency semantics.} On the raw multigraph a forward GAT never delivers a message to an Application (Section~\ref{sec:4.1}), so the $+0.113$ gain of \texttt{GAT-P-QoS} over \texttt{GAT-QoS} could come from edge direction rather than from dependency semantics. A control passes every raw-graph edge in both directions, with shared weights and an unchanged parameter count (\texttt{GAT-QoS-R}; Amendment~16, Table~\ref{tab:a16}). It reaches $0.676$: direction alone recovers $+0.041$ of the gain, which is not significant (Holm $p = 0.064$), and \texttt{GAT-P-QoS} still exceeds it by $+0.072$ $[+0.034, +0.113]$ on 10 of 12 folds (Holm $p = 0.014$). The derived dependency graph therefore adds beyond edge direction. Reverse edges also cost transfer: \texttt{GAT-QoS-R} reaches $0.744$ zero-shot, against $0.805$ for \texttt{GAT-QoS} and $0.806$ for \texttt{GAT-P-QoS} (Table~\ref{tab:system_models_transfer}).

\section{Discussion, Threats to Validity, and Limitations}
\label{sec:8}

\subsection{Dependency Representation versus Model Complexity}
\label{sec:representation}

The central finding of this study is that, for the reachability and queue-flow simulators, explicit dependency representations contributed more to ranking performance than model complexity. Deriving a dependency graph from publish--subscribe deployment manifests enabled both analytical and learned approaches: attention-based learners improved on it compared with the raw multigraph (\texttt{GAT-P-QoS} $0.748$ vs.\ \texttt{GAT-QoS} $0.635$), and rankings computed directly from it, such as the direct-dependent count ($0.764$; not statistically distinguishable from \texttt{GAT-P-QoS}, $0.748$) and the rate-weighted first-order approximation ($0.830$), were not distinguishable from, or exceeded, the best learned models ($0.748$ and $0.799$). Pure learners on the raw multigraph did not outperform the training-free baseline, because messages never reached the scored components. Explicit dependency derivation is therefore not merely a preprocessing step for graph learning; in the evaluated corpus, it is the principal source of predictive signal, and this holds against a control for edge direction: a raw-graph GAT that passes every edge in both directions recovers $+0.041$ of the $+0.113$ (not significant), and the derived graph adds $+0.072$ beyond it (Holm $p = 0.014$; Section~\ref{sec:rq2}). The multi-criteria simulator is the exception: there, raw degree and betweenness, whose terms align with fragmentation, ranked highest.

\subsection{When Learning Adds Value, and Relative to What}
\label{sec:8.2}

The study does not show that learning is never useful; it shows where learning adds value and against which comparator. Relative to the training-free baseline, learning helped in two ways. First, hybrids that correct a closed-form prior significantly outperformed that baseline ($+0.103$ and $+0.130$, 11 of 12 folds), and in an exploratory comparison they were the most consistent learned models across the three simulators. This gain is modest evidence for learning: the baseline is the weakest analytical ranker, carries the articulation defect, and is nested in the hybrids as their prior, and neither hybrid differs from its own base learner ($+0.035$, $p = 0.73$; $+0.048$, $p = 0.30$). Correcting the prior's defect does not change this: the corrected-prior hybrids beat the corrected baseline by $+0.136$ and $+0.107$ but their base learners by only $+0.034$ and $+0.018$ (Holm $p = 0.94$), so the gain belongs to the comparator, not the correction. With the direct-dependent count as the prior, both learners reproduce that count to within $\pm 0.012$. Second, learned models transferred zero-shot to unfamiliar architectures better than the baseline ($\approx 0.81$ vs.\ $0.53$). Relative to analytical references built on the same dependencies, however, no learned model showed additional skill. The references were indistinguishable from or exceeded the learned models in-distribution and ranked higher in transfer ($0.863$--$0.938$), and ordering among components that actually propagate failures remained weak for every learned model ($\rho_{>0} \le 0.342$). Learning is therefore likely to contribute most where impact depends on mechanisms that no available analytical approximation captures, a condition this corpus did not exercise. A per-regime breakdown of these results by architecture type is given in Supplementary Section~\ref{supp:regimes}.

\noindent\textbf{How message passing contributes.} On the raw multigraph, learning mainly used node properties. Three checks explain how these learned rankers worked. First, gradient-boosted decision trees using only per-node features (no graph message passing, \texttt{GBM-Feat}) reach $\rho = 0.642$ under LOSO, similar to \texttt{GAT-QoS} ($0.635$). Second, in the raw multigraph, all structural links point away from Applications, so standard forward GAT convolutions do not send messages to the scored nodes---removing all edges does not change their outputs. Third, HGT reaches Applications only through reverse edge passes, and removing them has no effect (\texttt{HGT-QoS-U}, $-0.010$, $p = 0.91$). So, on the raw multigraph, neural models acted as non-linear combiners of precomputed centralities and degree metrics, not as relational message-passing models. On the derived dependency graph, directed edges go from dependents to dependencies: three layers of message passing gather information from the true dependent neighborhood, letting \texttt{GAT-P-QoS} outperform \texttt{GBM-Feat} by $+0.106$. Since every learner also gets an in-degree feature (Section~\ref{sec:3.5}), this margin does not mean attention finds the dependent count on its own, and ablation tests show it does not: without the degree columns, \texttt{GAT-P-QoS} loses $0.136$, while a sum-aggregation network of the same size loses $0.011$ (Section~\ref{sec:rq2}).

\noindent\textbf{Homogeneous versus heterogeneous architectures.} On the raw multigraph, where message passing into Applications was inactive, adding typing made no measurable difference (main effect $-0.014$, interaction $+0.001$). On the dependency graph, where message passing is active, the heterogeneous transformer (\texttt{HGT-P-QoS}) was unstable across seeds in the tested configuration (width 100, fixed setup; mean within-fold seed standard deviation $0.254$, mean $\rho = 0.514$), while the homogeneous \texttt{GAT-P-QoS} was stable ($0.030$, $\rho = 0.748$). This means that, in this setup, relation-specific parameters did not improve accuracy, though they reduced stability. This does not mean typing is always harmful. Of the dependency-graph and raw-graph learners, only \texttt{HGT-QoS} and \texttt{GAT-P-QoS} were run under the registered selection rule (Section~\ref{sec:rq2}), so \texttt{HGT-P-QoS} ran only in its fixed configuration; averaging five seeds' predictions raises \texttt{HGT-P-QoS} to $0.618$ (still below the references), and denser topologies or architectures with messages reaching scored nodes may behave differently.

\noindent\textbf{Why the learned queue-flow approximation does not exceed the formula.} The gradient-boosted approximation (\texttt{GBM-P-QoS$\to$dyn}, $0.799$) outperforms the unweighted first-order expansion ($0.706$) because it reads declared publication rates and payload sizes, which $I_{\text{dyn}}$ uses and the unweighted expansion ignores. Once rates enter the analytical expansion (Eq.~\eqref{eq:rate-expansion}), it reaches $0.830$ and exceeds the learned approximation ($+0.031$, 10 of 12 folds; exploratory). The attention-based approximation (\texttt{GAT-P-QoS$\to$dyn}, $0.598$) received neither rates nor payloads, and it scores within $0.008$ of the same model trained on $I^*$. Whether a learned model given the same inputs as the formula, or trained to correct it, can exceed the formula is left to future work (Section~\ref{sec:limitations}).

\subsection{Restatement versus Prediction}
\label{sec:restatement}

Several of the highest-scoring rankings largely restate a simulator's propagation rule: the direct-dependent count and the first-order expansion for the reachability simulator, and the rate-weighted first-order approximation for the queue-flow simulator. The reference criterion (Section~\ref{sec:4.4}) distinguishes recovering a simulator's definition from predicting its outcomes, and it changes how both analytical and learned results should be read. A learned model that approaches a reference has learned the simulator's first-order rule, not necessarily anything beyond it. Because simulation-labeled benchmarks are common in architecture analysis, the criterion offers a general check for evaluations of this kind: before crediting a learned model with predictive skill, compare it against the simplest ranking that restates the simulator's own computation.

\subsection{Practical Consequences}
\label{sec:8.1}

\noindent\textbf{Choosing a ranker by simulator cost.} The usefulness of a ranker depends on how costly the simulator it approximates is. If the simulator is inexpensive, like the reachability simulator $I^*$ ($0.01$--$0.72$~s per pass over a corpus architecture's Applications; Section~\ref{sec:rq4}), practitioners can compute its ranking directly from the manifest. Publish--subscribe afferent coupling, a direct-dependent count used in architecture research for two decades \cite{martin2003agile,rud2006ais}, is not statistically distinguishable from any graph neural network tested at a fraction of the cost; because it restates the simulator's first wave (Section~\ref{sec:restatement}), its value is cost, not predictive skill. If the simulator is expensive, like the queue-flow simulator $I_{\text{dyn}}$ ($12.7$ CPU-hours to label the corpus), a rate-weighted first-order expansion computed from declared publication rates approximates it at $\rho = 0.830$ in milliseconds and exceeds a gradient-boosted approximation trained on its labels ($0.799$; exploratory). This study does not show that either simulator, or any of its approximations, predicts real outages.

\noindent\textbf{Choosing a ranker by failure notion.} Table~\ref{tab:guidance} summarizes the evidence by oracle. Practitioners must interpret these recommendations as conditional on simulation fidelity. If the discrete-event or cascade simulator does not capture specific physical failure modes (e.g., partial network partitions or disk thrashing), ranking efficacy on physical clusters could diverge. On the reachability oracle $I^*$, the best learned ranker is the dependency-graph GAT (\texttt{GAT-P-QoS}, $0.748$), followed by the hybrids ($0.657$--$0.683$); all require training, and none is statistically distinguishable from the direct-dependent reference ($0.764$). Where the reachability ranking itself is wanted, running $I^*$ directly is the simplest and cheapest option at corpus size. Where the queue-flow notion of impact matters ($I_{\text{dyn}}$), the rate-weighted first-order expansion ($0.830$) is the recommended ranker; it exceeds the learned approximation trained on queue-flow labels ($0.799$; exploratory), and this is the only simulator on which declared information carries measurable signal beyond the dependency structure, from publication rates and payload sizes rather than from QoS policies or QoS-weighted scores. Where failure involves fragmentation and throughput loss ($I_{\text{comp}}$), training-free topological scores (\texttt{Topo-QoS}, $\rho = 0.702$) rank highest because their betweenness term aligns with fragmentation (the articulation term is zero; Section~\ref{sec:6.2}); among learned models, pure neural rankers collapse ($\le 0.334$), while hybrids retain robustness ($\rho = 0.585$). On unfamiliar topologies like the five system models, learned rankers transfer zero-shot at about $0.81$ against $0.526$ for the training-free baseline. Still, active-stratum agreement is weak ($\rho_{>0} \le 0.342$), and the result rests on five models by one author.

\noindent\textbf{Mitigating Alert Fatigue with a Two-Tiered Triage Protocol.} Using a top-20\% threshold on the direct-dependent count (\texttt{InDeg}) recovers about half of the true top-20\% set on $I^*$ ($0.49$), while the rest of the flagged items are not in that set; the best learned ranker does no better (\texttt{GAT-P-QoS}, $0.48$). Figure~\ref{fig:recall} shows the trade-off: recovering 80\% of the critical set takes the top 45\% by \texttt{InDeg} ($0.83$) or the top 40\% by \texttt{GAT-P-QoS} ($0.81$), \texttt{Topo-QoS} does not reach this level within the top 50\%, and no predictor reaches 90\% within the top 50\%. To catch most critical components, a gate would need to flag nearly half the system, making these rankers unsuitable as automated pass/fail filters. In a system with over 100 services, flagging 40--50 would overwhelm developers with alerts.

To operationalize these rankings constructively, we propose a conceptual \emph{two-tiered triage protocol} as an architecture inspection heuristic, rather than an automated blocking gate. We emphasize that this protocol is an architectural proposal requiring human-factors and operational workflow validation before industrial adoption:
\begin{enumerate}\tightlist
    \item \textbf{Tier 1 (Commit-stage triage):} When reviewing pull requests, compute the direct-dependent count (about 11~ms, an estimated 0.086~mWh, 0.31~J) and the rate-weighted first-order expansion (Eq.~\eqref{eq:rate-expansion}; about a millisecond; an exploratory result, not confirmed on new data). Show the top 5 components by each as an informational note in the pull request review. This highlights potential cascade risks for peer review without blocking developers or causing alert fatigue.
    \item \textbf{Tier 2 (Staging and sprint verification):} During nightly builds or sprint architecture reviews, run the simulators on the Tier-1 shortlist within a fixed inspection budget, such as the ten highest-ranked services, and reserve redundant broker routing or chaos fault injection for the components the simulation confirms.
\end{enumerate}

\noindent\textbf{Cost and Green CI/CD.} As shown in Table~\ref{tab:cost-ll}, the count is the cheapest ranker, followed by a single pass of $I^*$. Where the reachability ranking is wanted, running $I^*$ or counting dependents is simpler and cheaper than any learned approximation. The same holds for the queue-flow simulator, where the rate-weighted expansion replaces an estimated $355.6$~Wh ($12.7$ CPU-hours at $28$~W TDP) of simulation for the corpus with a computation of milliseconds. From a Green CI/CD perspective \cite{schwartz2020greenai,verdecchia2023greenai,calero2015green}, training-free dependency analysis is therefore the lower-energy choice at both commit and staging time. The energy figures are estimates derived from processor TDP, not measurements (Section~\ref{sec:threats}).

\subsection{Threats to Validity}
\label{sec:8.3}
\label{sec:threats}

\noindent\textbf{Construct validity and oracle circularity.} All labels are simulated, and no ranker is validated against observed failures in physical deployments. We conducted no empirical fault injection (e.g., chaotic network partitions, process crashes, or disk exhaustion) on running distributed clusters. Because all rankers and references are evaluated against simulator-generated labels, the findings establish what can be predicted within the evaluated simulation framework, not what necessarily predicts real-world failures; external validation remains necessary. Discrete-event simulations omit complex real-world distributed runtime dynamics: kernel TCP buffer bloat, socket starvation, thread pool exhaustion, garbage collection freezes, asymmetric network partition drops, and cascading retry storms. In physical deployments, such dynamics can induce non-local, non-monotonic cascade failures: for example, a low-degree peripheral logging or monitoring service that encounters a slow disk or socket buffer bloat can cause upstream worker threads to block on synchronous backpressure, exhausting connection pools across the cluster and precipitating a total system outage. In such scenarios, physical failure impact decouples from structural graph degree, and training-free topological rankings will misestimate criticality. Evaluating SaG under live physical fault injection is therefore indispensable to establish whether structural rankings remain effective when nonlinear transport dynamics dominate. The circularity between the primary oracle and the rankers is analyzed in Section~\ref{sec:4.4}: the dependency counts are references for $I^*$, the rate-weighted expansion is a reference for $I_{\text{dyn}}$, closed-form centrality is term-aligned with $I_{\text{comp}}$, and the learned rankers inherit part of the overlap through their degree features, which ablation experiments show they depend on. Inert components are separated by construction, which is why $\rho_{>0}$ is reported beside $\rho$. We decided to reclassify the counts as references after all results were finalized, and this change did not affect any numbers. The two other oracles bound, but do not remove, the threat: $I_{\text{dyn}}$ shares the topology and the first-order effect, and $I_{\text{comp}}$'s weights encode a declared rather than an elicited priority vector. No learned ranker exceeded the analytical references on any simulator: the learned queue-flow approximation outperformed only the unweighted expansion, and the rate-weighted expansion, itself a reference for $I_{\text{dyn}}$, exceeded it. More fundamentally, all three oracles are well approximated by low-order functions of the dependency graph: a first-order expansion recovers $0.808$ of $I^*$ and a rate-weighted one $0.830$ of $I_{\text{dyn}}$, and $I_{\text{comp}}$'s terms track degree and betweenness. The benchmark therefore cannot exhibit a regime in which learning exceeds an analytical ranking aligned with the simulator, and the absence of such a regime here is a property of these oracles, not evidence that none exists. Representation and direction were confounded for the learned rankers, because forward message passing on the raw multigraph never reaches Applications. A reverse-edge control (Amendment~16) separates them: direction accounts for $+0.041$ of the $+0.113$ gain (not significant), and the derived graph adds $+0.072$ beyond it (Holm $p = 0.014$). The control shares one set of convolution weights across both directions; a direction-typed variant was not tested. The evaluation is confined to Applications, so dependency Rules~2--4 and~6, which govern brokers and hosts, are untested.

\noindent\textbf{Internal validity, reproducibility, and drift.} No ranker reads simulator output, which regression tests verify; the raw-graph learners do read the structural edges the oracles traverse, which is an overlap of inputs, not of labels. We held model capacity, depth, and early stopping constant across comparison arms. The registered selection rule was not applied to the published learned results, a deviation disclosed in Section~\ref{sec:6.3}; a post hoc sensitivity check applies it to \texttt{HGT-QoS} and \texttt{GAT-P-QoS} (Section~\ref{sec:rq2}), and every other statement regarding a learned ranker is conditional on one fixed configuration. The learned rankers are also seed-sensitive. Across the five seeds of a fold, the mean within-fold standard deviation of $\rho$ is $0.099$ for \texttt{HGT-QoS}, $0.254$ for \texttt{HGT-P-QoS}, $0.024$ for \texttt{GAT-QoS} and $0.030$ for \texttt{GAT-P-QoS}, and single \texttt{HGT} seeds differ from others in the same fold by more than $1.0$. These are runs that converge to a ranking anti-correlated with the oracle: one of 60 \texttt{HGT-QoS} seed runs (Telecom RAN) and four of 60 \texttt{HGT-P-QoS} runs (ATM, Industrial SCADA, IoT) have $\rho < 0$, against none for either GAT. They are kept in the per-seed means, as the plan registers, so the \texttt{HGT} rows reflect training instability as much as typing. Averaging the five seeds' \emph{predictions} instead of their $\rho$ values raises every learned ranker, most of all the unstable ones (\texttt{HGT-P-QoS} from $0.514$ to $0.618$); the tables report the registered statistic, the mean of per-seed $\rho$. Across revision cycles and compute devices, learned cells drifted by up to $0.172$ ($\pm 0.041$ on \texttt{HGT-QoS}), more than several effects this paper reports (the primary contrast, $+0.069$; the QoS main effect, $+0.073$; the typing effects, $-0.014$ and $-0.036$). Differences between learned rankers smaller than this drift should not be interpreted, whatever their nominal $p$-value. For that reason, every learned cell in Tables~\ref{tab:hybrid}, \ref{tab:contrasts_matched} and~\ref{tab:system_models_transfer} is reported from one named CPU sweep whose per-seed logs reproduce the published mean exactly, the sensitivity verification sweep re-ran every learned comparator to an exact match, and a hierarchical bootstrap that resamples seeds within folds widens the learned rows' intervals only slightly. The Connectivity Degradation Index samples nodes with hash-dependent tie-breaking, so \texttt{PYTHONHASHSEED=0} is fixed. We reconcile all reported values mechanically against released artifacts.

\noindent\textbf{External validity and the single-modeler threat.} Synthetic topologies come from a single generator family, which may induce parametric regularities not representative of heterogeneous industrial architectures. The five system models are hand-authored approximations (22--41 Applications) of open-source projects, each written by the first author from public documentation. All five RQ3 results are exposed to this threat, and it is not mitigated: no second modeler authored any model independently, and no inter-modeler reliability or agreement metric is reported. The system models also differ structurally from the synthetic folds: a larger share of their Applications has zero simulated impact, and their fan-in is more concentrated, favoring \texttt{Reach} and inflating full-population $\rho$. Furthermore, two of the five (Train-Ticket and Online Boutique) are synchronous RPC systems re-expressed as asynchronous publish--subscribe meshes by decomposing each RPC call into reciprocal request and reply topics mediated by broker intermediaries. While this translation faithfully mirrors bidirectional dataflow, mapping synchronous request--reply call graphs into decoupled pub-sub event topics may introduce semantic distortions into dependency relations, because it neglects synchronous blocking, client-side timeouts, and upstream thread starvation. We did not evaluate architectures with tens of thousands of components; we timed the counting path up to $10{,}000$ components (Section~\ref{sec:rq4}), and we did not evaluate the learned rankers or the oracles. We did not reproduce published learned criticality models (FINDER, DrBC) because they do not support typed multigraphs or pub-sub semantics.

\noindent\textbf{Sustainability and energy estimation validity.} Energy figures (Section~\ref{sec:rq4}) are wall-clock time multiplied by the processor's $28$~W base power (\path{reproduce/energy_estimate.py}), not readings from RAPL counters or power meters. They ignore frequency scaling, turbo power above base (up to $64$~W on this processor), DRAM and idle power, and attribute whole-package power to single-threaded work. They support order-of-magnitude comparisons between milliseconds and hours of computation, not energy or emissions accounting.

\noindent\textbf{Conclusion validity.} The only confirmatory results are the plan's two co-primary contrasts, both null (Section~\ref{sec:6.3}). Everything else, including the two hybrid contrasts, is registered secondary or exploratory and was designed after the primary null was known. LOSO folds share ten of eleven training scenarios, so the Wilcoxon $p$-values are nominal and anti-conservative; the Nadeau--Bengio corrected test, which accounts for the overlap, leaves the hybrid contrasts significant and the primary null. For training-free rankers, the folds are simply twelve scenarios from one generator, so the effective sample is small, and with twelve folds a bootstrap CI over folds is coarse; over five system models it is indicative only. Equivalence, which a claim that one ranker ``matches'' another requires, is not established for any pair at $\pm 0.05$; with twelve folds the study is underpowered for equivalence at that margin (the $90\%$ interval of the per-fold difference between \texttt{GAT-P-QoS} and \texttt{InDeg} is $\pm 0.076$). Results are also sensitive to how folds are weighted: weighting by $|V_{\text{app}}|$ raises \texttt{Topo-QoS} to $0.596$, level with the raw-graph learned rankers ($0.595$--$0.606$).

\subsection{Limitations and Future Work}
\label{sec:8.4}
\label{sec:limitations}

Five directions follow from the study's central question, in order of priority:
\begin{enumerate}\tightlist
    \item \textbf{Validation against real failures:} controlled fault injection on ROS~2, Kafka and MQTT deployments (for example with Chaos Mesh or ChaosBlade), reference systems with known faults such as Train-Ticket \cite{zhou2018trainticket}, and incident data from industrial publish--subscribe systems. This should be coupled with runtime distributed tracing standards (e.g., OpenTelemetry, W3C Trace Context) to empirically validate whether static declared dependency paths faithfully reflect dynamic runtime message flow trajectories under normal and degraded conditions.
    \item \textbf{Infrastructure and broker validation:} extending cascade-impact evaluation beyond Applications to message brokers, topics, and compute hosts (evaluating Rules~2--4 and~6), which were outside the Application-scoped evaluation of this study.
    \item \textbf{Independent modelers:} replication of the five system models by additional modelers, with inter-modeler agreement reported.
    \item \textbf{Alternative impact models:} testing whether the conclusions hold for simulators with different failure mechanisms, including synchronous call semantics, which the current dependency rules do not model, and oracles with non-first-order mechanisms such as backpressure onto publishers, retry amplification and heterogeneous service capacity, where an aligned analytical approximation may not exist.
    \item \textbf{When learning exceeds analytical methods:} identifying impact-generation mechanisms whose predictive signal is not captured by explicit dependency structure. This includes learned corrections on top of the rate-weighted approximation, learned approximations that receive the same rate and payload information as the analytical formulas, and a confirmation corpus generated after the analysis is frozen.
\end{enumerate}
Further extensions are automatic extraction of architecture graphs from ROS~2 launch files, Kubernetes manifests and Helm charts; integration with service mesh telemetry and distributed tracing (e.g., OpenTelemetry, Jaeger) for runtime dependency drift detection; hardware-measured energy accounting (for example via RAPL); a queue-flow run with QoS policies disabled; a tie-aware listwise loss with scenario-level validation; a full hyperparameter search for every learned model; and validation of the proposed explanation layer.

\section{Conclusion}
\label{sec:9}

This paper presented Software-as-a-Graph (SaG), a pre-deployment framework that derives explicit dependency graphs from publish--subscribe deployment manifests and supports analytical, hybrid, and learned approaches to cascade-impact ranking. Using twelve synthetic architectures, three failure simulators and five stylized models of open-source systems, the study examined when graph learning improves on rankings derived directly from explicit architectural dependencies. The primary registered contrast was null, and the findings below are registered secondary or exploratory.

For the reachability and queue-flow simulators, explicit dependency representations provided most of the predictive signal. Attention-based learners benefited from the derived dependency graph ($\rho = 0.748$ vs.\ $0.635$ on the raw multigraph), but simple analytical rankings built on the same dependencies were not distinguishable from, or exceeded, the learned models. Counting direct dependents ($\rho = 0.764$) was not statistically distinguishable from the best learned model on the reachability simulator ($0.748$; equivalence at $\pm 0.05$ not established). On the expensive queue-flow simulator, a rate-weighted first-order approximation computed in milliseconds ($0.830$) exceeded a learned approximation trained on $12.7$ CPU-hours of simulation labels ($0.799$; exploratory). In this corpus, representation choice mattered more than model complexity, and the learned gain from the derived graph survives a control that passes raw-graph edges in both directions ($+0.072$, Holm $p = 0.014$).

Learning added value only relative to a weak comparator. Hybrids that correct a closed-form prior significantly outperformed the training-free baseline, which they nest and which is the weakest analytical ranker, also after its defect was corrected, but not their own base learners; and learned models transferred zero-shot to unfamiliar architectures better than that baseline ($\approx 0.81$ vs.\ $0.53$). In both cases, however, dependency-based references remained competitive or stronger, and ordering among components that actually propagate failures remained weak.

These results have implications for both research and practice. For researchers, they show the importance of evaluating graph-learning approaches against analytical alternatives aligned with the simulator, and of distinguishing prediction from restatement of a simulator's rule. For practitioners, they suggest that training-free dependency analysis provides effective and inexpensive support for prioritizing architectural review. Learned models can be expected to add value only where no analytical approximation aligned with the simulator is available. All three simulators studied here admit such an approximation, so this corpus could not exercise that condition, and no regime was found in which learning exceeded it.

These findings concern simulated failures on synthetic architectures and single-modeler system models, and their validation against real outages is the natural next step (Section~\ref{sec:limitations}). More broadly, the study suggests that the central challenge in architecture-level cascade-impact analysis is not selecting increasingly sophisticated learning algorithms, but deriving meaningful dependency representations and understanding when learning adds value beyond them. By making this comparison explicit and by releasing a reproducible benchmark with reconciled results, Software-as-a-Graph provides a foundation for more principled evaluation of analytical and learned methods for pre-deployment architecture analysis.
