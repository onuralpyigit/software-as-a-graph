\title{Software-as-a-Graph: When Does Graph Learning Improve
  Cascade-Impact Ranking in Publish--Subscribe Systems?}

\author[itu]{Ibrahim Onuralp Yigit\corref{cor1}}
\ead{yigiti@itu.edu.tr}
\author[itu]{Feza Buzluca}

\cortext[cor1]{Corresponding author}

\begin{abstract}
Publish--subscribe middleware obscures failure propagation, which architects must assess before deployment, without telemetry. Graph learning has been applied to component criticality, but it is unclear whether its accuracy comes from the learning algorithm or the dependency representation. We present Software-as-a-Graph (SaG), which derives explicit dependency graphs from declared publish--subscribe architecture models, and compare analytical, hybrid, and learned rankers on twelve synthetic architectures, three failure simulators, and five stylized models of open-source systems. A reference criterion separates rankings that restate a simulator's propagation rule from those that predict it.

On a reachability simulator, graph attention on the derived dependency graph reaches Spearman's $\rho = 0.748$, $+0.072$ above the same model with reverse edges on the raw multigraph, also under sum aggregation; the registered co-primary contrasts on the raw multigraph were null. Counting direct dependents ($\rho = 0.764$), that is, afferent coupling, is not significantly different from the learned model, which approaches it as training architectures are added. For a queue-flow simulator requiring $12.7$ CPU-hours of labeling, a rate-weighted first-order approximation reaches $\rho = 0.830$ in milliseconds, above a gradient-boosted approximation trained on its labels ($\rho = 0.799$) and rate-fed graph networks; learners started from the formula do not improve on it.

Because these simulators propagate failures to first order by construction, the study shows when learning is unnecessary, not when it helps: representation mattered more than model complexity. Learned rankers should be evaluated against references aligned with the simulator, and training-free dependency analysis supports low-cost pre-deployment review.

\end{abstract}

\section{Introduction}
\label{sec:1}

\subsection{Motivation and Problem}
\label{sec:1.1}

Large distributed systems increasingly use asynchronous publish-subscribe (pub-sub) middleware: ROS 2 for autonomous driving \cite{macenski2022robot}, Apache Kafka for enterprise event streams \cite{kreps2011kafka}, DDS in cyber-physical systems \cite{omg2015dds}, MQTT in IoT \cite{oasis2019mqtt}, and cloud-native microservices \cite{dragoni2017microservices,newman2015building}. Pub-sub separates producers and consumers in space, time and synchronization \cite{eugster2003faces}; components communicate via topics and brokers, and Quality-of-Service (QoS) policies set at deployment control reliability, durability, priority and deadlines. This decoupling also hides how failures spread. Outages and backpressure propagate through brokers, shared topics, colocated hosts and shared libraries, in sequential cascades (a failed publisher starves its subscribers, or a slow subscriber fills a broker queue) and in simultaneous blasts (a library crash takes down every service that uses it), much as overload cascades through complex and interdependent networks \cite{motter2002cascade,buldyrev2010cascade}. Neither kind is visible in architecture diagrams or call graphs. Fault prevention and architecture evaluation belong to design time \cite{avizienis2004basic,bass2012software}, before deployment, when no telemetry exists, so architects must identify, from the declared architecture alone, the application services whose failures have the greatest cascading impact.

Current practice leaves a gap between service-level analysis and system dependability. Architectural properties arise from how components interact rather than from any single component \cite{perry1992foundations}, and architectural smells are invisible at the level of individual modules \cite{garcia2009catalogue}: a system can have no defect in any service yet fail through hidden single points of failure or mismatched QoS contracts. The Architecture Tradeoff Analysis Method (ATAM) relies on manual input \cite{kazman1998atam}, static code analysis inspects services in isolation \cite{sonarsource2024clean,chidamber1994metrics}, and chaos engineering \cite{basiri2016chaos}, fault injection \cite{meiklejohn2021service} and dependency tracing \cite{yu2021microrank} require a running system and considerable computation \cite{verdecchia2023greenai,schwartz2020greenai}. Graph representations have been used for reliability and defect analysis \cite{yacoub2002reliability,zimmermann2008predicting}, and graph learning has recently been applied to network criticality \cite{fan2020keyplayers,fan2019learning} and microservices \cite{khodabandeh2025linkpred}. It remains unclear whether such models' performance stems from the learning algorithm or from the dependency representation it reads, and whether and when graph learning adds measurable value beyond analytical methods based on the same dependencies. Software-as-a-Graph (SaG) addresses this question by deriving explicit dependency graphs from declared publish--subscribe architecture models and enabling a controlled comparison of analytical, hybrid, and learned approaches to cascade-impact ranking before deployment.

\subsection{The Software-as-a-Graph (SaG) Approach}
\label{sec:1.3}

SaG models an event-driven architecture as a typed, directed multigraph over Applications, Brokers, Topics, Execution Hosts and Shared Libraries (Figure~\ref{fig:1}), derives an explicit \texttt{DEPENDS\_ON} dependency graph through publish--subscribe rules (Section~\ref{sec:3.3}), and supports analytical, hybrid and learned cascade-impact rankings on it (Sections~\ref{sec:4} and~\ref{sec:6.2}). Labels come from three simulators on the raw topology that encode different failure notions: structural reachability ($I^*$), discrete-event queue saturation ($I_{\text{dyn}}$) and multi-criteria fragmentation ($I_{\text{comp}}$) (Section~\ref{sec:4.3}). Because simulators and rankers read the same architecture, some analytical rankings restate a simulator's rule; a reference criterion (Section~\ref{sec:4.4}) treats these as analytical truncations of the simulation rule and reports them as references rather than predictors, so circular agreement is not mistaken for predictive skill. The reachability simulator is fast, serving to calibrate the method; the queue-flow simulator models message rates and queues and costs hours to run, but because it propagates no failure beyond one hop by construction, a closed-form first-order approximation of it is to be expected (Section~\ref{sec:4.3}).

\subsection{Findings in Brief}
\label{sec:1.findings}

Explicit dependency representations provide most of the predictive signal for the reachability and queue-flow simulators.

\emph{Making dependencies explicit enables graph learning.} On the raw multigraph every relation points away from Applications, so message passing never reaches the scored nodes, and the registered co-primary contrasts (a heterogeneous graph transformer, with and without the QoS channel, against the training-free baseline on that graph) were null (QoS-weighted: $\Delta\rho = +0.069$, $p = 0.266$). On the dependency graph, a graph attention network (\texttt{GAT-P-QoS}) reaches Spearman $\rho = 0.748$ against the reachability simulator, against $0.635$ on the raw multigraph. Neither edge direction ($+0.072$ over a GAT that passes every raw edge both ways, Holm $p = 0.014$) nor the input features that compute part of the simulator account for the gain: with all of them removed, the dependency-graph GAT beats an equally stripped reverse-edge control by $+0.231$ (Holm $p = 0.0068$). Nor does the attention aggregator: with sum aggregation on both graphs, which can count neighbors, the dependency graph still wins by $+0.239$ (12 of 12 folds, Holm $p = 0.0015$).

\emph{The same representation yields analytical rankings that no learned model significantly exceeded.} Counting direct dependents, publish--subscribe afferent coupling, reaches $0.764$, not significantly different from the best learned model (equivalence not established). On the queue-flow simulator ($12.7$ CPU-hours to label the corpus), a rate-weighted first-order approximation reaches $0.830$ in milliseconds; a gradient-boosted approximation trained on the simulator's labels reaches $0.799$, graph networks given the same declared rates at most $0.665$, and learners that start from the formula do not improve on it: as an extra input it leaves a gradient-boosted model at its value, and as a prior it leaves a graph attention network below it ($-0.018$).

\emph{Against afferent coupling, no learned model showed additional skill.} The comparison that matters in practice is between a learned ranker and the dependency count an architect can compute directly; on the reachability simulator they are not significantly different, and under the registered nested selection protocol the learner falls further behind. The registered training-free baseline, QoS-weighted betweenness, is weaker: hybrids that correct it beat it ($+0.103$ and $+0.130$) but not their own base learners, and learned models transfer zero-shot better than it, while dependency counts rank higher still and ordering among active components remains weak. With fewer training architectures the dependency-graph learners were further from the dependency count, and the gap narrowed from $0.160$ to $0.017$ as their training set grew to eleven architectures, without closing (Section~\ref{sec:rq2}). In practice, the results favor training-free dependency analysis for routine use: it needs no training and runs in milliseconds. On $I^*$, recovering 80\% of the critical set requires reviewing about 40--45\% of Applications, so rankings suit prioritized review rather than blocking gates (Section~\ref{sec:8.1}); on $I_{\text{dyn}}$, the rate-weighted reference reaches 81\% recall within a 20\% review budget.

\subsection{Research Questions}
\label{sec:1.4}

Knowing when learning is unnecessary is as useful as knowing when it succeeds. Because the three simulators studied here are dominated by first-order propagation by construction, this study answers the title question for that regime only: it tests whether learning exceeds aligned analytical truncations of such simulators, and it cannot characterize the regimes in which learning would exceed them, which require simulators with non-first-order mechanisms (Section~\ref{sec:limitations}). Software engineering research has repeatedly shown that simple metrics can match more complex models when the right information is available \cite{zimmermann2008predicting,premraj2011network,hellendoorn2017deep,errica2020fair}. We therefore evaluate learned models against analytical rankings derived from the same dependencies:

\begin{itemize}\tightlist
\item \textbf{RQ1 (Ranking accuracy):} \emph{How accurately do analytical baselines, hybrid models, and learned approaches rank components by cascading-failure impact on unseen architectures, and can learned models exceed analytical truncations of the simulator's propagation rule?}
\item \textbf{RQ2 (Sources of predictive performance):} \emph{At matched model capacity, which factors contribute most to ranking performance: the dependency representation, degree information, relation typing, QoS information, the aggregator, the model family, or the number of training architectures?}
\item \textbf{RQ3 (Transfer):} \emph{How well do learned models trained on synthetic architectures transfer zero-shot to stylized models of five open-source systems, and does their ordering of components that actually propagate failures hold?}
\item \textbf{RQ4 (Cost):} \emph{What do analytical and learned approaches cost at CI/CD time in latency and estimated energy, and how does this compare with running each simulator directly?}
\end{itemize}

The evaluation follows an analysis plan pre-specified in the replication repository. Only its two co-primary contrasts are confirmatory, and both were null; the headline findings above are registered secondary or exploratory (Section~\ref{sec:6.3}).

\subsection{Contributions}
\label{sec:1.5}

\begin{enumerate}\tightlist
    \item \textbf{Dependency derivation for publish--subscribe architectures} (Section~\ref{sec:3}): typed rules that derive explicit dependency graphs from declared architecture models. The Application--Library projection evaluated here (Rules~1 and~5) extends the Application-level rule of \cite{yigit2025graph} with library-mediated dependencies; four infrastructure rules are formalized but not evaluated.
    \item \textbf{An evaluation guideline for simulator-labeled benchmarks} (Section~\ref{sec:4.4}): an order-$k$ reference criterion, truncating a simulator's own computation, against which learned rankers are compared to separate genuine cascading prediction from first-order topological rule restatement.
    \item \textbf{A controlled comparison of analytical, hybrid, and learned rankers} (Sections~\ref{sec:rq1}--\ref{sec:rq3}) that separates the effects of representation, degree information, relation typing, QoS information and model family.
    \item \textbf{Analytical and learned approximations of a queue-flow simulator} (Section~\ref{sec:rq1}): a rate-weighted first-order approximation (Eq.~\eqref{eq:rate-expansion}) of a simulator that is first-order by construction, compared with tabular and graph-learned approximations given the same declared rates.
    \item \textbf{A reproducible benchmark, cost analysis and practitioner guidance} (Sections~\ref{sec:6.1}, \ref{sec:rq4} and~\ref{sec:8.1}) over twelve synthetic architectures labeled by three simulators and five system models labeled by the reachability simulator.
\end{enumerate}

A previous conference paper \cite{yigit2025graph} introduced the publish--subscribe multigraph, the Application-level subscriber-to-publisher dependency (Rule~1 of Table~\ref{tab:2}) and a closed-form betweenness--articulation score similar to the training-free baseline (Eq.~\eqref{eq:topo}), validated against a reachability-loss simulation. Everything else here is new: the Library and infrastructure rules, QoS weighting, the reference criterion, the learned and hybrid rankers, the simulator approximations, leave-one-scenario-out (LOSO) cross-validation and zero-shot evaluation, the second and third simulators, the matched controls and the cost analysis. Under this broader evaluation, the closed-form score family of \cite{yigit2025graph} is the weakest analytical ranker, and the present results supersede that paper's implicit recommendation of it.

Section~\ref{sec:2} reviews related work, Sections~\ref{sec:3} and~\ref{sec:4} present the model and the rankers, Sections~\ref{sec:6} and~\ref{sec:7} the evaluation, Section~\ref{sec:8} the discussion and threats, and Section~\ref{sec:9} concludes.

\section{Related Work}
\label{sec:2}

\subsection{Dependability and Failure-Impact Analysis of Distributed Systems}
\label{sec:2.1}

Runtime dependability methods such as broker clustering, backpressure, autoscaling, failover and chaos engineering \cite{basiri2016chaos} require a running cluster and significant computing resources, a concern in green software engineering \cite{verdecchia2023greenai,schwartz2020greenai}. Pre-production methods such as service-level fault injection \cite{meiklejohn2021service} and microservice dependency localization with PageRank (MicroRank \cite{yu2021microrank}) are lighter, and benchmark platforms with cataloged, replayable faults such as Train-Ticket \cite{zhou2018trainticket} measure failure impact on a running deployment. Architecture-based reliability prediction has a long history, from Cheung's Markov model of control transfer between components \cite{cheung1980user} to Yacoub and Ammar \cite{yacoub2002reliability}, who combined component dependency graphs with complexity and failure severity to rank components by risk; state, path and additive reliability models \cite{gosevapopstojanova2001architecture} and the Palladio Component Model \cite{becker2009palladio} are other classic examples.

Error propagation has also been analyzed at the architecture level \cite{abdelmoez2004error,popic2005error,cortellessa2007modeling,hiller2004epic}, and safety-critical practice uses model-based failure analysis such as HiP-HOPS \cite{papadopoulos1999hiphops} and the AADL Error Model Annex \cite{delange2014aadl}. These frameworks derive propagation paths from structural descriptions, as SaG's dependency projection does, but they need failure-mode annotations, propagation probabilities or operational profiles, which deployment manifests do not carry.

Telemetry-based methods localize faults in running microservices, among them Seer \cite{gan2019seer}, Sage \cite{gan2021sage}, MicroRCA \cite{wu2020microrca} and GNN-based root-cause frameworks such as Eadro \cite{lee2023eadro}, reviewed by Zhang et al.~\cite{zhang2024failurediag}. All need data from a live system; SaG works before any code is run. Production traces show that real dependency graphs are large and dynamic \cite{luo2021alibaba}, and that metastable failures are sustained by load feedback rather than by the structure that failed \cite{bronson2021metastable,huang2022metastable}, which a structural ranking cannot see. SaG's focus is close to change impact analysis \cite{bohner1996impact} and microservice dependency management \cite{esparrachiari2018tracking}, and ranking by impact relates to learning-to-rank defect prediction \cite{yang2015ltr}.

Failure-impact rankings are often evaluated against a simulator rather than observed outages, so a ranking may agree with a simulator because it encodes the simulator's propagation rule rather than because it predicts its behavior. The concern is not new: simulation methodology treats a model used as ground truth as something to be validated \cite{sargent2013verification}, a node's spreading influence is predicted by a simple structural index, its k-shell position \cite{kitsak2010influential}, and learned models exploit shortcuts that encode the labeling rule \cite{geirhos2020shortcut,kapoor2023leakage}. What we add is an operational check for simulator-labeled ranking benchmarks (Section~\ref{sec:4.4}).

\subsection{Static Analysis and Architectural Dependency Metrics}
\label{sec:2.2}

Static code analysis tools such as SonarQube \cite{sonarsource2024clean} measure complexity \cite{mccabe1976complexity}, cohesion and coupling \cite{chidamber1994metrics} within individual services to identify defect-prone modules \cite{nagappan2005static,zimmermann2007predicting}. In defect prediction, Zimmermann and Nagappan \cite{zimmermann2008predicting} applied network analysis to dependency graphs, and Premraj and Herzig's replication \cite{premraj2011network} found that simple code and coupling metrics often perform as well. Such analysis cannot see inter-service messaging, broker saturation or cross-host propagation. Architecture recovery tools rebuild system structure from code \cite{bushong2021static}, including microservice architecture reconstruction tools such as MicroART \cite{granchelli2017microart}, and HAROS \cite{santos2019haros} and ROSDiscover \cite{timperley2022rosdiscover} recover the run-time architecture of ROS systems, the kind of extraction SaG would need on real systems. Architecture-level coupling metrics count a service's consumers: afferent coupling \cite{martin2003agile}, the Absolute Importance of the Service \cite{rud2006ais} and service fan-in \cite{bogner2017maintainability}. In publish--subscribe systems this count is a typed two-hop query (publisher to topic to subscriber), which SaG's dependency rules define; because it matches the reachability oracle's first propagation wave, this paper benchmarks it both as an established structural baseline and as an analytical reference (Section~\ref{sec:4.4}). Such analyses support the detection of anti-patterns \cite{garcia2009catalogue,taibi2018microservice} and architectural technical debt \cite{li2015technicaldebt} in CI/CD \cite{humble2010continuous}.

\subsection{Graph Learning on Dependency Structures}
\label{sec:2.4}

Closed-form indices \cite{freeman1977centrality,brandes2001faster,brin1998pagerank,newman2010networks}, including this study's training-free baseline, and cascade models of network robustness \cite{albert2000error,motter2002cascade,buldyrev2010cascade} assume homogeneous, usually undirected graphs, so a single untyped score mixes topics, libraries and hosts. Learned node-importance methods such as FINDER \cite{fan2020keyplayers}, DrBC \cite{fan2019learning} and PowerGraph \cite{varbella2024powergraph}, and learned approximations of betweenness and closeness \cite{maurya2021gnnbet}, also assume homogeneity; GENI \cite{park2019geni} estimates node importance on heterogeneous knowledge graphs. Closest to the present setting, InfGCN \cite{zhao2020infgcn} and RCNN \cite{yu2020rcnn} train node rankers on labels from simulated SIR spreading and report gains over centrality indices; neither compares the learner with a truncation of the simulated process itself, the comparison Section~\ref{sec:4.4} makes. Homogeneous GNNs such as GAT \cite{velickovic2018graph} ignore relation identity unless it is a feature, and softmax attention averages over neighbors and cannot count them, whereas sum aggregation can \cite{xu2019gin,corso2020pna}; message-passing GNNs are limited in counting substructures without explicit features \cite{chen2020can}. Because the main reference here is a neighbor count, this difference matters (Section~\ref{sec:rq2}). Heterogeneous GNNs such as HGT \cite{hu2020hgt} learn relation-specific transformations, but Lv et al.~\cite{lv2021revisiting} found that they often fail to beat well-tuned homogeneous baselines; relation-typed models that sum rather than attend, such as R-GCN \cite{schlichtkrull2018rgcn} and Lv et al.'s Simple-HGN, are not evaluated here (Section~\ref{sec:threats}). GNN rankings are also sensitive to splits and tuning \cite{shchur2018pitfalls}, and label propagation with shallow models can outperform GNNs \cite{huang2021combining}. Khodabandeh et al.~\cite{khodabandeh2025linkpred} use graph attention on microservice call graphs to predict upcoming interactions; we predict the effect of removing a node from a declared topology. Learned performance models such as DeepPerf \cite{ha2019deepperf} likewise approximate an expensive measurement or simulation, connecting to classic simulation metamodeling \cite{kleijnen2015design}, and performance engineering has long combined analytical models with machine learning, using the analytical model where it is accurate and learning only its residual \cite{didona2015enhancing}; SaG's hybrids and its learners started from Eq.~\eqref{eq:rate-expansion} follow that design. Where impact arises from interacting queues, learned models have succeeded without an analytical anchor: RouteNet \cite{rusek2020routenet} learns per-path delay and loss from simulated networks of queues and generalizes to unseen topologies, routing and traffic, the multi-hop regime that the simulators studied here do not implement (Section~\ref{sec:8.2}).

\subsection{Positioning of This Study}
\label{sec:2.5}

This study builds on findings that simple or tuned shallow methods can match deep learning at a fraction of its cost \cite{hellendoorn2017deep,errica2020fair,fu2017easy,majumder2018faster} and that network measures add little over simple coupling metrics \cite{zimmermann2008predicting,premraj2011network}. It differs from prior work in three ways: it derives explicit dependency graphs from publish--subscribe deployment manifests rather than starting from an existing architectural graph; it evaluates analytical, hybrid and learned rankers on the same representation and asks where their performance originates; and it applies an operational reference criterion to separate rankings that restate a simulator's rule from those that predict its outcomes. Rather than asking whether graph learning can rank cascade impact, it asks whether learning adds measurable value beyond analytical baselines derived directly from the explicit dependency structure.

\section{The Software-as-a-Graph (SaG) Architectural Model}
\label{sec:3}

Figure~\ref{fig:1} shows the SaG framework. The front end reads a declared architecture model (the components, topics, hosts and library links that Architecture-as-Code manifests declare; the models evaluated here are generated or hand-authored, and no manifest importer is evaluated), builds a typed multigraph, derives a logical dependency layer that makes failure paths explicit, and extracts typed node properties, so that analytical, hybrid and learned rankings are computed from the same representation and can be compared under identical dependency information.

\subsection{Multigraph Definition}
\label{sec:3.1}

A distributed system is described as a typed, weighted, directed multigraph
\begin{equation}
\label{eq:sag_multigraph}
\mathcal{G} = (V, E, \tau_V, \tau_E, w_V, w_E),
\end{equation}
where $V = V_{\text{app}} \cup V_{\text{broker}} \cup V_{\text{topic}} \cup V_{\text{host}} \cup V_{\text{lib}}$ holds the five entity types of Table~\ref{tab:1}, $\tau_V$ and $\tau_E$ assign entity and relation types, and $w_V, w_E \in (0, 1]$ weight entity criticality and connection strength; an entity's $w_V$ aggregates the QoS weights $w(t)$ (Section~\ref{sec:3.2}) of its topics (Supplementary Section~\ref{supp:weights}). The raw multigraph is $G_{\text{structural}}$; the analysis graph $G_{\text{analysis}}$ adds the derived \texttt{DEPENDS\_ON} edges (Section~\ref{sec:3.3}) and the node properties computed from them (Section~\ref{sec:3.5}). Supplementary Section~\ref{supp:notation} lists the notation.

\noindent\textbf{Scope.} The evaluation ranks \emph{Applications} only: microservice containers, service agents or communicating processes, the developer-authored code that changes in CI/CD. Brokers, Topics, Hosts and Libraries are modeled because failures propagate through them, but ranking them is a provisioning question rather than a commit-time one (Section~\ref{sec:limitations}).

\subsection{Quality-of-Service Link Weighting}
\label{sec:3.2}

A \texttt{RELIABLE} topic with \texttt{TRANSIENT\_LOCAL} durability couples services more strongly than a \texttt{BEST\_EFFORT} telemetry stream. Each topic $t$ therefore has a weight $w(t) \in (0, 1]$ combining its QoS policies (reliability, durability, priority) with payload size and publication frequency, with policy weights from an Analytic Hierarchy Process (AHP) \cite{saaty1980ahp} matrix (Supplementary Section~\ref{supp:ahp}). Declared QoS policies turned out to carry no measurable signal on either the reachability or the queue-flow simulator (Sections~\ref{sec:rq1} and~\ref{sec:rq2}); for $I^*$ this is largely fixed by design, because it barely reads QoS (Section~\ref{sec:4.3}). The dependency counts reported in this paper are unweighted.

\subsection{Logical Dependency Projection (\texttt{DEPENDS\_ON})}
\label{sec:3.3}

Structural edges do not show how failures spread: a subscriber depends on a publisher, but no edge joins them. SaG therefore derives \texttt{DEPENDS\_ON} edges from the dependent to the dependency (if the target fails, the source is affected) using the rules of Table~\ref{tab:2}. The resulting graph is the common input of the analytical, hybrid and learned rankers.

\begin{table}[htbp]

Rule~1 combines the topics $T$ connecting a pair by probabilistic union \cite{pearl1988probabilistic}, so multiple failure paths strengthen the connection; Rule~5 uses the harmonic mean $H(x, y) = 2xy/(x+y)$ \cite{hardy1952inequalities}. Rule~1 captures sequential cascades (a failed publisher starves its subscribers) and Rule~5 simultaneous blasts (a crashed library fails every Application using it); neither is stated explicitly in a manifest.

\noindent\textbf{Remark 1 (the dependency count is a typed two-hop count).} Let $G_{\text{flow}}$ be the Application--Library projection (Rules~1 and~5) and $v$ an Application. By construction,
\begin{equation}
\label{eq:indeg}
\texttt{InDeg}(v) \;=\; \bigl|\{\,u \neq v : \exists t \in V_{\text{topic}},\; (v, t) \in \texttt{PUBLISHES\_TO} \wedge (u, t) \in \texttt{SUBSCRIBES\_TO}\,\}\bigr|,
\end{equation}
because Rule~5 edges end at Libraries, so every edge into an Application is a Rule~1 edge, and parallel topics between a pair collapse into one edge. The right side is publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais}, a typed two-hop query on the raw multigraph; the projection defines which query to use (the equality holds exactly on all seventeen corpus graphs). The derivation adds value beyond this count: including Rule~5 raises the agreement of transitive reach with $I^*$ by $+0.058$ (9 of 12 folds, Holm $p = 0.0068$; Section~\ref{sec:rq1}). Because $I^*$'s first propagation wave matches this set (Section~\ref{sec:4.4}), \texttt{InDeg} and its transitive version \texttt{Reach} serve as both established structural baselines and first-order analytical references. The in-degree \emph{feature} the learners receive is the normalized in-degree on the full \texttt{DEPENDS\_ON} graph, where Rule~1 is also applied through \texttt{USES} chains of up to three hops (an Application inherits the publications and subscriptions of the Libraries it uses) and Libraries can be dependents; the \texttt{InDeg} reference counts direct subscriptions only. The two differ for 940 of the 1{,}321 Applications, with per-fold rank agreement $\rho = 0.55$--$1.00$ (Supplementary Section~\ref{supp:features}).

\subsection{Dual Graph Views}
\label{sec:3.4}

The \textbf{structural graph} $G_{\text{structural}}$ is the raw deployment topology; the \textbf{analysis graph} $G_{\text{analysis}}$ adds the \texttt{DEPENDS\_ON} edges and code metrics (Figure~\ref{fig:2}). Every ranker's node features are computed on $G_{\text{analysis}}$, and no ranker reads simulator output. The learners pass messages either over $G_{\text{structural}}$ or over the \texttt{DEPENDS\_ON} projection (the \texttt{-P} models), and the difference matters: on $G_{\text{structural}}$ every relation points away from Applications (\texttt{PUBLISHES\_TO}, \texttt{RUNS\_ON}, \texttt{USES}), so forward message passing never reaches them and forward GNNs collapse into per-node models over precomputed features. On the \texttt{DEPENDS\_ON} graph each Application receives messages from its dependents. Because the views also differ in edge direction, Section~\ref{sec:rq2} adds a raw-graph learner that passes every message in both directions, separating dependency semantics from direction.

\subsection{Typed Node Feature Encoding}
\label{sec:3.5}

All five entity types share 18 normalized metrics computed on $G_{\text{analysis}}$, including PageRank, reverse PageRank, betweenness, closeness, in- and out-degree, an articulation score, QoS and dependency weights, multi-path coupling, fan-out criticality and the Connectivity Degradation Index (CDI); type-specific blocks extend the vector to 19--25 dimensions (Applications and Libraries add a code-quality penalty and its four static-code inputs). The full schema is in Supplementary Section~\ref{supp:features}. Four centralities use QoS-weighted edges, so the QoS-off condition is not entirely free of QoS. Several features compute part of what the reachability simulator computes: in-degree and its QoS-weighted version $w_{\text{in}}$ are rank-correlated with \texttt{InDeg}, CDI is a removal-and-reachability computation, and multi-path coupling, reverse PageRank, fan-out criticality and the articulation score are also aligned with it. Every published learner reads these \emph{oracle-aligned} features and so inherits part of the oracle's circularity; Section~\ref{sec:rq2} reports learners with all of them removed.

\section{Ranking Methods, Simulation Oracles, and the Reference Criterion}
\label{sec:4}

The study compares analytical rankings derived directly from dependency structure (the training-free baseline \texttt{Topo-QoS} and the references of Section~\ref{sec:6.2}), hybrid methods that correct an analytical prior with a learned model, and learned methods: graph neural networks on the typed multigraph or the dependency graph, and gradient-boosted models on per-Application features (Figure~\ref{fig:engines}). Full hyperparameters and training commands are in the replication repository's experiment pages.

\subsection{Heterogeneous Graph Transformer and Attention Networks}
\label{sec:4.1}

The main learned ranker, \texttt{HGT-QoS}, is a three-layer Heterogeneous Graph Transformer \cite{hu2020hgt} (PyTorch Geometric \cite{fey2019fast}; hidden dimension $64$, four heads) with entity-specific input projections and type-parameterized attention per meta-relation (Supplementary Section~\ref{supp:hgt}). It passes messages over its input graph and its transpose: $G_{\text{structural}}$ for \texttt{HGT-QoS}, the \texttt{DEPENDS\_ON} projection for \texttt{HGT-P-QoS} (width $100$, keeping parameters within $1\%$). The homogeneous Graph Attention Networks (\texttt{GAT-QoS}, and \texttt{GAT-P-QoS} on the dependency graph) use three \texttt{GATConv} layers with four heads at a matched parameter budget and pass messages forward only, except the direction control \texttt{GAT-QoS-R}, which also passes every edge in reverse. Each edge carries a 16-dimensional vector (coupling weight, path count, a one-hot relation encoding and seven middleware QoS parameters) that is projected and added before attention. Because the vector encodes the relation, the ``untyped'' GAT receives relation identity as a feature, but this matters only where messages reach Applications (Section~\ref{sec:3.4}); on the dependency projection every edge carries the same relation.

\subsection{Prediction Head and Training Objective}
\label{sec:4.2}

A composite head predicts the simulated cascade impact, with an auxiliary head $\hat{a}_1$ regressing on $I^*_R$, the number of subscribers that the same simulator run marks as impacted (normalized like the main label). The training objective combines regression with listwise and margin-ranking terms:
\begin{equation}
\label{eq:loss_active}
\mathcal{L} = \text{MSE}(\hat{I}^*, I^*) + 0.5 \cdot \text{MSE}(\hat{a}_1, I^*_R) + 0.3 \cdot \mathcal{L}_{\text{rank}} + 0.1 \cdot \mathcal{L}_{\text{pairwise}},
\end{equation}
where $\mathcal{L}_{\text{rank}}$ is the Listwise Maximum Likelihood Estimation (ListMLE) loss \cite{xia2008listwise} over the permutation $\pi$ induced by the simulated labels,
\begin{equation}
\label{eq:listmle}
\mathcal{L}_{\text{rank}} = -\frac{1}{N}\sum_{i=1}^N \Big( \hat{s}_{\pi_i} - \log \sum_{j=i}^N \exp(\hat{s}_{\pi_j}) \Big),
\end{equation}
and $\mathcal{L}_{\text{pairwise}}$ is a margin-ranking loss with $\gamma = 0.05$. Tied labels (about 31\% of Applications have $I^* = 0$) enter $\pi$ in the generator's creation order; a node-order permutation control and a tie-aware variant of the loss, in which tied labels form groups that share one risk set, test whether this affects the results (Section~\ref{sec:rq2}).

Models are trained with AdamW ($\eta = 3 \times 10^{-4}$, weight decay $10^{-4}$) and cosine warm restarts for up to 300 epochs, with early stopping (patience 60) on a 20\% node-level validation split of the largest training scenario of each fold, over five fixed seeds. The split never touches the held-out scenario; a held-out validation scenario instead would remove one of the eleven training graphs and score early stopping on 26--300 Applications, and the registered nested protocol that does so is reported as a sensitivity check (Section~\ref{sec:rq2}). All reported evaluations are inductive under leave-one-scenario-out cross-validation. Hyperparameters and loss coefficients were fixed before the first sweep and kept across all experiments, rather than selected by the registered nested procedure (Section~\ref{sec:6.3}); no model family received a separate tuning budget.

\subsection{Simulation Oracles}
\label{sec:4.3}

Labels come from three failure simulators (``oracles'') that run on the raw multigraph $G_{\text{structural}}$ and define different notions of cascade impact rather than observations of real failures:
\begin{itemize}\tightlist
    \item \textbf{Reachability cascade oracle ($I^*$, primary):} crashes component $v$, propagates outages through dependent topics, brokers and links by breadth-first traversal, and computes the mean fractional feed loss across intact subscribers, with each topic's loss scaled by a declared, uncalibrated QoS severity ladder ($\times 1.2$ for \texttt{RELIABLE}, $\times 1.15$ or $\times 1.05$ for high or medium priority). A subscriber whose feed loss exceeds the propagation threshold ($0.2$) fails with a probability that is one in the first wave and decays by $0.15$ per later wave (floor $0.25$); these constants and the severity ladder are declared, not calibrated, and were not swept; the label averages five seeds of this stochastic propagation (pseudocode in Supplementary Section~\ref{supp:istar}). Disabling QoS scaling leaves the Application ordering largely intact ($\rho = 0.965$ across the twelve folds), and substituting durability-aware rescaling moves it less still ($\rho = 0.977$): $I^*$ is predominantly a topological reachability metric.
    \item \textbf{Queue-flow oracle ($I_{\text{dyn}}$):} a discrete-event SimPy \cite{team2020simpy} simulation of message rates, bounded subscriber queues and service contention that measures the drop in delivered message rate for surviving consumers, using declared publication rates and QoS contracts (history depth, reliability, deadlines, lifespan, priority) that $I^*$ ignores. It does not read declared payload sizes (every message has the same size), model brokers or network links, block publishers on full queues, or retry; a consumer that loses its inputs keeps publishing. Its first-order effect, consumers losing a failed publisher's messages, is therefore again subscriber loss, and by construction it propagates no failure beyond one hop. It labels all $1{,}321$ Applications (five seeds) in $12.7$ CPU-hours, against seconds for $I^*$, and agrees with $I^*$ at a mean $\rho = 0.711$. A single $I_{\text{dyn}}$ run agrees with another at $\rho = 0.43$--$0.96$ per fold; the five-seed mean used as the label has an estimated reliability of $r = 0.79$--$0.99$ (Spearman--Brown), so no ranker can agree with it by more than $\sqrt{r} \approx 0.89$--$0.996$ per fold, and every ranker in Table~\ref{tab:independent_oracles} stays below $r$, and therefore below $\sqrt{r}$, on every fold. The Spearman--Brown formula is an approximation for rank correlations, so these bounds are indicative.
    \item \textbf{Composite multi-criteria oracle ($I_{\text{comp}}$):} the composite multi-criteria failure simulator, run on all Applications, scores each removal as $I_{\text{comp}}(v) = 0.35\,\text{RL}(v) + 0.25\,\text{FR}(v) + 0.25\,\text{TL}(v) + 0.15\,\text{FD}(v)$ over reachability loss, fragmentation, throughput loss and flow disruption. The weights are declared and uncalibrated, and the sensitivity of ranker order to them was not tested, so $I_{\text{comp}}$ is a multi-objective stress test rather than a measure of subscriber loss; it is never a training label.
\end{itemize}

\subsection{Input--Label Separation and the Reference Criterion}
\label{sec:4.4}

No simulation output is used as an input (a regression test enforces this). Procedural separation does not remove construct overlap, however: a ranking may agree with a simulator because it reproduces the simulator's rule rather than because it infers impact from independent evidence.

\noindent\textbf{The reference criterion.} Let an oracle $O$ compute the impact of removing $v$ by propagating the failure in waves over its inputs, and let $T_k(O)$ be the same computation stopped after wave $k$. A ranking $R$ is an \emph{order-$k$ reference} for $O$, for $k \ge 1$ or $k = \infty$ (the cascade run to its fixpoint), if $R$ equals $T_k(O)$, computed from the inputs $O$ reads, after at most the following simplifications: (S1)~the expectation in place of $O$'s seed-dependent stochastic propagation; (S2)~omitting a severity rescaling that $O$ applies to each loss term; (S3)~omitting the mechanisms $O$ adds on top of propagation (queueing, drops, deadlines); (S4)~uniform weights in place of per-component rates or normalizations; and (S5)~the support of a wave (the number of affected components) in place of its weighted loss. Each simplification removes exactly one mechanism that the oracle definitions of Section~\ref{sec:4.3} state (seeded propagation, the severity ladder, queueing, per-topic rates and normalizations, the weighting of a wave's loss); none changes which components a wave reaches or the direction in which failures propagate. No other simplification is admitted: in particular, no change of propagation edges or direction, no path-based or spectral score in place of a wave, and no parameter of $R$ fitted to the output of $O$. Whether a ranking qualifies is therefore decided by derivation from the simulator's definition, not by its score, and the classification does not follow the scores: Eq.~\eqref{eq:rate-expansion} is a reference for $I_{\text{dyn}}$ but a predictor for $I^*$, which reads no rates, although it reaches $0.756$ on $I^*$; \texttt{Reach}, a reference, scores below the best learned predictor; and a GAT given the direct-dependent count as its prior ($0.763$) and the gradient-boosted queue-flow approximation ($0.799$) are predictors that score at the level of the corresponding references. For $I^*$, whose first wave reaches exactly the direct subscribers of the failed component, the first-order expansion (Eq.~\eqref{eq:analytic_istar}) is $T_1(I^*)$ under S1, S2 and S4 (equal publication rates, and no division of a subscriber's loss by its number of feeds), \texttt{InDeg} is its support (S5; Remark~1), and \texttt{Reach} is the support of the untruncated cascade, an order-$\infty$ reference (S1, S5). For $I_{\text{dyn}}$, the rate-weighted expansion (Eq.~\eqref{eq:rate-expansion}) is $T_1(I_{\text{dyn}})$ under S3 and S4, the delivered-rate loss after one wave without queueing. $I_{\text{dyn}}$ is a discrete-event simulation rather than a wave computation, but because it propagates no failure beyond one hop its whole effect is a single wave; Supplementary Section~\ref{supp:advisor-v6} derives Eq.~\eqref{eq:rate-expansion} from its delivery accounting. \texttt{Topo-QoS}, the hybrids and every learned ranker fail the definition and are \emph{predictors}. For $I_{\text{comp}}$ no ranking is a truncation, but its fragmentation and flow terms respond to removing high-degree and high-betweenness nodes, so \texttt{Topo-QoS} and raw degree are \emph{term-aligned} with it and read with the same caution.

A reference measures how much of $O$ its own rule recovers, a property of the oracle rather than predictive skill. Comparisons between a predictor and a reference are therefore descriptive anchors (how close a predictor comes to the oracle's own first-order rule), not registered contrasts, and the statement that no learned model significantly exceeded a reference is descriptive; the one exception, the exploratory paired comparison of Eq.~\eqref{eq:rate-expansion} with the learned queue-flow approximation, is flagged where it appears (Section~\ref{sec:rq1}). We defined the criterion post hoc, after simple dependency counts performed strongly; reclassifying them changed no number, but the criterion has not been applied to a corpus generated after the analysis was frozen (Section~\ref{sec:limitations}).

Learned methods are not references by this definition, but they are not less circular: they are fitted to the oracle they are scored against and read oracle-aligned features (Section~\ref{sec:3.5}). We therefore also report learners with those features removed and learners' agreement with $I_{\text{dyn}}$ after $I^*$ or the first-order term is partialled out (Section~\ref{sec:7}). Neither replaces validation against real failures (Section~\ref{sec:8.3}).

\section{Experimental Setup}
\label{sec:6}

The design asks whether ranking performance originates from the dependency representation or from the learning algorithm operating on it. If it arises from the representation, analytical and learned rankers built on that representation should perform similarly; if learning adds information, learned rankers should outperform analytical alternatives built on the same dependencies.

\noindent\textbf{Training-free baseline.} \texttt{Topo-QoS} is computed on the Application--Library \texttt{DEPENDS\_ON} graph (Rules 1 and 5):
\begin{equation}
\label{eq:topo}
\text{Topo-QoS}(v) = 0.6 \cdot \text{BT}_{w}(v) + 0.4 \cdot \text{AP}(v),
\end{equation}
where $\text{BT}_{w}$ is betweenness over edge distances $d(e) = 1/(w(e) + 10^{-6})$ and AP flags articulation points. Due to an implementation defect, the AP term is zero for every node: the scorer reads the articulation flag under a key (\texttt{ap\_c\_score}) that the cached metrics do not contain, and falls back to zero, so every table reports QoS-weighted betweenness alone. The defect slightly favors the baseline: restoring the term lowers \texttt{Topo-QoS} from $0.553$ to $0.533$, so it does not bias comparisons toward the learned models or the references. The hybrids' prior $p(v)$ inherits the defect. The registered contrasts stay against the registered value, because replacing a comparator after its contrasts were registered would be an undeclared deviation; Table~\ref{tab:hybrid} reports the corrected value beside it, and hybrids retrained on the corrected prior are compared with it in Section~\ref{sec:rq1} (Supplementary Table~\ref{tab:a16}). The comparator was fixed when the analysis plan was written, before the dependency counts had been analyzed, and continues the score family of \cite{yigit2025graph}; in hindsight, afferent coupling would have been the natural comparator, and it is reported beside the baseline as a reference.

\noindent\textbf{References.} Three training-free rankings restate the reachability oracle's propagation rule. The first is the post hoc first-order expansion of $I^*$ (Analytic $I^*$):
\begin{equation}
\label{eq:analytic_istar}
\hat{I}^*_1(v) = \sum_{t \in \text{pub}(v)} \frac{|\text{sub}(t)|}{|\text{pub}(t)|},
\end{equation}
where $|\text{pub}(t)| \ge 1$ for all topics published by $v$. The second is \texttt{InDeg}$(v)$, the number of direct dependents on the \texttt{DEPENDS\_ON} graph (Remark~1), and the third \texttt{Reach}$(v)$, the number of transitive dependents normalized by $|V| - 1$. For the queue-flow simulator $I_{\text{dyn}}$, the corresponding reference weights each term of Eq.~\eqref{eq:analytic_istar} by the topic's declared publication frequency $r_t$:
\begin{equation}
\hat{I}^{\mathrm{rate}}_{\mathrm{dyn},1}(v) \;=\; \sum_{t \in \mathrm{pub}(v)} \frac{r_t}{|\mathrm{pub}(t)|}\,\lvert \mathrm{sub}(t) \rvert.
\label{eq:rate-expansion}
\end{equation}
Here, $r_t$ is the declared publication rate (msg/s) of topic $t$. It is a first-order truncation of $I_{\text{dyn}}$, which reads the same rates, and was evaluated after the registered analyses (exploratory). \subsection{Metrics, Protocols and Statistics}
\label{sec:6.3}

\noindent\textbf{Metrics and protocols.} Every ranker is scored on the Application set $V_{\text{app}}$ with Spearman $\rho$ against each oracle, the active-stratum $\rho_{>0}$ over components with true impact above zero, and Overlap@$K$, the fraction of the true top-$K$ recovered by the predicted top-$K$ ($K \approx 20\%$ of $|V_{\text{app}}|$); PR-AUC, $F_1@\tau$ and nDCG@10 are in Supplementary Section~\ref{supp:identification}. Under LOSO, learned models train on eleven scenarios and are tested on the twelfth, for all 12 folds and five seeds, and the reported value is the mean $\rho$ across seeds. For zero-shot transfer, models trained on all twelve scenarios are evaluated on the five system models without fine-tuning. Training-free rankers are scored on the same scenarios and labels.

\noindent\textbf{Statistics.} The summary $\rho$ is the mean over folds with a 95\% bootstrap interval ($B = 2{,}000$) \cite{efron1993introduction}, or the mean over the five system models with their per-system range. Contrasts use paired two-sided Wilcoxon signed-rank tests across folds \cite{wilcoxon1945individual,arcuri2011practical}, and, because LOSO folds share ten of eleven training scenarios, every registered contrast is also tested with the Nadeau--Bengio corrected resampled $t$-test \cite{nadeau2003inference}. The test was derived for repeated random splits, but its correction targets the same dependence LOSO creates, overlapping training sets across folds; we use the test-to-train ratio $1/11$, one held-out scenario per eleven training scenarios, and taking Applications as the unit instead changes no conclusion (for example, $p = 0.019$ vs.\ $0.020$ for Hybrid-HGT). ``Won'' is the number of folds on which a ranker beats its comparator, a sign count reported beside the paired $\Delta\rho$ and its interval, not an effect size in its own right. ``Not significantly different'' does not mean statistically equivalent; equivalence is claimed only where a two one-sided test at $\pm 0.05$ passes, and where the paper says one ranker ``matches'' another, it means the two are not significantly different. Overlap@$K$ breaks ties by a deterministic but arbitrary order (NumPy's default sort over components ordered by identifier); Figure~\ref{fig:recall} resolves ties in expectation instead. Differences are computed from unrounded values, so a reported $\Delta\rho$ can differ in the last digit from the difference of two rounded means. Partial Spearman correlations (Table~\ref{tab:independent_oracles}) are computed per fold as the Pearson correlation of the residuals of both ranks after linear regression on the rank of the controlled ranking, then averaged over folds with the same bootstrap interval.

\noindent\textbf{Analysis plan and the status of each result.} The protocol is pre-specified in the replication repository, not lodged with a third-party registry: the plan was committed on 6 September 2026 (commit \texttt{44713326}), before the revised harness produced any result, and every amendment is logged with its commit (Supplementary Section~\ref{supp:amendments}). Table~\ref{tab:claims} gives the status of each headline result. \emph{Confirmatory}: the plan's two co-primary contrasts (\texttt{HGT-QoS} and \texttt{HGT} vs.\ \texttt{Topo-QoS}), both null. \emph{Registered secondary}: arms committed before they ran but after the primary null was known (the matched $2\times2$, the hybrids, the reference counts, the derivation value, the full-population queue-flow labels and the control arms of Section~\ref{sec:rq2}), each Holm-corrected within its family. \emph{Exploratory}: post hoc analyses, the dependency-graph learners' contrasts, the reference reclassification (which changed no figure) and the rate-weighted reference with the attribution of the learned queue-flow approximation. \textbf{Plan deviation}: the registered nested hyperparameter selection was replaced by one fixed configuration, and the registered rule was run later as a sensitivity check (Section~\ref{sec:rq2}). An omnibus Holm correction across the 13 decision-bearing contrasts (Supplementary Section~\ref{supp:amendments}) leaves the hybrid contrasts significant (Hybrid-GAT $p_{\text{omni}} = 0.019$, Hybrid-HGT $p_{\text{omni}} = 0.041$) and the primary contrast null ($p_{\text{omni}} \ge 0.46$). The headline findings of this paper are therefore registered secondary or exploratory, not confirmatory.

\noindent\textbf{The reference level.} The references measure how much of $I^*$ restating its rule recovers, not predictive skill. The first-order expansion (Eq.~\eqref{eq:analytic_istar}) reaches $0.808$ ($\rho_{>0} = 0.631$): direct subscriber loss is most of what $I^*$ measures. \texttt{InDeg}, the support of that first wave (Remark~1), is a coarser version of it ($0.764$, $\rho_{>0} = 0.516$), and \texttt{Reach} reaches $0.732$. The derivation matters for the latter: without Rule~5, \texttt{Reach} drops by $0.058$ (9/12 folds, Holm $p = 0.0068$). Untyped raw-graph metrics do not recover the reference (total degree $0.199$, reverse PageRank $0.089$).

\noindent\textbf{Learners on the dependency graph approach the reference.} \texttt{GAT-P-QoS} reaches $\rho = 0.748$, $0.016$ below the direct-dependent count per seed and $0.008$ above it as a five-seed ensemble ($0.772$, Table~\ref{tab:independent_oracles}). The closeness depends on the degree features (Section~\ref{sec:rq2}).

\noindent\textbf{Hybrids beat the baseline, not their base learners.} A hybrid takes the \texttt{Topo-QoS} score as an input and corrects its logit, so it nests its comparator. Hybrid-HGT ($+0.103$) and Hybrid-GAT ($+0.130$) beat \texttt{Topo-QoS} on 11 of 12 folds, also under the omnibus Holm correction ($p_{\text{omni}} = 0.041$ and $0.019$), the Nadeau--Bengio corrected $t$ ($p = 0.019$ and $0.014$) and $|V_{\text{app}}|$ weighting. The hybrid gain therefore reflects the weakness of the comparator, not the learned correction. Given \texttt{InDeg} as their prior instead, both hybrids land within $\pm 0.012$ of \texttt{InDeg} (F10): a learner handed the reference reproduces it.

\noindent\textbf{Beyond the reachability oracle.} On $I_{\text{dyn}}$, which agrees with $I^*$ at $\rho = 0.711$, the references outperform all GNNs (first-order expansion $0.706$, \texttt{InDeg} $0.664$, GNNs $0.496$--$0.615$; Table~\ref{tab:independent_oracles}). After removing the rank of $I^*$, \texttt{InDeg} keeps $0.272$ $[0.188, 0.366]$, \texttt{Reach} $0.117$, \texttt{Topo-QoS} $0.134$ and the GNNs $0.107$--$0.173$, all intervals excluding zero; after removing the first-order expansion instead, the raw-multigraph GNNs keep $0.212$--$0.217$, some queue-flow signal beyond the unweighted first-order term but less than the rate-weighted reference ($0.573$).

\noindent\textbf{What declared rates add on the queue-flow oracle.} Weighting each term of the first-order expansion ($0.706$ on $I_{\text{dyn}}$) by the topic's declared publication rate (Eq.~\eqref{eq:rate-expansion}) raises it to $0.830$ $[0.778, 0.872]$ without training (exploratory). A gradient-boosted model trained on $I_{\text{dyn}}$ labels, reading counts, the first-order expansion, declared rates and payload sizes, reaches $0.799$: above the unweighted expansion ($+0.093$, Holm $p = 0.019$), but it falls below the rate-weighted reference, which exceeds it by $+0.031$ $[+0.013, +0.049]$ on 10 of 12 folds (Holm $p = 0.009$ within its exploratory family). The difference is small, comparable to the per-fold variation that node order alone induces in the GNNs (Section~\ref{sec:rq2}), so we read it as the learned approximation not exceeding the formula rather than as a margin of superiority. In an exploratory attribution (Supplementary Section~\ref{supp:advisor-v6}), the declared rate and payload columns alone add $+0.097$ (9/12 folds, Holm $p = 0.021$), and the seven QoS-derived columns ($w(t)$-weighted scores and policy shares) add $-0.005$ ($p = 0.68$). Because $I_{\text{dyn}}$ reads no payload (Section~\ref{sec:4.3}), that gain is rate signal; the payload columns cannot carry any. The GNN trained on the same labels, which received no rates, reaches only $0.598$. Given each node's summed declared rate, and each Rule-1 edge's share of Eq.~\eqref{eq:rate-expansion} as an edge input, it improves on that ($+0.027$, 11 of 12 folds), and a sum-aggregation GNN, which can represent Eq.~\eqref{eq:rate-expansion} exactly from these inputs, reaches $0.665$ ($+0.067$, 10 of 12 folds; Supplementary Table~\ref{tab:a19}). Every rate-fed GNN stays far below the gradient-boosted approximation ($-0.134$ for the best) and below Eq.~\eqref{eq:rate-expansion} itself ($-0.165$, Holm $p = 0.0015$; Table~\ref{tab:controls}): with the rates in hand, the deficit is not one of missing inputs.

\noindent\textbf{Learning on top of the rate-weighted reference.} The direct test of whether learning adds value beyond the aligned approximation is a learner that starts from it (Table~\ref{tab:controls}, F12). Given Eq.~\eqref{eq:rate-expansion} as one more input column, the gradient-boosted approximation reaches $0.830$, the formula's value ($+0.000$, 5 of 12 folds, Holm $p = 0.97$); trained to correct the formula's residual, it reaches $0.824$ ($-0.006$, Holm $p = 0.68$); and the GAT trained on $I_{\text{dyn}}$ with the formula as its prior gains $+0.214$ over the same GAT without it (12 of 12 folds) but still falls below the formula ($0.812$, $-0.018$, 1 of 12 folds, Holm $p = 0.0029$). The learned approximations recover the formula's information and add none that is detectable here. On $I_{\text{dyn}}$ this approaches equivalence: the interval of the gradient-boosted model given the formula ($[-0.013, +0.015]$) lies well inside $\pm 0.05$, unlike the comparison of \texttt{GAT-P-QoS} with \texttt{InDeg} on $I^*$.

\noindent\textbf{How much is left to learn.} The five-seed $I_{\text{dyn}}$ label has an estimated reliability of $r = 0.79$--$0.99$ per fold, so no ranker can exceed $\sqrt{r} \approx 0.89$--$0.996$ (Section~\ref{sec:4.3}). Per fold, the formula leaves $\sqrt{r_f} - \rho_f = 0.047$--$0.291$ of attainable agreement (mean $0.132$). The learners started from the formula captured none of it. Whether that residual reflects mechanisms a learner could exploit with more data or is reachable only by simulating queueing is not resolved by this corpus (Section~\ref{sec:limitations}).

\noindent\textbf{The multi-criteria oracle favors different rankers.} On $I_{\text{comp}}$, learned rankers without a prior perform poorly ($0.144$--$0.334$), the hybrids keep $0.58$, and training-free scores aligned with its fragmentation and flow terms rank highest (\texttt{Topo-QoS} $0.702$, raw total degree $0.719$), which again reflects overlap with the oracle's terms. No ranker is best across all three oracles.

\noindent\textbf{Identifying the critical set.} Figure~\ref{fig:recall} shows the share of the true top-20\% set that each ranker places in its top $k\%$, with ties resolved by averaging. At $k = 20\%$, \texttt{GAT-P-QoS} recovers $0.48$ of the critical set and \texttt{Topo-QoS} $0.38$; to recover 80\%, \texttt{GAT-P-QoS} must flag the top 40\% ($0.81$), and \texttt{Topo-QoS} does not reach 80\% within 50\%. On $I_{\text{dyn}}$ (panel~B), \texttt{GAT-P-QoS} reaches $0.74$ at 40\% and $0.82$ at 50\%, compared to $0.80$ at 40\% for the \texttt{InDeg} reference; the rate-weighted reference, which restates $I_{\text{dyn}}$'s first-order rule, recovers $0.81$ of that set at 20\% and $0.96$ at 30\% (exploratory).

\noindent\textbf{The ``QoS'' factor was mostly the weighted in-degree.} In the capacity-matched $2\times2$ on the raw multigraph (Supplementary Table~\ref{tab:contrasts_matched}), relation typing has no effect ($-0.014$, $p_{\text{Holm}} = 0.940$) and the ``QoS'' inputs add $+0.073$ ($p_{\text{Holm}} = 0.127$). The QoS-off arms, however, also zero $w_{\text{in}}$, a QoS-weighted version of \texttt{InDeg}; with $w_{\text{in}}$ held in both arms (F4), the ``QoS'' effect drops to $+0.030$, so more than half of it was the weighted in-degree. Closed-form controls agree: unweighted betweenness ($0.591$) and constant topic weights ($0.595$) match or exceed QoS-weighted betweenness ($0.553$), and permuting QoS profiles across topics has no effect ($\Delta = -0.006$, $p = 0.733$). Because messages never reach Applications on the raw multigraph (Section~\ref{sec:3.4}), this $2\times2$ compares per-node models and says nothing about relational typing (Section~\ref{sec:8.2}).

\noindent\textbf{Degree features and the aggregator.} Removing the in-degree and $w_{\text{in}}$ columns lowers \texttt{GAT-P-QoS} by $0.136$ (F1). This confirms known expressivity results rather than adding a new one: softmax attention averages over neighbors and cannot count them, whereas sum aggregation can \cite{xu2019gin,corso2020pna}, and a GIN of the same size (GINE layers, which add the edge vector to each message) keeps $0.721$ without the same columns (F2, not significant after Holm). In zero-shot transfer the degree columns matter little ($0.810$--$0.821$ without them), because the system models are ranked mostly by separating inert from active components.

\noindent\textbf{Direction versus dependency semantics.} The $+0.113$ gain of \texttt{GAT-P-QoS} over \texttt{GAT-QoS} could come from edge direction rather than dependency semantics, so a control passes every raw-graph edge in both directions, with shared weights and an unchanged parameter count (\texttt{GAT-QoS-R}, F8). It reaches $0.676$: direction alone recovers $+0.041$ of the gain, which is not significant (Holm $p = 0.064$), and \texttt{GAT-P-QoS} still exceeds it by $+0.072$ $[+0.034, +0.113]$ on 10 of 12 folds (Holm $p = 0.014$). The direction effect itself lies within the node-order spread reported below. Reverse edges also cost transfer ($0.744$ zero-shot, against $0.805$--$0.806$; Table~\ref{tab:system_models_transfer}).

\noindent\textbf{Without the oracle-aligned features.} Every published learner reads features that compute part of $I^*$ (Section~\ref{sec:3.5}). With all of them zeroed (F11), the raw-graph learners collapse (\texttt{GAT-QoS} to $0.369$, the reverse-edge control to $0.378$), whereas the dependency-graph GAT keeps $0.610$ and beats the equally stripped reverse-edge control by $+0.231$ (10 of 12 folds, Holm $p = 0.0068$). The oracle-aligned set costs \texttt{GAT-P-QoS} $0.138$, about what the two degree columns alone cost. Without them, sum aggregation beats attention on the dependency graph ($+0.115$, 9 of 12 folds, Holm $p = 0.027$), and without any node features at all, a sum-aggregation GNN on the dependency graph reaches $0.719$, $0.045$ below \texttt{InDeg} (1 of 12 folds): from structure alone it learns most of the dependent count, which the derived graph makes available and the raw multigraph does not. This too is what sum aggregation's ability to count neighbors predicts \cite{xu2019gin,chen2020can}.

\noindent\textbf{Representation or aggregator?} On the raw multigraph a direct dependent is two typed hops away (publisher, topic, subscriber), and the reverse-edge control above averages with attention, so the dependency-graph gain could be an attention artefact that a counting aggregator on the raw graph would remove. A sum-aggregation GNN on the raw multigraph with every edge also reversed (\texttt{GIN-QoS-R}; Table~\ref{tab:controls}) reaches $0.668$, level with its attention counterpart ($-0.008$), and with the oracle-aligned features removed it recovers $46\%$ of the gap between the stripped attention models ($0.485$ against $0.378$). The dependency graph still wins under matched sum aggregation: by $+0.239$ without the oracle-aligned features (12 of 12 folds, Holm $p = 0.0015$), by $+0.064$ with them (Holm $p = 0.0049$), and by $+0.289$ with no node features at all, where the raw-graph GNN reaches $0.430$ against the dependency-graph GNN's $0.719$. The projection's advantage is therefore not specific to attention: making each direct dependent an in-neighbor gives either aggregator the count that, on the raw multigraph, neither learned from the same eleven training graphs.

\noindent\textbf{Message passing, node order and the selection rule.} On the raw multigraph, a gradient-boosted model on the same per-node features and no graph (\texttt{GBM-Feat}) reaches $\rho = 0.642$ under LOSO, level with \texttt{GAT-QoS} ($0.635$), and removing HGT's reverse pass, its only route to Applications, has no effect (\texttt{HGT-QoS-U}, $-0.010$, $p = 0.91$). ListMLE breaks label ties in input order (Section~\ref{sec:4.2}); permuting node order before training (F13; \texttt{GAT-P-QoS-perm}) scores $0.712$ against $0.748$ ($-0.035$, 3 of 12 folds, $p = 0.012$), which triggered the registered flag. Across three permutations, seeds 17, 18 and 19 give $0.712$, $0.740$ and $0.734$ (mean $0.729$), and the per-fold spread across the three permutations averages $0.044$. All three lie below the published order, so three permutations cannot separate variance from a favorable published order; at their mean, \texttt{GAT-P-QoS} sits $0.035$ below the direct-dependent count rather than $0.016$. Tie order is not its main source: with a tie-aware listwise loss, in which tied labels share one risk set, \texttt{GAT-P-QoS} is unchanged ($0.747$, $-0.001$, Holm $p = 0.97$), still exceeds the equally trained reverse-edge control ($+0.069$, Holm $p = 0.019$), and three node-order permutations still spread by $0.047$ per fold. The remaining order dependence lies in the order-dependent parts of training, such as the node-level validation split, not in the loss. Learned-ranker differences smaller than this spread should not be read as differences between models; a mixed-effects model with seeds nested in folds gives the same conclusions for the direction, oracle-aligned-feature, aggregator and tie-loss contrasts (Supplementary Section~\ref{supp:controls}). Finally, the plan's nested hyperparameter selection, applied later on the stage-1 grid, changes \texttt{HGT-QoS} from $0.622$ to $0.677$ ($+0.055$) and \texttt{GAT-P-QoS} from $0.748$ to $0.693$ ($-0.054$), neither significant (Holm $p = 0.259$); nested \texttt{HGT-QoS} versus \texttt{Topo-QoS} is $+0.123$ on 9 of 12 folds, still not significant (Holm $p = 0.192$). That harness trains on one scenario fewer and stops early on a held-out scenario, so it compares two protocols, not only two configurations (Section~\ref{sec:6.3}). Under that protocol \texttt{GAT-P-QoS} falls $0.071$ below the direct-dependent count ($3$ of $12$ folds, $p = 0.11$). Configuration swings of $\pm 0.055$ are as large as several differences reported in this section, so every learned result here is conditional on one fixed configuration; no model family received its own tuning budget.

\noindent\textbf{Training-set size.} Figure~\ref{fig:lc} retrains three learners on $K$ of each fold's eleven training scenarios (three nested draws per $K$). On the dependency graph the learners improve with more architectures: \texttt{GAT-P-QoS} rises from $0.605$ at $K = 1$ to $0.670$ at $K = 4$ and $0.748$ at $K = 11$ ($+0.078$ from four to eleven, Holm $p = 0.015$), narrowing its gap to the direct-dependent count from $0.160$ to $0.017$, and \texttt{GIN-P-QoS} rises from $0.645$ to $0.732$. The step from eight to eleven architectures is small ($+0.015$ and $+0.001$), but its interval for \texttt{GAT-P-QoS} ($[+0.003, +0.028]$) does not rule out further gains, so by the registered rule the curve neither saturates nor keeps rising (Supplementary Table~\ref{tab:a19lc}). On the raw multigraph \texttt{GAT-QoS} is flat from $K = 4$ ($0.622$ to $0.635$). Within this generator family, more training architectures brought the dependency-graph learners closer to the dependency count without exceeding it; whether many more would is not tested. At width $64$ instead of $288$, \texttt{GAT-P-QoS} loses $0.110$ on every fold ($0.638$), so the published width is not over-parameterized for this task.

Measured like for like (Table~\ref{tab:cost-ll}), one labeling pass of the reachability oracle over a corpus architecture's Applications takes $0.01$--$0.72$~s, the counting path that restates its first wave is $17$--$176\times$ cheaper (median $45\times$), and the feature extraction every learned ranker needs $4.5$--$72.5\times$ more (median $16.9\times$); the ordering holds on generated graphs of up to $5{,}000$ components. The articulation and CDI phase accounts for $88$--$91\%$ of feature extraction, so this cost belongs to the chosen feature set, not to learned ranking as such: a sum-aggregation GNN with no node features reaches $0.719$ (Table~\ref{tab:controls}, F11) and would not pay it. Where the $I^*$ ranking itself is wanted, running the oracle is therefore cheaper than approximating it with a learned ranker at every size measured. The computationally intensive oracle is $I_{\text{dyn}}$: labeling the corpus took $12.7$ CPU-hours (about $7$~s per fault run and seed). The cost comes from simulating every message event to measure an effect that is one hop deep by construction; the rate-weighted reference computes that first-order delivered-rate loss in at most about a millisecond per architecture. Estimating energy as wall-clock time multiplied by the processor's $28$~W base power (Section~\ref{sec:threats}), labeling the corpus with $I_{\text{dyn}}$ took about $355.6$~Wh, the five-seed $I^*$ labeling sweep $11.1$~s ($0.086$~Wh), and the full detection gate $106.9$~s ($0.83$~Wh). Summed over the twelve folds, the feature extraction that the learned rankers read took $70.0$~s (about $0.54$~Wh), and the dependency count $0.037$~s (about $1$~J). Training is a separate one-off cost per model version: the last sweep with recorded wall-clock took $7.7$ CPU-hours for four learned arms of 60 fits each (Supplementary Section~\ref{supp:gate-ratio}), about $0.22$~kWh by the same estimate. At these magnitudes, raw per-inference energy differences are practically negligible; what governs operational feasibility in continuous integration (CI/CD) is the amortized lifecycle break-even. A learned model incurs an upfront cost for simulator label generation (about $30$~Wh per corpus architecture, $355.6$~Wh over twelve) plus training ($0.22$~kWh), which must be amortized against recurrent CI evaluation runs. The training-free rate-weighted reference incurs neither cost and was at least as accurate on this corpus, so no learned approximation of $I_{\text{dyn}}$ evaluated here repays its labeling and training cost against it, whatever the number of CI runs.

\section{Discussion, Threats to Validity, and Limitations}
\label{sec:8}

\subsection{Dependency Representation versus Model Complexity}
\label{sec:representation}
\label{sec:restatement}

For the reachability and queue-flow simulators in this corpus, explicit dependency representations accounted for more of the ranking performance than model complexity did. The derived dependency graph enabled both analytical and learned approaches: learners improved on it relative to the raw multigraph, and the improvement survives a control for edge direction, the removal of every feature that computes part of the reachability simulator, and a change of aggregator from attention to sum aggregation. Yet rankings computed directly from the same graph were not significantly different from, or exceeded, the best learned models. In this corpus, explicit dependency derivation appears to be the principal source of predictive signal, not a preprocessing step for learning. Rule~1 encodes the same subscriber-on-publisher assumption as $I^*$'s first wave (Remark~1), so this is the advantage of a representation aligned with the simulators' propagation mechanism; whether real failures propagate along Rules~1 and~5 is untested (Section~\ref{sec:threats}). The multi-criteria simulator is the exception: there, raw degree and betweenness, whose terms align with fragmentation, ranked highest.

Several of the highest-scoring rankings largely restate a simulator's propagation rule. The reference criterion (Section~\ref{sec:4.4}) separates recovering a simulator's definition from predicting its outcomes, and it changes how learned results should be read: a learned model that approaches a reference has learned the simulator's first-order rule, not necessarily anything beyond it. Because simulation-labeled benchmarks are common in architecture analysis, the criterion offers a general check: before crediting a learned model with predictive skill, compare it with the simplest ranking that restates the simulator's own computation.

The circularity also bears on the simulators. That publish--subscribe afferent coupling, a coupling metric architects already compute, recovers most of $I^*$ is first a statement about $I^*$: as a ground truth for cascade impact, it adds little beyond that metric, and the same holds for $I_{\text{dyn}}$ and its rate-weighted expansion. The findings therefore bound what learning adds over analytical rankings on oracles of this kind, which are first-order by construction; they do not show that graph learning lacks value for cascade-impact analysis in general, where feedback such as backpressure, retries or synchronous call chains makes impact depend on more than a component's direct dependents.

\subsection{When Learning Adds Value, and Relative to What}
\label{sec:8.2}

Relative to the training-free baseline, learning helped in two ways, both weak evidence for learning. Hybrids outperformed the baseline they nest but not their own base learners, so the gain belongs to the baseline's weakness; and learned models transferred zero-shot better than the baseline, mainly by separating inert from active components. Relative to analytical references built on the same dependencies, no learned model showed additional skill, and the most direct test, learners that start from the rate-weighted approximation, found no improvement on it. The learned queue-flow approximation beat the unweighted expansion only because it read declared rates; once rates enter the analytical expansion, the deficit is not one of missing inputs, and graph networks given the same rates stayed further below it. Learning is likely to contribute most where cascade impact depends on multi-hop, non-linear mechanisms that no low-order approximation captures, such as broker queue congestion, backpressure onto publishers, retry storms or heterogeneous service capacities; learned network models have succeeded in that regime \cite{rusek2020routenet}. None of the three simulators implements them (Section~\ref{sec:4.3}). Under the first-order reachability and rate-loss mechanisms they do implement, explicit dependency derivation supplied the structural signal directly, and learners trained on eleven architectures in one fixed configuration added none beyond it, although the dependency-graph learners were still approaching the dependency count as their training set grew. Whether learning helps where those mechanisms are present, or with many more training architectures, is untested here (Section~\ref{sec:limitations}). A per-regime breakdown by architecture type is given in Supplementary Section~\ref{supp:regimes}.

\noindent\textbf{How message passing contributes.} On the raw multigraph, learning used node properties, not relations: a graph-free model on the same features matches the GAT, and removing HGT's only route to Applications has no effect (Section~\ref{sec:rq2}). On the derived dependency graph, message passing gathers the dependent neighborhood; attention still needs the degree columns to approach the dependent count, whereas sum aggregation recovers most of it from structure alone. These observations confirm known results on the expressivity of aggregators \cite{xu2019gin,corso2020pna,chen2020can}. The aggregator does not substitute for the representation, however: on the raw multigraph with reverse edges, where each dependent is two typed hops away, sum aggregation recovered less than half of the gap and, from structure alone, little of the dependent count.

\noindent\textbf{What the study can say about relation typing.} Little. On the raw multigraph, where typing was compared at matched capacity, messages never reach Applications, so that comparison is between per-node models. On the dependency graph the projection has only two relation types, and the heterogeneous transformer (\texttt{HGT-P-QoS}) ran in one untuned configuration in which some seeds converged to rankings anti-correlated with the oracle (mean within-fold seed standard deviation $0.254$, mean $\rho = 0.514$), while \texttt{GAT-P-QoS} was stable ($0.030$, $\rho = 0.748$). That is an optimization failure of one configuration, not evidence about typing; testing typing would need a substrate with active message passing, more relation types and a tuned heterogeneous model.

\subsection{Practical Consequences}
\label{sec:8.1}

\noindent\textbf{Choosing a ranker.} Table~\ref{tab:guidance} summarizes the evidence by failure notion; it is conditional on simulation fidelity, and neither simulator, nor any approximation of it, has been shown to predict real outages. If the simulator is cheap, like $I^*$, its ranking can be computed directly from the declared architecture model, and publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais} costs a fraction of that; its value is cost, not predictive skill. If the simulator is expensive, like $I_{\text{dyn}}$, the rate-weighted expansion approximates it in milliseconds, and declared publication rates, not QoS policies, are the only declared information that carried signal. Training-free dependency analysis is therefore also the lower-energy choice at commit and staging time \cite{schwartz2020greenai,verdecchia2023greenai}.

Closed-form rankings are also deterministic, whereas learned rankings vary with the seed (within-fold standard deviation $0.024$--$0.030$ for the GATs, up to $0.254$ for the unstable \texttt{HGT-P-QoS}) and with node order (Section~\ref{sec:rq2}). Learned models transfer zero-shot better than the training-free baseline mainly by separating inert from active components, so they should not be relied on to order the components that actually propagate failures ($\rho_{>0} \le 0.342$). The same holds for the direct-dependent count ($\rho_{>0} = 0.321$ on the system models). Only transitive reach ordered the active components there ($0.871$), and it does so because it restates the oracle's own cascade (Section~\ref{sec:rq3}); where $I^*$ is the impact definition, running $I^*$ gives that ordering directly.

\noindent\textbf{A two-tiered triage protocol.} On $I^*$, recovering 80\% of the true critical set takes the top 40--45\% of Applications by the best rankers, and no predictor reaches 90\% within the top 50\% (Figure~\ref{fig:recall}); on $I_{\text{dyn}}$, the rate-weighted reference recovers 81\% within the top 20\%, but it restates that simulator's first-order rule. A gate that catches most critical components by $I^*$ would flag nearly half the system, so these rankers are unsuitable as automated pass/fail filters for reachability impact. We instead propose a two-tiered triage protocol as an inspection heuristic, which needs human-factors and workflow validation before adoption:
\begin{enumerate}\tightlist
    \item \textbf{Tier 1 (commit stage):} compute the direct-dependent count and the rate-weighted expansion (milliseconds; the latter exploratory) and show the top five components by each as an informational note in pull-request review, without blocking developers.
    \item \textbf{Tier 2 (staging and sprint review):} run the simulators on the Tier-1 shortlist within a fixed inspection budget, such as the ten highest-ranked services, and reserve redundant broker routing or chaos fault injection for the components the simulation confirms.
\end{enumerate}

\subsection{Threats to Validity}
\label{sec:8.3}
\label{sec:threats}

\noindent\textbf{Construct validity and oracle circularity.} All labels are simulated: no ranker is validated against observed failures, so the findings establish what can be predicted within the evaluated simulators, not what predicts real failures. The simulators omit runtime dynamics such as buffer bloat, thread-pool exhaustion, garbage-collection pauses and retry storms, and some real outages are sustained by load feedback rather than structure \cite{bronson2021metastable,huang2022metastable}. The circularity is analyzed in Section~\ref{sec:4.4}: because the simulation oracles are low-order by construction, low-order analytical truncations under Simplifications S1--S5 capture their primary signal ($I_{\text{dyn}}$ propagates no failure beyond one hop; Section~\ref{sec:4.3}). The representation and the primary oracle also share an assumption: Rule~1 and $I^*$'s first wave both let a failure pass from a publisher to its subscribers, which is why the direct-dependent count equals that wave's support (Remark~1). The advantage of the derived graph is therefore conditional on real failures propagating along Rules~1 and~5, which this study does not test. $I^*$ and $I_{\text{dyn}}$ are well approximated by low-order functions of the dependency graph (a first-order expansion recovers $0.808$ of $I^*$ and a rate-weighted one $0.830$ of $I_{\text{dyn}}$), and $I_{\text{comp}}$'s terms track degree and betweenness, which rank highest on it ($0.70$--$0.72$). The benchmark therefore did not exhibit a regime in which learning exceeds an aligned analytical ranking. Its absence here is a property of these oracles, not evidence that none exists, and the study's negative answer is bounded accordingly. The reverse-edge controls share one set of weights across both directions; \texttt{HGT-QoS} passes reverse relations as separate types but aggregates with attention, and summing relation-typed models (R-GCN \cite{schlichtkrull2018rgcn}, Simple-HGN \cite{lv2021revisiting}) were not tested. Rules~2--4 and~6 are untested.

\noindent\textbf{Internal validity and reproducibility.} No ranker reads simulator output (regression tests verify this). Capacity, depth and early stopping were held constant across arms, but every learned result is conditional on one fixed configuration (Section~\ref{sec:6.3}); the registered nested selection, run later, moved learned rankers by up to $\pm 0.055$. The learners were also trained in a small-data regime (eleven architectures, about $1{,}000$--$1{,}300$ labeled Applications per fold, roughly $430{,}000$ parameters). The learning curve shows the dependency-graph learners still approaching the dependency count at eleven architectures, so at this corpus size the comparison may favor the analytical side; more than eleven training architectures were not tested (Section~\ref{sec:rq2}). The learned rankers are seed-sensitive: the mean within-fold standard deviation of $\rho$ is $0.099$ for \texttt{HGT-QoS}, $0.254$ for \texttt{HGT-P-QoS} and $0.024$--$0.030$ for the GATs, and one of 60 \texttt{HGT-QoS} runs and four of 60 \texttt{HGT-P-QoS} runs converge to rankings anti-correlated with the oracle; they are kept in the per-seed means, as registered. Between earlier sweeps a learned fold mean moved by up to $0.172$, for three documented causes: a since-fixed device-placement defect in PyTorch Geometric, resumption from stale checkpoints, and non-deterministic CUDA reductions. Every learned-versus-learned contrast is therefore paired within one CPU sweep in which every comparator is re-run, and in each such sweep the re-run comparators reproduced their published per-seed values exactly; paired contrasts were not repeated on a second device. Node order adds a variance of about $0.04$ per fold, which a tie-aware loss does not remove (Section~\ref{sec:rq2}). CDI uses hash-dependent tie-breaking, so \texttt{PYTHONHASHSEED=0} is fixed, and all reported values are reconciled mechanically against released artifacts.

\noindent\textbf{External validity and the single-modeler threat.} Synthetic topologies come from a single generator family, which may induce regularities not representative of industrial architectures. The five system models (22--41 Applications) were each written by the first author from public documentation; no second modeler authored any of them, and no automated manifest extractor was used. They also differ structurally from the synthetic folds in ways that favor \texttt{Reach} (Section~\ref{sec:rq3}), and two are RPC systems re-expressed as publish--subscribe meshes. No topology was extracted from a real deployment manifest: the released tooling has no importer for launch files or for compose or Kubernetes manifests, and the five models are encoded by hand. No fault-injection experiment on a deployed system was run, and the replication package's re-modeling protocol, which reports per-type Jaccard agreement between independently authored models (\path{reproduce/model_agreement.py}), has not yet been executed by an independent modeler. We timed the counting path up to $10{,}000$ components but did not evaluate rankers or oracles at that scale. We did not reproduce published learned criticality models (FINDER, DrBC), which do not support typed multigraphs or pub-sub semantics.

\noindent\textbf{Energy estimation and Green AI.} Energy figures are wall-clock time multiplied by the processor's $28$~W base power (Intel Core i7-1370P; \path{reproduce/energy_estimate.py}), because RAPL counters required privileges unavailable to us. This is a nameplate estimate, not a bound in either direction: single-threaded work may draw less than the package's base power and turbo frequencies more, and DRAM and idle power are ignored. At the magnitudes involved, fractions of a watt-hour per corpus for every training-free and learned ranking against $355.6$~Wh to label the corpus with $I_{\text{dyn}}$, the energy argument of this paper rests on the break-even of a learned $I_{\text{dyn}}$ approximation (Section~\ref{sec:rq4}), not on differences between rankers \cite{schwartz2020greenai,verdecchia2023greenai}. The feature-extraction cost of the learned rankers belongs to the chosen feature set, not to learning as such.

\noindent\textbf{Conclusion validity.} Only the plan's two co-primary contrasts are confirmatory, and both were null (Section~\ref{sec:6.3}). LOSO folds share ten of eleven training scenarios, so Wilcoxon $p$-values are anti-conservative; the Nadeau--Bengio corrected test leaves the hybrid contrasts significant and the primary null. Twelve folds from one generator make the study underpowered for equivalence at $\pm 0.05$: it is not established for any pair of independently derived rankers, and holds only for learners given a reference as their prior, which reproduce it (Table~\ref{tab:controls}, F10); on $I_{\text{dyn}}$, the interval of the learner started from Eq.~\eqref{eq:rate-expansion} also lies within that margin. Where the paper says one ranker ``matches'' another, it means the two are not significantly different (Section~\ref{sec:6.3}).

\subsection{Limitations and Future Work}
\label{sec:8.4}
\label{sec:limitations}

Five directions follow, in order of priority:
\begin{enumerate}\tightlist
    \item \textbf{A confirmation corpus:} scenarios generated after the analysis is frozen, on which the reference criterion and the registered secondary and exploratory claims are re-tested. Because each topology regenerates exactly from its configuration and labeling with $I^*$ takes seconds, this is the cheapest way to make the present headline findings confirmatory.
    \item \textbf{Real topologies, real failures and independent modelers:} automatic extraction of SaG models from real artifacts (ROS~2 launch files with HAROS or ROSDiscover \cite{santos2019haros,timperley2022rosdiscover}, docker-compose and Kubernetes manifests); controlled fault injection on ROS~2, Kafka and MQTT deployments and on reference systems with known faults such as Train-Ticket \cite{zhou2018trainticket}; distributed tracing to check whether declared dependency paths match runtime message flow; and re-authoring of the five system models by additional modelers with agreement reported.
    \item \textbf{Non-first-order impact models:} queue-flow variants with backpressure onto publishers, finite broker capacity, retry amplification and heterogeneous service capacity, and simulators with synchronous call semantics, where an aligned analytical approximation may not exist. These are the regimes in which learning could exceed analytical methods, and the only ones in which this study's title question could receive a positive answer.
    \item \textbf{The learning regime:} learning curves beyond eleven training architectures, which need newly generated scenarios, caches and labels; a matched tuning budget for every model family; and relation-typed summing models (R-GCN, Simple-HGN).
    \item \textbf{Brokers and hosts:} evaluating Rules~2--4 and~6 by ranking Brokers and Hosts.
\end{enumerate}
Further extensions include measured energy (RAPL or IPMI) in place of the nameplate estimate, a queue-flow run with QoS policies disabled, a payload-aware queue-flow oracle (registered but not run), the sensitivity of $I^*$ and $I_{\text{comp}}$ to their declared constants and weights, zero-shot transfer of the learned $I_{\text{dyn}}$ approximations (the system models carry $I^*$ labels only), and validation of the proposed explanation layer.

\section{Conclusion}
\label{sec:9}

This paper presented Software-as-a-Graph (SaG), a pre-deployment framework that derives explicit dependency graphs from declared publish--subscribe architecture models, supporting analytical, hybrid, and learned approaches to cascade-impact ranking. Using twelve synthetic architectures, three failure simulators, and five stylized open-source system models, the study examined when graph learning improves rankings derived directly from explicit architectural dependencies. The registered co-primary contrasts were null, and the findings below are registered secondary or exploratory.

For the reachability and queue-flow simulators, which are dominated by first-order propagation by construction, explicit dependency representations provided most of the predictive signal observed in the evaluated corpus. Learners benefited from the derived dependency graph ($\rho = 0.748$ vs.\ $0.635$ on the raw multigraph), a gain that survives controls for edge direction, for features that compute part of the simulator and for the aggregator, but simple analytical rankings built on the same dependencies did not differ significantly from, or exceeded, the learned models. Counting direct dependents ($\rho = 0.764$) was not significantly different from the best learned model on the reachability simulator, and on the expensive queue-flow simulator a rate-weighted first-order approximation computed in milliseconds ($0.830$) exceeded a learned approximation trained on $12.7$ CPU-hours of simulation labels ($0.799$) and graph networks given the same declared rates; learners that start from that approximation matched it at best. In this simulated corpus, representation mattered more than model complexity.

Against afferent coupling, the dependency count an architect can compute directly, no learned model showed additional skill. With more training architectures the dependency-graph learners came closer to it, and whether many more would carry them past it is untested. Learning outperformed only the weak registered baseline, QoS-weighted betweenness, through hybrids that did not differ from their own base learners and through zero-shot transfer, where dependency counts ranked higher still and ordering among the components that actually propagate failures remained weak. These conclusions hold for learners trained on up to eleven synthetic architectures in one fixed configuration, against simulators rather than observed failures.

These results have implications for both research and practice. For researchers, they show the importance of evaluating graph-learning approaches against analytical alternatives aligned with the simulator, and of distinguishing prediction from restatement of a simulator's rule. For practitioners, they suggest that training-free dependency analysis provides effective and inexpensive support for prioritizing architectural review. Learned models can be expected to add value only where no analytical approximation aligned with the simulator is available, as under backpressure, buffer-overflow drops or retry storms. Each simulator studied here is closely tracked by such an approximation, so this condition did not arise in this corpus.

Sections~\ref{sec:threats} and~\ref{sec:limitations} discuss limitations, including the reliance on simulated failures; re-testing these findings on a corpus generated after the analysis was frozen, under non-first-order simulators and against real outages, is the natural next step. More broadly, the study suggests that the central challenge in architecture-level cascade-impact analysis is not selecting increasingly sophisticated learning algorithms, but deriving explicit dependency representations and understanding when learning adds value beyond them. By making this comparison explicit and releasing a reproducible benchmark, Software-as-a-Graph provides a foundation for more principled evaluation of analytical and learned methods for pre-deployment architecture analysis.
