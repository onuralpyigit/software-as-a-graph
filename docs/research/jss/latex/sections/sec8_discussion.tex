\section{Discussion, Threats to Validity, and Limitations}
\label{sec:8}

\subsection{Discussion and Practical Consequences}
\label{sec:8.1}

\noindent\textbf{When to use Topo-QoS, and when to use HGT-QoS.}
The findings do not support an unequivocal recommendation of the learned model over the closed-form alternative; we present empirical trade-offs directly.

\begin{itemize}\tightlist
\item \textbf{Training-free ranking (\texttt{Topo-QoS}) vs.\ Direct Simulation.} \texttt{Topo-QoS} eliminates training, checkpoint storage, and tuning, achieving $\rho = 0.553$ zero-shot across twelve synthetic architectures and $0.526$ across five open-source systems. Learned models do not yield statistically significant ranking gains ($+0.085$, $p = 0.151$, 95\% CI spanning zero; and $0.888$ vs.\ $0.769$ favoring baseline on Cloud Microservices' full population). Thus, \texttt{Topo-QoS} serves as the zero-maintenance default for scalar ranking in resource-constrained CI pipelines. Alternatively, where queue parameters exist and graphs are small-to-medium ($N < 500$), direct simulation ($0.14$--$7.2\,\text{s}$) offers exact ground-truth traces without surrogate approximation.
\item \textbf{One learned mechanism, not two (\texttt{GAT-N-QoS} or \texttt{HGT}).} Relation typing or QoS edge channels individually yield substantial improvements over unweighted baselines ($+0.234$ and $+0.287$, Holm-corrected $p \le 0.0015$); combining both provides minimal additional benefit. Untyped QoS-weighted GNNs offer a superior efficiency trade-off, achieving $\rho = 0.604$ with $28{,}168$ parameters vs.\ \texttt{HGT-QoS}'s $0.638$ with $434{,}620$ parameters. Unweighted homogeneous models (\texttt{GAT-N}, $\rho = 0.317$) underperform heuristics, indicating GNNs lacking relational signals fail on this task.
\item \textbf{Capabilities without a closed-form counterpart.} The typed model exposes one unique diagnostic: per-relation attention (Section~\ref{sec:7.3.4}). However, measured spread across relation types is narrow ($0.15$--$0.23$), governed by destination in-degree, and unstable under regeneration; it establishes that typed attention is active, not that it is diagnostically reliable. We decline to advance this as a reason to adopt typing on the present evidence.
\item \textbf{Ingestion boundary.} Deployment must condition on communication synchrony (Table~\ref{tab:drivers}): on asynchronous pub-sub systems (ROS~2, DDS, MQTT, Kafka) \texttt{HGT-QoS} transfers positively on active components, whereas on the synchronous Train-Ticket call tree it inverts and should not be deployed — use static call-graph reachability tools instead. \texttt{Topo-QoS} is not the substitute: it is negative on the active components of both RPC meshes.
\end{itemize}

\noindent\textbf{Dual-Engine Consensus Protocol.}
Because prediction dispersion $\hat{\sigma}$ correlates negatively with margin over \texttt{Topo-QoS} ($\rho_s = -0.126$, Section~\ref{sec:7.2.1}), automated fallback is withdrawn. Instead, SaG executes dual-prediction evaluating \texttt{HGT-QoS} and \texttt{Topo-QoS} concurrently, flagging unanimous top-$K$ nodes and highlighting divergent rankings for review.

\noindent\textbf{Role of the Explanation Layer.}
The RM profile ($Q(v)$, Section~\ref{sec:5}) provides standards-compliant architectural diagnostics under ISO/IEC 25010. While neural and centrality predictors govern triage priority, RM decomposes structural mechanics to inform refactoring (distinguishing single-point-of-failure Availability replication from cascade Fault Tolerance circuit breakers). However, elicited AHP weights rank worse than a uniform prior; pending user studies, we recommend the uniform prior.

\subsection{Performance and Computational Sustainability Implications}
\label{sec:8.2}

\noindent\textbf{What sustainability means for a pre-deployment gate.}
Green software engineering assesses energy across development, assurance, and execution \cite{calero2015green,schwartz2020greenai,strubell2019energy,patterson2021carbon,georgiou2022greenframeworks,lannelongue2021green,verdecchia2023greenai}. While live chaos sweeps require cluster-hours across provisioned nodes, pre-deployment static analysis aims to eliminate cloud staging footprints. Direct physical energy measurement in joules requires dedicated hardware counters (RAPL, NVML) and profilers \cite{lannelongue2021green,schmidt2021codecarbon,noureddine2021joularjx}, which we outline as an instrumentation protocol for future testbeds.

\noindent\textbf{Where the cost actually sits.}
We withdraw the efficiency claim: cold static analysis does not reduce CPU computation over simulation. Global connectivity degradation ($79.3\,\text{s}$ on Enterprise) is roughly eighteen times slower than cascade traversal ($4.5\,\text{s}$) due to CDI's $O(|V|^2 + |V||E|)$ cost. In CI, sustainability would be achieved via incremental graph caching: caching base metrics across commits and extracting features only for PR delta subgraphs would reduce latency to the sub-second forward pass ($56\,\text{ms}$). Without caching, static analysis consumes more CPU time than the simulation it displaces.

\subsection{Threats to Validity}
\label{sec:8.3}

\noindent\textbf{Construct Validity.} Ground-truth impact $I^*(v)$ is derived from simulation rather than live production outages. While $I^*$ correlates with dynamic queue flow $I_{\text{dyn}}$ ($\rho = 0.627$ against a $0.811$--$1.000$ ceiling, Section~\ref{sec:7.3.convergent}), top-$K$ Jaccard reaches only $0.27$--$0.37$. Furthermore, $I^*(v)$ is recovered at $\rho = 0.965$ by topology-only relabeling, confirming the target captures reachability rather than runtime anomalies. Additionally, transcribing open-source architectures into multigraphs relied on standardized heuristics without multiple independent coders, introducing potential transcription subjectivity.

\noindent\textbf{Internal Validity.} Feature leakage is prevented by strict graph separation: predictors consume $G_{\text{analysis}}$, while simulation oracles traverse $G_{\text{structural}}$ (CI-asserted). Parity is maintained via matched datasets, depths, and early stopping. However, comparing \texttt{HGT-QoS} to \texttt{GAT-N-QoS} conflates typing with a $15.4\times$ capacity gap ($434{,}620$ vs.\ $28{,}168$) and bidirectional passing ($103{,}725$ reverse-projection parameters in \texttt{HGTConv}), requiring registered control variants (\texttt{GAT-N-C}, \texttt{GAT-N-QoS-C}, \texttt{HGT-QoS-U}, Section~\ref{sec:8.4}) to isolate. Six active QoS dimensions govern profiles, with one reserved extension point.

\noindent\textbf{External Validity.} The benchmark corpus comprises 2,812 components across seventeen system architectures deliberately spanning six distinct architectural domains: robotics (autonomous driving / ROS~2), smart cities, healthcare integration, financial trading, enterprise application integration (centralized ESB broker hubs and microservices), and industrial/edge IoT (EdgeX Foundry, Home Assistant). This cross-domain diversity was intentionally curated to establish external validity across divergent structural topologies, interaction patterns, and failure cascade dynamics, preventing empirical conclusions from reflecting an idiosyncratic software monoculture. While this deliberate heterogeneity reveals an architectural boundary condition on the active stratum—pub-sub cascades propagate forward via starvation, whereas synchronous RPC microservices cascade backward along invocation trees via timeouts \cite{zhou2021fault}—it ensures that our findings regarding baseline competitiveness and inductive biases are grounded across varied software engineering contexts. Zero-shot transfer to active components reflects this boundary: \texttt{HGT-QoS} maintains positive transfer across asynchronous pub-sub systems ($\rho_{>0} \in [+0.262, +0.770]$, subtotal mean $+0.516$, Table~\ref{tab:9b}), while synchronous call trees invert (subtotal mean $-0.071$) and all training-free baselines turn negative on active nodes (Table~\ref{tab:9c}). GNN directional biases must therefore be conditioned on communication synchrony. Scaling beyond 2,000 nodes requires incremental caching or mini-batching (GraphSAINT \cite{zeng2020graphsaint}).

\noindent\textbf{Conclusion Validity.} Distributions are evaluated using non-parametric correlations (Spearman $\rho$, Kendall $\tau$), bootstrap intervals ($B = 2{,}000$), and Wilcoxon signed-rank tests. Analyses are stratified because pooling node types aggregates strata whose correlations differ by a factor of four (Node $\rho = 0.138$ to Application $0.597$), leaving the pooled figure ($0.217$) at less than two fifths of the stratum this paper actually scores on. We do not claim a strict Simpson reversal on this corpus: pooled correlation exceeds the Node stratum. Because folds share training graphs, test observations exhibit positive dependence; nominal Wilcoxon $p$-values are optimistic and interpreted descriptively. Primary non-parametric evidence rests on 12-fold sign consistency, though sign tests over overlapping splits inherit positive dependence as well. Furthermore, synthetic graphs derive from a single generator family, bounding empirical generalizability.

\noindent\textbf{Repeatability.} Seed spread and run-to-run displacement are distinct quantities, and only the former is reported in Table~\ref{tab:7}. At fixed code and fixed seeds the pipeline is deterministic: two consecutive executions of the zero-shot transfer experiment reproduced every reported figure exactly, learned and training-free alike. Across a code revision, however, the two halves behave differently. Re-executing the in-distribution grid at identical seeds and against the identical corpus digest, after intervening changes to the codebase, reproduces all $120$ training-free cells exactly (maximum $|\Delta\rho| = 0.0000$), while the $240$ learned cells move by up to $0.93$ at the level of an individual seed-cell and $0.21$ at the level of a scenario mean (AV/\texttt{HGT}, $0.637 \rightarrow 0.845$) --- a displacement exceeding the $+0.085$ primary contrast. The same revision moved the real-world active stratum itself, cutting $n_{>0}$ by between $26\%$ and $56\%$ per system, so $\rho_{>0}$ figures are not comparable across code revisions even though each is individually reproducible. The practical consequence is that a learned figure in this paper is pinned by the commit its artifact names and not merely by its seed, whereas a structural figure is pinned by the corpus alone; the provenance stamp carried by every artifact (Data Availability) is what makes that distinction checkable rather than assumed.

\subsection{Limitations and Future Work}
\label{sec:8.4}

\noindent\textbf{Correction of the Real-World Baseline.} On raw multigraphs, betweenness vanishes for Application nodes; evaluating on \texttt{DEPENDS\_ON} flow projections enables \texttt{Topo-QoS} across all five real-world systems (Table~\ref{tab:9b}).

\noindent\textbf{Explanation Layer Validation.} SaG separates Availability from Fault Tolerance, but human studies have not yet validated actionability. Elicited AHP weights perform worse than a uniform prior at ranking (Section~\ref{sec:7.3}); user evaluations and mutation benchmarks are prioritized for future work.

\noindent\textbf{Uncontrolled Confounds in Typing.} Table~\ref{tab:contrasts} holds substrate, training set, depth, and early stopping constant, but parameter capacity ($434{,}620$ vs. $28{,}168$) and reverse message directionality ($103{,}725$ reverse-relation parameters in \texttt{HGTConv}) remain unmatched. Because $I^*(v)$ measures downstream reachability, upstream visibility confers an advantage unrelated to typing; the $+0.134$ effect reflects the joint transition to HGT. Registered control variants (\texttt{GAT-N-C}, \texttt{GAT-N-QoS-C}, \texttt{HGT-QoS-U}) are prioritized to isolate these factors.

\noindent\textbf{Absence of Live Incident Telemetry.} Ground-truth simulation oracles ($I^*(v)$, $I_{\text{comp}}$, $I_{\text{dyn}}$, $I_M$) derive from simulation and static fault injection. While ensuring determinism and byte-identical regeneration, this does not replace post-mortem incident logs, distributed tracing (e.g., OpenTelemetry spans), or physical chaos experiments on live clusters. Validating topological cascades against production outages remains an essential prerequisite for industrial adoption.

\noindent\textbf{Model Selection and Incremental Caching.} Early stopping employs an inner validation split on the primary graph; held-out scenario validation is a prioritized extension. Prediction dispersion does not reliably signal out-of-distribution fallback (Section~\ref{sec:7.2.1}). Production deployment requires incremental graph caching over pull request diffs to amortize feature extraction.

\noindent\textbf{Future Directions.} Key extensions include: (1) modeling distributed LLM serving backbones (vLLM, DeepSpeed); (2) measuring hardware energy via RAPL/NVML to benchmark static gating against live sweeps in joules; and (3) advancing to prescriptive synthesis, generating automated pull requests with circuit breakers.
