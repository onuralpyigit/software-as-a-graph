\section{Discussion, Threats to Validity, and Limitations}
\label{sec:8}

\subsection{Discussion and Practical Consequences}
\label{sec:8.1}

\noindent\textbf{When to use Topo-QoS, and when to use HGT-QoS.}
The findings do not support an unequivocal recommendation of the learned model over the closed-form alternative; we present empirical trade-offs directly.

\begin{itemize}\tightlist
\item \textbf{Training-free ranking (\texttt{Topo-QoS}) vs.\ Simulation.} \texttt{Topo-QoS} eliminates training, checkpoint storage, and tuning, achieving $\rho = 0.553$ zero-shot across twelve synthetic architectures and $0.526$ across five open-source systems. Crucially, on large-diameter architectures ($N \ge 500$, such as the 520-node Enterprise ESB in Table~\ref{tab:drivers}), \texttt{Topo-QoS} achieves $\rho = 0.795$ vs.\ \texttt{HGT-QoS}'s $0.461$, because global shortest-path betweenness resolves systemic bottlenecks that fixed 3-hop convolutions localize. Learned models do not yield statistically significant ranking gains ($+0.085$, $p = 0.151$, 95\% CI spanning zero). \texttt{Topo-QoS} thus serves as the zero-maintenance default for scalar ranking in resource-constrained CI. Alternatively, where queue parameters exist and graphs are small ($N < 150$), direct simulation ($0.08$--$4.5\,\text{s}$) offers exact ground truth without approximation.
\item \textbf{When to deploy \texttt{HGT-QoS}.} \texttt{HGT-QoS} is justified when systems feature dense, irregular topologies with multi-tenant shared library or host dependencies under $N < 150$, where relational attention gains $+0.210$ to $+0.229$ over \texttt{Topo-QoS} (e.g., on Cloud Microservices and ATM), and when teams require scoring of unsimulated non-runnable entities (physical hosts, shared packages) that node-level simulation leaves unscored. Otherwise, untyped QoS-weighted GNNs offer a superior efficiency trade-off ($\rho = 0.604$ with $28{,}168$ parameters vs.\ \texttt{HGT-QoS}'s $0.638$ with $434{,}620$), as combining typing and QoS yields minimal additive benefit.
\item \textbf{Capabilities without a closed-form counterpart.} Per-relation attention (Section~\ref{sec:7.3.4}) offers a typed diagnostic, but measured spread across relation types is narrow ($0.15$--$0.23$) and governed by destination in-degree, making it active but diagnostically unreliable on present evidence.
\item \textbf{Ingestion boundary.} Deployment must condition on communication synchrony (Table~\ref{tab:drivers}): on asynchronous pub-sub systems (ROS~2, DDS, MQTT, Kafka) \texttt{HGT-QoS} transfers positively on active components, whereas on the synchronous Train-Ticket call tree it inverts and should not be deployed — use static call-graph reachability tools instead. \texttt{Topo-QoS} is not the substitute: it is negative on the active components of both RPC meshes.
\end{itemize}

\noindent\textbf{Dual-Engine Consensus Protocol.}
Because prediction dispersion $\hat{\sigma}$ correlates negatively with margin over \texttt{Topo-QoS} ($\rho_s = -0.126$, Section~\ref{sec:7.2.1}), automated fallback is withdrawn. Instead, SaG executes dual-prediction evaluating \texttt{HGT-QoS} and \texttt{Topo-QoS} concurrently, flagging unanimous top-$K$ nodes and highlighting divergent rankings for review.

\noindent\textbf{Role of the Explanation Layer.}
The RM profile ($Q(v)$, Section~\ref{sec:5}) provides standards-compliant architectural diagnostics under ISO/IEC 25010. While neural and centrality predictors govern triage priority, RM decomposes structural mechanics to inform refactoring (distinguishing SPOF Availability replication from cascade Fault Tolerance circuit breakers). However, elicited AHP weights rank worse than a uniform prior; pending user studies, we recommend the uniform prior.

\subsection{Performance and Computational Sustainability Implications}
\label{sec:8.2}

\noindent\textbf{What sustainability means for a pre-deployment gate.}
Green software engineering assesses energy across development, assurance, and execution \cite{calero2015green,schwartz2020greenai,strubell2019energy,patterson2021carbon,georgiou2022greenframeworks,lannelongue2021green,verdecchia2023greenai}. While live chaos sweeps require cluster-hours across provisioned nodes, pre-deployment static analysis eliminates cloud staging footprints. Direct physical energy measurement in joules requires dedicated hardware counters (RAPL, NVML) and profilers \cite{lannelongue2021green,schmidt2021codecarbon,noureddine2021joularjx}, which we outline as an instrumentation protocol for future testbeds.

\noindent\textbf{Where the cost actually sits.}
We withdraw the efficiency claim: cold static analysis does not reduce CPU computation over simulation. Global connectivity degradation ($79.3\,\text{s}$ on Enterprise) is roughly eighteen times slower than cascade traversal ($4.5\,\text{s}$) due to CDI's $O(|V|^2 + |V||E|)$ cost. In CI, sustainability requires incremental caching: caching base metrics across commits and extracting features only for PR delta subgraphs reduces latency to the sub-second forward pass ($56\,\text{ms}$). We emphasize this is an engineering hypothesis: delta latency depends on the PR diff's topological centrality (leaf worker vs.\ central broker), and benchmarking commit-diff extraction across PR topologies is prioritized.

\subsection{Threats to Validity}
\label{sec:8.3}

\noindent\textbf{Construct Validity.} Ground-truth impact $I^*(v)$ derives from simulation rather than live outages. While $I^*$ correlates with dynamic queue flow $I_{\text{dyn}}$ ($\rho = 0.627$ against a $0.811$--$1.000$ ceiling, Section~\ref{sec:7.3.convergent}), top-$K$ Jaccard reaches only $0.27$--$0.37$, and $I^*(v)$ is recovered at $\rho = 0.965$ by topology-only relabeling, confirming the target captures reachability rather than runtime queue collapse or retry storms. Validating topological cascades against production incident telemetry remains the central empirical frontier. Additionally, transcribing open-source architectures into multigraphs relied on standardized heuristics without multiple independent coders.

\noindent\textbf{Internal Validity.} Feature leakage is prevented by strict graph separation: predictors consume $G_{\text{analysis}}$, while simulation oracles traverse $G_{\text{structural}}$ (CI-asserted). Parity is maintained via matched datasets, depths, and early stopping. Comparing \texttt{HGT-QoS} to \texttt{GAT-N-QoS} conflates typing with a $15.4\times$ capacity gap ($434{,}620$ vs.\ $28{,}168$) and bidirectional passing ($103{,}725$ reverse parameters in \texttt{HGTConv}), requiring registered control variants (\texttt{GAT-N-C}, \texttt{GAT-N-QoS-C}, \texttt{HGT-QoS-U}, Section~\ref{sec:8.4}) to isolate. Six active QoS dimensions govern profiles, with one reserved extension point.

\noindent\textbf{External Validity.} The corpus comprises 2,812 components across seventeen architectures spanning six domains: robotics (ROS~2), smart cities, healthcare, finance, enterprise ESB, and edge IoT (EdgeX Foundry, Home Assistant). Heterogeneity exposes the active-stratum boundary condition: pub-sub cascades propagate forward via starvation ($\rho_{>0} \in [+0.262, +0.770]$, Table~\ref{tab:9b}), whereas synchronous RPC microservices cascade backward along call trees via timeouts \cite{zhou2021fault}, where active correlation inverts ($-0.071$) and baselines fail (Table~\ref{tab:9c}). Directional biases must condition on synchrony. Scaling beyond 2,000 nodes requires incremental caching or mini-batching (GraphSAINT \cite{zeng2020graphsaint}).

\noindent\textbf{Conclusion Validity.} Distributions are evaluated using non-parametric correlations (Spearman $\rho$, Kendall $\tau$), bootstrap intervals ($B = 2{,}000$), and Wilcoxon signed-rank tests. Analyses are stratified because pooling node types conflates disparate strata (Node $\rho = 0.138$ vs.\ Application $0.597$), leaving the pooled figure ($0.217$) at less than two fifths of the evaluated stratum. Because folds share training graphs, nominal Wilcoxon $p$-values are optimistic and interpreted descriptively alongside 12-fold sign consistency; synthetic graphs derive from a single generator family.

\noindent\textbf{Repeatability.} Seed spread and run-to-run displacement are distinct quantities; only the former is reported in Table~\ref{tab:7}. At fixed code and seeds the pipeline is deterministic: consecutive runs reproduced every reported figure identically. Across code revisions, re-executing at identical seeds and corpus digests reproduced all $120$ training-free cells identically ($|\Delta\rho| = 0.0000$), while the $240$ learned cells moved by up to $0.93$ at seed level and $0.21$ at scenario mean (AV/\texttt{HGT}, $0.637 \rightarrow 0.845$)---exceeding the $+0.085$ contrast. Revisions also altered the active stratum ($n_{>0}$ shift $26\%$--$56\%$), making $\rho_{>0}$ non-comparable across revisions. Learned figures are pinned to commit artifacts; provenance tracking in Data Availability makes this auditable.

\subsection{Limitations and Future Work}
\label{sec:8.4}

\noindent\textbf{Correction of the Real-World Baseline.} On raw multigraphs, betweenness vanishes for Application nodes; evaluating on \texttt{DEPENDS\_ON} flow projections enables \texttt{Topo-QoS} across all five real-world systems (Table~\ref{tab:9b}).
\textbf{Explanation Layer Validation.} Elicited AHP weights perform worse than a uniform prior at ranking (Section~\ref{sec:7.3}); user studies and mutation benchmarks are prioritized.
\textbf{Uncontrolled Confounds in Typing.} Table~\ref{tab:contrasts} holds substrate, depth, and training splits constant, but capacity ($434{,}620$ vs.\ $28{,}168$) and reverse directionality ($103{,}725$ parameters in \texttt{HGTConv}) remain unmatched; the $+0.134$ effect reflects the joint transition to HGT. Registered control variants (\texttt{GAT-N-C}, \texttt{GAT-N-QoS-C}, \texttt{HGT-QoS-U}) are prioritized to isolate these factors.
\textbf{Absence of Live Incident Telemetry.} Simulation oracles ($I^*, I_{\text{comp}}, I_{\text{dyn}}, I_M$) ensure determinism but do not replace incident logs or chaos tests; validating topological cascades against production outages remains essential.
\textbf{Model Selection and Incremental Caching.} Early stopping uses an inner validation split; held-out scenario validation is a prioritized extension. Prediction dispersion fails as an out-of-distribution fallback signal (Section~\ref{sec:7.2.1}). Practical CI deployment requires incremental graph caching over PR diffs.
\textbf{Future Directions.} Key extensions include: (1) modeling hybrid distributed architectures (e.g., synchronous REST/gRPC frontends feeding asynchronous Kafka pipelines) by conditioning edge directional semantics on synchrony (\texttt{SYNCHRONOUS\_CALL} with backward timeout cascading vs.\ \texttt{PUBLISH\_SUBSCRIBE} with forward starvation); (2) modeling distributed LLM serving backbones (vLLM, DeepSpeed); (3) measuring hardware energy via RAPL/NVML in joules; and (4) advancing to prescriptive synthesis generating pull requests with circuit breakers.
