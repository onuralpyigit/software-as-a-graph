\section{Discussion, Threats to Validity, and Limitations}
\label{sec:8}

\subsection{Discussion and Practical Consequences}
\label{sec:8.1}

\noindent\textbf{When to use Topo-QoS, and when to use HGT-QoS.}
The findings do not support an unequivocal recommendation of the learned model over the closed-form alternative; we present empirical trade-offs directly.

\textbf{(1)~Training-free ranking (\texttt{Topo-QoS}).} Eliminates model training, checkpoint storage, or retraining, achieving $\rho = 0.553$ zero-shot across twelve synthetic architectures and $0.526$ across five open-source systems. Learned models do not yield statistically significant ranking gains ($+0.085$, $p = 0.151$, 95\% CI spanning zero; and $0.888$ vs.\ $0.649$ favoring baseline on Cloud Microservices). Thus, \texttt{Topo-QoS} serves as a robust default for scalar criticality.
\textbf{(2)~One learned mechanism, not two (\texttt{GAT-N-QoS} or \texttt{HGT}).} Relation typing or QoS edge channels individually yield substantial improvements over unweighted baselines ($+0.234$ and $+0.287$, Holm-corrected $p \le 0.0015$); combining both provides minimal additional benefit. Untyped QoS-weighted GNNs offer a superior efficiency trade-off, achieving $\rho = 0.604$ with $28{,}168$ parameters vs.\ \texttt{HGT-QoS}'s $0.638$ with $434{,}620$ parameters. Unweighted homogeneous models (\texttt{GAT-N}, $\rho = 0.317$) underperform heuristics, indicating GNNs lacking relational signals fail on this task.
\textbf{(3)~Capabilities without a closed-form counterpart.} The typed model exposes one unique diagnostic: per-relation attention (Section~\ref{sec:7.3.4}). However, measured spread across relation types is narrow ($0.15$--$0.23$), governed by destination in-degree, and unstable under regeneration; it establishes that typed attention is active, not that it is diagnostically reliable. A capability argument for typed architectures remains open.
\textbf{(4)~Ingestion boundary by communication paradigm.} Practitioners should condition model selection on communication synchrony: for asynchronous pub-sub systems (ROS~2, DDS, MQTT, Kafka), \texttt{HGT-QoS} provides superior operational critical-set capture ($F_1@K = 0.50$--$0.63$). Conversely, for synchronous RPC/REST meshes, \texttt{HGT-QoS} inverts on active components due to backward failure propagation; here, \texttt{Topo-QoS} ($\rho = 0.888$) or static call-graph reachability tools should be deployed instead.

\noindent\textbf{Architectural and Systemic Drivers of Graph Learning Success.}
Across seventeen architectures, graph neural network performance is governed by five systemic factors:
\textbf{(1)~Communication synchrony.} Message-passing directional bias must align with physical failure dissemination. In pub-sub networks (ROS~2, DDS, MQTT), failures propagate forward via topic starvation, yielding positive transfer on active propagators ($\rho_{>0} \in [+0.304, +0.704]$). In synchronous call trees, failures propagate backward via timeouts and thread starvation \cite{zhou2021fault}, causing directional GNN rankings to invert ($\rho_{>0} = -0.029$ on Microservices, $-0.213$ on Train-Ticket).
\textbf{(2)~Scale and diameter.} Fixed 2-layer message passing covers diameter in small graphs ($N < 150$), but localizes in large graphs ($N \ge 500$). On 520-node Enterprise, \texttt{HGT-QoS} exhibits its largest deficit against \texttt{Topo-QoS} ($\rho = 0.461$ vs.\ $0.795$), where global shortest paths resolve bottlenecks that 2-hop convolutions miss.
\textbf{(3)~Topology and symmetry.} Symmetrical topologies hinder GNN discrimination. In centralized integration graphs (broker-hub ESB scenario, $\rho = 0.472$), peripheral spokes share isomorphic 1-hop neighborhoods, yielding near-identical node embeddings. Conversely, in dense irregular meshes (microservices, ATM), relational attention untangles multi-channel paths where centrality saturates ($+0.210$ to $+0.229$ over \texttt{Topo-QoS}).
\textbf{(4)~Relational heterogeneity.} For shared hosts or libraries inducing blast radii, typing is essential (untyped GNNs drop to $\rho = 0.317$). With declared QoS contracts, typing and QoS encodings act as empirical substitutes (Section~\ref{sec:7.2}).
\textbf{(5)~Inert-node base rates.} Between $21\%$ and $52\%$ of applications carry zero simulated impact ($I^*(v) = 0$). High inert sink fractions inflate full-population correlation via trivial inertness filtering, halving correlation when restricted to active propagators ($\rho_{>0} / \rho \approx 51\%$--$56\%$, Section~\ref{sec:7.1.active}).

\noindent\textbf{Dual-Engine Consensus Protocol.}
Earlier versions proposed automated fallback based on dispersion $\hat{\sigma}$. Because $\hat{\sigma}$ correlates negatively with margin over \texttt{Topo-QoS} ($\rho_s = -0.126$, Section~\ref{sec:7.2.1}), we withdrew that recommendation. Instead, SaG executes dual-prediction evaluating \texttt{HGT-QoS} and \texttt{Topo-QoS} concurrently, flagging unanimous top-$K$ nodes and highlighting divergent rankings for review.

\noindent\textbf{Role of the Explanation Layer.}
The RM profile ($Q(v)$, Section~\ref{sec:5}) provides standards-compliant architectural diagnostics under ISO/IEC 25010. By distinguishing single-point-of-failure exposure (Availability) from cascade reach (Fault Tolerance), RM offers actionable remediation guidance (replication vs.\ decoupling) that numeric rankers cannot supply.

\subsection{Performance and Computational Sustainability Implications}
\label{sec:8.2}

\noindent\textbf{What sustainability means for a pre-deployment gate.}
Green software engineering assesses energy across development, assurance, and execution \cite{calero2015green,schwartz2020greenai,strubell2019energy,patterson2021carbon,georgiou2022greenframeworks,lannelongue2021green,verdecchia2023greenai}. While live chaos sweeps require cluster-hours across provisioned nodes, pre-deployment static analysis eliminates cloud staging footprints, though verifying exact energy reductions requires hardware counters \cite{lannelongue2021green,schmidt2021codecarbon,noureddine2021joularjx}.

\noindent\textbf{The efficiency claim we withdraw, and where the cost actually sits.}

We withdraw the previously stated efficiency claim: cold static analysis does not reduce CPU computation over simulation. Global connectivity degradation ($82.7\,\text{s}$ on Enterprise) is eleven times slower than cascade traversal ($7.2\,\text{s}$) due to the $O(|V|^2 + |V||E|)$ cost of CDI. In continuous integration, sustainability is achieved strictly via incremental graph caching: caching base metrics across commits and extracting features only for pull-request delta subgraphs reduces gating latency to the sub-second forward pass ($56\,\text{ms}$). Without caching, static analysis consumes more CPU time and energy than the simulation it was designed to displace.

\subsection{Threats to Validity}
\label{sec:8.3}

\noindent\textbf{Construct Validity.} Ground-truth impact $I^*(v)$ is derived from discrete-event simulation rather than live production outages. While $I^*$ correlates with dynamic queue flow $I_{\text{dyn}}$ ($\rho = 0.627$ against a $0.811$--$1.000$ ceiling, Section~\ref{sec:7.3.convergent}), top-$K$ Jaccard reaches only $0.27$--$0.37$. Furthermore, $I^*(v)$ is recovered at $\rho = 0.965$ by topology-only relabeling, showing the target captures topological reachability ($I_{\text{reach}}$) rather than runtime anomalies. The learned models act as structural surrogates for cascade simulation; no oracle is measured against production telemetry, bounding empirical construct validity.

\noindent\textbf{Internal Validity.} Feature leakage is prevented by strict graph separation: predictors consume $G_{\text{analysis}}$, while simulation oracles traverse $G_{\text{structural}}$ (CI-asserted). Parity is maintained via matched training sets, depths, and early stopping. However, the typing comparison between \texttt{HGT-QoS} and \texttt{GAT-N-QoS} conflates relational typing with a $15.4\times$ capacity gap ($434{,}620$ vs.\ $28{,}168$) and bidirectional message passing ($103{,}725$ backward parameters), requiring three registered control variants (\texttt{GAT-N-C}, \texttt{GAT-N-QoS-C}, \texttt{HGT-QoS-U}, Section~\ref{sec:8.4}) to isolate. Six active QoS dimensions govern profiles, with one reserved extension point.

\noindent\textbf{External Validity.} The evaluation covers twelve synthetic scenarios and five open-source systems. Zero-shot transfer does not generalize to active components (mean $\rho_{>0} = +0.265$, inverting on microservice call trees, Section~\ref{sec:7.4.learned}). As Zhou et al.~\cite{zhou2021fault} document, microservices cascade backward along call trees via timeouts and retry storms, whereas pub-sub cascades propagate forward via starvation. GNN directional biases must be conditioned on communication synchrony. Scaling beyond 2,000 nodes requires incremental caching or mini-batching (GraphSAINT \cite{zeng2020graphsaint}).

\noindent\textbf{Conclusion Validity.} Heavy-tailed distributions are evaluated using non-parametric correlations (Spearman $\rho$, Kendall $\tau$), bootstrap confidence intervals ($B = 2{,}000$), and Wilcoxon signed-rank tests. All analyses are strictly stratified to prevent Simpson’s paradox (pooled $\rho = 0.098$ vs. per-type $0.119$--$0.566$). Zero-excluded metrics isolate ranking from inertness detection. Folds share ten training graphs, and synthetic graphs are derived from a single generator family, which bounds empirical generalizability.

\subsection{Limitations and Future Work}
\label{sec:8.4}

\noindent\textbf{Correction of the Real-World Baseline.} Earlier versions omitted \texttt{Topo-QoS} from Table~\ref{tab:9b} due to computing betweenness on raw multigraphs rather than \texttt{DEPENDS\_ON} projections. Because all five open-source adapters declare QoS parameters (or middleware defaults), \texttt{Topo-QoS} is now reported across all systems.

\noindent\textbf{Explanation Layer Validation.} SaG separates Availability from Fault Tolerance, but human studies have not yet validated practitioner actionability. Elicited AHP weights perform worse than a uniform prior at ranking (Section~\ref{sec:7.3}); user evaluations and counterfactual mutation benchmarks are prioritized for future work.

\noindent\textbf{Uncontrolled Confounds in Typing.} Table~\ref{tab:contrasts} holds substrate, training set, depth, and early stopping constant, but parameter capacity ($434{,}620$ vs. $28{,}168$) and reverse message directionality ($103{,}725$ parameters in \texttt{HGTConv}) remain unmatched. Because $I^*(v)$ measures downstream reachability, upstream visibility confers an advantage unrelated to typing. The $+0.134$ main effect must be interpreted as the joint transition to HGT rather than isolated relational typing. Three registered control variants---\texttt{GAT-N-C}, \texttt{GAT-N-QoS-C}, and \texttt{HGT-QoS-U}---are prioritized for subsequent iterations to isolate these factors.

\noindent\textbf{Absence of Live Incident Telemetry.} Ground-truth metrics ($I^*(v)$, $I_{\text{dyn}}$, $I_{\text{reach}}$) are generated via discrete-event simulation and static topological fault injection. While ensuring reproducibility, determinism, and byte-identical scenario regeneration, this does not substitute for empirical post-mortem incident logs, distributed tracing (e.g., OpenTelemetry spans), or physical chaos experiments on live clusters. Validating whether topological cascades align with real-world outage dynamics in production remains an essential prerequisite for industrial adoption.

\noindent\textbf{Model Selection and Caching.} Early stopping employs an inner validation split on the primary graph; held-out scenario validation is a prioritized extension. Prediction dispersion does not reliably signal out-of-distribution fallback (Section~\ref{sec:7.2.1}). Production deployment requires incremental graph caching over pull request diffs to amortize $O(|V|^2 + |V||E|)$ feature extraction.

\noindent\textbf{Future Directions.} Key extensions include: (1) modeling distributed LLM serving backbones (vLLM, DeepSpeed); (2) measuring hardware energy directly via RAPL/NVML to benchmark static gating against live chaos sweeps in joules; and (3) advancing from predictive diagnostics to prescriptive synthesis, generating automated pull requests with circuit breakers and broker replicas.
