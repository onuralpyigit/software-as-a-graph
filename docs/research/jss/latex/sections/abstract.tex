Publish--subscribe middleware decouples distributed components, obscuring failure propagation before deployment when telemetry is unavailable. Graph learning has been applied to component criticality, but whether accuracy stems from the learning algorithm or the dependency representation remains unexamined. We present Software-as-a-Graph (SaG), which derives explicit dependency graphs from declarative architecture specifications. We evaluate analytical, hybrid, and learned rankers across twelve synthetic architectures, three failure simulators, and five stylized open-source system models. An order-$k$ reference criterion separates rankings that restate a simulator's propagation rule from those predicting it, preventing circular validation.

On a reachability simulator, graph attention on the derived dependency graph reaches Spearman's $\rho = 0.748$, $+0.072$ above the same model with reverse edges on the raw multigraph, where co-primary contrasts were null. Counting direct dependents ($\rho = 0.764$) is not significantly different from the learned model. For a queue-flow simulator requiring $12.7$ CPU-hours of labeling, a rate-weighted first-order approximation reaches $\rho = 0.830$ in milliseconds, exceeding a learned approximation trained on its labels ($\rho = 0.799$; exploratory); learners that start from the formula do not improve on it. In zero-shot transfer, learned models and dependency counts separate inert from active components ($\rho \approx 0.81$ vs.\ $0.53$), though active-stratum discrimination remains weak.

On these simulators, whose propagation is first-order by construction, representation provided the predictive signal. Learning did not outperform aligned analytical references. We recommend evaluating graph learning against low-order analytical references aligned with the simulation oracle, while training-free dependency analysis enables rapid pre-deployment review.
