Assessing distributed system dependability before deployment is hindered by absent runtime telemetry and static code analysis's blindness to communication topology. We present Software-as-a-Graph (SaG), a static system analysis framework that constructs typed multigraphs from Architecture-as-Code manifests across five entity types. SaG pairs two parameter-independent pathways: a relation-specific Heterogeneous Graph Transformer (HGT) with Quality-of-Service (QoS) edge encodings to forecast cascading failure blast radii, and an interpretable ISO/IEC 25010 layer that attributes fragility to Availability (single points of failure) or Fault Tolerance (cascade hubs) to guide targeted repairs.

Across seven synthetic scenarios and three open-source reference systems (Autoware.universe ROS~2, GCP Online Boutique, Train-Ticket), empirical results show: (1) under distribution shift, relation typing provides a decisive generalization advantage under strict substrate and feature parity ($\rho = 0.608$ vs.\ $0.363$, 8/8 folds, $p = 0.0078$), whereas in-distribution performance matches untyped models ($\rho = 0.653$ vs.\ $0.630$, $p = 0.938$), showing that typing is an inductive generalization bias rather than a fitting advantage; (2) against a training-free QoS-weighted centrality baseline, the learned model achieves comparable ranking ($+0.037$, $p = 0.64$) and critical-set identification ($F_1@K = 0.414$ vs.\ $0.380$; 4/8 folds, $p = 0.47$); (3) SaG transfers zero-shot to reference systems ($\rho = 0.685$--$0.778$), though its release gate passes on none of them; and (4) an HGT forward pass takes $43.7\,\text{ms}$ for 2{,}000 components, with the full gate executing in $0.02$--$27.4\,\text{s}$. Training a neural model is thus justified by relational attention, per-relationship criticality, and standards-grounded attribution, not by ranking accuracy alone.
