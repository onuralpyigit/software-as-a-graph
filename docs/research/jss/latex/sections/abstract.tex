Publish--subscribe middleware decouples producers and consumers, improving scalability but obscuring the dependency chains along which one component's failure cascades. Runtime telemetry does not exist before deployment, and code-level static analysis is blind to system-level topology, so identifying which components are critical, and why, remains difficult. We present \textbf{Software-as-a-Graph (SaG)}, a pre-deployment \textbf{Static System Analysis} framework modeling a pub-sub system as a typed, weighted, directed multigraph over five component classes with logical dependencies derived through typed projection rules. On this representation we train a relation-specific \textbf{Heterogeneous Graph Transformer} to forecast cascading failure impact, paired with an interpretable Reliability--Maintainability (RM) attribution baseline, both validated against discrete-event cascade simulators operating on a structurally disjoint view of the same model under an input--label independence guarantee. Across seven synthetic topologies and three graphs transcribed from open-source architectures we report four results. \textbf{(1)} Typed learning leads the strongest non-learning baseline on rank correlation (\(\rho = 0.730\) vs \(0.595\)), though a paired test does not establish that margin; the critical-set advantage is more robust (\(F_1@K = 0.465\) vs \(0.308\)). \textbf{(2)} Heterogeneity's advantage is concentrated in generalisation, not in-distribution fit. \textbf{(3)} The two cascade oracles used as ground truth agree only weakly (\(\rho = 0.394\)), bounding construct validity. \textbf{(4)} Edge criticality, measured by simulated removal rather than inferred, shows most individual links replaceable. SaG also runs as a blocking CI/CD quality gate in well under a minute even at 500+ components, though its anti-pattern catalog's agreement with the cascade oracle is modest and the gate is currently absolute rather than delta-aware.
