Publish--subscribe middleware decouples components in space and time, and in doing so hides the paths along which failures cascade. Architects need to know which components are systemically critical before deployment, when no runtime telemetry exists. We present Software-as-a-Graph (SaG), a framework that turns architecture models into typed multigraphs and, through six publish--subscribe rules, derives an explicit graph of logical dependencies. It ranks components by cascading-failure impact with closed-form, learned and hybrid engines, and explains each flagged component with an ISO/IEC 25010 reliability and maintainability profile. Under leave-one-scenario-out cross-validation over twelve synthetic architectures, the derived dependency graph is the decisive ingredient. Counting a component's dependents on it ranks simulated cascade impact at Spearman $\rho = 0.764$, above closed-form centrality on all twelve held-out architectures and far above counting raw connections ($+0.565$). On hand-authored models of five open-source systems, counting transitive dependents reaches $\rho = 0.938$ without any training. Graph neural networks gain $+0.08$ to $+0.11$ when they read the dependency graph instead of the raw multigraph, reaching $\rho = 0.758$: level with dependency counting, not above it. Hybrid engines, in which a learned model corrects closed-form centrality, beat that centrality on 11 of 12 architectures under decision rules registered before their runs. Declared Quality-of-Service contracts help learned engines through three node-level coupling features. Dependency counting takes milliseconds. Deriving explicit dependency graphs from architecture models thus makes cascading-failure risk rankable before deployment.
