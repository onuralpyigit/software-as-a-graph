Publish--subscribe middleware decouples producers and consumers, improving scalability but obscuring the dependency chains along which one component's failure cascades. Runtime telemetry is absent before deployment and code-level static analysis is blind to system-level topology, so identifying \emph{which} components are critical --- and \emph{why} --- remains difficult. We present \textbf{Software-as-a-Graph (SaG)}, a pre-deployment \textbf{Static System Analysis} framework that models a pub-sub system as a typed, weighted multigraph and derives logical dependencies through typed projection rules. On this representation we train a relation-specific \textbf{Heterogeneous Graph Transformer} to forecast cascading failure impact, and pair it with an interpretable score decomposing criticality into Reliability, Maintainability, Availability and Vulnerability (RMAV). Both are compared against discrete-event cascade simulators under an input--label independence guarantee. Across seven synthetic topologies and three graphs transcribed from open-source architectures we report four results. \textbf{(1)} Typed learning leads the strongest non-learning baseline on rank correlation (\(\rho = 0.730\) vs \(0.595\)), though unconfirmed by a paired test; the critical-set advantage is more robust (\(F_1@K = 0.465\) vs \(0.308\)). \textbf{(2)} Attribution earns its place as explanation rather than accuracy: equal dimension weights outperform the calibrated weighting. \textbf{(3)} The two cascade oracles agree only weakly (\(\rho = 0.394\)), bounding construct validity. \textbf{(4)} Edge criticality is measured by removal rather than inferred, showing most links replaceable. Finally, SaG operates as a blocking CI/CD gate, evaluating a candidate topology in under a minute, though the anti-pattern catalog's agreement with the cascade oracle is modest, and the gate is currently absolute rather than delta-aware.
