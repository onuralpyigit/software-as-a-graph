Modern distributed software---publish--subscribe middleware and microservices---decouples components to achieve scalability, but that decoupling obscures how cascading failures propagate across message brokers, topics, shared libraries, and host nodes. Detecting systemically critical components \emph{before} deployment is hard precisely because operational telemetry does not yet exist, and static code analysis cannot observe distributed communication topology. Uncontained cascades that reach production trigger costly downtime, emergency restart loops, and wasted energy.

We present \textbf{Software-as-a-Graph (SaG)}, an AI-driven framework for pre-deployment reliability analysis that represents a distributed architecture as a typed multigraph over Applications, Brokers, Topics, Execution Nodes, and Shared Libraries. Its primary instrument is a \textbf{predictive pathway}: a relation-specific \textbf{Heterogeneous Graph Transformer (HGT)} that learns multi-layer propagation patterns to forecast cascading failure blast radii, rank critical components, and score per-relationship criticality from Architecture-as-Code manifests alone. Because a rank says \emph{where} to act but not \emph{what to do}, SaG pairs the predictor with an \textbf{explanation layer}: an interpretable Reliability--Maintainability attribution model grounded in ISO/IEC 25010 and 25019 that diagnoses the structural root cause of a flagged component's fragility. The two share no parameters, and only the predictor is scored against the simulation oracle.

We evaluate SaG on 1,770 components from seven synthetic scenarios and three real-world open-source systems (Autoware.universe ROS~2, GCP Cloud Microservices, Train-Ticket) against independent discrete-event cascade simulators under a strict input--label independence guarantee:
\begin{itemize}
    \item \textbf{Typing decides transfer.} On unseen architectures the typed model reaches \(\rho = 0.608\); relation-specific typing alone accounts for \(+0.353\) over its homogeneous counterpart (\(\rho = 0.439\) vs.\ \(0.086\)), winning all eight cross-scenario folds (\(p = 0.008\)). QoS edge encoding adds \(+0.169\) out of distribution (7/8 folds, \(p = 0.016\)).
    \item \textbf{Critical-set identification and CI/CD-viable cost.} The predictor identifies the critical top-\(K\) set better than any alternative evaluated (\(F_1@K = 0.414\)), and inference costs \(44\,\text{ms}\) on a 2,000-component system --- two orders of magnitude below the structural analysis feeding it, making per-commit architectural gating practical.
    \item \textbf{An explicit boundary.} Against a training-free QoS-weighted structural baseline the ranking advantage is \(+0.037\) and \emph{not} significant (\(p = 0.64\)). We report this directly: graph learning earns its cost through transfer to unfamiliar architectures and through the typed attention, multi-task outputs, and relationship-level criticality it supplies alongside the ranking, not through ranking accuracy alone.
    \item \textbf{Real-world generalization.} SaG transfers zero-shot to authentic cyber-physical and cloud-native systems (\(\rho = 0.688\) to \(0.778\)), capturing up to \(100\%\) of failure-impactful services within the predicted critical set.
\end{itemize}

By enabling automated architectural analysis inside CI/CD before deployment, SaG bridges the Architecture--Code Gap, fostering resilient, dependable, and energy-efficient software systems.
