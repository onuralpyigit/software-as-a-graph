\section{Ranking Methods, Simulation Oracles, and the Reference Criterion}
\label{sec:4}

The study compares analytical rankings derived directly from dependency structure (the training-free baseline \texttt{Topo-QoS}, QoS-weighted betweenness on the dependency graph, and the references of Section~\ref{sec:6.2}), hybrid methods that correct an analytical prior with a learned model, and learned methods: graph neural networks on the typed multigraph or the dependency graph, and gradient-boosted models on per-Application features (Figure~\ref{fig:engines}). All are trained on or evaluated against simulation oracles that run on a separate graph view (Section~\ref{sec:4.3}). Full hyperparameters and training commands are in the replication repository's experiment pages (Section~\ref{sec:6.1}).

\subsection{Heterogeneous Graph Transformer and Attention Networks}
\label{sec:4.1}

The main learned ranker, \texttt{HGT-QoS}, is a three-layer Heterogeneous Graph Transformer (HGT) \cite{hu2020hgt} built with PyTorch Geometric \cite{fey2019fast}. It uses a hidden dimension of $D=64$ and $H=4$ heads; on the dependency graph, which has fewer relation types, \texttt{HGT-P-QoS} uses width $100$ so that its parameter count ($430{,}680$) stays within $1\%$ of \texttt{HGT-QoS} ($434{,}620$). Entity-specific linear projections map raw node features $x_v \in \mathbb{R}^{19\text{--}25}$ into the hidden space, with $h_v^{(0)} = \text{LayerNorm}(\text{GELU}(W_{\tau(v)} x_v))$. For each meta-relation $\langle \tau(u), \phi(e), \tau(v)\rangle$, attention uses type-parameterized keys, queries, and values, scaled by a learned per-meta-relation prior $\mu_{\langle \tau(u), \phi(e), \tau(v)\rangle}$; full layer-wise formulations are in Supplementary Section~\ref{supp:hgt}. HGT passes messages over its input graph and its transpose: $G_{\text{structural}}$ for \texttt{HGT-QoS} and the \texttt{DEPENDS\_ON} projection for \texttt{HGT-P-QoS}. The GATs pass messages forward only, except the direction control \texttt{GAT-QoS-R}, which also passes every edge in reverse. In the raw multigraph $G_{\text{structural}}$, native relations point away from Applications (e.g., \texttt{PUBLISHES\_TO}, \texttt{RUNS\_ON}, \texttt{USES}), so forward message passing cannot propagate messages to the scored Application nodes, and forward GNNs on it collapse into per-node models over precomputed features (Section~\ref{sec:8.2}). The dependency graph directs edges from dependents to dependencies, so forward message passing aggregates information from each Application's dependents. The homogeneous Graph Attention Network (\texttt{GAT-QoS}, and \texttt{GAT-P-QoS} on the dependency graph) uses a three-layer architecture with four attention heads and width $D=288$ ($D=296$ in the unweighted control for parameter matching), projecting all node types into a joint embedding space before applying homogeneous \texttt{GATConv} layers.

Each directed edge has a 16-dimensional vector. Index 0 represents the coupling weight, index 1 is the normalized path count, indices 2 to 8 are a one-hot encoding of the relation, and indices 9 to 15 are middleware QoS parameters such as reliability, durability, priority, transport departure mode, deadline constraints, and max-blocking time. The edge vector is projected and added before attention. Because indices 2 to 8 encode the relation, the ``untyped'' \texttt{GAT-QoS} receives relation identity as an edge feature. This matters only where messages reach Applications: on the raw multigraph forward GAT messages never do, and on the dependency projection every edge carries the same relation, so the encoding is constant.

\subsection{Prediction Head and Training Objective}
\label{sec:4.2}

A composite head predicts the simulated cascade impact, supplemented by an auxiliary head $\hat{a}_1$ regressing on $I^*_R$, the reliability component that the same simulator run records beside $I^*$. The operational training objective combines mean-squared error regression with listwise and margin-ranking terms:
\begin{equation}
\label{eq:loss_active}
\mathcal{L} = \text{MSE}(\hat{I}^*, I^*) + 0.5 \cdot \text{MSE}(\hat{a}_1, I^*_R) + 0.3 \cdot \mathcal{L}_{\text{rank}} + 0.1 \cdot \mathcal{L}_{\text{pairwise}},
\end{equation}
where $\mathcal{L}_{\text{rank}}$ is Listwise Maximum Likelihood Estimation (ListMLE) \cite{xia2008listwise} over the permutation $\pi$ induced by the simulated labels,
\begin{equation}
\label{eq:listmle}
\mathcal{L}_{\text{rank}} = -\frac{1}{N}\sum_{i=1}^N \Big( \hat{s}_{\pi_i} - \log \sum_{j=i}^N \exp(\hat{s}_{\pi_j}) \Big),
\end{equation}
and $\mathcal{L}_{\text{pairwise}}$ is a margin-ranking loss with $\gamma = 0.05$ over pairs differing by more than $\gamma$. Tied labels, which affect about 31\% of Applications with $I^* = 0$, enter $\pi$ in input order, which is the generator's creation order. This injects an arbitrary ordering among inactive nodes into ListMLE; the margin-ranking term ignores pairs separated by less than $\gamma = 0.05$, and a control that permutes node order before training tests whether the ordering leaks into the results (Section~\ref{sec:rq2}).

Models are trained with AdamW ($\eta = 3 \times 10^{-4}$, weight decay $10^{-4}$) using cosine warm restarts for up to 300 epochs. We set early stopping at 60 epochs of patience on a 20\% node-level validation split from the largest training scenario of each fold (when the corpus's largest scenario is held out, the next largest takes its place), using five fixed seeds ($\{42, 123, 456, 789, 2024\}$); while this node-level split is transductive with respect to that scenario's internal graph, all reported evaluations are strictly inductive under leave-one-scenario-out cross-validation. We set hyperparameters and loss coefficients before the first sweep and kept them the same across all experiments. This approach differs from the registered plan, which called for selecting every hyperparameter using nested inner-LOSO selection (two-fold inner holdout). Instead, the published results use one fixed configuration, chosen during the main experiments to keep computation manageable across seeds and folds. We explain this difference in Section~\ref{sec:6.3}. We ran the registered selection later as a sensitivity analysis on the eight-configuration stage-1 grid (varying depth and rank normalization of features and labels). That harness also holds one training scenario out for early stopping, so it trains on one scenario fewer and stops on a different signal; it therefore compares two protocols, not only two hyperparameter choices, which is why it does not reproduce the published scores on the folds where it selected the published configuration (Section~\ref{sec:rq2}). The main null finding does not change under nested tuning.

\subsection{Simulation Oracles}
\label{sec:4.3}

Labels come from three failure simulators (``oracles''), which define different notions of cascade impact rather than observations of real failures and run on the raw multigraph $G_{\text{structural}}$:
\begin{itemize}\tightlist
    \item \textbf{Primary reachability cascade oracle ($I^*$):} Crashes component $v$, propagates outages through dependent topics, brokers and links via breadth-first traversal on $G_{\text{structural}}$, and computes the mean fractional feed loss across intact subscribers. Feed loss is scaled by a declared, uncalibrated QoS severity ladder ($\times 1.2$ \texttt{RELIABLE}, $\times 1.15$ high priority, $\times 1.05$ medium) and clamped to $[0, 1]$. Each propagation wave is processed in a seeded random order, which decides ties at the propagation threshold; the label is the mean over five seeds. Disabling QoS scaling leaves the Application ordering largely intact ($\rho = 0.965$ across the twelve folds), and substituting durability-aware rescaling moves it less still ($\rho = 0.977$), showing that $I^*$ is predominantly a topological reachability metric.
    \item \textbf{Queue-flow discrete-event oracle ($I_{\text{dyn}}$):} A discrete-event SimPy \cite{team2020simpy} simulation of message emission rates, queue saturation and network latency that measures the drop in delivered message rate for surviving consumers, using declared rates, payload sizes and QoS contracts that $I^*$ ignores. QoS policies act on the queues (drop order on overflow, durable replay, priority, deadlines and lifespans, history depth); no run with them disabled was made, so its sensitivity to QoS is not quantified. Its mechanism differs from reachability, but its first-order effect, consumers losing a failed publisher's messages, is again subscriber loss, and it models configured parameters, not operating-system dynamics. It provides labels for all $1{,}321$ Applications, averaging over five seeds, and takes $12.7$ CPU-hours for the full corpus, compared to seconds for $I^*$. A sensitivity check restricted to the first $30$ Applications per fold in lexicographic order is reported in Supplementary Section~\ref{supp:round8} (Table~\ref{tab:r8-n30}). $I_{\text{dyn}}$ agrees with $I^*$ at a mean $\rho = 0.711$ $[0.625, 0.794]$. Across seeds, a single $I_{\text{dyn}}$ run agrees with another at $\rho = 0.43$--$0.96$ per fold; the five-seed mean used as the label has an estimated reliability of $r = 0.79$--$0.99$ (Spearman--Brown), so no ranker can agree with it by more than $\sqrt{r} \approx 0.89$--$0.996$ per fold. Every ranker in Table~\ref{tab:independent_oracles} stays below even $r$ on every fold; per-fold values are in the replication package.
    \item \textbf{Composite multi-criteria failure oracle ($I_{\text{comp}}$):} An auxiliary benchmark uses the Validate-stage failure simulator. We run it on all $1{,}321$ Applications with QoS weighting and a primed baseline flow. Each removal is scored as a linear combination of four degradation components: $I_{\text{comp}}(v) = 0.35\,\text{RL}(v) + 0.25\,\text{FR}(v) + 0.25\,\text{TL}(v) + 0.15\,\text{FD}(v)$, representing Reachability Loss ($\text{RL}$), Fragmentation ($\text{FR}$; $0.70$ structural component loss $+\,0.30$ severity), Throughput Loss ($\text{TL}$), and Flow Disruption ($\text{FD}$). The weights are declared, not elicited, so $I_{\text{comp}}$ serves as a declared multi-objective stress test of fragmentation and throughput disruption rather than just subscriber loss. Since fragmentation and flow disruption occur with almost every removal, $I_{\text{comp}}(v) > 0$ for nearly every Application. $I_{\text{comp}}$ is never used as a training label.
\end{itemize}

\subsection{Input--Label Separation and the Reference Criterion}
\label{sec:4.4}

No simulation output is used as an input: features are computed on $G_{\text{analysis}}$ and labels come only from the oracles (a regression test enforces this), although the raw-graph learners pass messages over the structural edges the oracles traverse.

Procedural separation does not remove construct overlap: a ranking may agree with a simulator because it reproduces the simulator's rule rather than because it infers impact from independent evidence.

\noindent\textbf{The reference criterion.} We defined the criterion post hoc, after simple dependency counts performed strongly, and state it here in operational form. A ranking $R$ is an \emph{order-$k$ reference} for an oracle $O$ if $R$ is what $O$ computes when its propagation is truncated after $k$ waves, with stated simplifications, from the same inputs $O$ reads. Whether a ranking qualifies is therefore decided by derivation from the simulator's definition, not by its score. For $I^*$: the first-order expansion (Eq.~\eqref{eq:analytic_istar}) is the expected feed loss after one wave; \texttt{InDeg} is the support of that first wave, its size without the per-topic fractions (Remark~1; classical publish--subscribe afferent coupling \cite{martin2003agile,rud2006ais}); and \texttt{Reach} is the unweighted support of the untruncated cascade. For $I_{\text{dyn}}$, the rate-weighted expansion (Eq.~\eqref{eq:rate-expansion}) is the delivered-rate loss after one wave, ignoring queueing. A reference measures how much of $O$ its own rule recovers, a property of the oracle rather than predictive skill, so comparisons with it are not claims of superiority. All other rankers, namely the training-free baseline and the learned and hybrid methods, are \emph{predictors}. For $I_{\text{comp}}$, no ranking is a truncation; its fragmentation and flow terms respond to removing high-degree and high-betweenness nodes, so \texttt{Topo-QoS} and raw degree are \emph{term-aligned} with it. They are not references under the definition above, but their performance is interpreted with the same caution. How much of each oracle its own rule recovers is read directly from the reference rows: the first-order expansion reaches $\rho = 0.808$ on $I^*$, and the rate-weighted expansion $0.830$ on $I_{\text{dyn}}$ (Tables~\ref{tab:hybrid} and~\ref{tab:independent_oracles}). The learned methods are not references by this definition, but this does not make them less circular: they are fitted to the oracle they are scored against and read features that compute part of it (Section~\ref{sec:3.5}). We therefore apply the same accounting to them, reporting each learner's agreement with $I^*$ after the first-order expansion is partialled out (Section~\ref{sec:rq1}), and learners with the oracle-aligned features removed (Section~\ref{sec:rq2}). Two analyses limit the circularity without removing it: every ranker is scored on all three oracles, and its agreement with $I_{\text{dyn}}$ is also reported after removing $I^*$ or the first-order term (Section~\ref{sec:rq1}). Neither replaces validation against real failures (Section~\ref{sec:8.3}).
