$|V|$ is the sum of all five entity-type counts per scenario and sums to exactly the corpus total stated above. $|E|$ counts every raw structural relationship instance recorded in the scenario file (\texttt{PUBLISHES\_TO}, \texttt{SUBSCRIBES\_TO}, \texttt{ROUTES}, \texttt{RUNS\_ON}, \texttt{CONNECTS\_TO}, \texttt{USES}) --- the substrate the simulation oracles traverse --- not the denser derived \texttt{DEPENDS\_ON} projection used for GNN training.

The three real-world architectures are hand-transcribed from open-source repositories using dedicated architectural adapters. The seven synthetic scenarios are produced by a parameterised topology generator: each is fully specified by a committed configuration giving a random seed, per-entity-type counts, seven-number summaries (mean, median, standard deviation, min, max, $Q_1$, $Q_3$) for application publish and subscribe fan-out, for applications per host, for library fan-in and for topic payload size, and categorical distributions over the three QoS dimensions. Degree distribution and clustering are \emph{emergent} from those inputs rather than specified directly. \subsubsection{Reproducibility of the Corpus}
\label{sec:6.1.repro}

The corpus is regenerable rather than merely archived. Each dataset is produced from its configuration by

\begin{quote}
\texttt{python cli/generate\_graph.py batch --input-dir data/scenarios --output-dir <dir>}
\end{quote}

\noindent and a manifest records, per dataset, the seed, the entity counts, the generating commit, and a SHA-256 digest of the emitted topology. A regression test asserts that every committed dataset regenerates \emph{byte-identically} from its configuration and that the manifest matches what is on disk, so a divergence between the published numbers and the published data fails the test suite rather than passing unnoticed. A third party can therefore reproduce the exact graphs these results were computed on, not merely graphs drawn from the same distribution.

\subsection{Baselines and Evaluated Predictors}
\label{sec:6.2}

We compare four primary predictor configurations, split into training-free baselines and the learned predictors proposed in this paper:
\begin{enumerate}
    \item \textbf{Topo-BL} (baseline): Unweighted structural centrality (betweenness centrality and articulation point scoring).
    \item \textbf{Topo-QoS} (baseline): QoS-weighted topological centrality baseline.
    \item \textbf{GL / GL-QoS} (proposed): Homogeneous Graph Attention Networks (GAT) \cite{velickovic2018graph} trained on the flattened, untyped graph projection.
    \item \textbf{HGL / HGL-QoS} (proposed): Relation-specific Heterogeneous Graph Transformers (Section~\ref{sec:5}).
\end{enumerate}
\noindent The out-of-distribution table (Table~\ref{tab:7}) additionally reports \textbf{RM / $Q(v)$} (the deterministic hierarchical quality attribution model of Section~\ref{sec:4}) as a non-competing diagnostic reference point, not as a fifth predictor: RM is not fitted to rank components, and its row exists to show how much the predictive path adds over static attribution (Section~\ref{sec:1.2}), not to compete on ranking accuracy. The same deterministic RM scorer is also the instrument behind every sensitivity sweep in Section~\ref{sec:7.3}: because RM is a closed-form function of its declared constants, sweeping those constants isolates their effect from training variance in a way the learned predictors cannot.

\subsection{Evaluation Metrics and Protocols}
\label{sec:6.3}

\begin{itemize}
    \item \textbf{Ranking Accuracy:} Spearman rank correlation ($\rho$) and Kendall's tau ($\tau$) between predicted rankings and ground-truth simulated impact $I^*(v)$, the primary oracle declared in Section~\ref{sec:5.1}.
    \item \textbf{Critical-Set Identification:} $F_1@K$, Precision@$K$, and Recall@$K$ for top-$K$ critical components, where $K$ is $20\%$ of the evaluated node population, rounded to nearest. Because the predicted and true sets both contain exactly $K$ elements, precision, recall and $F_1$ coincide at $K$; the figure is a top-$K$ overlap and we read it as such.
    \item \textbf{Statistical Significance:} Paired Wilcoxon signed-rank tests \cite{wilcoxon1945individual} ($p < 0.05$) and bootstrap 95\% confidence intervals ($B = 2,000$) \cite{efron1993introduction,spearman1904proof}.
\end{itemize}

\subsubsection{Evaluation Population}

Every predictor in a given table is scored on an identical node set, resolved from the graph and the labels alone --- never from any variant's predictions --- so that no comparison is confounded by which nodes a particular method happened to score. Unless stated otherwise that set is the \textbf{Application} population: it is the population the framework's central claim is about (topology predicts application-layer cascade criticality), and it is the only one every variant can score. This matters more than it may appear. Pooling node types into a single correlation mixes populations with different impact scales and base rates, and on this corpus that pooling is not benign --- it moves the RM composite's rank correlation \emph{outside} the range spanned by its own per-type correlations (Section~\ref{sec:7.3}). We therefore report stratified, single-population figures throughout, and flag explicitly wherever a pooled figure appears.

\subsubsection{Evaluation Protocols}
\begin{itemize}
    \item \textbf{In-Distribution Evaluation:} 60\% train / 20\% validation / 20\% test node splits pinned by node identity within each scenario, evaluated over five random seeds $\{42, 123, 456, 789, 2024\}$.
    \item \textbf{Inductive Leave-One-Scenario-Out (LOSO):} Across all eight cached scenarios (the seven synthetic scenarios plus the ATM case study, Section~\ref{sec:7.4}), models are trained on the remaining seven and evaluated zero-shot on the held-out scenario, for eight folds total, to test out-of-distribution generalizability.
    \item \textbf{Real-World Architectural Transfer:} Evaluating zero-shot transfer on authentic open-source architectures.
\end{itemize}
