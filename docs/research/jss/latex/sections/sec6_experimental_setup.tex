\section{Experimental Setup}
\label{sec:6}

The design asks whether ranking performance originates from the dependency representation or from the learning algorithm operating on it: RQ1 compares learned approaches with analytical rankings derived from the same dependencies, and RQ2 isolates the contributions of representation, degree information, oracle-aligned features, relation typing, QoS information and model family.

\subsection{Corpus and Replication Package}
\label{sec:6.1}

The corpus includes 2,812 components from seventeen architectures (see Table~\ref{tab:4}). Twelve synthetic topologies make up the LOSO folds, covering areas like autonomous vehicles, financial trading, healthcare, industrial SCADA, smart-city IoT, telecom RAN, logistics, gaming, microservices, enterprise integration, and air-traffic management. Because all twelve topologies and their code metrics come from the same family, LOSO tests transfer across several parameter settings of that generator, not across unrelated industrial systems. We can regenerate each topology exactly from its configuration, and continuous integration checks this using a SHA-256 manifest.

The five open-source systems are hand-crafted models. Autoware.universe (ROS~2), EdgeX Foundry, Home Assistant, and two meshes based on Online Boutique and Train-Ticket were each created by the first author as typed multigraphs using public architectural documentation. We did not mechanically extract them from source code or container manifests, and no second modeler re-derived any of them, so modeler bias is possible and not quantified (Section~\ref{sec:threats}). Brokers, QoS profiles, code metrics and host specifications are partly assumed. Online Boutique and Train-Ticket are RPC systems: we decomposed each synchronous call into a request topic and a reply topic mediated by broker channels (Online Boutique becomes a 22-application mesh with four brokers; Train-Ticket's service-discovery registry acts as the broker), which keeps the bidirectional dataflow but drops timeouts, thread-pool exhaustion and synchronous backpressure (per-system composition in Supplementary Section~\ref{supp:corpus}). Consequently, no topology in this study comes from a real deployment manifest: SaG's derivation is exercised only on generated and hand-authored inputs, and RQ3 tests transfer to stylized single-modeler models, not to real production systems.

Replication package. All datasets, harnesses, checkpoints, and result artifacts are stored on Zenodo (see Data Availability). In addition, the public repository provides documentation for each experiment, including its protocol, hyperparameters, \texttt{make} target, artifacts, and extended results (\sagexperiments).

Table~\ref{tab:predictor_taxonomy} groups the rankers as analytical, hybrid and learned; other training-free baselines (Degree-raw, PR-raw, RevPR-raw, Topo) and smaller or projection variants are in Supplementary Sections~\ref{supp:baselines} and~\ref{supp:taxonomy}. Analytical rankings that restate a simulator's rule are listed as references, not predictors. For GNNs, ``-QoS'' means the 16-dimensional QoS edge vector (Section~\ref{sec:4.1}) plus three QoS node columns ($w$, $w_{\text{in}}$, $w_{\text{out}}$), and ``Hybrid-X'' is model X corrected by the baseline prior. \noindent\textbf{Training-free baseline.} \texttt{Topo-QoS} is computed on the Application--Library \texttt{DEPENDS\_ON} graph (Rules 1 and 5):
\begin{equation}
\label{eq:topo}
\text{Topo-QoS}(v) = 0.6 \cdot \text{BT}_{w}(v) + 0.4 \cdot \text{AP}(v),
\end{equation}
where $\text{BT}_{w}$ is betweenness over edge distances $d(e) = 1/(w(e) + 10^{-6})$, so tightly coupled edges attract shortest paths, and AP flags articulation points. Because of an implementation defect (an index mismatch when the articulation scores are read), the AP term is zero for every node, so the score that was executed, and that every table reports, is QoS-weighted betweenness alone. Restoring the term lowers \texttt{Topo-QoS} from $0.553$ to $0.533$, so the defect does not favor the reference counts; Table~\ref{tab:hybrid} reports the corrected value beside it, and hybrids retrained on the corrected prior are reported in Section~\ref{sec:rq1}. The comparator was fixed when the analysis plan was written, before the dependency counts had been analyzed, and continues the closed-form score family of \cite{yigit2025graph}; in hindsight, afferent coupling would have been the natural comparator, and it is reported beside the baseline as a reference. The unweighted Topo baseline is reported in Supplementary Section~\ref{supp:baselines}.

Three training-free rankings restate the reachability oracle’s propagation rule and are reported as references. The first is the post hoc first-order expansion of $I^*$ (Analytic $I^*$):
\begin{equation}
\label{eq:analytic_istar}
\hat{I}^*_1(v) = \sum_{t \in \text{pub}(v)} \frac{|\text{sub}(t)|}{|\text{pub}(t)|},
\end{equation}
where $|\text{pub}(t)| \ge 1$ holds for all published topics $t \in \text{pub}(v)$ by construction ($v$ publishes to $t$), preventing any division by zero. The second is \texttt{InDeg}$(v)$, the number of direct dependents of $v$ on the Application--Library \texttt{DEPENDS\_ON} graph, which for an Application equals publish–subscribe afferent coupling and is exactly the set $I^*$'s first wave reaches (Remark~1). The third is \texttt{Reach}$(v)$, the number of its transitive dependents normalized by $|V| - 1$, which is the set a reachability cascade can visit. For the queue-flow simulator $I_{\text{dyn}}$, the corresponding reference is the rate-weighted first-order expansion
\begin{equation}
\hat{I}^{\mathrm{rate}}_{\mathrm{dyn},1}(v) \;=\; \sum_{t \in \mathrm{pub}(v)} \frac{r_t}{|\mathrm{pub}(t)|}\,\lvert \mathrm{sub}(t) \rvert,
\label{eq:rate-expansion}
\end{equation}
where $r_t$ is the declared publication frequency of topic $t$. Eq.~\eqref{eq:rate-expansion} weights each term of the first-order expansion of $I^*$ (Eq.~\eqref{eq:analytic_istar}) by the topic's declared publication rate. It is therefore a first-order truncation of the queue-flow simulator $I_{\text{dyn}}$, which reads the same rates, and it is reported as a reference for $I_{\text{dyn}}$ rather than as a predictor. It was evaluated after the registered analyses and is exploratory. It is the natural reference for learned approximations of that simulator, and in practice a training-free ranking for queue-flow impact (Section~\ref{sec:8.1}). Raw-multigraph topic counts (Pubs-raw) and transitive closure without Rule~5 (Reach-R1) are archived in the replication repository. References carry no contrast against \texttt{Topo-QoS}, and a learner’s distance from them is reported as such, not as a test. The one exception is the paired comparison between the rate-weighted reference and the learned queue-flow approximation (Section~\ref{sec:rq1}), which is labeled exploratory.

\subsection{Metrics, Protocols and Statistics}
\label{sec:6.3}

\noindent\textbf{Population.} Every ranker is scored on the Application set $V_{\text{app}}$.

Metrics. We use Spearman $\rho$ to measure ranking against the simulation oracles. To distinguish between active components and those with zero impact, we report both the full-population Spearman $\rho$ and the active-stratum Spearman $\rho_{>0}$, which only includes components with true impact greater than zero. To identify critical sets, we use Overlap@$K$, the fraction of the true top-$K$ recovered by the predicted top-$K$, where $K$ is about 20\% of $|V_{\text{app}}|$. PR-AUC, $F_1@\tau$, and nDCG@10 are reported in Supplementary Section~\ref{supp:identification}.

Protocols. In the LOSO setup, we train learned models on eleven scenarios and test on the twelfth, repeating this for all 12 folds and five random seeds. The reported value is the average $\rho$ across seeds. For zero-shot transfer, we evaluate models built on all twelve scenarios across the five system models without any fine-tuning. Training-free rankers are not fitted to any data, so for them, both protocols become per-scenario analyses on the same twelve scenarios and five models. We include them in the same tables to ensure every row is scored on the same scenarios and labels.

Statistics. The analysis emphasizes effect sizes with confidence intervals rather than a single winner; ``matches'' means not significantly different, not statistically equivalent (Section~\ref{sec:threats}). The summary $\rho$ is the mean Spearman correlation over folds or systems, with a 95\% bootstrap interval over folds ($B = 2{,}000$) \cite{efron1993introduction}; contrasts use paired two-sided Wilcoxon signed-rank tests across folds \cite{wilcoxon1945individual,arcuri2011practical} (smallest attainable $p = 0.00049$), and, because LOSO folds share ten of eleven training scenarios, every registered contrast is also tested with the Nadeau--Bengio corrected resampled $t$-test \cite{nadeau2003inference}. As the effect size we report the number of folds on which a ranker beats its comparator (``won''), the paired probability of superiority; the unpaired Vargha--Delaney $\hat{A}_{12}$ does not apply to fold-paired data. Fisher-$z$ averaging does not change the row order of Table~\ref{tab:hybrid}; weighting folds by $|V_{\text{app}}|$ changes it for \texttt{Topo-QoS} (Section~\ref{sec:rq1}). Spearman $\rho$ gives ties their average rank; Overlap@$K$ breaks ties at the boundary by node order, so Section~\ref{sec:rq1} also reports tie-aware recall.

\noindent\textbf{Analysis plan and the status of each result.} The protocol is pre-specified in the replication repository with commit timestamps, not lodged with a third-party registry; seventeen numbered amendments were registered, none withheld. Every result has one of three tiers. \emph{Confirmatory}: the plan's two co-primary contrasts (\texttt{HGT-QoS} and \texttt{HGT} vs.\ \texttt{Topo-QoS}, Holm across the two), both null. \emph{Registered secondary}: arms committed before they ran but after the primary null was known, including the matched $2\times2$, the hybrids, the reference counts, the derivation value, the full-population queue-flow labels, the sensitivity, direction and corrected-prior arms, and the oracle-aligned-feature, node-order and learning-on-Eq.~\eqref{eq:rate-expansion} controls, each Holm-corrected within its family. \emph{Exploratory}: post hoc analyses, the dependency-graph learners' contrasts (declared exploratory when the arms were registered), the reference reclassification (which changed no figure), and the rate-weighted reference (Eq.~\eqref{eq:rate-expansion}) with the attribution of the learned queue-flow approximation. \textbf{Plan deviation}: the registered nested selection was replaced by one fixed configuration, with the registered rule run later as a sensitivity check (Section~\ref{sec:rq2}). Because sequential amendments accumulate family-wise error, an omnibus Holm correction is also applied across the 13 decision-bearing contrasts: the two co-primary contrasts, the two hybrids against \texttt{Topo-QoS} and against their base learners, the three effects of the matched $2\times2$, and four typing controls (\texttt{HGT-QoS} against \texttt{GAT-QoS}, \texttt{GAT-w} and \texttt{HGT-QoS-U}, \texttt{HGT} against \texttt{GAT}). The hybrid contrasts survive it (Hybrid-GAT $p_{\text{omni}} = 0.019$, Hybrid-HGT $p_{\text{omni}} = 0.041$) and the primary contrast stays null ($p_{\text{omni}} \ge 0.46$); the amendment log (Supplementary Section~\ref{supp:amendments}) lists every family. The headline findings of this paper are therefore registered secondary or exploratory, not confirmatory.

Taken together, the rankers allow comparison of representation-centric and model-centric explanations of ranking performance. If performance arises primarily from the dependency representation, analytical and learned rankers built on that representation should perform similarly. If learning adds information, learned rankers should outperform analytical alternatives built on the same dependencies. Section~\ref{sec:7} reports the results against these two expectations.
