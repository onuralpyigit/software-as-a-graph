\section{Conclusion}
\label{sec:9}

Software-as-a-Graph (SaG) creates clear dependency graphs from publish--subscribe deployment manifests and ranks components based on simulated cascade impact before deployment. We tested several learned cascade-impact rankers, including graph neural networks on both the raw multigraph and the dependency graph, hybrid engines, and gradient-boosted surrogates. We compared these to a training-free baseline across twelve synthetic architectures and five hand-crafted open-source system models, using three failure-propagation simulators.

\begin{enumerate}\tightlist
    \item \textbf{Derived dependency graphs enable accurate cascade prediction.} Creating explicit dependency graphs gives neural models the message-passing paths they need. Graph attention networks reached a Spearman correlation of 0.748 for reachability cascades in leave-one-scenario-out cross-validation, and transferred well to stylized models based on open-source systems with 0.805--0.806. However, within-cascade discrimination dropped on the active stratum, where it remained at or below 0.342. Causal ablation studies show that the model's accuracy matches the first-order reference of 0.764 by using degree features, which means neural attention can learn topological cascade rules.
    \item \textbf{Factored analysis clarifies graph learning biases.} Preregistered comparisons show that relation typing does not improve accuracy when model capacity is matched, and the main difference from the training-free baseline was not significant ($+0.069$, $p = 0.266$). Rather than indicating a weakness, this marks the limits of graph learning in software systems: on raw multigraphs where messages cannot reach target nodes, complex neural models add extra parameters without improving performance.
    \item \textbf{Learned surrogates improve results for costly dynamic oracles.} In high-fidelity dynamic queue-flow simulation, labeling the data took 12.7 CPU-hours. A learned surrogate that combines analytical expansion, rate, and payload features with dependency-graph properties achieved 0.799 on held-out architectures, clearly outperforming all closed-form approximations (0.706; Holm p = 0.019). This shows that machine learning surrogates can capture complex runtime queuing dynamics and declared QoS contracts better than analytical formulas.
    \item \textbf{Hybrid graph architectures prevent structural fragmentation.} In multi-criteria failure conditions ($I_{\text{comp}}$), where outages split the network and reduce throughput, pure neural models perform worse ($\le 0.334$). Hybrid engines that combine neural models with domain knowledge maintain stable performance on familiar architectures ($\rho = 0.585$). Together, these results show hybrid architectures are needed for complex failure modes similar to training data, while pure learned models transfer better to very different systems ($0.760$--$0.805$ vs. $0.662$--$0.695$).
    \item \textbf{A sustainable two-tiered approach for continuous deployment.} Timing and energy measurements provide a practical plan for Green CI/CD. When the oracle is fast, like reachability ($<1$~s), static counting uses very little energy ($\sim 0.086$~Wh) and works well as a zero-cost triage filter for developer commits. When simulation is more demanding, like dynamic queue-flow ($\sim 355.6$~Wh), learned surrogates reduce the carbon footprint by providing sub-second inference for staging pipelines. Taken together, this balances predictive accuracy with sustainability and helps prevent developer alert fatigue.
\end{enumerate}

By turning complex publish--subscribe deployment manifests into clear dependency graphs and using learned surrogates to speed up heavy simulations, Software-as-a-Graph provides a practical and sustainable base for AI-assisted architecture design and ongoing resilience engineering. Although testing against real-world production incidents is still a goal for future work, our results show that connecting static graph models with continuous deployment pipelines creates a practical and eco-friendly path to resilient distributed software systems.
