\section{Conclusion}
\label{sec:9}

Software-as-a-Graph (SaG) derives explicit dependency graphs from publish--subscribe deployment manifests and ranks components by simulated cascade impact before deployment. We used it to benchmark closed-form centrality, dependency counts, graph neural networks and hybrid engines on twelve synthetic architectures and five hand-authored models of open-source systems, against three simulators.

The registered primary contrast, a heterogeneous graph transformer against weighted centrality, was null. In exploratory analyses, the simplest ranker won: counting a component's direct dependents, which is publish--subscribe afferent coupling and a typed two-hop query on the raw graph, ranked reachability-simulated impact at $\rho = 0.764$ and beat centrality on all twelve synthetic architectures. That agreement is largely by construction, because the reachability simulator's first propagation wave is the same count. On a queue-flow simulator the count kept a partial correlation of $0.259$ beyond the reachability oracle, on a sample of 30 Applications per fold; on a multi-criteria simulator, weighted centrality ranked above it. Graph attention networks reading the dependency graph matched the count but never exceeded it, and no learned engine beat it on any oracle. The count identifies the critical set only moderately: catching $80\%$ of the true top fifth requires flagging the top $45\%$.

For practice, the evidence supports a modest recommendation. Once publish--subscribe dependencies are stated explicitly, afferent coupling is a cheap ordering for architectural review, computable in milliseconds, and it is the baseline that any learned ranker for this task must beat; on this benchmark none did. Whether that ordering, or any simulator it approximates, predicts real outages remains the open question.
