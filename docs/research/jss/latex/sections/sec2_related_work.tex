\section{Related Work}
\label{sec:2}

This research intersects four major domains: distributed systems dependability, static system analysis, graph representation learning for network vulnerability, and software quality models.

\subsection{Dependability in Distributed and Pub-Sub Systems}
\label{sec:2.1}

The publish--subscribe paradigm provides foundational communication decoupling for distributed systems \cite{eugster2003faces}. Formal middleware specifications---such as DDS \cite{omg2015dds}, MQTT \cite{oasis2019mqtt}, ROS~2 \cite{macenski2022robot}, and distributed commit logs like Kafka \cite{kreps2011kafka}---enable fine-grained QoS policies governing durability, liveliness, and transport reliability. Prior research on pub-sub dependability has predominantly focused on runtime mechanisms: fault-tolerant event routing, broker clustering, dynamic consensus, and adaptive message retransmission.

In parallel, runtime verification and chaos engineering \cite{basiri2016chaos} systematically inject faults into staging or production clusters to observe steady-state recovery. While essential for validating operational resilience, runtime techniques operate late in the software lifecycle, require complete infrastructure deployments, and cannot evaluate architectural alternatives during initial design. Our work addresses the complementary, pre-deployment phase: predicting cascading vulnerability from architectural models \emph{before} systems are deployed.

\subsection{Static Code Analysis vs. Static System Analysis}
\label{sec:2.2}

Traditional Static Code Analysis (SCA) analyzes source code abstract syntax trees (ASTs) to measure cyclomatic complexity \cite{mccabe1976complexity}, module coupling (e.g., LCOM, CBO) \cite{chidamber1994metrics,fenton2014metrics}, and code duplication. While SCA effectively identifies internal code smells and defect-prone modules \cite{basili1996validation,nagappan2005static,zimmermann2007predicting,menzies2007data}, it is entirely oblivious to inter-process communication, container placement, and middleware topologies.

To bridge this ``Architecture--Code Gap,'' \textbf{Static System Analysis (SSA)} elevates static analysis to the system architecture level. By modeling distributed components, message channels, and infrastructure hosts as a global dependency graph, SSA frameworks propagate code-level quality attributes across topological links. This enables continuous pre-deployment verification in modern CI/CD pipelines \cite{humble2010continuous,chen2015continuous}, catching structural anti-patterns \cite{garcia2009catalogue,garcia2009identifying,taibi2018microservice,dragoni2017microservices} and architectural degradation \cite{cunningham1992wycash,li2015technicaldebt} at commit time.

\subsection{Network Science and Graph Representation Learning}
\label{sec:2.3}

Network science offers established metrics for identifying critical network elements, including degree, closeness, betweenness centrality \cite{freeman1977centrality,brandes2001faster}, articulation points, and PageRank \cite{brin1998pagerank,newman2010networks}. Studies on random failure tolerance \cite{albert2000error}, cascading overload \cite{motter2002cascade}, and interdependent networks \cite{buldyrev2010cascade} have provided deep mathematical foundations for systemic vulnerability. However, standard network metrics suffer from two fundamental limitations when applied to software architectures:
\begin{enumerate}
    \item \emph{Dimensional Collapse:} A single centrality score cannot distinguish a structural Single Point of Failure (SPOF) from an error-propagating cascade hub or a high-maintenance bottleneck.
    \item \emph{Semantic Collapse:} Discarding node and edge types treats an asynchronous pub-sub topic the same as a physical host or a shared library, masking distinct failure propagation mechanics.
\end{enumerate}

To overcome the limitations of hand-engineered graph metrics, recent research has applied machine learning on graphs for network dismantling and criticality estimation (e.g., FINDER \cite{fan2020keyplayers}, DrBC \cite{fan2019learning}, and PowerGraph \cite{varbella2024powergraph}). However, most existing models rely on homogeneous message passing (GCN \cite{kipf2017semi}, GraphSAGE \cite{hamilton2017inductive}, GAT \cite{velickovic2018graph}). Because distributed middleware is inherently multi-typed and heterogeneous, homogeneous aggregation mixes fundamentally incompatible semantic relationships. Heterogeneous Graph Neural Networks (RGCN \cite{schlichtkrull2018rgcn}, HAN \cite{wang2019han}, HGT \cite{hu2020hgt}, MAGNN \cite{fu2020magnn}) address this by parameterizing relation-specific transformations. We build upon the Heterogeneous Graph Transformer (HGT) architecture \cite{hu2020hgt} to maintain typed relational semantics during cascade impact forecasting.

\subsection{Software Quality Models and Multi-Criteria Evaluation}
\label{sec:2.4}

Software product quality is standardized by the ISO/IEC 25010:2023 product quality model \cite{iso25010_2023} (comprising nine characteristics including Reliability, Maintainability, and Security) and the ISO/IEC 25019:2023 Quality-in-Use standard \cite{iso25019_2023} (evaluating stakeholder harm over Beneficialness, Freedom from Risk, and Acceptability). Quality evaluation distinguishes between \emph{internal quality} (measured statically on software artifacts at rest) and \emph{external quality} (measured dynamically on executing systems) \cite{iso25023_2016,iso25021_2012}.

Synthesizing multi-attribute structural metrics into actionable quality indices constitutes a classic Multi-Criteria Decision Making (MCDM) problem. The Analytic Hierarchy Process (AHP) \cite{saaty1980ahp} provides a mathematically rigorous pairwise-comparison framework equipped with an explicit Consistency Ratio ($CR \le 0.10$) to validate expert weighting schemes. In this work, we use AHP to construct an audited, interpretable Reliability--Maintainability attribution baseline that serves as a transparent benchmark for our learned GNN models.
