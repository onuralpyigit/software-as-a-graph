\section{Related Work}
\label{sec:2}

This research intersects four foundational domains: distributed systems dependability, static system analysis, software quality models, and graph representation learning.

\subsection{Dependability in Distributed and Pub-Sub Systems}
\label{sec:2.1}

The publish--subscribe (pub-sub) paradigm decouples communication components to achieve high scalability in distributed software \cite{eugster2003faces}. Modern middleware standards---such as ROS~2 \cite{macenski2022robot}, Apache Kafka \cite{kreps2011kafka}, DDS \cite{omg2015dds}, and MQTT \cite{oasis2019mqtt}---support fine-grained Quality-of-Service (QoS) policies governing message durability, transport reliability, and delivery deadlines. Prior dependability research has focused predominantly on \textbf{runtime mechanisms}, including dynamic consensus protocols, broker clustering, adaptive retransmission, and automated failover.

In parallel, \textbf{chaos engineering and runtime verification} \cite{basiri2016chaos} inject simulated faults into running staging or production clusters to observe recovery behavior. While runtime fault injection is valuable for testing operational infrastructure, it has fundamental limitations:
\begin{itemize}
    \item It requires fully deployed, operational testbeds.
    \item It carries operational risk if run near production.
    \item It operates too late in the software lifecycle to evaluate alternative architectural designs before systems are built.
\end{itemize}

Our work addresses the complementary \textbf{pre-deployment phase}: predicting systemic cascading vulnerabilities directly from Architecture-as-Code descriptors before runtime infrastructure is provisioned.

\subsection{Static Code Analysis (SCA) vs. Static System Analysis (SSA)}
\label{sec:2.2}

Traditional \textbf{Static Code Analysis (SCA)} tools (such as SonarQube) inspect source code Abstract Syntax Trees (ASTs) within individual services. They evaluate cyclomatic complexity \cite{mccabe1976complexity}, class cohesion, module coupling (e.g., LCOM, CBO) \cite{chidamber1994metrics,fenton2014metrics}, and duplicated code to flag internal code smells and defect-prone components \cite{basili1996validation,nagappan2005static,zimmermann2007predicting,menzies2007data}. However, SCA cannot observe runtime communication topology: it is blind to inter-service messaging channels, message broker queues, and cross-host container placement.

To bridge this ``Architecture--Code Gap,'' \textbf{Static System Analysis (SSA)} extends static analysis from single-service source code to the global system architecture. By modeling distributed applications, message topics, brokers, execution nodes, and shared libraries as a connected graph, SSA propagates code-level metrics across architectural dependencies. This allows software teams to identify structural anti-patterns \cite{garcia2009catalogue,taibi2018microservice} and architectural technical debt \cite{li2015technicaldebt} early during continuous integration (CI/CD) \cite{humble2010continuous,chen2015continuous}.

\subsection{Software Quality Models and Multi-Criteria Evaluation}
\label{sec:2.3}

Software product quality is standardized by the \textbf{ISO/IEC 25010:2023} product quality model \cite{iso25010_2023} (which defines characteristics including Reliability, Maintainability, and Performance Efficiency) and the \textbf{ISO/IEC 25019:2023} Quality-in-Use model \cite{iso25019_2023}. Software measurement distinguishes between \emph{internal quality} (measured on static artifacts at rest) and \emph{external quality} (measured on executing software) \cite{iso25023_2016,iso25021_2012}.

Combining multi-attribute structural metrics into an overall quality score is a classic Multi-Criteria Decision Making (MCDM) problem. The \textbf{Analytic Hierarchy Process (AHP)} \cite{saaty1980ahp} provides a structured pairwise-comparison method with an explicit Consistency Ratio ($CR \le 0.10$) to ensure weighting schemes remain mathematically sound. In this study, we use AHP to construct an audited, explainable Reliability--Maintainability (RM) quality baseline, providing transparent architectural diagnostics alongside our learned graph models.

\subsection{Network Science and Graph Representation Learning}
\label{sec:2.4}

Network science provides established centrality metrics to identify critical nodes, such as degree, closeness, betweenness centrality \cite{freeman1977centrality,brandes2001faster}, articulation points, and PageRank \cite{brin1998pagerank,newman2010networks}. Foundational studies on network robustness \cite{albert2000error}, cascading overloads \cite{motter2002cascade}, and interdependent networks \cite{buldyrev2010cascade} model how failures propagate across connected systems. However, standard network metrics suffer from two major limitations when applied to software architectures:
\begin{enumerate}
    \item \textbf{Dimensional Collapse:} A single centrality scalar cannot distinguish \emph{why} a component is critical---for instance, whether it is a single point of failure (SPOF), an error-propagating cascade hub, or an over-shared library.
    \item \textbf{Semantic Collapse:} Standard metrics treat all nodes and edges identically. They conflate fundamentally different architectural entities, such as an asynchronous message topic, a shared library, and a physical execution host.
\end{enumerate}

To move beyond hand-engineered graph metrics, recent research has applied machine learning to network vulnerability (e.g., FINDER \cite{fan2020keyplayers}, DrBC \cite{fan2019learning}, and PowerGraph \cite{varbella2024powergraph}). However, most existing models rely on \textbf{homogeneous message passing} (GCN \cite{kipf2017semi}, GraphSAGE \cite{hamilton2017inductive}, GAT \cite{velickovic2018graph}), which averages signals across all connections indiscriminately. Because distributed software architectures are inherently \textbf{heterogeneous} (comprising distinct entity types and relationship rules), homogeneous models blur critical architectural boundaries.

Heterogeneous Graph Neural Networks (RGCN \cite{schlichtkrull2018rgcn}, HAN \cite{wang2019han}, HGT \cite{hu2020hgt}, MAGNN \cite{fu2020magnn}) solve this by using relation-specific transformations. We build upon the \textbf{Heterogeneous Graph Transformer (HGT)} architecture \cite{hu2020hgt} to preserve typed relational semantics when forecasting cascading failure blast radii.

A learned ranker is actionable only if practitioners can interpret its underlying rationale. Attention coefficients provide the most direct signal in transformer-style architectures and are examined in Section~\ref{sec:7.3}. Perturbation- and mask-based explainers, such as GNNExplainer \cite{ying2019gnnexplainer}, instead identify the minimal subgraph that preserves a prediction. Both approaches explain a model in its own terms (which nodes and edges were influential), but neither clarifies \emph{why} a flagged component is architecturally fragile according to quality standards. Section~\ref{sec:5} addresses this gap with an explanation layer.
