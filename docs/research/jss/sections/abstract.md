# Abstract

Modern asynchronous publish-subscribe and microservice architectures present significant deployment challenges. In the absence of end-to-end visibility, these systems are vulnerable to critical outages caused by latent mismatches in middleware contracts, a phenomenon referred to as the Architecture-Code Gap. To facilitate pre-deployment reliability assessment without relying on runtime telemetry, this study introduces Software-as-a-Graph (SaG), a static analysis framework that converts Architecture-as-Code manifests into typed multigraphs comprising five principal entity types. The central assertion is that two independent analytical pathways can evaluate reliability prior to deployment: a relation-specific Heterogeneous Graph Transformer with Quality-of-Service (QoS) edge encodings (HGT-QoS) for forecasting cascade blast radii, and an interpretable, though unvalidated, ISO/IEC 25010/25019-based attribution layer that produces diagnostic remediation profiles.

Evaluation across twelve inductive scenarios and five open-source systems using simulation oracles demonstrates that relation typing and QoS encodings enhance rank correlation under distribution shift. Compared to a training-free QoS-weighted centrality baseline, the learned model does not achieve a statistically significant improvement in ranking. Zero-shot transfer attains an overall $\rho$ of $0.767$, which decreases to $+0.265$ for components that actively propagate failures and reverses on synchronous call trees. Forward inference requires $56\,\text{ms}$, whereas deterministic feature extraction results in cold static analysis being eleven times slower than direct simulation. These results support the central hypothesis that the model’s relational inductive bias and typed attention maps provide advantages under distribution shift.

**Keywords:** Heterogeneous graph neural networks; Distributed systems dependability; Publish–subscribe architecture; Cascading failures; Static system analysis; Explainable AI.
