# Abstract

Publish–subscribe middleware hides how failures cascade, leaving architects without pre-deployment evidence on which components are systemically critical. Software-as-a-Graph (SaG) models event-driven architectures as typed multigraphs, derives explicit dependency graphs from deployment manifests, and ranks components by simulated cascade impact. We benchmark closed-form centrality, graph neural networks, hybrid engines and learned surrogates on twelve synthetic architectures under leave-one-scenario-out and on five hand-authored models of open-source systems, against three simulators. The reachability simulator’s first propagation wave is exactly a component’s number of direct dependents, so dependency counts are reported as references, not predictors: its first-order expansion reaches Spearman $\rho = 0.808$ and the count $0.764$. The registered primary contrast, a heterogeneous graph transformer against weighted centrality, was null ($\Delta\rho = +0.069$, $p = 0.27$). Hybrids beat centrality ($+0.103$, $+0.130$, Holm-significant) but not their own base learners. Graph attention networks on the dependency graph reached $0.748$, statistically indistinguishable from the count but not equivalent to it, and only with their degree features. On a queue-flow simulator whose labels cost $12.7$ CPU-hours, a gradient-boosted surrogate trained on those labels ranked held-out architectures above every closed-form approximation ($0.799$ against $0.706$), and only there did declared QoS contracts carry signal. On the system models, the best learned engines reached $0.81$ zero-shot, but at most $0.34$ among components with nonzero impact. On the same graphs, one reachability simulation costs less than the learned engines’ feature extraction ($4.5$–$72\times$). Graph learning adds little where the oracle is cheap; learned surrogates pay where it is expensive.

**Keywords:** Dependency graphs; cascading failures; publish–subscribe; graph neural networks; software architecture; dependability; empirical study
