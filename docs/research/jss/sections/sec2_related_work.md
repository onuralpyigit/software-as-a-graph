# 2. Related Work

This research combines four main areas: dependability, performance, and sustainability in distributed software systems; static code and system analysis; software quality analysis and multi-criteria evaluation; and graph representation learning with explainable artificial intelligence (XAI). By bringing these fields together, we aim to predict cascading vulnerabilities arising from Architecture-as-Code descriptors before deploying runtime infrastructure. The main contribution of this work is SaG, an SSA-based approach for predicting cascade blast radii from declared topologies before deployment.

## 2.1 Dependability, Performance, and Sustainability in Distributed Software Systems

Publish-subscribe (pub-sub) and asynchronous event-driven systems separate communicating entities by space, time, and synchronization. This setup allows scalable, high-throughput operations [7]. Modern middleware like ROS 2 [1], Apache Kafka [2], DDS [3], and MQTT [4] manage these exchanges with Quality-of-Service (QoS) policies. In cloud-native microservice meshes and distributed AI or LLM serving systems, asynchronous message passing and queueing are the main ways components communicate, which directly affects latency, throughput, and hardware usage.

Earlier research on dependability and performance has focused on runtime methods like dynamic consensus, broker clustering, backpressure throttling, autoscaling, automated failover, chaos engineering, and runtime fault injection [23]. These techniques intentionally disrupt live clusters to observe how systems degrade and recover. While runtime testing yields realistic results, it requires a running cluster, can interrupt services, and uses significant computing resources. Because of these drawbacks, it is not practical during early design or for commit-level CI/CD. Green software engineering therefore focuses on development-time computations [29, 30, 31, 32, 33]. This study suggests assessing dependability from Architecture-as-Code descriptors before setting up infrastructure, using SaG to predict cascading vulnerabilities.
A solid analytical foundation supports predicting dependability from architectural descriptions. Cheung’s absorbing Markov chain model [34] calculates system reliability using component reliabilities and control flow graphs. Goseva-Popstojanova and Trivedi [35] later classified state-based, path-based, and additive approaches, as Immonen and Niemelä [36] review. Model-driven frameworks like the Palladio Component Model [37] and layered queueing networks [38] estimate performance and reliability from component specifications. Annotation-based methods, such as the AADL Error Model Annex [39], create fault trees from declared error states. These methods answer broader questions but require pre-calibrated operational profiles and failure rates, which are usually unavailable at commit time. SaG, by contrast, focuses on a specific question using only manifests: which component failures spread most widely in the system? For example, Seer [40] and Sage [41] predict Quality-of-Service (QoS) violations using hardware counters and traces, while MicroRCA [42] and TraceRCA [43] find root causes through service-dependency graphs. DeepTraLog [44], Eadro [45], and MicroCause [46] use graph neural networks to analyze traces, logs, and metrics, as Zhang et al. summarize in a survey of 98 studies [47]. Zhou et al. [48] found that in synchronous microservices, cascading outages often result from thread-pool exhaustion, RPC timeouts, and retry storms along call trees. In contrast, failures in publish-subscribe systems spread through broker queue saturation and message starvation. All these methods require a running cluster that produces runtime telemetry, but SaG offers a pre-deployment option by analyzing static manifests before code runs.

## 2.2 Static Code Analysis (SCA) vs. Static System Analysis (SSA)

Traditional Static Code Analysis (SCA) tools like SonarQube [19] examine source code Abstract Syntax Trees (ASTs) within each service. They measure cyclomatic complexity [20], class cohesion, module coupling (such as Lack of Cohesion in Methods [LCOM] and Coupling Between Objects [CBO]) [21, 22], and code duplication to find code smells and modules likely to have defects [49, 50, 51, 52]. However, SCA cannot detect runtime communication interactions, so it misses inter-service messaging, message broker queue saturation, and failures that spread across services. Bushong et al. [53] create communication diagrams from static code analysis, and a recent review covers nine architecture recovery tools [54]. In robotics and publish-subscribe systems, tools like HAROS [55] extract computation models to find structural problems before launch. This research intends to build accurate system models to help understand and detect changes. SaG, in contrast, uses a declared topology to predict cascade blast radii before deployment, focusing on prediction rather than recovery. By modeling distributed applications, message topics, brokers, execution nodes, and shared libraries as a connected multigraph, SSA carries code-level quality metrics across architectural dependencies. This approach helps engineering teams detect structural anti-patterns [56, 57] and architectural technical debt [58] early in the continuous integration (CI/CD) process [59, 60], before deploying defective topologies. In this study, SaG is the SSA-based approach used to forecast cascading vulnerabilities arising from the dependencies, which is the main contribution of the work.

## 2.3 Software Quality Models and Multi-Criteria Evaluation

The ISO/IEC 25010:2023 product quality model [13] and the ISO/IEC 25019:2023 Quality-in-Use model [14] define software product quality. From the characteristics listed under Reliability, Maintainability, and Efficiency of Performance in ISO/IEC 25010:2023, SaG uses only those that can be derived from deployment topology: Availability, Fault Tolerance, Modularity, Modifiability, and Analyzability (§5.1). The main point is that Faultlessness, Recoverability, Reusability, and Testability cannot be analyzed topologically, so SaG focuses only on the quality aspects it can measure. This selection clarifies SaG’s contribution by limiting it to topology-derived quality attributes.
Software engineering looks at both internal quality (structural features checked on static artifacts) and external quality (runtime dependability and behavior during execution) [61, 62]. In distributed systems, technical debt such as over-centralized message topics or unreplicated brokers lowers internal quality and can lead to performance bottlenecks, queue congestion, and outages.
Combining different structural metrics into a quality score is a common Multi-Criteria Decision Making (MCDM) problem. The Analytic Hierarchy Process (AHP) [63] utilizes structured pairwise comparisons and includes a Consistency Ratio ($CR \le 0.10$) to ensure consistent judgments. While this ratio can flag inconsistencies, it cannot detect matrices filled with preset answers, which this study tackles in its weighting process (§5.2). In this study, AHP creates an audited, explainable Reliability–Maintainability (RM) quality baseline that supports the main contribution by making the scoring process transparent.

## 2.4 Graph Representation Learning and Explainable AI

Network science uses centrality indicators such as degree, closeness, betweenness centrality [24, 26], articulation points, and PageRank [25, 27] to identify important nodes. Key studies on network robustness [10], cascading overloads [8], and interdependent networks [9] show how disruptions spread in connected systems. Percolation models usually compare network breakdowns, but their analytical limits consider uniform, undirected connections and cannot be solved exactly for directed multigraphs with different entity types, channel capacities, and continuous QoS contracts. Because of this, this study uses centrality-based, training-free baselines (§6.2) and suggests targeted multi-type percolation fragmentation as a useful future baseline. We use these baselines to compare SaG’s results.

Standard network measures have two main problems in software architectures. First, Dimensional Collapse happens when a single centrality value cannot explain why a component is critical, such as telling apart a single point of failure, a cascade hub, or an overused library. Second, Semantic Collapse occurs when unweighted metrics treat all nodes and edges the same, mixing up different architectural elements like message topics, shared libraries, and execution hosts.

To get past the limits of hand-crafted metrics, recent studies have used machine learning for network vulnerability analysis (such as FINDER [64], DrBC [65], PowerGraph [66]). Most models use homogeneous message passing (GCN [67], GraphSAGE [68], GAT [69]) and average signals across all connection types. Because distributed software architectures vary widely, these models blur entity boundaries and generalize poorly to new situations. Heterogeneous Graph Neural Networks (RGCN [70], HAN [71], HGT [72], MAGNN [73]) deal with this by using relation-specific transformations. This study uses the Heterogeneous Graph Transformer (HGT) [72] to keep relational types distinct when predicting cascade blast radii. Graph learning has also been used for microservice topologies; for example, Khodabandeh et al. [74] predict future service interactions using graph attention on segmented call graphs. However, that method predicts edge existence based on earlier interactions. In contrast, this method uses a declared topology to predict the blast radius after removing a node.

A major challenge in using modern AI for software engineering is the black-box problem: deep neural models produce risk scores or embeddings without explaining the underlying causes. In actual situations, these unclear risk rankings make it hard for developers and site reliability engineers (SREs) to decide whether to replicate hosts, set up circuit breakers, or refactor shared libraries. Some methods identify influential subgraphs through edge masking or parameterized learning. Although these methods help, they interpret models through internal hidden representations rather than standardized software engineering concepts. SaG tackles this problem with a decoupled dual-pathway design. The predictive HGT pathway shows typed mutual-attention distributions that indicate which architectural relationships spread the cascade (§7.3.3). At the same time, the deterministic explanation layer links fragility to standardized ISO/IEC quality sub-characteristics (§5), turning raw predictions into practical, cost-effective remediations.
