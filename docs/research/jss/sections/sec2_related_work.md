# 2. Related Work

This research lies at the intersection of four principal domains: (1) dependability, performance, and sustainability in distributed software systems; (2) static code and system analysis; (3) software quality analysis and multi-criteria evaluation; and (4) graph representation learning and explainable artificial intelligence (XAI). Together, these areas support pre-deployment static forecasting of cascading vulnerabilities from Architecture-as-Code descriptors before runtime infrastructure is provisioned.

## 2.1 Dependability, Performance, and Sustainability in Distributed Software Systems

The publish–subscribe (pub-sub) and asynchronous event-driven paradigms decouple communicating entities across space, time, and synchronization, enabling elastic scalability and high throughput [7]. Contemporary middleware standards, such as ROS 2 [1], Apache Kafka [2], DDS [3], and MQTT [4], regulate these exchanges through fine-grained Quality-of-Service (QoS) policies. Within cloud-native microservice meshes and distributed AI/LLM serving infrastructures, asynchronous message passing and queueing topologies form the primary communication substrate and directly affect tail latencies, throughput bottlenecks, and hardware utilization.

Prior research on dependability and performance has emphasized runtime mechanisms, including dynamic consensus, broker clustering, backpressure throttling, autoscaling, automated failover, chaos engineering, and runtime fault injection [23], which intentionally disrupt live clusters to observe system degradation and recovery. Although runtime testing offers realistic validation, it requires a provisioned cluster, presents risks of service disruption, and incurs considerable computational costs. These limitations restrict its use during early design phases and commit-level continuous integration and continuous deployment (CI/CD), aligning it with development-time computations addressed by green software engineering [29, 30, 31, 32, 33]. In contrast, this investigation’s core claim is that dependability can be evaluated from Architecture-as-Code descriptors before infrastructure provisioning.

A solid analytical foundation supports dependability prediction from architectural descriptions. Cheung’s absorbing Markov chain model [34] derives system reliability from component reliabilities and transfer-of-control graphs, while Goseva-Popstojanova and Trivedi [35] classify subsequent state-based, path-based, and additive approaches, as Immonen and Niemelä [36] review. Model-driven frameworks, such as the Palladio Component Model [37] and layered queueing networks [38], estimate performance and reliability using parameterized component specifications. Annotation-based methods, including the AADL Error Model Annex [39], generate fault trees from declared error states. While these approaches address broader questions than those considered here, they require pre-calibrated operational profiles and failure rates, which are generally unavailable at commit time. In contrast, SaG addresses a single targeted question using only manifests: which components’ failures propagate most extensively through the system? For instance, Seer [40] and Sage [41] predict Quality-of-Service (QoS) violations using hardware counters and traces, while MicroRCA [42] and TraceRCA [43] identify root causes via service-dependency graphs. DeepTraLog [44], Eadro [45], and MicroCause [46] utilize graph neural networks to analyze multimodal traces, logs, and metrics, as comprehensively surveyed by Zhang et al. across 98 studies [47]. Zhou et al. [48] demonstrate in industrial benchmarks that cascading outages in synchronous microservices frequently result from thread-pool exhaustion, remote procedure call (RPC) timeouts, and recursive retry storms propagating along call trees. Conversely, failures in publish–subscribe systems propagate through broker queue saturation and message starvation. All these methods require a running cluster that emits runtime telemetry, whereas SaG offers a pre-deployment alternative by analyzing static manifests before code execution.

## 2.2 Static Code Analysis (SCA) vs. Static System Analysis (SSA)

Traditional **Static Code Analysis (SCA)** tools (e.g., SonarQube [19]) inspect source code Abstract Syntax Trees (ASTs) within individual services. They evaluate cyclomatic complexity [20], class cohesion, module coupling (e.g., Lack of Cohesion in Methods [LCOM], Coupling Between Objects [CBO]) [21, 22], and code duplication to flag internal code smells and defect-prone modules [49, 50, 51, 52]. However, SCA cannot observe runtime communication topology: it does not capture inter-service messaging channels, message broker queue saturation, or cross-host failure propagation.

Static recovery of system-level structure is an active area of complementary research. Bushong et al. [53] derive communication diagrams from static code analysis, and a recent review evaluates nine architecture recovery tools [54]. In robotics and publish–subscribe ecosystems, specialized static analysis tools such as HAROS [55] extract computation models to identify structural defects before system launch. This body of literature aims to construct accurate representations of implemented systems to support comprehension and drift detection. In contrast, SaG uses a declared topology as input to forecast cascade blast radii.

To address the “Architecture–Code Gap,” **Static System Analysis (SSA)**—distinct from static single assignment—extends static analysis from individual service source code to the global system architecture. Using modeling of distributed applications, message topics, brokers, execution nodes, and shared libraries as a connected multigraph, SSA propagates code-level quality metrics across architectural dependencies. This methodology helps engineering teams detect structural anti-patterns [56, 57] and architectural technical debt [58] early in the continuous integration (CI/CD) process [59, 60], before deploying defective topologies.

## 2.3 Software Quality Models and Multi-Criteria Evaluation

Software product quality is standardized by the **ISO/IEC 25010:2023** product quality model [13] and the **ISO/IEC 25019:2023** Quality-in-Use model [14]. Of the characteristics ISO/IEC 25010:2023 defines under Reliability, Maintainability and Efficiency of Performance, SaG operationalizes only the strict subset derivable from deployment topology: Availability and Fault Tolerance, plus Modularity, Modifiability and Analyzability (§5.1). The core claim is that Faultlessness, Recoverability, Reusability and Testability lie outside topological analysis.

Software engineering measurement explicitly distinguishes between *internal quality* (inherent structural attributes assessed on static artifacts) and *external quality* (runtime dependability and behavioral characteristics noted during system execution) [61, 62]. In distributed architectures, architectural technical debt—such as over-centralized message topics or unreplicated brokers—reduces internal quality and can cause substantial external performance bottlenecks, queue congestion, and outages.

Aggregating multi-attribute structural metrics into an auditable quality score is a classic Multi-Criteria Decision Making (MCDM) problem. The Analytic Hierarchy Process (AHP) [63] supplies a structured pairwise-comparison methodology that incorporates an explicit Consistency Ratio ($CR \\le 0.10$) to guarantee consistency among elicited judgments. While this statistic detects inconsistency, it does not identify matrices completed with predetermined answers, a limitation this study addresses in the weighting process (§5.2). This work applies AHP to establish an audited, explainable Reliability–Maintainability (RM) quality baseline alongside learned graph models, making the claim that the baseline is both explainable and audited.

## 2.4 Graph Representation Learning and Explainable AI

Network science offers established centrality indices for identifying critical nodes, such as degree, closeness, betweenness centrality [24, 26], articulation points, and PageRank [25, 27]. Fundamental studies on network robustness [10], cascading overloads [8], and interdependent networks [9] model the propagation of disruptions over interconnected topologies. While percolation models act as natural theoretical comparators for network disintegration, analytical bond and site percolation limits assume statistically homogeneous, undirected connectivity and cannot be computed in closed form for directed multigraphs with asymmetric entity semantics, heterogeneous channel capacities, and continuous Quality-of-Service (QoS) contracts. Consequently, the training-free baselines in this study are centrality-based (§6.2), and targeted multi-type percolation fragmentation is a promising direction for future baseline development.

Standard network measures present two major shortcomings in the context of software architectures. First, Dimensional Collapse arises when a single centrality value cannot distinguish the underlying causes of a component’s criticality, such as differentiating between an isolated single point of failure, an error-propagating cascade hub, or an over-shared library. Second, Semantic Collapse occurs when unweighted metrics treat all nodes and edges equally, conflating fundamentally distinct architectural entities such as asynchronous message topics, shared libraries, and physical execution hosts.

To overcome the limitations of hand-engineered metrics, recent research has applied machine learning to network vulnerability analysis (e.g., FINDER [64], DrBC [65], PowerGraph [66]). However, most models employ homogeneous message passing (GCN [67], GraphSAGE [68], GAT [69]) and indiscriminately average signals across connection types. Given the inherent heterogeneity of distributed software architectures, these models obscure entity boundaries and generalize poorly to out-of-distribution scenarios. Heterogeneous Graph Neural Networks (RGCN [70], HAN [71], HGT [72], MAGNN [73]) address this issue through relation-specific transformations. This study uses the Heterogeneous Graph Transformer (HGT) [72] to preserve typed relational semantics when forecasting cascade blast radii. Graph learning has also been directly applied to microservice topologies; for instance, Khodabandeh et al. [74] predict future service interactions using graph attention over temporally segmented call graphs. However, that approach forecasts edge existence relying on observed interaction history. In contrast, the present method uses a declared topology as input and predicts the blast radius resulting from node removal.

A major challenge in applying modern artificial intelligence to software engineering is the black-box barrier: deep neural models generate risk scores or continuous embeddings without elucidating basic structural causality. In production environments, these uninterpretable risk rankings hinder actionable decision-making, as developers and site reliability engineers (SREs) cannot determine whether to replicate hosts, configure circuit breakers, or refactor shared libraries.

Existing graph neural network (GNN) explanatory methods, such as GNNExplainer [75] and PGExplainer [76], identify influential subgraphs through edge masking or parameterized learning. Although these methods are valuable, they interpret models using internal hidden representations rather than standardized software engineering concepts. SaG tackles this limitation through a decoupled dual-pathway design. The predictive HGT pathway reveals typed mutual-attention distributions that indicate which architectural relations propagated the cascade (§7.3.3). Concurrently, the deterministic explanation layer attributes fragility to standardized ISO/IEC quality sub-characteristics (§5), translating raw predictions into implementable, cost-effective remediations.
