# 4. Ranking Methods, Simulation Oracles, and the Reference Criterion

This study evaluates three categories of ranking methods: analytical rankings derived directly from dependency structure, hybrid methods that combine an analytical prior with a learned correction, and learned methods that infer rankings from graph representations. The training-free baseline, `Topo-QoS`, applies QoS-weighted betweenness to the dependency graph, and §5.2 defines the analytical references. The learned methods use graph neural networks on the typed multigraph and the dependency graph, and gradient-boosted models with per-Application dependency-graph features (§§4.1–4.2 and 5.2). Hybrid methods adjust the `Topo-QoS` score with a learned correction (Figure 3). All methods are trained on or evaluated against simulation oracles that run on a separate graph view (§4.3). Because several rankings are derived from the same failure-propagation assumptions the simulators use, the evaluation distinguishes rankings that restate a simulator’s rule from those that predict its outcomes (§4.4). Figure 3 illustrates the methods and their evaluation; full hyperparameters and training commands are in the experiment pages of the replication repository (§5.1).

## 4.1 Heterogeneous Graph Transformer and Attention Networks

The main learned ranker, `HGT-QoS`, is a three-layer Heterogeneous Graph Transformer (HGT) [72] built with PyTorch Geometric [80]. It uses a hidden dimension of $D=64$ and $H=4$ heads; on the dependency graph, which has fewer relation types, `HGT-P-QoS` uses width $100$ so that its parameter count ($430{,}680$) stays within $1\%$ of `HGT-QoS` ($434{,}620$). Entity-specific linear projections map raw node features $x_v \in \mathbb{R}^{19\text{--}25}$ into the hidden space, with $h_v^{(0)} = \text{LayerNorm}(\text{GELU}(W_{\tau(v)} x_v))$. For each meta-relation $\langle \tau(u), \phi(e), \tau(v)\rangle$, attention uses type-parameterized keys, queries, and values, scaled by a learned per-meta-relation prior $\mu_{\langle \tau(u), \phi(e), \tau(v)\rangle}$; full layer-wise formulations are in Supplementary §S2.1. Message passing runs over both $G_{\text{analysis}}$ and its transpose. In the raw multigraph $G_{\text{structural}}$, native relations point away from Applications (e.g., `PUBLISHES_TO`, `RUNS_ON`, `USES`), so forward message passing cannot propagate messages to the scored Application nodes. As a result, forward GNNs on $G_{\text{structural}}$ collapse structurally into per-node MLPs operating over precomputed centrality features (§7.2). In contrast, the derived dependency graph $G_{\text{analysis}}$ explicitly directs edges from dependents to dependencies, allowing forward message passing to aggregate information from downstream consumers. The homogeneous Graph Attention Network (`GAT-QoS`, and `GAT-P-QoS` on the dependency graph) uses a three-layer architecture with four attention heads and width $D=288$ ($D=296$ in the unweighted control for parameter matching), projecting all node types into a joint embedding space before applying homogeneous `GATConv` layers.

Each directed edge has a 16-dimensional vector. Index 0 represents the coupling weight, index 1 is the normalized path count, indices 2 to 8 are a one-hot encoding of the relation, and indices 9 to 15 are middleware QoS parameters such as reliability, durability, priority, transport departure mode, deadline constraints, and max-blocking time. The edge vector is projected and added before attention.

## 4.2 Prediction Head and Training Objective

A composite head predicts the simulated cascade impact, supplemented by an active auxiliary head $\hat{a}_1$ regressing on the simulator’s reliability column $I^*_R$. (A secondary maintainability head defined in the schema is masked out of backpropagation because the simulator produces no maintainability labels.) The operational training objective combines mean-squared error regression with listwise and margin-ranking terms: $$\tag{3}
\mathcal{L} = \text{MSE}(\hat{I}^*, I^*) + 0.5 \cdot \text{MSE}(\hat{a}_1, I^*_R) + 0.3 \cdot \mathcal{L}_{\text{rank}} + 0.1 \cdot \mathcal{L}_{\text{pairwise}},$$ where $\mathcal{L}_{\text{rank}}$ is Listwise Maximum Likelihood Estimation (ListMLE) [81] over the permutation $\pi$ induced by the simulated labels, $$\tag{4}
\mathcal{L}_{\text{rank}} = -\frac{1}{N}\sum_{i=1}^N \Big( \hat{s}_{\pi_i} - \log \sum_{j=i}^N \exp(\hat{s}_{\pi_j}) \Big),$$ and $\mathcal{L}_{\text{pairwise}}$ is a margin-ranking loss with $\gamma = 0.05$ over pairs differing by more than $\gamma$. Tied labels, which affect about 31% of Applications with $I^* = 0$, enter $\pi$ in a fixed deterministic sequence (ordered by entity identifier). While this injects an arbitrary ordering among inactive nodes into ListMLE, the margin-ranking term explicitly ignores pairs separated by less than $\gamma = 0.05$, dampening gradient penalties from tied inactive components.

Models are trained with AdamW ($\eta = 3 \times 10^{-4}$, weight decay $10^{-4}$) using cosine warm restarts for up to 300 epochs. We set early stopping at 60 epochs of patience on a 20% node-level validation split from the largest training scenario, using five fixed seeds ($\{42, 123, 456, 789, 2024\}$); while this node-level split is transductive with respect to that scenario’s internal graph, all reported evaluations are strictly inductive under leave-one-scenario-out cross-validation. We set hyperparameters and loss coefficients before the first sweep and kept them the same across all experiments. This approach differs from the registered plan, which called for selecting every hyperparameter using nested inner-LOSO selection (two-fold inner holdout). Instead, the published results use one fixed configuration, chosen during the main experiments to keep computation manageable across seeds and folds. We explain this difference in §5.3. We ran the registered selection later as a sensitivity analysis on the eight-configuration stage-1 grid (varying depth and rank normalization of features and labels). This analysis also used early stopping on a held-out training scenario, which is another difference from the published protocol (§6.2). The results confirm that the main null finding does not change under nested tuning.

## 4.3 Simulation Oracles

The simulators define three different notions of cascade impact rather than direct observations of real failures, so they serve as evaluation criteria whose assumptions can favor some ranking methods over others. Labels come from three failure simulators, which serve as label oracles (we use the two terms interchangeably), on the raw structural multigraph $G_{\text{structural}}$:

-   **Primary reachability cascade oracle ($I^*$):** Crashes component $v$, propagates outages through dependent topics, brokers and links via breadth-first traversal on $G_{\text{structural}}$, and computes the mean fractional feed loss across intact subscribers. Feed loss is scaled by a QoS severity ladder ($\times 1.2$ `RELIABLE`, $\times 1.15$ high priority, $\times 1.05$ medium) and clamped to $[0, 1]$. Each propagation wave is processed in a seeded random order, which decides ties at the propagation threshold; the label is the mean over five seeds. Disabling QoS scaling leaves the Application ordering largely intact ($\rho = 0.965$ across the twelve folds), and substituting durability-aware rescaling moves it less still ($\rho = 0.977$), showing that $I^*$ is predominantly a topological reachability metric.

-   **Queue-flow discrete-event oracle ($I_{\text{dyn}}$):** A discrete-event SimPy [82] simulation to model dynamic message emission rates, queue buffer saturation, and network latency. It measures the drop in delivered message rate for surviving consumers under load, using declared rates, payload sizes, and QoS contracts that $I^*$ ignores. QoS policies act on the queues directly: on overflow, a `RELIABLE` topic drops its oldest message and a `BEST_EFFORT` topic the newest; durable topics replay retained messages after the fault; transport priority orders service; deadlines and lifespans expire messages; and history depth sets queue capacity. No run with these policies disabled was made, so the simulator’s sensitivity to QoS is not quantified. Its mechanism differs from reachability, but it shares the same pub-sub topology, and its first-order effect—consumers that lose a failed publisher’s messages—is again subscriber loss. While $I_{\text{dyn}}$ models declared rates and buffer limits, it operates on configured parameters free of physical operating-system dynamics like socket buffer backpressure, thread scheduling, or garbage collection pauses. It provides labels for all $1{,}321$ Applications, averaging over five seeds, and takes $12.7$ CPU-hours for the full corpus, compared to seconds for $I^*$. A sensitivity check restricted to the first $30$ Applications per fold in lexicographic order is reported in Supplementary §S38 (Table S62). $I_{\text{dyn}}$ agrees with $I^*$ at a mean $\rho = 0.711$ $[0.625, 0.794]$. Across seeds, a single $I_{\text{dyn}}$ run agrees with another at $\rho = 0.43$–$0.96$ per fold; the five-seed mean used as the label has an estimated reliability of $r = 0.79$–$0.99$ (Spearman–Brown), so no ranker can agree with it by more than $\sqrt{r} \approx 0.89$–$0.996$ per fold. Every ranker in Table 6 stays below even $r$ on every fold; per-fold values are in the replication package.

-   **Composite multi-criteria failure oracle ($I_{\text{comp}}$):** An auxiliary benchmark uses the Validate-stage failure simulator. We run it on all $1{,}321$ Applications with QoS weighting and a primed baseline flow. Each removal is scored as a linear combination of four degradation components: $I_{\text{comp}}(v) = 0.35\,\text{RL}(v) + 0.25\,\text{FR}(v) + 0.25\,\text{TL}(v) + 0.15\,\text{FD}(v)$, representing Reachability Loss ($\text{RL}$), Fragmentation ($\text{FR}$; $0.70$ structural component loss $+\,0.30$ severity), Throughput Loss ($\text{TL}$), and Flow Disruption ($\text{FD}$). The weights were chosen, not elicited: the AHP matrix behind them was filled in to reproduce this vector. $I_{\text{comp}}$ therefore serves as a declared multi-objective stress test to assess resilience to network fragmentation and throughput disruption, rather than just subscriber loss. Since fragmentation and flow disruption occur with almost every removal, $I_{\text{comp}}(v) > 0$ for nearly every Application. $I_{\text{comp}}$ is never used as a training label.

## 4.4 Input–Label Separation and the Reference Criterion

No simulation output is used as an input: node features are computed on $G_{\text{analysis}}$, and labels come only from the oracles, which execute on $G_{\text{structural}}$; a regression test in the replication package ensures this separation. The separation is between inputs and labels, not between graphs: the raw-graph learners pass messages over the same structural edges the oracles traverse.

Procedural separation does not eliminate construct overlap, which is the main risk discussed in this paper. High agreement with a simulator does not necessarily imply predictive skill: a ranking may correlate strongly with a simulator because it reproduces the simulator’s propagation rule, not because it infers impact from independent evidence.

**The reference criterion.** We established the formal concept of the reference criterion post hoc to understand why simple dependency counts performed so strongly. A ranking is a *reference* for an oracle $O$ if it is a closed-form simplification of $O$’s own computation using the same inputs. A reference measures how much of $O$ comes from its own rule, not predictive skill, so comparisons with it are not claims of superiority. All other rankers, namely the training-free baseline and the learned and hybrid methods, are *predictors*. For $I^*$, the first propagation wave corresponds to the set of `InDeg` counts (see Remark 1), which is classical publish–subscribe afferent coupling [54, 55]; the references are therefore its first-order expansion (Eq. 6), `InDeg`, `Reach`, and their raw-graph equivalents. For $I_{\text{dyn}}$, the rate-weighted first-order expansion (Eq. 7) truncates its computation to direct subscriber loss weighted by declared publication rates, so it is the reference for that simulator; the $I^*$ references are also reported for comparison. For $I_{\text{comp}}$, no ranking is a truncation; its fragmentation and flow terms respond to removing high-degree and high-betweenness nodes, so `Topo-QoS` and raw degree are *term-aligned* with it. They are not references under the definition above, but their performance is interpreted with the same caution. How much of each oracle its own rule recovers is read directly from the reference rows: the first-order expansion reaches $\rho = 0.808$ on $I^*$, and the rate-weighted expansion $0.830$ on $I_{\text{dyn}}$ (Tables 5 and 6). The learned methods are not references by this definition, but they use in-degree features and are trained on the oracle they are scored against, so they share some overlap (§6.2 measures this). References are therefore reported to show how much agreement can be obtained by encoding a simulator’s assumptions directly, and predictors are evaluated against them to determine whether learning adds information beyond explicit dependency structure. Two analyses limit the circularity instead of removing it. Every ranker is evaluated on all three oracles, and its agreement with $I_{\text{dyn}}$ is also reported after removing the effect of $I^*$ (and separately, the first-order term) (§6.1). However, none of these analyses replaces validation against real failures in live distributed systems, which this study does not include (§7.5). All results are therefore conditional on simulation fidelity.
