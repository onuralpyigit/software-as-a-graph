# 9. Conclusion

This study explored how well heterogeneous graph neural networks can support pre-deployment dependability analysis in asynchronous distributed systems. We used Software-as-a-Graph (SaG) to turn Architecture-as-Code manifests into typed multigraphs. We then compared a relation-specific Heterogeneous Graph Transformer with QoS edge encodings to unparameterized structural baselines and an ISO/IEC 25010/25019 attribution layer without runtime telemetry. Our main question was whether relation typing and QoS encodings improve prediction when used together or separately.

The main finding is that relation typing and 16-dimensional QoS edge encodings act as substitutes rather than working together. Each one has a significant effect under inductive distribution shift ($\Delta\rho = +0.134$ and $+0.187$, Holm $p = 0.0015$, with typing indicating the move to HGT), but when combined, their interaction is negative ($-0.199$ across all twelve folds, $p = 0.0005$; $-0.233$ after a Fisher transformation). In other words, the sub-additivity comes from the mechanisms themselves, not the metric: typing adds $+0.234$ without QoS and only $+0.035$ with it. Using both together gives little extra benefit, which suggests both channels encode similar traversal semantics for a nearly topological simulation target (recovered at $\rho = 0.965$ without QoS). Typing also brings a $15.4\times$ capacity gap and changes message-passing directionality.

These outcomes have practical consequences for distributed software engineering: (1) In complex asynchronous publish–subscribe event meshes like ROS 2, DDS, or MQTT, `HGT-QoS` gives important relational inductive bias under distribution shift, achieving strong zero-shot transfer on active failure spreaders ($+0.517$ on Autoware, $+0.702$ on Home Assistant) where training-free baselines fail; (2) for lightweight CI/CD gating with limited resources, the closed-form `Topo-QoS` baseline ($\rho = 0.553$) offers instant deterministic ranking with no training or GPU use; (3) for production pre-deployment gating, the Dual-Engine Consensus Protocol combines both tools, prioritizing components that both rank as top-$K$ critical and highlighting ranking differences for expert review; (4) the ISO/IEC 25010 explanation layer provides clear root-cause attribution to guide targeted refactoring (Availability replication vs. Fault-Tolerance circuit breakers) instead of continuous ranking. Meanwhile, while forward neural inference runs in $56\,\text{ms}$, deterministic feature extraction takes $2$ to $18$ times longer than the simulation it replaces (median $5.6\times$ over twelve scenarios). This shows that static analysis helps avoid extra infrastructure (like live staging clusters) rather than providing a raw CPU speed advantage, unless used with incremental topology caching. Two main following steps remain: internally, the predictors are currently scored against a deterministic function of their own input, so the next test is to compare them to the queue-flow oracle, whose behavior cannot be recovered from the graph in closed form. Externally, and more importantly, none of these outcomes have been validated against real failures. Whether these pre-deployment pipelines can predict live production outages is still the main empirical question, and this study does not answer it.
