Triage Walkthrough

A ranking says which components matter. A diagnosis says why. Triage is where the two meet, and where the method decides how loudly to speak: a note on a pull request, a warning, or a block. This page shows the join, then follows one small change through each tier.

1 · the bridge

A shortlist from one pathway, a root cause from the other, joined by id

The ranking supplies the top three. Each is then looked up in the deterministic quality profile for its pattern, level, first action and owner. A trained model carries no cause of its own, so nothing is ever read off its weights. With no trained model the quality score supplies the ranking too; that is the cold start.

3 · tier 1 · pull-request time

Closed-form references produce a note, not a verdict

At commit time only training-free references run: the count of direct dependents and the rate-weighted first-order expansion. They cost almost nothing, so they can run on every push. Their output is an informational comment listing the services the change makes more critical.

4 · the gate

Block on what the change introduces, not on what was already there

An absolute gate fails any system with a critical finding, which here means the baseline too. The delta-aware gate compares the candidate's findings with the merge-base's and counts only the new ones.

5 · tier 2 · staging time

Targeted simulation measures what the change actually does

Simulation is slower, so it runs later and only where tier 1 pointed. Each application is failed in turn on the baseline and on the candidate, and the cascade impact is compared.

Reading the result

What the tiers did with one change

    How this was produced. python examples/run_triage_walkthrough.py on examples/mini_atm.json and a copy with one topic added: Client.diagnose(k=3) and Client.triage for the bridge, derive_flow_projection and the rate-weighted closed form for tier 1, saag.analysis.delta_gate.delta_gate for the gate, and FaultInjector with five seeds for tier 2.

    The method does not fix a tier-2 blocking threshold; that is a service-level decision for the team. The change was chosen to be clearly harmful, so the tiers agree. On a real system most changes are less clear, which is why reachability rankings are kept as notes and not as blocking gates.
