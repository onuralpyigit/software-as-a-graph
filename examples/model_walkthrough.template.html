Model Walkthrough

Everything the method later predicts, diagnoses or simulates starts from one file describing an architecture. Model turns that file into a weighted graph in two moves: it weighs what is declared, then derives who depends on whom. This page follows both moves on a 15-component air-traffic system, and every number is recomputed and checked against what the repository stored.

1 · the input

The file states facts an architect already has: which applications publish and subscribe to which topics, which broker routes each topic, what runs on which host, which library is used by whom, and each topic's delivery contract. Nothing here is measured at run time.

publishes / subscribesroutesuseslabels show the weight each component ends up with
2 · weigh the topics

A topic's weight says how much it matters if it is lost. Three declared properties decide it: the delivery contract, the payload size and the publish rate. The contract dominates.

Topic
3 · weigh the components

Components inherit weight from what they touch

An application has no contract of its own. It takes its weight from its topics, a broker from the topics it routes, a library from the applications that use it, and a host from the heaviest thing running on it.

4 · derive the dependencies

Data flows from publisher to subscriber; dependency runs the other way. Rules read the raw structure and write a DEPENDS_ON edge from each dependent to what it depends on. Select a rule to filter the matrix, and a cell to see how that edge was derived and weighted.

5 · project the layers

Four views of the same graph, each for a different question

Later steps never analyse everything at once by default. They pick a layer, which keeps some component types and some dependency rules.

Reading the result

What the model now holds, and what it deliberately keeps apart

    How this was produced. python examples/run_model_walkthrough.py on examples/mini_atm.json: MemoryRepository.save_graph and derive_dependencies. The repository returns finished weights only, so the script recomputes each topic weight, component weight and edge weight with the public helpers in saag/core/models.py and asserts that they match.

    Two of the seven derivation rules do not fire here: mini-ATM has one broker per host, so no broker-to-broker edge, and no switches or routers, so no host-to-device edge.
