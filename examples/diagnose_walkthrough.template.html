Diagnose Walkthrough

Diagnose does not predict anything. It reads the structural metrics and explains, in the terms of the ISO quality model, why a component is risky: is it a hub others lean on, a single point whose loss splits the system, or a bottleneck that is costly to change? Every number here follows from a fixed formula, shown term by term.

Component
1 · three sub-scores

Each sub-score is a weighted sum of structural metrics, normalised against the rest of the system so that 1.0 means "the most extreme component here". The weights are fixed in advance; nothing is fitted to this system.

2 · the roll-up

Two fixed combinations turn three sub-scores into one

Fault tolerance and availability combine into reliability. Reliability and maintainability combine into Q(v).

3 · the level

Levels are relative. The quartiles of Q(v) across the system set the boundaries, and a component is critical only if it sits beyond the upper fence. There are no absolute cut-offs.

4 · the explanation

For components rated high or critical, the scores are turned into a named pattern, the metric that drives each elevated dimension, a first action and the role it belongs to.

Reading the result

What this run shows

    How this was produced. python examples/run_diagnose_walkthrough.py on examples/mini_atm.json: Client.analyze(layer="system") then Client.diagnose. The quality model returns only totals, so the script retraces each term from the model's own normalisation table and weights and checks that the terms sum to the reported sub-scores.

    Fifteen components give coarse quartiles: one component moving changes a boundary. The page shows how a diagnosis is derived, not how well it matches reality; that is the Validate step's job.
